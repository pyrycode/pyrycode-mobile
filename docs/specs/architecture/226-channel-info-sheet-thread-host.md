## Context

`ChannelInfoSheet` + `ChannelInfoUiModel` landed in #217 as a stateless, host-agnostic component. The thread overflow scaffold landed in #251 (introduced `ThreadEvent` + `onOverflowEvent`, `ChannelInfo` as a no-op stub) and #252 (mounted the menu, wired the event sink through `MainActivity`). This ticket connects the two: tapping **Channel info** in the overflow menu now opens the populated sheet.

`#229` (StatusSheet — Effort + YOLO) merged first (PR #263) and reshaped `ThreadUiState` (added `selectedModel` / `selectedEffort` / `yoloEnabled` / token fields) and collapsed the `state` builder into a **5-argument** `combine` with grouped `TransientDialogs` / `RunConfig` flows. We design against that merged baseline. The single most important constraint is that we must not exceed the 5-arg `combine` ceiling.

Rename's downstream dialog flow is already wired (#141), so emitting `ThreadEvent.Rename` from the sheet fully takes effect. `ChangeWorkspace` remains a no-op pending its own ticket — emitting it is harmless and forward-compatible. Archive / Delete from the sheet are deliberately *not* wired to the repository here; sibling **#227** adds the real archive/delete-from-sheet flow (it needs a one-shot pop-back navigation mechanism + a delete-confirmation dialog).

## Design

Three edit sites. No new files. No visibility widening.

### 1. `ThreadEvent` — one new case (`ThreadViewModel.kt`)

Add a dismiss event mirroring `RenameDismiss`:

```kotlin
data object ChannelInfoDismiss : ThreadEvent   // mirrors RenameDismiss
```

`ChannelInfo` already exists; no other event is added (Install is a pure no-op lambda with no event; Archive/Delete from the sheet route through `ChannelInfoDismiss` only — see § 4).

### 2. `ThreadUiState` — `channelInfoOpen` + 3 ingredient fields (`ThreadViewModel.kt`)

`ChannelInfoUiModel` is `internal`; `ThreadUiState` is `public`. **Do not put the model on the state** (public-API-exposes-internal-type error). Instead expose the raw, stdlib-typed ingredients and assemble the model in the screen layer (§ 3). New fields, all defaulted so no construction site (previews, `initialValue`, tests) is forced to change:

```kotlin
val channelInfoOpen: Boolean = false,
val workspacePath: String = "",          // conv.cwd — full path, distinct from the leaf-only workspaceLabel
val lastUsedAt: Instant? = null,         // conv.lastUsedAt; formatted in the screen layer
val sessionCount: Int = 0,               // conv.sessionHistory.size — already reachable, no new flow
```

Requires `import kotlinx.datetime.Instant` in `ThreadViewModel.kt`.

`conversationName`, `channelId`, `createdLabel`, and `messageCount` need **no** new fields — they derive from existing `displayName`, `conversationId`, and `items` (see § 3).

### 3. State plumbing — fold into the existing groups (`ThreadViewModel.kt`)

- New private source: `private val pendingChannelInfo = MutableStateFlow(false)` (precedent: `pendingRenameDialog`).
- Extend the **existing** `transientDialogs` inner `combine` from 2 → 3 args (still well under the arity limit) and add the field to `TransientDialogs`:

```kotlin
private data class TransientDialogs(
    val renameVisible: Boolean,
    val saveAsChannel: SaveAsChannelDialogState?,
    val channelInfoOpen: Boolean,        // new
)
// combine(pendingRenameDialog, pendingSaveAsChannelDialog, pendingChannelInfo) { rename, save, channelInfo -> … }
```

- The top-level `state` `combine` stays **5 args** (unchanged). In its mapping block, populate the new `ThreadUiState` fields:
  - `channelInfoOpen = dialogs.channelInfoOpen`
  - `workspacePath = conv?.cwd ?: ""`
  - `lastUsedAt = conv?.lastUsedAt`
  - `sessionCount = conv?.sessionHistory?.size ?: 0`

- `onOverflowEvent`: lift `ChannelInfo` out of the no-op branch and add the two handlers:

```kotlin
ThreadEvent.ChannelInfo -> pendingChannelInfo.value = true
ThreadEvent.ChannelInfoDismiss -> pendingChannelInfo.value = false
// no-op branch shrinks to: ThreadEvent.NewSession, ThreadEvent.ChangeWorkspace -> Unit
```

### 4. Screen layer — pure mapper + sheet host (`ThreadScreen.kt`)

**Pure mapping helper** (extension on `ThreadUiState`, `internal` so the JVM unit test can call it directly — same-module visibility). This keeps the derivation out of the composable and unit-testable with an injectable `now`:

```kotlin
internal fun ThreadUiState.toChannelInfoUiModel(now: Instant = Clock.System.now()): ChannelInfoUiModel
```

Behavior (one line per field — assert in the unit test, § Testing):
- `conversationName = displayName`
- `workspacePath = workspacePath`
- `createdLabel` = `formatRelativeTime(items.firstOrNull()?.timestamp() ?: <fallback>, now)`; when `items` is empty, render the em-dash `"—"` (no thread stream → no created anchor).
- `lastActivityLabel` = `lastUsedAt?.let { formatRelativeTime(it, now) } ?: "—"`
- `sessionCount = sessionCount`
- `messageCount = items.count { it is ThreadItem.MessageItem }`
- `memoryPlugins = emptyList()` (no plugin data source until Phase 3+; renders the `None` + Install empty-state)
- `channelId = conversationId`

`items` is chronological-ascending (the screen reverses it for display via `asReversed()`), so `items.first()` is the earliest item. Small private helper for the timestamp, near `mostRecentSessionBoundaryIndex`:

```kotlin
private fun ThreadItem.timestamp(): Instant = when (this) {
    is ThreadItem.MessageItem -> message.timestamp
    is ThreadItem.SessionBoundary -> occurredAt
}
```

**Sheet host** — slot a new block alongside the existing `if (sheetVisible) { StatusSheet(…) }` host (gate on the ViewModel-driven flag, not local screen state, because the trigger arrives through `onOverflowEvent`):

```kotlin
if (state.channelInfoOpen) {
    ChannelInfoSheet(
        model = state.toChannelInfoUiModel(),
        onRename = { onOverflowEvent(ThreadEvent.Rename); onOverflowEvent(ThreadEvent.ChannelInfoDismiss) },
        onChangeWorkspace = { onOverflowEvent(ThreadEvent.ChangeWorkspace); onOverflowEvent(ThreadEvent.ChannelInfoDismiss) },
        onArchive = { onOverflowEvent(ThreadEvent.ChannelInfoDismiss) },   // placeholder — see warning below
        onDelete = { onOverflowEvent(ThreadEvent.ChannelInfoDismiss) },    // placeholder — see warning below
        onInstallMemoryPlugin = { /* TODO: Phase 3+ */ },                  // no event, no dismiss
        onDismiss = { onOverflowEvent(ThreadEvent.ChannelInfoDismiss) },
    )
}
```

New imports in `ThreadScreen.kt`: `ChannelInfoSheet`, `ChannelInfoUiModel`, `formatRelativeTime` (all `internal` in the `components` package — visible same-module), and `kotlinx.datetime.Clock`.

> **⚠️ `onArchive` / `onDelete` must NOT emit `ThreadEvent.Archive`.** `ThreadEvent.Archive` *is* already wired to `repository.archive(...)` (`ThreadViewModel.kt:199-202`) — the obvious-looking wiring is the wrong one here. The sheet's Archive needs a pop-back navigation after archiving (the channel leaves the list) and Delete needs a confirmation dialog; both are owned by sibling **#227**. Until then, the sheet's Archive and Delete buttons **only dismiss the sheet**. Emitting `ThreadEvent.Archive` here would archive the channel with no nav follow-up — a half-built flow. Dismiss-only is intentional.

> **`onInstallMemoryPlugin`** is an empty lambda carrying only a `// TODO: Phase 3+` comment — no event, no dismiss, no user-visible feedback (per AC).

## State + concurrency model

- **Single source of state** unchanged: `ThreadViewModel.state: StateFlow<ThreadUiState>` via `stateIn(WhileSubscribed(5_000))`. `channelInfoOpen` is one more `MutableStateFlow<Boolean>` (`pendingChannelInfo`) folded through the existing `transientDialogs` group — identical lifecycle to `renameVisible`. No new `viewModelScope` job, no dispatcher change, no repository call (display + local UI flag only).
- **Ordering on Rename/ChangeWorkspace:** the two `onOverflowEvent` calls set two independent `MutableStateFlow`s; the `transientDialogs` combine coalesces to a consistent final emission (`renameVisible = true, channelInfoOpen = false`). A one-frame overlap of dialog + closing sheet is visually negligible and matches the existing rename-from-menu path. No special sequencing needed.
- **Relative-time freshness:** labels are formatted at composition with `Clock.System.now()` (default arg), recomputed on each recomposition — same behavior as every existing list row. The sheet is transient, so drift is a non-issue.

## Error handling

No new failure modes. Pure display + local flag flips:
- **Missing conversation** (`conv == null`, e.g. ghost id): `workspacePath = ""`, `lastUsedAt = null` → `lastActivityLabel = "—"`, `sessionCount = 0`. Sheet still opens, degraded but safe — consistent with the existing `displayName` fallback to `conversationId`.
- **Empty thread stream** (`items` empty): `createdLabel = "—"`, `messageCount = 0`. Edge case (channel info on a message-less channel); no crash.
- No network/IO/parse paths touched (Phase 0, fake data layer).

## Testing strategy

**Unit (`./gradlew test`, `ThreadViewModelTest`)** — add to the existing class using `makeVm` + `fixedRepo`/`FakeConversationRepository`:
- `onOverflowEvent(ChannelInfo)` flips `state.channelInfoOpen` true (collector + `advanceUntilIdle`, as in the rename tests).
- `onOverflowEvent(ChannelInfoDismiss)` flips it back to false.
- `ChannelInfo` does not call `repository.archive` (RecordingRepo).
- **Update existing `onOverflowEvent_otherCases_doNotCallArchive` (line 644):** it currently emits `NewSession`, `ChangeWorkspace`, `ChannelInfo` and asserts archive isn't called. `ChannelInfo` no longer no-ops (it sets `channelInfoOpen`), but it still doesn't archive, so the assertion holds — leave it asserting "archive not called", optionally also assert `channelInfoOpen == true` after the `ChannelInfo` emit. Move `ChannelInfo` to its own positive test if cleaner.
- `state` populates `workspacePath` / `lastUsedAt` / `sessionCount` from a seeded `Conversation` (use `fixedRepo(listOf(channel))` with a known `cwd`, `lastUsedAt`, multi-entry `sessionHistory`).

**Unit — pure mapper (`toChannelInfoUiModel`)**, the highest-value new coverage (no device needed):
- Given a `ThreadUiState` with seeded `items` (a couple `MessageItem`s + a `SessionBoundary`) and a fixed `now`, assert: `messageCount` counts only `MessageItem`s; `createdLabel == formatRelativeTime(earliest item timestamp, now)`; `lastActivityLabel == formatRelativeTime(lastUsedAt, now)`; `sessionCount`, `channelId`, `conversationName`, `workspacePath` pass through; `memoryPlugins` empty.
- Empty `items` → `createdLabel == "—"`, `messageCount == 0`.
- `lastUsedAt == null` → `lastActivityLabel == "—"`.

**Instrumented (`./gradlew connectedAndroidTest`, follow `ThreadScreenOverflowTest`)** — `createComposeRule`, render `ThreadScreen` with `channelInfoOpen = true` + a recording `onOverflowEvent`:
- Sheet is displayed and shows the channel name, workspace path, and message/session counts.
- Tapping **Rename** records `[Rename, ChannelInfoDismiss]`.
- Tapping **Change workspace** records `[ChangeWorkspace, ChannelInfoDismiss]`.
- Tapping **Archive** / **Delete** records `[ChannelInfoDismiss]` only (no `Archive`).
- Swipe-down / close records `ChannelInfoDismiss`.

## Open questions

- **Workspace path for scratch conversations.** The sheet is reached from a channel thread, so `cwd` is normally a real path. For a scratch `cwd` (`DEFAULT_SCRATCH_CWD`) the row would show the sentinel path verbatim rather than the chip's "scratch" label. Out of scope to special-case here (the chip's `workspaceLabel()` helper is for the leaf chip, not this sheet); raise to PO if scratch display matters.
- **Created-date semantics.** "Earliest thread item timestamp" approximates conversation-creation time; it shifts if the oldest session is pruned from the stream. Acceptable for Phase 0. A real persisted `Conversation.createdAt` is explicitly deferred to a future schema ticket (per ticket Technical Notes — adding it now cascades ~45 constructor literals across ~16 files and breaks S).
