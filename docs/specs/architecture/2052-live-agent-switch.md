## Design

The existing isolated primary test instance gains Codex when the effective real-test selection includes this scenario: default whole class, curated full LIVE or an exact focused method/class selection. The normalized selection drives provisioning and instrumentation; unrelated focused and deterministic selections remain independent. A Python lease wrapper runs before daemon startup, validates explicit `PYRY_CODEX_CAPTURE_BIN` and `PYRY_CODEX_CAPTURE_HOME`, installs cancellation handling before preparation, acquires a nonblocking kernel lock in the dedicated home before either probe, checks version against the daemon minimum 0.156.1 using an empty temporary Codex home, and checks sign-in with discarded output. Both probes and the daemon shell use `CodexHomeLease.run_owned`: an isolated process group, inherited lease/lifetime descriptors, bounded cancellation/timeout and confirmed group plus descriptor-holder exit before the next phase or release. It links only the test instance's `codex-home` to the canonical dedicated home, never reads/copies sign-in files, and passes the executable to `-pyry-codex` before Claude's passthrough arguments. The gate's Claude authentication remains inherited. Missing prerequisites become fixed instrumentation reason codes; the named method fails rather than skipping. Deterministic mode never enters provisioning.

The wrapper owns the link and lock through confirmed daemon exit. The resolved test-instance name is explicitly passed to it. It starts the shell in an isolated process group and passes a lease descriptor and lifetime-pipe writer through the shell, controller and primary daemon. The controller terminates, kills on timeout and joins its daemon; shell cleanup preserves a controller failure. If shell/controller failure leaves owners alive, the wrapper terminates that group, escalates to kill after a bounded grace period, and requires both lifetime-pipe EOF and absence of live process-group members before unlinking. Codex app-server preserves this group through Go `os/exec` even though it closes inherited descriptors. Every shell exit checks the group, including after witness EOF. Cancellation leaves the polling wait immediately and enters bounded group termination/escalation instead of an unbounded shell wait. The lock file carries a fixed active marker before any probe starts and is cleared only after confirmed exit. An unconfirmed exit retains the link and unavailable marker; subsequent acquisitions fail `cleanup_unconfirmed` until operator-confirmed recovery. Inherited lease holders also preserve kernel exclusivity on abrupt wrapper death. Cleanup unlinks only the exact link it created and never deletes the source home. Direct use of the dedicated home by other tools must honour the same exclusive-use contract; Go live tests must not run concurrently.

The scenario creates and owns one fresh Claude channel. Private helpers select uncut, uniquely labelled, rendered rows from both agents; choices and effort expectations come from published metadata. Both model taps and Switch confirmations use Compose semantics in Run configuration opened by Tune. After each confirmation a host-bound repository observation requires the same channel, target agent, a distinct successor session and a fresh non-held reading matching that successor and model. The sheet's complete effort-radio set must equal the selected row's advertised levels. Three distinct test-authored markers identify finalized replies. After each switch, durable messages retain their original relative order and every earlier user/reply row is independently scrolled into view. The reversed LazyColumn’s key-to-index semantics prove rendered relative order without requiring adjacent authored rows to share a viewport. Each authored reply’s successful turn ID must also match its expected daemon-owned session/agent provenance in the isolated instance’s durable history, through a fixed loopback controller endpoint returning only a boolean; legacy message session fields cannot substitute for this proof. Cleanup deletes only the created channel, preserving original failures if cleanup also fails.

## State and concurrency model

Existing app ViewModels and relay lifetimes remain unchanged. Test observations use bounded `runBlocking`/`withTimeout`, with no persistent test coroutine. The host Python wrapper installs SIGTERM/SIGINT handling before preparation and owns one kernel lease across prerequisite probes and the shell; shell EXIT cleanup joins its controller, and the wrapper independently fences descriptor owners with lifetime-pipe EOF and actual agent descendants with process-group exit before release. SIGTERM/SIGINT immediately enter bounded group teardown even if the shell ignores them. Acquisition fails immediately when busy.

## Error handling

Only fixed prerequisite codes reach instrumentation; binary output, credentials and source-home paths never do. Missing published rows fail within the normal bounded model-menu deadline. Switch, reply or history failures use static assertion descriptions. Cleanup failures fail a green test or are suppressed on its original exception. No ignored assertion or manual gating of durable proof.
