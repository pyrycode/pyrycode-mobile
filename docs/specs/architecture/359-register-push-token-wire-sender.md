# Spec — `RemoteConversationRepository.registerPushToken` over v2 (`register_push_token`) (#359)

> Adds the **outbound wire capability** for FCM push registration: encode a `register_push_token`
> request, send it over the live Noise session pump, and await the correlated `ack`/`error` —
> **reusing** the `sendAndAwaitReply` request↔reply primitive (#346) and the `mapError` →
> `RelayErrorException` mapping unchanged. No new error mapping, no new `onInbound` branch, no
> projection mutation. Dormant until the Firebase sibling provides a real token and a live caller.

## Context

Phase 4 backend integration. The daemon already ships the server-side `register_push_token` handler
on the v2 path (pyrycode #250); the client side is unbuilt. This slice adds **only** the outbound
wire capability: a phone tells the paired daemon where to send a wake notification when backgrounded.

**Scope is deliberately one wire round-trip.** No Firebase, no token persistence, no lifecycle
policy, no UI — those are sibling slices. This slice exposes a `registerPushToken(token)` capability
that takes a token string *from anywhere* and performs exactly one request/reply. It is **dormant**:
nothing in the shipped app calls it yet (the Firebase sibling adds the live caller).

**The capability is NOT a `ConversationRepository` interface method.** Push-token registration is a
device/connection concern, not a conversation operation. Per `[[post-352-connection-scoped-repo-behind-facade]]`,
`RemoteConversationRepository` is now connection-scoped (built per connection in
`RelayRepositoryCoordinator.onConnection()`) behind the process-lifetime `StableConversationRepository`
facade that ViewModels hold — and that facade only delegates the `ConversationRepository` interface.
A method that is **not** on the interface therefore will **not** reach consumers through the facade.
That is intentional and correct: reaching this dormant capability from a live caller is the **Firebase
sibling's** job, not this slice's. **Do not add facade exposure, a new interface method, or DI
reachability here.** The AC only require the method to exist on the concrete repo and perform one
correct round-trip against a fake pump.

## Design

### Home: a method on `RemoteConversationRepository`, reusing the private primitive

`registerPushToken` is hosted as a public `suspend` method on `RemoteConversationRepository`,
reusing the existing **private** `sendAndAwaitReply`. This is the simplicity-first default the ticket
calls for and matches the three live mutations (#346/#347/#348), each of which hosts its request
encoder + builder on the repo over the same private primitive.

**A shared-sender extraction is explicitly NOT taken.** Extracting `sendAndAwaitReply` (plus
`pendingRequests`, `requestId`, the `ack`/`error` `onInbound` arms, and `mapError`) into a shared
collaborator touches the correlation core and re-wires the three existing call sites — it balloons
past S and is its own ticket. If a future device-concern slice (e.g. the Firebase caller) makes the
"this isn't a conversation operation, why is it on the conversation repo" tension acute, **route that
extraction back to PO as a separate refactor ticket** rather than smuggling it in here.

### New wire model (encode-only DTO) — its own file

New file `app/src/main/java/de/pyryco/mobile/data/network/RegisterPushTokenPayloadDto.kt`, one
`@Serializable data class`, file named after the class (the #347/#348 file-per-DTO convention; the
ktlint single-public-class filename rule, `[[ktlint-filename-rule-single-class]]`, makes a
dedicated file mandatory anyway).

- **Wire SSOT (pin, do not invent):** server `internal/protocol/push.go` `RegisterPushTokenPayload`
  (spec #275); golden `internal/protocol/testdata/register_push_token.json`; `docs/protocol-mobile.md`
  § `register_push_token`. Three fields, **all required**, Go-struct order: `platform`, `token`,
  `device_name`. Wire type string `register_push_token`.
- Encode-only (the phone only ever sends it; the reply is a bare `ack`, never a typed payload — do
  **not** model a response). `@SerialName("device_name")`; `platform` and `token` are single-word wire
  names needing no `@SerialName`. Always encode via `MobileJson`. Contract:

  ```kotlin
  @Serializable
  data class RegisterPushTokenPayloadDto(
      val platform: String,
      val token: String,
      @SerialName("device_name") val deviceName: String,
  )
  ```

  All three fields are non-nullable with no defaults (all required on the wire). `platform` is carried
  as a plain `String` (not an enum): the value is the constant `"fcm"` supplied by the caller-side
  constant below, and an encode-only DTO models only what it sends.

### `registerPushToken` itself

Public method on `RemoteConversationRepository` (concrete class only, **not** an interface override):

```kotlin
suspend fun registerPushToken(token: String)
```

Behavior (≤ ~12 lines, no projection mutation):
1. Build the request `Envelope(id = requestId.incrementAndGet(), type = TYPE_REGISTER_PUSH_TOKEN,
   ts = Clock.System.now().toString(), payload = MobileJson.encodeToJsonElement(
   RegisterPushTokenPayloadDto(platform = PLATFORM_FCM, token = token, deviceName = deviceName)))`.
2. `sendAndAwaitReply(request)` — **ignore the returned `{}` ack payload**. This call already:
   - throws `IllegalStateException` when `pump.send` returns `false` (session not Open) → AC #5;
   - suspends until the correlated reply lands → AC #1;
   - returns normally on the empty `ack` → AC #3;
   - rethrows the collector's exceptional completion on `error` → AC #4 (a `RelayErrorException`
     carrying `code`/`retryable` via the unchanged `mapError`).
3. Return `Unit`. **No projection is read or written** — unlike `sendMessage`/`createDiscussion`/
   `promote`, this capability registers a token and produces no domain object; the success signal is
   "the call returned without throwing".

That is the entire method. No `UUID` mint (no message id), no `recordLastMessage`/`appendMessages`/
`upsertConversation`, no decode of the reply.

### Device-name plumbing — defaulted constructor param, live wiring deferred

`device_name` must equal `NoiseClientInfo.deviceName` (the same value `hello` sends). That value lives
at the session/transport layer and is **not** currently injected into `RemoteConversationRepository`
(constructor is `(pump, scope)`). Per `[[post-352-connection-scoped-repo-behind-facade]]`, threading
the **live** value would mean a new constructor param **and** a matching param on
`RelayRepositoryCoordinator` supplied from `NoiseClientInfo` in `AppModule`'s coordinator block.

**This slice takes the minimal touch: a defaulted constructor param only.**

```kotlin
class RemoteConversationRepository(
    private val pump: SessionPump,
    scope: CoroutineScope,
    private val deviceName: String = "",
) : ConversationRepository {
```

- The param is **last and defaulted**, so the one production construction site
  (`RelayRepositoryCoordinator.onConnection()` → `RemoteConversationRepository(pump, childScope)`) and
  all ~30 existing test sites compile unchanged. **Zero edit fan-out; `AppModule` and the coordinator
  are not touched** — which is precisely what removes the original #352 conflict that parked this
  ticket (re-verified merged on `main` 2026-06-06).
- Tests inject a concrete `deviceName` (named arg) to assert the wire field.
- **Handoff contract (loud):** the default `""` is never exercised in production *today* because the
  capability has **no live caller**. The **Firebase sibling** that adds the live caller **must also**
  thread the live `NoiseClientInfo.deviceName` — by adding a `deviceName` param to
  `RelayRepositoryCoordinator` and supplying it from `NoiseClientInfo` in the `AppModule` coordinator
  block (the deferred two-line change). A live caller wired *without* that threading would send
  `device_name: ""`, polluting the server's `(platform, token, device_name)` dedup triple. This is the
  one cross-slice invariant the Firebase ticket owns; it is named here so the developer does not
  silently rely on the default.

### New companion constants

Add to the existing `private companion object`:
- `TYPE_REGISTER_PUSH_TOKEN = "register_push_token"` — the request wire type.
- `PLATFORM_FCM = "fcm"` — the Android push platform value (AC #2).

No new error-code constant: the push error codes (`server.binary_busy`, `auth.invalid_token`) are
**not** special-cased — they flow through `mapError`'s existing `else` arm to `RelayErrorException`.

## State + concurrency model

- **No new state, no new collector, no new scope.** `registerPushToken` reuses `requestId`
  (`AtomicLong`), `pendingRequests` (`ConcurrentHashMap`), and the single `init` inbound collector
  exactly as the three mutations do. It launches nothing.
- **No projection is mutated.** Distinct from every other mutation in the class — this is a pure
  request/reply with no read-path side effect. `projection` / `lastMessages` / `messagesByConversation`
  are untouched, so their KDoc writer-lists need **no** update (contrast #346, which had to amend
  them).
- **Suspension is in the caller's coroutine.** `registerPushToken` suspends on
  `CompletableDeferred.await()` inside `sendAndAwaitReply`, in whatever scope the (future) Firebase
  caller invokes it from. Caller cancellation → `CancellationException` → `finally` removes the
  registry entry (no leak), identical to #346.
- **Reply delivery rides the existing single collector.** The connection-scoped collector resolves
  the deferred on `ack`/`error`; `complete`/`completeExceptionally` are thread-safe and idempotent.
- **Dispatcher.** None chosen here — in-memory state + a non-blocking `pump.send`. Transport
  dispatching lives below the pump.

## Error handling

| Failure | Surfaced as | State mutated? |
|---|---|---|
| Server `error` `server.binary_busy` (retryable) | `RelayErrorException(code="server.binary_busy", retryable=true, …)` (AC #4) | No |
| Server `error` `auth.invalid_token` (not retryable) | `RelayErrorException(code="auth.invalid_token", retryable=false, …)` (AC #4) | No |
| Server `error`, any other code | `RelayErrorException(code, retryable, message)` (AC #4) | No |
| Not connected (`pump.send` returns `false`) | `IllegalStateException` (AC #5) | No |
| Malformed `error` payload (can't decode) | fallback `RelayErrorException` — waiter unblocked, collector survives (existing `mapError` behavior) | No |
| Caller coroutine cancelled mid-await | `CancellationException` (standard) | No |

Every non-success path throws from the single `sendAndAwaitReply` call; nothing is mutated on any
path (there is nothing to mutate). All mapping is **inherited** from #346 — this slice adds no error
type and no `mapError` branch.

## Testing strategy

Unit only (`./gradlew testDebugUnitTest --tests
"de.pyryco.mobile.data.repository.RemoteConversationRepositoryTest"`, per
`[[gradle-single-test-class-task]]`). Extend `RemoteConversationRepositoryTest` with the existing
`runTest` + `runCurrent()` + `FakeSessionPump` idiom (no device, no Firebase, no real crypto). Add a
`startRegisterPushToken(repo, token)` launch-on-`backgroundScope` helper mirroring `startSend`
(1249-1257), returning a `() -> Result<Unit>` getter. Construct the repo with an injected
`deviceName` (e.g. `RemoteConversationRepository(pump, backgroundScope, deviceName = "Pixel-8")`).

New scenarios (bullet form — write in the project idiom; reuse the existing `ackEnvelope` /
`errorEnvelope` helpers):

- **AC #1/#2 request shape:** call `registerPushToken("fcm-tok-123")`; read `pump.sent.last()`;
  assert exactly one sent envelope with `type == "register_push_token"` and payload
  `{platform:"fcm", token:"fcm-tok-123", device_name:"Pixel-8"}` (assert all three fields, including
  `device_name` sourced from the injected ctor param); then feed `ackEnvelope(sent.id)` so the
  launched coroutine completes cleanly.
- **AC #3 ack completes successfully:** call; feed `ackEnvelope(sent.id)`; assert the `Result<Unit>`
  is success (no throw).
- **AC #4 retryable server error:** feed `errorEnvelope(sent.id, code = "server.binary_busy",
  retryable = true)`; assert the call fails with `RelayErrorException` exposing
  `code == "server.binary_busy"` and `retryable == true`.
- **AC #4 non-retryable server error:** feed `errorEnvelope(sent.id, code = "auth.invalid_token",
  retryable = false)`; assert `RelayErrorException` with `retryable == false` (proves a caller can
  branch on `retryable`).
- **AC #5 not-Open fails fast:** set `pump.sendResult = false`; call; assert it throws
  `IllegalStateException` and does **not** hang (no reply is ever fed).

`ComposeTestRule` is not involved (pure data layer). No fixture cascade — the constructor param is
defaulted, so existing tests are untouched.

## Open questions

- **None blocking.** The design is fully determined by the reused #346 infrastructure and the pinned
  wire SSOT.
- **Connection-drop-mid-await leak** is inherited verbatim from #346 (a stranded deferred is freed on
  caller cancellation; no timeout added — no observed hang; Evidence-Based Fix Selection). Flagged,
  not fixed; not specific to this slice.
- **Live device-name threading** is the named handoff to the Firebase sibling (see Device-name
  plumbing) — intentionally deferred, not an open question for this slice.

## Security review

**Verdict:** PASS

**Findings:**

- **[1. Trust boundaries]** No new boundary. The send path constructs an *outbound* payload from
  `token` (caller-supplied), `deviceName` (constructor constant), and the literal `"fcm"`, addressed
  only to the paired, already-authenticated daemon over the established Noise channel (below the
  pump). The only *inbound* untrusted data is the `ack`/`error` reply, decoded through the **existing**
  `mapError` → `MobileJson` boundary (reused unchanged); a malformed `error` yields the existing
  fallback `RelayErrorException` and cannot crash or hang the single collector. No new parsing, no
  injection surface (no eval/shell/SQL/path/URL built from payload data).
- **[2. Tokens, secrets, credentials]** SHOULD FIX (developer constraint). The FCM push token is a
  sensitive routing credential. The design itself logs nothing and stores nothing — the token is held
  only transiently inside the request `Envelope` payload for one round-trip. **Developer constraint
  (code-review must verify):** do **not** add `Log.*` / `Timber` of the token, the request payload, or
  the envelope; the `RelayErrorException.message` carries only the server's human-facing `error.message`
  (server-authored control text), never the token. Mirrors the #346 posture. Token *storage, rotation,
  revocation, and expiry* are **OUT OF SCOPE** → the Firebase sibling (named).
- **[3. File / storage operations]** N/A by design — this slice performs one wire round-trip and
  persists nothing. No file/path/storage operation exists to traverse, TOCTOU, or leave partial.
- **[4. Inter-process / Android attack surface]** N/A by design — no Intent, deep link, exported
  component, `PendingIntent`, content provider, or WebView. Pure data-layer send.
- **[5. Cryptographic primitives]** N/A — no crypto introduced. The channel is the existing
  authenticated `Noise_IK` session below the pump. The request *envelope* id is a non-security
  monotonic `AtomicLong` correlation handle (reused), not a token; no RNG is added (this method mints
  no id).
- **[6. Network & I/O]** No findings. No new OkHttp client / WS config / frame-size or TLS setting —
  all transport posture is inherited below `SessionPump`. The payload is small and bounded (one token
  + device name + a 3-char constant). Not-Open fails fast (`check(pump.send(...))` throws), so a
  hostile/slow relay state cannot hang the call.
- **[7. Error messages, logs, telemetry]** No findings beyond the [2] developer constraint. The design
  emits no logs and no telemetry. `RelayErrorException.message` is server-authored text only.
- **[8. Concurrency]** No findings. Reuses #346's model exactly: no new coroutine/scope/collector;
  the caller's coroutine suspends on `CompletableDeferred.await()`; `pendingRequests` entries are
  removed in `finally` on success/error/cancellation (bounded, no unbounded growth). No new shared
  mutable state, no projection write, so no check-then-mutate TOCTOU is introduced.
- **[9. Threat model alignment]** No MUST FIX. The token travels only over the authenticated Noise
  channel to the paired server, never to an arbitrary endpoint; interception requires breaking the
  pairing/transport layer (out of scope). `device_name` is the same value already disclosed in
  `hello` — no new disclosure. Out-of-scope, named: token lifecycle/storage (Firebase sibling) and
  live-caller reachability (Firebase sibling).
