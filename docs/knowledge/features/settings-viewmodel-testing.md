## Testing

`app/src/test/java/de/pyryco/mobile/ui/settings/SettingsViewModelTest.kt` — 66 methods through #751 (57 through #723, 51 through #714, 48 through #750). Uses the `AppPreferencesTest` rig (real `PreferenceDataStoreFactory` over `TemporaryFolder` + real `AppPreferences`, no fake) plus `Dispatchers.setMain(UnconfinedTestDispatcher())` + `runTest(dispatcher) { … advanceUntilIdle() … }` from [`ChannelListViewModelTest`](channel-list-viewmodel.md). Since #164 a hand-rolled `ConversationRepository` stub backed by a `MutableSharedFlow<List<Conversation>>(replay = 0)` drives the archived-count and (since #723) `defaultWorkspaceLabel` scenarios; the prior nine theme/wallpaper tests + five `defaultEffort` tests (#233) + five `defaultModel` tests (#232) + three `defaultYolo` tests (#234) + seven `defaultWorkspace`/workspace-picker tests (rekeyed to an explicit owner by #714, still not individually enumerated below — a gap from #235's doc run) + three #714 tests (below) + three `pushNotifications` tests (#268) + six #723 `defaultWorkspaceLabel_*` tests (below) all stay untouched through the `makeVm` helper — `makeVm(prefs, repo = stubRepo(), ownerServerId: String = "", hosts: Flow<List<SettingsHost>> = MutableStateFlow(emptyList()), pairedServers: PairedServerCollectionStore = Store()) = SettingsViewModel(prefs, repo, ownerServerId, hosts, pairedServers)` (#749; the last three params are defaulted — #750/#714/#723 left this shape untouched, #751 widened it with a fourth defaulted `pairedServers`) — precisely so every existing call site compiles unchanged, replacing #398's defaulted `connectionStatus` param in the same slot. A `host(serverId, displayName = null, relayUrl = "wss://relay.example/$serverId", status = MutableStateFlow(OFFLINE))` helper (unchanged) builds `SettingsHost` fixtures; a private `SettingsViewModel.rows(): List<SettingsHostRow>` extension added by #750 reads `(connection.value as Loaded).hosts` so the cases below don't repeat that cast. Since #723 a private `conversationAt(cwd, label, archived = false, id = "c-$cwd")` helper builds `Conversation` fixtures for the new cases — `OWNER`/`OTHER` are the two case-differing host ids from the #714 workspace-picker tests, reused by #751's `hostEditor_*` cases, and `FOO`/`BAR` are the two cwd fixtures. Since #751 a private in-memory `Store : PairedServerCollectionStore` — `put(serverId, relayUrl, displayName)`, `renames`/`removals` lists, `failWrite`/`failRemove` switches — is the `pairedServers` default and the fixture the nine new `hostEditor_*` cases (below) configure directly; the same fixture shape `HostChannelListViewModelTest`'s own `Store` already established for the channel list's side of this machine.

Since #714 the class also swaps `RelayLog.sink` for an in-memory `logs: MutableList<String>` around each test (`@Before`/`@After`, mirroring `HostChannelListViewModelTest`'s pattern) — `RelayLog`'s default sink is real `android.util.Log.println`, which throws on plain JVM, so the first `RelayLog.d` call added to a ViewModel reddens every test in its class, including ones that never touch the new code. Capturing into a list also turns "this log carries no server id and no path" into an assertion (`workspacePickerLogs_carryNoServerIdAndNoPath`) rather than a claim. The workspace tests use two ids differing only in case (`OWNER = "Host"`, `OTHER = "host"`) as fixtures, so a passing round-trip pins case-sensitive keying rather than merely two distinct strings.

- `pushNotifications_initialState_emitsTrue_whenNoStoredValue` — fresh datastore, collector + `advanceUntilIdle`, `value == true` (#268). The **inverted** mirror of `defaultYolo_initialState_emitsFalse_…` — guards the load-bearing `true` default at the VM layer (the data-layer guard is `AppPreferencesTest.notificationsEnabled_defaultsToTrue`).
- `pushNotifications_initialState_mirrorsPersistedFalse` — pre-write `false` (the **non-default**), construct VM, assert `vm.pushNotifications.value == false` (#268). Persisting `false` is the meaningful mirror: it proves a stored value overrides the `true` default.
- `onTogglePushNotifications_persistsAndFlowReEmits` — `false → true` walk, asserting both `prefs.notificationsEnabled.first()` (persistence) and `vm.pushNotifications.value` (re-emission) on each step (#268). Three tests total, same boolean compression as the `defaultYolo` trio — default expectations inverted throughout.
- `onSelectDefaultWorkspace_withNoPickerOpen_writesNothing` (#714) — a pick after a dismiss, and a second pick behind a first pick, both write nothing; pins that the handler reads the target off the *pending* value rather than off `ownerServerId`, so a late arrival has somewhere to fail rather than somewhere to retarget.
- `blankOwner_neverOpensThePicker_andWritesNothing` (#714) — a destination with no captured owner: `onDefaultWorkspaceTapped()` leaves `workspacePickerServerId` at `null`, and a forced `onSelectDefaultWorkspace(...)` call writes neither the blank-id key nor the app-wide unqualified default.
- `workspacePickerLogs_carryNoServerIdAndNoPath` (#714) — drives all four log-producing branches (blank-owner reject, open, no-open-picker reject, dismiss) and asserts the exact four content-free strings, pinning the security review's "event name and static code only" claim as code rather than prose.
- `defaultWorkspaceLabel_namesTheBoundPath_fromItsOwnHostsConversation` (#723) — a bound default whose host has a conversation at that exact cwd carrying a label reads back that label, not a basename.
- `defaultWorkspaceLabel_readsEveryConversation_soAnArchivedOneStillNames` (#723) — the only conversation at the bound cwd is archived; the label still resolves, proving the `ConversationFilter.All` arm actually reaches production rather than being masked by the cache. Depends on `archivedDiscussionCount_passesArchivedFilter`'s exact-pair assertion (below) to pin the filter this scenario relies on.
- `defaultWorkspaceLabel_isNull_forAnUnmatchedCwdOrABlankLabel` (#723) — no conversation at the bound cwd yields `null`; a conversation there with a blank (`"   "`) label is skipped in favor of a later, properly named one at the same cwd — proving the scan selects on non-blank, not non-null.
- `defaultWorkspaceLabel_followsRenameAndClear_withoutRewritingTheSavedPath` (#723) — AC2's live half across one VM and one collector: a rename then a clear on the matching conversation move the value label → different label → `null`, and `AppPreferences.defaultWorkspace(OWNER)` still reads the original path afterward.
- `defaultWorkspaceLabel_isNull_forAnUnboundDefault` (#723) — a labelled conversation sitting at `DEFAULT_SCRATCH_CWD`, and another at `""`, cannot name an unbound default; asserted both for the sentinel and (after `setDefaultWorkspace(OWNER, "")`) the empty string.
- `defaultWorkspaceLabel_cannotReadAnotherHostsLabelForTheSameCwd` (#723) — two VMs for two case-differing host ids (`OWNER`/`OTHER`), both defaulting to the same cwd under different labels on their own stub repositories: each VM reads only its own — the at-this-layer form of "a compatibility-selection change cannot retarget the row," since selection is not observable at this layer at all.
- `connection_listsEverySavedHostAndMarksTheOwner` — two saved hosts; asserts `Loaded.hosts` carries both in store order, each with its own name/relayUrl/status, `isOwner` true for exactly the second, and `ownerMissing == false` (#750, replacing #749's `host_resolvesOwnerAmongTwoSavedHosts`, which asserted only the resolved `Owned` and threw the other host away).
- `connection_followsEachHostsOwnStatusIndependently` — mutate one host's status flow and assert the *other* saved host's row is unaffected; new in #750, since a single-host projection had no second row to prove isolation against.
- `connection_keepsOwnerAcrossHostListReemission` — the at-this-layer form of a compatibility-selection change, since selection isn't observable at this layer at all: re-emit the same two hosts in swapped order and assert the row order follows, the owned row's `serverId`/`status` are unchanged, and `isOwner` moved with it rather than with position (#749; extended #750 to also assert the non-owner row survives the reorder).
- `connection_followsRenameAndStatusChangeWhileSubscribed` — mutate the owner's status flow, then re-emit the host list with a new `displayName` for the same id, asserting `vm.rows().single()` picks up both while the flow stays subscribed and `isOwner` stays true (#749 as `host_followsOwnerRenameAndStatusUpdates`; renamed and re-asserted through `rows()` by #750).
- `connection_namesUnnamedHostByItsServerId` — `displayName = null` and a blank `"   "` both resolve a row's `name` to the server id (#749 as `host_namesUnnamedOwnerByItsServerId`, asserting `Owned.name`; #750 renamed it and asserts `vm.rows().single().name` instead, since naming is now a row property, not an owner-only one).
- `connection_reportsOwnerMissingButStillListsSavedHosts` — owner id absent from a two-host list → `ownerMissing == true` **and** both saved hosts still in `Loaded.hosts`, neither `isOwner` (#750, replacing #749's `host_reportsUnknownWhenOwnerIsNotSaved`, which discarded the saved hosts and returned bare `Unknown`).
- `connection_reportsOwnerMissingWhenTheOwnerIsRemovedWhileOpen` — owner present then the host list re-emits without it → `ownerMissing == true` with the remaining host still listed (#750, replacing #749's `host_reportsUnknownWhenTheOwnerIsRemovedWhileOpen`, which asserted bare `Unknown` over an empty remaining list).
- `connection_listsHostsWithoutOwningOneWhenTheDestinationOwnsNoHost` — blank `ownerServerId`: every saved host is still listed, none `isOwner`, `ownerMissing == false` even as a host subsequently appears in `hosts` (#750, replacing #749's `host_reportsUnpairedWhenTheDestinationOwnsNoHost`, whose blank-owner short-circuit never even subscribed to `hosts` — dropped in #750 because a blank-owner destination must still list every saved host, not just synchronously report `Unpaired`).
- `connection_reportsNoHostsForAnEmptyList` — parameterised over both a blank and a non-blank `ownerServerId`, asserts an empty `hosts` upstream produces `Loaded(emptyList(), ...)` rather than stalling at `Resolving` forever (#750). Pins the `combine`-over-empty-array short-circuit named in § How it works — without it this state has no way to ever leave `Resolving`.
- `connection_resolvesBeforeTheFirstHostEmission` — non-blank owner, `hosts` a cold `MutableSharedFlow` that has not emitted yet → `connection.value == SettingsConnectionState.Resolving` (#749 as `host_resolvesBeforeTheFirstHostEmission`; renamed by #750). Pins the `stateIn` initial value, not a race — the test never lets `hosts` emit.
- `archivedDiscussionCount_initialValue_isZero` — fresh VM, no source emission; collector launched + `advanceUntilIdle`; `value == 0` (#164).
- `archivedDiscussionCount_reflectsArchivedUnpromotedConversations` — emit three `archivedDiscussion(...)` fixtures; `value == 3` (#164).
- `archivedDiscussionCount_excludesPromotedArchivedConversations` — emit `[archivedDiscussion("disc-1"), archivedChannel("chan-1"), archivedChannel("chan-2")]`; `value == 1` (locks in the `!isPromoted` post-filter, #164).
- `archivedDiscussionCount_updates_whenConversationArchived` — emit `emptyList()` → 0, then emit `[archivedDiscussion]` → 1 (#164).
- `archivedDiscussionCount_updates_whenConversationUnarchived` — emit `[archivedDiscussion]` → 1, then emit `emptyList()` → 0 (#164).
- `archivedDiscussionCount_passesArchivedFilter` — `stubRepo(source, captureFiltersInto = captured)` records every `ConversationFilter` value the VM passes to `observeConversations`; asserts **`captured == [ConversationFilter.All, ConversationFilter.Archived]`** (#164; list widened by #723). The hand-rolled stub exists primarily for this assertion — the real `FakeConversationRepository` would require either internal inspection or contrived count differentials to verify the filter value. The two filters are recorded in this exact order because both chains are built in the constructor's field initializers — `defaultWorkspaceLabel` (`All`) before `archivedDiscussionCount` (`Archived`) in declaration order — so the list reflects construction order, not collection order; #723 widened the assertion from a single-element list because a second stream now exists, not because the archived-count stream itself changed.
- `hostEditor_opensOnTheCapturedOwnerWithItsIdentityRelayAndName` (#751) — AC1: `openOwnerHostEditor()` opens on `ownerServerId`, carrying `serverId`/`serverIdentity`/`relayAddress`/`initialName` off the store's own record.
- `hostEditor_rejectsABlankOwnerWithoutOpening` (#751) — AC1/AC4: a blank `ownerServerId` publishes nothing and logs `event=settings_host_editor_rejected code=no_owner` — the second lock behind the screen's own row-gating.
- `hostEditor_doesNotOpenForAnOwnerThatIsNoLongerPaired` (#751) — AC4: an id absent from the store publishes nothing; needs no dedicated branch because `open` already rejects an absent record.
- `hostEditor_savesTheNameUnderTheOwnersOwnId` (#751) — AC1: a trimmed rename writes through `store.renames` keyed by the owner's id and closes the editor.
- `hostEditor_decliningTheUnpairWritesNothingAndKeepsTheEditorOpen` (#751) — AC2: decline clears `confirmingUnpair`, leaves the store untouched, and the typed name (`initialName`) intact on the still-open editor.
- `hostEditor_unpairingRemovesOnlyTheOwnersPairingWorkspaceAndNothingElse` (#751) — AC2 in full: confirming removes exactly the owner's pairing and its own `AppPreferences.defaultWorkspace(OWNER)`, while `OTHER`'s pairing, `OTHER`'s workspace, `defaultModel` and `notificationsEnabled` (two arbitrary app-wide preferences) all survive unchanged.
- `hostEditor_aFailedRemovalKeepsTheEditorOpenAndThePairingIntact` (#751) — AC3: `failRemove` leaves `unpairFailed` set, `saving` cleared, the pairing and its workspace both intact, and every captured log line free of the id, the name and the relay address.
- `hostEditor_aFailedRenameKeepsTheEditorOpenWithoutReopeningIt` (#751) — AC3: `failWrite` leaves `failed` set, `saving` cleared, and nothing written to `store.renames`.
- `hostEditor_dismissClosesItWithoutWriting` (#751) — dismissal from mid-confirmation writes nothing to either `store.removals` or `store.renames`.

Tests that read `vm.themeMode.value` / `vm.useWallpaperColors.value` / `vm.defaultModel.value` / `vm.defaultEffort.value` / `vm.defaultYolo.value` / `vm.pushNotifications.value` / `vm.archivedDiscussionCount.value` / `vm.defaultWorkspaceLabel.value` `launch` a no-op collector and `advanceUntilIdle()` first to keep the `WhileSubscribed(5_000L)` upstream subscribed; otherwise `.value` stays at the `initialValue` literal (`ThemeMode.DARK` / `false` / `Model.OPUS_4_7` / `Effort.HIGH` / `false` / **`true`** for `pushNotifications` / `0` / `null` for `defaultWorkspaceLabel`) and the test asserts the wrong thing — note `pushNotifications`'s initial is `true`, so a missing collector would make `pushNotifications_initialState_mirrorsPersistedFalse` *pass for the wrong reason* (it would read the `true` literal instead of the persisted `false`), which is exactly why that test launches the collector. Tests that read through `prefs.themeMode.first()` / `prefs.useWallpaperColors.first()` / `prefs.defaultModel.first()` / `prefs.defaultEffort.first()` / `prefs.defaultYolo.first()` / `prefs.notificationsEnabled.first()` directly don't need the collector — they bypass the VM's `stateIn` projection.
