# Settings modal

The Settings entry opens a dark, full-height modal at the optional `settings` route. Its current design is [Figma node `17:2`](https://www.figma.com/design/g2HIq2UyPhslEoHRokQmHG?node-id=17-2); the [shared mobile modal](mobile-modal.md) supplies its header, close control, separator, scrolling and safe-area handling.

## What it does

**Notifications and Thread are the only sections.** Notifications contains a “Push notifications when claude responds” Material switch and a “Notification sound” row with “Default” and a chevron. The sound row has no click action or picker. Below it, **Thread** (added #1634, Figma `726:8150`) is a second heading in the same style, with one row: “Collapse assistant tool uses” and a trailing switch, shown on by default. Connection, Appearance, Defaults, Memory, Storage and About have no Settings rows. The separate [sidebar Archive entry](navigation.md#archive-a-required-owner-destination-two-doors-715) remains available; removing the old Settings rows does not clear saved preferences.

The push switch reflects `SettingsViewModel.pushNotifications`, backed by `AppPreferences.notificationsEnabled` (default `true`). Toggling persists the choice across modal reopen and app restart. Turning it on also invokes the existing Android notification-permission request in `PyryNavHost`; turning it off does not request permission. See [push messaging](push-messaging-service.md#attention-alerts-and-the-tap-route-685) for the delivery path.

The Thread switch reflects `SettingsViewModel.collapseToolUses`, backed by `AppPreferences.collapseToolUses` (default `true`), phone-local and never sent to the daemon. It requests no permission on either edge. Nothing reads the stored value yet — the [#1576](https://github.com/pyrycode/pyrycode-mobile/issues/1576) follow-up folds tool rows in the thread using it. The switch carries `Modifier.semantics { contentDescription = "Collapse assistant tool uses" }`, the same pattern `McpServersSection` uses, so TalkBack names what it controls and the screen test can select it unambiguously now that two switches exist.

**Copying a switch row whose label is one line, not two, changes the row's height.** The push row's 12 dp vertical padding was measured beside a two-line label, where the label's own height exceeds the switch's 48 dp Material 3 touch target. The Thread row's "Collapse assistant tool uses" label is one line, so the 48 dp target becomes the tallest child; 12 dp padding would have produced a 72 px row and put the label 8 px below frame `726:8150`. The row uses 4 dp vertical padding instead — the target's own 8 dp above and below its 32 px track reproduces the frame's 56 px row and 12 px inset exactly. Only `SettingsScreenGeometryTest`'s offsets caught the mismatch; it does not show up in a screenshot comparison at a glance.

The title reads “Settings”. The header Close control, filled Done action at bottom right, and Android Back all call `onDismissRequest`, which pops this destination to the previous view. Outside taps do not dismiss. The shared shell starts this caller's content directly below the header and lets it scroll at compact height; the two rows wrap at narrow width and enlarged text. The Settings instance has no generic frame's extra 4 dp outer top inset. Figma omits Android system bars, while the actual dialog respects safe drawing insets. See the [labelled 412 × 892 comparison](../../../app/src/androidTest/assets/settings-1239/comparison-412x892.png) and [compact 2× capture](../../../app/src/androidTest/assets/settings-1239/emulator-320x640-scale-2.png).

## Wiring and verification

`SettingsScreen(pushNotifications, onTogglePushNotifications, collapseToolUses, onToggleCollapseToolUses, onDismissRequest)` is stateless; the Thread pair was added after the push pair by #1634. Its route collects both preference flows, forwards each toggle to the ViewModel, requests Android notification permission only on the push switch's enable edge, and dismisses with `navController.popBackStack()`. The optional route argument remains for existing entry points but supplies no content to this modal. `SettingsRow` and `ThemeMode.label()` remain in the settings package for the separate [About screen](about-screen.md) and theme picker; neither adds a Settings row.

The Notifications label, the push row, the "Notification sound" headline and its "Default" line each carry a local `LineHeightStyle(Center, Trim.None)` so their text boxes match the frame's line heights instead of Compose's trimmed default — see [shared typography § Density-1.0 hinting and the trimmed line box](shared-typography.md#density-10-hinting-and-the-trimmed-line-box-1489). `SettingsScreenGeometryTest` asserts all rows' offsets from the sheet's top against frame `17:2` / `726:8150` — Thread at 279, its label at 327 (centred on the switch track, not the frame's nominal 323), the switch track itself at 323 — and Done's bottom sits 24 dp above the sheet's edge, matching every other entry point on the [shared modal shell](mobile-modal.md).

The focused [screen tests](../../../app/src/sharedTest/java/de/pyryco/mobile/ui/settings/SettingsScreenTest.kt) check both headings and rows, absence of removed sections, the inert sound row, both switch callbacks (selected by index or by the Thread switch's content description, since two switches exist) and dismissal. [Navigation tests](../../../app/src/sharedTest/java/de/pyryco/mobile/ui/settings/SettingsNavigationTest.kt) exercise the production graph and preference persistence across reopening for both switches; [device tests](../../../app/src/androidTest/java/de/pyryco/mobile/ui/settings/SettingsDensityDeviceTest.kt) check focused system Back and text layout at 412 × 892 and 320 × 640 with 2× text, including the two new Thread labels in its clipping list. A semantics text assertion can pass when fractional intrinsic width causes visible overflow: the sound label and subtitle fill their available column width, and the device test checks `TextLayoutResult.hasVisualOverflow`. Dialog semantics use the dialog window's coordinates, so activity-window system-bar helpers cannot assess its bounds.
