# ConversationRepository — data-layer contract — Conventions

Split into [ConversationRepository — data-layer contract](conversation-repository.md) on 2026-09-23 to keep that document under the 50000-byte cap the docs guard enforces. This section, Conventions, moved here verbatim, headings and anchors intact, and gained the #890 entries below.

## Conventions

- **Streams are cold `Flow`s.** `observeConversations`, `observeMessages`, `observeLastMessage` (#161), `recentWorkspaces` (#209), `observeStall` (#395), `observeQueue` (#460), `observeApiRetry` (#593), `observeCompacting` (#596), `observeResetting` (#871), `observeSessionSettings` (#590), `observeModelMenu` (#791), `observeThinkingProgress` (#801), `observeUsageLimit` (#802), `observeAnnouncedModel` (#890), and `observeSessionFacts` (#890) emit the current value on subscription and every subsequent change. Cancellation follows the collector's scope. `observeSessionSettings` re-issues its read on four triggers, not just subscription — the owning host's reconnect, that conversation's session transition, and a caller's `refreshSessionSettings` invalidation — but the *stream contract* is the same one every entry here honours: it is still cold, still per-collector, and a superseded read is cancelled before the next one starts (the live impl's `flatMapLatest`), so late data never overwrites current data.
- **Mutators are `suspend` one-shots that return the affected entity.** Callers don't need to re-fetch; the observed stream re-emits the same change. The single non-`Unit` exception is `archive`, which returns `Unit` because no follow-up handle is meaningful.
- **Default-implementations are reserved for the cascade-escape valve.** Every interface member except `recentWorkspaces` (#209), `createWorkspaceFolder` (#210), `delete` (#218), `requestScreenSnapshot` (#375), `observeStall` (#395), `observeQueue` (#460), `dropQueuedMessage` (#466), `setSessionSettings` (#543), `observeApiRetry` (#593), `observeCompacting` (#596), `observeResetting` (#871), `requestHistory` (#623), `observeSessionSettings` (#590), `refreshSessionSettings` (#590), `observeModelMenu` (#791), `observeThinkingProgress` (#801), `observeUsageLimit` (#802), `requestSystemPrompt` (#823), `setSystemPrompt` (#823), `observeAnnouncedModel` (#890), and `observeSessionFacts` (#890) is `abstract` and forces an explicit override in every implementation (the convention since #3). All twenty-one deviations exist for the same reason — the anonymous `object : ConversationRepository` test fakes inherit the default so the addition didn't cascade `TODO("not used")` stubs across the test suite (13 such doubles by #543). Default-body *shape* depends on the method's return semantics: `recentWorkspaces()` ships `flowOf(emptyList())`, `observeStall(id)` (#395) ships `flowOf(false)`, `observeQueue(id)` (#460) ships `flowOf(emptyList())`, `observeApiRetry(id)` (#593) ships `flowOf(ApiRetryStatus.NotRetrying)`, `observeCompacting(id)` (#596) ships `flowOf(false)`, `observeResetting(id)` (#871), `observeSessionSettings(id)` (#590), `observeModelMenu(id)` (#791), `observeThinkingProgress(id)` (#801), `observeUsageLimit(id)` (#802), `observeAnnouncedModel(id)` (#890), and `observeSessionFacts(id)` (#890) ship `flowOf(null)` because each has a semantically-meaningful zero ("a repo that doesn't track workspace history has no recents"; "a repo without an interactive wire is never stalled / never queues / never retrying / never compacting / never resetting"; "a repo with no settings wire has no reading, ever"; "a repo that heard no `model_list` has no menu, ever"; "a repo that heard no `thinking_progress` has no reading, ever"; "a repo that heard no `rate_limited` has nothing to read, ever"; "a repo that heard no `model_announced` / `session_facts` has no reading, ever" — `null` is the same "unavailable" value a failed live read produces, so the default isn't a separate case) — an empty/false/`NotRetrying`/`null` stream a non-overriding impl can honestly serve; `createWorkspaceFolder`, `delete`, `requestScreenSnapshot` (#375), `dropQueuedMessage` (#466), `setSessionSettings` (#543), `requestHistory` (#623), `requestSystemPrompt` (#823), and `setSystemPrompt` (#823) ship `error("<method> is not implemented for this ConversationRepository")` because none of a path `String`, a destructive `Unit` mutator, a rendered-snapshot `String` read, a one-shot `Unit` outbound send, a session-scoped settings apply, a page of on-disk history, or the stored prompt reading has a meaningful zero (an empty `HistoryPage` would be indistinguishable from a real `atStart` terminal page, a default `SystemPromptReading(null, NoSession)` would be indistinguishable from a conversation that genuinely stores nothing, and silent-`Unit` success in a default body would let tests pass vacuously on under-stubbed fakes — `error(...)` surfaces accidental invocation loudly). `refreshSessionSettings(id)` (#590) is a **third** default shape — a bare `Unit` no-op, neither a semantic-zero stream nor a throwing stub. It earns the exception the "silent no-op is syntactically free but semantically wrong" rule below warns against: it sends no frame and asserts no state, so a no-overriding impl has nothing to get wrong by doing nothing, and a caller invalidating a reading that was already unavailable has nothing to recover from either way. `error(...)` is preferred over `NotImplementedError` for the clearer call-site message. The throws are unreachable in tests today (no test fake calls any of them); the Workspace Picker is the only production consumer for `createWorkspaceFolder`, the Channel Info sheet for `delete`, the manual-snapshot UI / stall fallback (#372) for `requestScreenSnapshot`, the per-row drop affordance (#467, not yet shipped) for `dropQueuedMessage`, the Status sheet's run-configuration controls ([#544](../codebase/544.md)) for `setSessionSettings`, the timeline fold (#645, not yet shipped) plus scroll-triggered paging (#646, not yet shipped) for `requestHistory`, the composer / footer (#649/#650/#651, not yet shipped) for `observeSessionSettings`/`refreshSessionSettings`, the same not-yet-shipped composer (#649) for `observeModelMenu` (#791), [`SaveAsChannelDialog`](save-as-channel-dialog.md) (#957), [`CreateChannelModal`](mobile-modal.md#callers) (#958) and [`EditChannelModal`](mobile-modal.md#callers) (#667) for `requestSystemPrompt`/`setSystemPrompt` — none through the shared editing state (#824, [`ui/conversations/components/SystemPromptEditor.kt`](system-prompt-editor.md)), which stays unclaimed (see that document), and a not-yet-shipped rendering ticket for `observeAnnouncedModel`/`observeSessionFacts` (#890). **Rule for future additions:** prefer a semantically-correct zero (empty `Flow`, empty list, `null`) when one exists; fall back to `error("…")` when it does not — *including* for `Unit`-returning destructive mutators where a silent no-op is syntactically free but semantically wrong (a genuine invalidation trigger like `refreshSessionSettings`, which mutates nothing and sends nothing itself, is the narrow exception, not a precedent for skipping this check). Never `TODO("not used")` — still the wrong shape for a default. The **override set** splits orthogonally from the body shape: `createWorkspaceFolder`, `delete`, `requestScreenSnapshot` (#375), `requestHistory` (#623), `observeSessionSettings` (#590), `refreshSessionSettings` (#590), `observeModelMenu` (#791), `requestSystemPrompt` (#823), and `setSystemPrompt` (#823) are overridden by **all three** impls (live, [fake](conversation-repository.md#phase-1-implementation--fakeconversationrepository), and [`StableConversationRepository`](stable-conversation-repository.md) facade); `observeStall` (#395), `observeQueue` (#460), `dropQueuedMessage` (#466), `observeApiRetry` (#593), `observeCompacting` (#596), `observeResetting` (#871), `observeThinkingProgress` (#801), `observeUsageLimit` (#802), `observeAnnouncedModel` (#890), and `observeSessionFacts` (#890) are overridden by the live [`RemoteConversationRepository`](remote-conversation-repository.md) and the facade **only** — the [fake](conversation-repository.md#phase-1-implementation--fakeconversationrepository) and the inline test doubles deliberately **inherit** the default. `setSessionSettings` (#543) splits differently again: the live repo and the **fake** both override it (§ Phase 1 implementation — the fake **records** rather than models state), while the facade delegation was deferred to, and **landed in**, [#544](../codebase/544.md) — its first
consumer, the [Status sheet](status-sheet.md) run-configuration controls. For `observeStall`/`observeQueue`/`observeApiRetry`/`observeCompacting`/`observeResetting`/`observeThinkingProgress`/`observeUsageLimit`/`observeAnnouncedModel`/`observeSessionFacts` the inherited default is a semantic zero ("never stalled" / "never queued" / "never retrying" / "never compacting" / "never resetting" / "never has a reading" / "never has a reading" / "never has a reading" / "never has a reading" is the correct fake behaviour, the same as a `whenAbsent = false`/`emptyList()`/`NotRetrying`/`false`/`null`/`null`/`null`/`null`/`null` facade with no live connection); for `dropQueuedMessage` it is the **throwing** default left unreachable — no fake-backed UI test drops a queued message (its only consumer, #467, calls through the facade → live repo), so the fake never overrides it. `requestHistory` (#623) joins the all-three-override group not because a fake with no history would be dishonest to stub, but because the fake's seeded messages *are* a real log — the [Phase 1 implementation](conversation-repository.md#phase-1-implementation--fakeconversationrepository) section walks it rather than approximating it, so the override is exercised, not unreachable. `observeSessionSettings`/`refreshSessionSettings` (#590) join the same all-three group for a *third* reason distinct from both: the fake overrides so a seeded reading (via its test-only `setSessionSettingsReading` seam) can drive a populated composer/footer preview and ViewModel test, not because its default would be dishonest (an unseeded fake conversation still correctly reads `null`) and not because it holds a "real" settings log the way `requestHistory`'s fake does. `requestSystemPrompt`/`setSystemPrompt` (#823) join for a *fourth* reason again: the fake holds a genuine `Map<String, String>` of stored prompts (the `requestHistory` reason), but unlike every prior throwing-default member its default would also be **dishonest**, not merely unexercised — an unseeded fake conversation reading the inherited `error(...)` would crash where the daemon (and this fake's actual override) reads `SystemPromptReading(null, NoSession)` successfully. `observeAnnouncedModel`/`observeSessionFacts` (#890) join the fake-inherits group for the plain reason, not a new one: the AC requires the fake to default to `null`, and an unseeded fake conversation reading `null` is honest — there is no seeded "announced model" or "session facts" log the way `requestHistory`'s messages or `requestSystemPrompt`'s stored map are. - **`mutationsSupported: Boolean` (#507) — the one capability *property*, not a method, in the default-cascade family.** A read-only `val` with a `true` default getter (`get() = true`, **not** an `= true` initializer — interface properties have no backing field, so an initializer is a compile error). It advertises whether an impl can actually perform the mutation methods (`archive` / `unarchive` / `rename` / `startNewSession` / `changeWorkspace` / `delete`); a UI gating consumer reads it to stop offering actions the backend can't service. Override set is exactly the [`observeStall`](stall-state.md) / [`observeQueue`](queued-backlog.md) group's: the live [`RemoteConversationRepository`](remote-conversation-repository.md) overrides it to `false` (relay has no v2 wire message for those mutations yet — it lives beside the throwing overrides) and the [`StableConversationRepository`](stable-conversation-repository.md) facade delegates it fail-safe-deny; the [fake](conversation-repository.md#phase-1-implementation--fakeconversationrepository) and every inline test double **inherit** `true` (the fake supports every mutation). Static per build config (fake-vs-relay is a Koin swap, never a runtime toggle), so it is a plain `Boolean`, not a `Flow` — [`ThreadViewModel`](thread-screen.md) snapshots it once at construction into `ThreadUiState.mutationsSupported`. Dormant as of #507 (no composable reads it); the consumer is #508. See [`../codebase/507.md`](../codebase/507.md).
- **Failures throw, they don't `Result`-wrap.** Unknown `conversationId` throws `IllegalArgumentException` (fake) — caller passed an id not from `observeConversations`, which is programmer error, not a runtime "not found" lookup. Phase 4's remote impl will introduce a separate not-found semantic for the network case. Promoting an already-promoted conversation is `IllegalStateException`; blank names are `IllegalArgumentException`. Stream-level errors terminate the flow and are caught at the UI's `catch { }`. **One deviation:** `delete(id)` (#218) is tolerant of unknown ids — silent no-op, no throw — because the contract converges on the post-condition ("conversation absent from `observeConversations`") rather than the in-progress action. Both an unknown id and a successful delete share that post-condition, so distinguishing them buys nothing. The deviation is documented in the `delete` KDoc with an explicit contrast line against `archive` / `unarchive`. See [`../codebase/218.md`](../codebase/218.md).
- **Dispatcher-agnostic.** No `flowOn(...)` in the contract; each impl picks its dispatcher (the Phase 1 fake stays in-memory and synchronous, Phase 4 will use `Dispatchers.IO`).
- **IDs are raw `String`.** The shipped #2 model uses `String` for `Conversation.id` and `Session.id`; matching that here avoids a model-wide value-class refactor inside a contract-only ticket. Promoting to `ConversationId` / `SessionId` value classes is a separate pass across `data/model/` + every call site.
