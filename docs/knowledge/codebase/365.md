# #365 — Re-register the FCM push token on every reconnect (connect-time orchestration)

Adds the **connect-time orchestration** that re-sends the phone's stored FCM push token to the daemon
whenever a fresh Noise session reaches `Open`, so the daemon's wake target self-heals across app
restarts and connection drops. Per the daemon's contract (`docs/protocol-mobile.md` § Phone background
behaviour) the phone re-registers on **every** WS connect; the server de-duplicates the
`(platform, token, device_name)` triple, so a repeat is a cheap (~100 B) no-op that heals registry
drift. The orchestration lives in
[`RelayRepositoryCoordinator`](../features/relay-repository-coordinator.md) (the only Phase 4 FCM slice
that touches the connection lifecycle), reusing [#359](359.md)'s wire sender unchanged.

This slice also **closes #359's `device_name: ""` defer**: it threads the live
`NoiseClientInfo.deviceName` (`Build.MODEL`) into the repo so the first real registration never sends
`device_name: ""`. An empty name would *fork* the server's dedup triple — pyrycode #319's handler
acks-with-**no-registry-touch** only when `(Platform, Token, DeviceName)` matches the stored device, so a
mismatched name creates a duplicate registry entry (QMD pyrycode `knowledge/codebase/250.md` / #319).

The capability is **dormant** until a token is stored (Firebase #361 via [#364](364.md)): with no
stored token the hook sends nothing. Split from #360. Size S; four production files + one test file.

## How it works — the connect-time hook

`onConnection` already builds a fresh pump + child scope + repository per live transport (see the
[feature doc](../features/relay-repository-coordinator.md)). This slice adds, after publishing the repo,
a single `childScope.launch { reregisterPushTokenOnOpen(pump, repo) }`. The hook
(`RelayRepositoryCoordinator.kt:116`), in order:

1. **Await the first transition out of `Handshaking`** — `pump.state.first { it is Open || it is Closed }`.
2. **Abort on a pre-Open `Closed`** (handshake fault / transport down) — `return`, nothing to register.
3. **Read the token** — `val token = pushToken() ?: return` — **no-op when null** (the dormant signal).
4. **Send once** — `repo.registerPushToken(token)`, swallowing failure (the daemon retries next connect).

It fires **exactly once per connection**, guaranteed *structurally*: each `onConnection` builds a fresh
pump + child scope + hook, the `PumpState` machine never revisits `Handshaking` (re-key stays `Open`),
and the hook awaits one transition and sends at most one frame. No client-side dedup — the server dedupes
the triple.

### The three load-bearing constraints (all carried from the spec, all honoured)

- **`onConnection` stays non-suspending.** Its doc comment declares it non-suspending *by design* (a
  cancellation-atomicity / key-wipe invariant — `RelayRepositoryCoordinator.kt:69-75`). `launch` schedules
  and returns immediately; all suspending work runs on the child scope, off the critical path. The hook is
  **never** awaited inline, and **no** second connection-state subscription or `currentRepository` observer
  is added — it reuses the one `onConnection` collector + the pump's existing `state`.
- **The hook uses the *concrete* repo handle.** `registerPushToken` is **not** on the
  `ConversationRepository` interface ([#359](359.md)), and the coordinator publishes the repo only as the
  interface-typed `currentRepository`. So the hook calls it through the concrete
  `RemoteConversationRepository` captured at construction (`val repo = RemoteConversationRepository(...)`,
  `:100`), never via `currentRepository`. This is the **first live caller** of the device-concern method
  #359 shipped dormant.
- **Swallow, but propagate cancellation.** A narrow `try { repo.registerPushToken(token) }` re-throws
  `CancellationException` (a connection drop cancels `childScope` mid-call — absorbing it would break
  structured-concurrency teardown) and swallows any other `Exception` **without logging**. A server `error`
  or not-Open `IllegalStateException` is swallowed; the daemon re-registers on the next connect by contract.

## Patterns established

- **The connect-time per-connection side-effect hook.** A one-shot effect that must run once a fresh Noise
  session reaches `Open` is launched from the non-suspending `onConnection` onto the per-connection
  `childScope`, awaits `pump.state.first { Open || Closed }`, and acts through the **concrete** repo handle.
  This is the template for any future per-connection device-concern send (the wire sender stays on the
  concrete repo per [#359](359.md); the *connect-time trigger* lives here). `active.scope` owns the
  coroutine, so a drop / `close()` cancels an in-flight effect — desirable.
- **Closing a cross-slice "defer" is owned by the slice that touches the construction site.** #359
  deliberately left `RemoteConversationRepository(deviceName = "")` defaulted and flagged that whichever
  slice adds the live caller must thread the real name. #365 is that slice (it is the only FCM slice that
  constructs the coordinator), so it owns both the live caller *and* the `deviceName` threading — they are
  the same edit. See [[post-352-connection-scoped-repo-behind-facade]].
- **`state` on the richer interface, not the data view.** Adding the lifecycle `state` to
  `ManagedSessionPump` (not `SessionPump`) keeps the repository's data-only view minimal (Interface
  Segregation) — the coordinator depends on the richer contract; consumers that only read `inbound`/`send`
  are unaffected.

## Lessons learned

- **`StateFlow.first { … }` checks the current value before suspending, so awaiting `Open` is race-free
  even if the pump is already `Open` when the hook launches — no missed-edge guard needed.** (Lifted from
  the PR body.) Because `onConnection` calls `pump.start()` and then `launch`es the hook, the pump could in
  principle reach `Open` before the hook's collector attaches; `first {}`'s current-value check closes that
  window with no extra synchronisation.
- **#359's `deviceName` param doc-comment is now stale (known, deferred follow-up).** Code review flagged
  (NIT) that `RemoteConversationRepository.kt:72-76` still says *"the live value is wired by the Firebase
  sibling"* and *"the default is never exercised in production today — `registerPushToken` has no live
  caller yet."* #365 **is** that live caller and AppModule now wires the live `deviceName`, so the comment
  misdescribes reality. It was left untouched — the file is outside this PR's surface and `CLAUDE.md`
  forbids touching adjacent code unnecessarily. A future slice that edits that file (e.g. Firebase #361)
  should correct it.
