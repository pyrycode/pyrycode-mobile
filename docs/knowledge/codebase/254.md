# #254 — feat(ui/sheets): StatusSheet scaffold + Model section UI (Figma 20:100)

Lands the first user-visible piece of the Status Sheet: a stateless `StatusSheet` composable rendering Material 3 `ModalBottomSheet` with a single **Model** section — `selectableGroup`-wrapped radio rows for Opus 4.7 / Sonnet 4.6 / Haiku 4.5, each pairing the existing `Model.label()` title with a short Figma-derived description (`best for complex work` / `faster, cheaper` / `fastest`). [`ThreadScreen`](../features/thread-screen.md) hosts sheet visibility via `rememberSaveable` and opens the sheet from the existing [`ThreadStatusRow`](../features/thread-status-row.md) `onExpandClick` (the placeholder shipped by [#145](./145.md)); a new `onModelSelected: (Model) -> Unit` parameter on `ThreadScreen` forwards row taps to the [#253](./253.md) `ThreadViewModel.onModelSelected`. The `onExpandClick: () -> Unit` parameter on `ThreadScreen` is **removed** — no remaining external consumer once the screen owns the sheet trigger; `MainActivity` drops the `// TODO(#146): open Status Sheet` placeholder and gains `onModelSelected = vm::onModelSelected` at the same call site. Split from [#228](https://github.com/pyrycode/pyrycode-mobile/issues/228); siblings [#229](https://github.com/pyrycode/pyrycode-mobile/issues/229) (Effort + YOLO sections) and [#230](https://github.com/pyrycode/pyrycode-mobile/issues/230) (Context window section) append into the same `StatusSheetContent` `Column` without re-shaping the shell.

## Summary

- **`StatusSheet` follows the [`WorkspacePickerSheet`](../features/workspace-picker-sheet.md) shell/`*Content` split verbatim.** Public `@OptIn(ExperimentalMaterial3Api::class) fun StatusSheet(selectedModel: Model, onModelSelected: (Model) -> Unit, onDismiss: () -> Unit, modifier: Modifier = Modifier, sheetState: SheetState = rememberModalBottomSheetState(skipPartiallyExpanded = true))` wraps `ModalBottomSheet(onDismissRequest = onDismiss, modifier = modifier, sheetState = sheetState)` and delegates into a sibling `internal fun StatusSheetContent(selectedModel, onModelSelected, onDismiss)`. The split exists because Compose `@Preview` and `createComposeRule()` don't render the `ModalBottomSheet` scrim/animation reliably — both previews and Compose tests target the `*Content` seam directly, with the runtime sheet exercised via manual install. Same convention as [`ChannelInfoSheet`](../features/channel-info-sheet.md) ([#217](./217.md)).
- **`TitleRow` and `SectionHeader` are private helpers re-declared in this file** (`start = 16.dp, end = 4.dp, top = 4.dp, bottom = 12.dp` padding on the title row; `start = 24.dp, end = 16.dp, top = 12.dp, bottom = 4.dp` on the section header; `titleLarge` + `onSurface` for the title, `labelLarge` + `onSurfaceVariant` for the header; `Icons.Filled.Close` tinted `onSurfaceVariant` with `contentDescription = "Close"`). Three sheets now carry identical-but-private `TitleRow` / `SectionHeader` (`WorkspacePickerSheet.kt`, `ChannelInfoSheet.kt`, `StatusSheet.kt`); extraction is deferred to the third-occurrence rule + a real shape divergence — none yet. The two are visually byte-identical so users perceive the sheets as one family.
- **Title literal is `"Run configuration"`** (Figma node `20:104`), inlined as a Kotlin string. `WorkspacePickerSheet` (`"Choose workspace"`) and `ChannelInfoSheet` (the conversation name) both inline their titles — no `strings.xml` extraction in this slice. Same applies to the section header `"Model"` and the three description strings.
- **`Model.entries.forEach` drives row ordering** rather than three hand-written `ModelRow(Model.OPUS_4_7, ...)` calls. Pinning the iteration to the enum's source order means a future enum-reorder propagates without a parallel UI edit; the AC's explicit Opus → Sonnet → Haiku order is enforced by the enum declaration at `data/preferences/Model.kt`. The `Column(modifier = Modifier.selectableGroup())` wrapper around the loop is the M3-recommended container for a radio set — TalkBack announces "1 of 3 selected" semantics at the group boundary rather than per row.
- **`ModelRow` owns the click via `Modifier.selectable`, not the `RadioButton`.** The row is `Row(Modifier.fillMaxWidth().selectable(selected, onClick, role = Role.RadioButton).padding(horizontal = 16.dp, vertical = 4.dp), verticalAlignment = Alignment.Top)` with `RadioButton(selected = selected, onClick = null)` inside — passing `onClick = null` on the radio is the documented M3 pattern for "the parent owns the click semantics". This makes the entire row a 48dp+ touch target (title + description height) rather than restricting taps to the 20dp radio circle, and the `Role.RadioButton` semantic flows through to TalkBack via the `selectable` modifier.
- **`Alignment.Top` on the row, not `CenterVertically`.** Description text wraps to multiple lines on narrow widths; the AC's "title + description" two-line layout looks broken if the radio recentres against the wrapped block. Top-aligning the radio to the title baseline keeps the visual anchor stable across description heights. The 12.dp horizontal spacer between the radio and the text column was tuned against the Figma `20:117/122/127` spacing.
- **`Model.description(): String` is a private file-local extension**, not a top-level reusable helper. Co-located in `StatusSheet.kt` mapping `OPUS_4_7 → "best for complex work"`, `SONNET_4_6 → "faster, cheaper"`, `HAIKU_4_5 → "fastest"` (Figma nodes `20:117/122/127` literal copy). Kept private because these are Figma-derived presentation strings specific to this sheet's "user picks a model" framing — a future Settings model-picker (`AppPreferences.setDefaultModel(...)` write-site, still pending per [`app-preferences`](../features/app-preferences.md) gap) may want different copy ("Default for new conversations" framing) or no descriptions at all. The label/title is [`Model.label()`](./253.md) from `data/preferences/Model.kt`; that extension *is* shared because it's the identifier-to-display-name shim.
- **Sheet visibility is `rememberSaveable`-hoisted into `ThreadScreen`, not held on `ThreadViewModel`.** `var sheetVisible by rememberSaveable { mutableStateOf(false) }` matches the precedent at [`WorkspacePicker.kt:45`](../features/workspace-picker.md). UI-local presentation state with no business meaning the VM needs to react to does not belong on `ThreadUiState`; pushing it into the VM would dirty the VM contract with screen-presentation concerns and break the "VM doesn't know about Compose" line that the rest of `ThreadViewModel` holds. `rememberSaveable` (over bare `remember`) means the sheet survives configuration changes (rotation) at zero VM-surface cost.
- **`ThreadScreen` swaps `onExpandClick: () -> Unit = {}` for `onModelSelected: (Model) -> Unit = {}` — the screen owns the sheet trigger now.** The status row's `onExpandClick = { sheetVisible = true }` is wired internally inside `ThreadScreen`; `MainActivity` no longer needs to pass anything for the row's tap behaviour. Removing the parameter (rather than keeping it as `onExpandClick = {}` for symmetry) is safe: the four pre-existing `@Preview` composables never passed it (all relied on the default), and `MainActivity` is the only production caller — the diff verified there are zero remaining `onExpandClick =` call sites after the swap. The new `onModelSelected` defaults to `{}` so previews keep compiling unchanged.
- **`StatusSheet` mounts as a `Scaffold` *sibling* at the end of `ThreadScreen`'s body**, wrapped in `if (sheetVisible) { ... }` (gated `if`, not `AnimatedVisibility`). `ModalBottomSheet` lives in its own window so source-order placement doesn't affect Z-order; the `if` gate is the standard idiom for "create the sheet composable only when visible" — same pattern as [`WorkspacePicker`](../features/workspace-picker.md)'s host. The sibling-placement choice mirrors how `WorkspacePicker` is hosted; placing the sheet inside the `Scaffold`'s content slot would have worked but would mix the sheet's window-managed lifecycle with the body's layout-managed siblings.
- **Auto-close on selection.** The `onModelSelected` lambda inside `ThreadScreen` is `{ model -> onModelSelected(model); sheetVisible = false }` — the screen flips visibility off immediately after forwarding the event. For a single-section sheet this is the M3 modal-bottom-sheet convention (action-completing sheet, user picked, work is done). `ModalBottomSheet`'s framework-managed hide animation runs on a coroutine the runtime owns — no `sheetState.hide()` call needed before flipping the flag. The auto-close decision will be revisited when [#229](https://github.com/pyrycode/pyrycode-mobile/issues/229) and [#230](https://github.com/pyrycode/pyrycode-mobile/issues/230) make the sheet a multi-setting surface (users may want to toggle multiple things without re-opening); for a single-section sheet, auto-close is correct.
- **`MainActivity` `CONVERSATION_THREAD` destination loses `onExpandClick = {}` + `// TODO(#146)` and gains `onModelSelected = vm::onModelSelected`.** Net diff at `MainActivity.kt:204-215`: −2 lines (the TODO comment + the `onExpandClick = {}` line), +1 line (`onModelSelected = vm::onModelSelected`). The method-reference syntax avoids fresh lambda allocations on every recomposition of the destination block, matching the existing `vm::sendMessage` / `vm::retry` style.
- **No new dependencies, no Koin changes, no `gradle/libs.versions.toml` edits, no `strings.xml` keys.** `ModalBottomSheet`, `RadioButton`, `selectable`, `selectableGroup`, `rememberSaveable`, `Icons.Filled.Close` are all already on the classpath via the existing Compose BOM (`composeBom = 2026.02.01`). `Model` + `Model.label()` come from [#253](./253.md); no schema change to `AppPreferences`.

## Patterns established

- **Re-declare `TitleRow` + `SectionHeader` privately inside each new sheet file rather than extracting.** Three occurrences across `WorkspacePickerSheet.kt`, `ChannelInfoSheet.kt`, `StatusSheet.kt` — all share the same two helpers byte-identical in shape, padding, and styling. The extract-on-third-use threshold has been met for *shape* but not for *variability*: none of the three sheets has needed to diverge yet, and the cost of a fourth re-declaration is 25 LOC. The first sheet that needs a different title row (trailing icon other than close, or a subtitle below the title) is the ticket that extracts the common shape into `ui/conversations/components/SheetChrome.kt` (or similar) and switches all four call sites; until then, the three privates stay. Same logic the [#253](./253.md) decision used for `Model.label()` co-location — co-locate until the cost of the next duplicate exceeds the cost of extraction.
- **`Modifier.selectable(role = Role.RadioButton)` on a `Row` parent, `RadioButton(onClick = null)` as a child** is the canonical M3 shape for a radio row whose tappable region is the whole row, not just the radio control. Apply to any future radio list in this codebase (the Settings effort-picker, the to-be-built model-picker on Settings, etc.). The `selectable` modifier carries TalkBack semantics through the parent; the inner `onClick = null` is the documented "don't double-handle the click" signal. `Column(selectableGroup())` wraps the row list so TalkBack announces group-membership ("1 of 3").
- **Sheet-visibility state is `rememberSaveable`-hoisted into the screen, not pushed onto the VM.** The rule: UI-local presentation state with no business meaning belongs on the screen; only state the VM needs to react to (or persist across VM lifetime) belongs on `ThreadUiState`. Sheet visibility for action-completing sheets clearly meets the "UI-local" bar — the VM does not change behaviour based on whether the sheet is open. The choice scales: future Status Sheet sections (#229's Effort + YOLO, #230's Context window) reuse the same `sheetVisible` flag, and the VM stays clean of `sheetVisible: Boolean` fields it would otherwise have to ignore.
- **Auto-close on selection for single-action sheets; revisit when the sheet becomes multi-section.** The pattern is `onSelected = { value -> vmHandler(value); sheetVisible = false }`. For a sheet whose entire job is "pick one thing", this matches user expectation (M3 modal-bottom-sheet convention). Multi-section sheets ([#229](https://github.com/pyrycode/pyrycode-mobile/issues/229) widens this one) may need to keep the sheet open across multiple toggles — re-evaluate when the second section lands, don't pre-emptively over-engineer the single-section case.
- **`if (visible) { ComposableThatHostsAModalBottomSheet(...) }` is the visibility gate idiom, not `AnimatedVisibility`.** `ModalBottomSheet` runs its own enter/exit animation via its `SheetState` and lives in its own window; wrapping in `AnimatedVisibility` would double-animate the sheet (the outer fade plus the inner slide-up). The gated `if` creates the composable on first show and destroys it on dismiss, which is what `ModalBottomSheet` expects. Same shape as [`WorkspacePicker`](../features/workspace-picker.md)'s host.

## Lessons learned

- **`assertIsSelected()` on the `RadioButton` node directly fails when the `selectable` modifier lives on the parent `Row`.** The Compose-test trap: `onNode(hasText("Sonnet 4.6"))` returns the `Text` node, which has no `Role.RadioButton` semantics; `onNode(isSelectable()).assertIsSelected()` matches the parent `Row` correctly but is ambiguous when three selectable rows exist. The right matcher is `onNode(isSelectable() and hasAnyDescendant(hasText("Sonnet 4.6"))).assertIsSelected()` — `hasAnyDescendant` walks down from the selectable parent to find the title text, uniquely identifying the row. The trap appears benign (the test passes locally if only one row is selectable) but breaks the moment additional sections add more selectable rows; pinning the descendant text avoids the future-test fragility.
- **`Model.entries.forEach` instead of three hand-written `ModelRow(Model.OPUS_4_7, ...)` calls.** Tempting to write the three rows explicitly to make the source order obvious — but the source order is *already* obvious from `data/preferences/Model.kt`'s `enum class Model { OPUS_4_7, SONNET_4_6, HAIKU_4_5 }` declaration. Iterating means a future enum extension (e.g. `Model.SONNET_4_7` added between Opus and Sonnet, or `Model.HAIKU_5` appended) lands at the data layer with zero UI change. The cost is one extra indirection (`Model.entries` rather than literal references); the saving is the eliminated drift surface.
- **`onClick = null` on a `RadioButton` inside a `selectable` parent is required, not optional.** Passing the same `onClick = { onModelSelected(model) }` to both the row's `selectable` and the inner `RadioButton.onClick` causes the click to fire twice — once via the row's hit detection and once via the radio's. Compose-test won't catch this if the recorder is a simple `mutableListOf<Model>().add` (the assertion `picks == listOf(Model.SONNET_4_6)` passes because the list contains the right value) but it manifests at runtime as double-firing analytics events or double-write to `MutableStateFlow.value` (idempotent for `Model` but a real bug for any non-idempotent handler). The lint-clean shape is `RadioButton(selected = selected, onClick = null)`.
- **Title and description strings stay as Kotlin literals — no `strings.xml` extraction yet.** The two sibling sheets ([`WorkspacePickerSheet`](../features/workspace-picker-sheet.md), [`ChannelInfoSheet`](../features/channel-info-sheet.md)) both inline their copy; the localisation pass is a separate concern that extracts everything together. Extracting only this sheet's strings would mix layers (some `stringResource` lookups, some literals) and add no immediate value. The three description strings (`"best for complex work"` etc.) are product-vendor descriptors that don't localise the way navigation labels do — they describe Anthropic's models in a tone product owns; first-localisation cut may rewrite them entirely. Apply to future sheets in this package: literal until the first-localisation ticket lands.
- **The `onExpandClick: () -> Unit = {}` parameter on `ThreadScreen` was a placeholder that has now been deleted.** [#145](./145.md) added it as a hoisted hook (anticipating that the host would own the sheet trigger); this slice discovered the cleanest shape is for the screen itself to own `sheetVisible`. The parameter had no remaining external consumer once the host's `onExpandClick = {}` no-op went away — `MainActivity` was the only production caller, and removing the parameter rather than keeping it as `onExpandClick: () -> Unit = {}` for symmetry kept the screen contract honest (callers can't pretend to handle a sheet trigger that the screen doesn't surface). The four pre-existing `@Preview` composables never passed it (all relied on the default), so removal had zero downstream churn. Lesson: when a placeholder parameter's only purpose evaporates, delete it rather than keeping it for "future symmetry". The architecture spec called this out as the safe move; the diff verified there were zero remaining `onExpandClick =` call sites in the repo before deletion.
