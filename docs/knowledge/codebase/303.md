# #303 — Noise_IK session re-key: fresh handshake + atomic CipherState swap (initiator)

The **in-place re-key mechanism** for the Phase 4 encrypted transport: extends the one-shot [#298](298.md) `NoiseIkSession` so an established session can refresh its AEAD keys without being torn down. Two new methods run a *fresh* `Noise_IK_25519_ChaChaPoly_BLAKE2s` handshake against the **same pinned server static `rs`**, derive a fresh sender/receiver `CipherStatePair`, and **atomically** swap it for the live pair under the session lock — wiping the old keys. The initiator mirror of the Go responder's atomic swap (`pyrycode` [#453](https://github.com/pyrycode/pyrycode/issues/453)). Split from #299; depends on [#298](298.md).

See the feature doc [`noise-ik-session.md`](../features/noise-ik-session.md) for the evergreen "how the session works / how re-key fits" reference (its § Lifecycle, § Edge cases → re-key, and § Exported types now cover the re-key surface). This file is the implementation record. **No new ADR** — this ticket consumes [ADR 0004](../decisions/0004-vendor-noise-java-crypto.md) (suite + vendored library) and [ADR 0006](../decisions/0006-keystore-wrap-at-rest-device-static-key.md) (local `s` custody), and aligns with pyrycode-side ADR 024 (Noise_IK for mobile E2E). `security-sensitive` (the asset is the encrypted transport across the rotation + the device static key + the new/old transport CipherStates).

## Scope

**The session-layer mechanism only — byte-array(+key) in, byte-array out.** The *triggers* that drive it (the 1-hour timer, the inbound `rekey_request` dispatch) live at the WS-message-pump layer and are a **separate, not-yet-built ticket** that needs the relay WS client (#301). This ticket adds no timer, no loop, no socket — only the two methods the pump will call.

## Summary

One production source file **modified** (`NoiseIkSession.kt`, +99 lines), verified by one **extended** pure-JVM test file (`NoiseIkSessionTest.kt`, +150 lines, 9 new `@Test`). **Purely additive: two new methods, two new private fields, no constructor or existing-signature change, zero edit fan-out.** No new dependency, no gradle/DI change — `NoiseSessionFactory` is the only non-test consumer and is untouched.

The load-bearing facts, all test-pinned:

1. **Re-key is a full fresh IK handshake** (not a Noise `rekey()` of the existing CipherState) — a brand-new `HandshakeState(PROTOCOL, INITIATOR)` per re-key, against the **same pinned `rs`**, with **empty handshake early-data** (the original `hello`/token is **not** re-sent — the handshake itself is the signal). Same call sequence as the initial handshake; empty prologue and `ad = null` preserved.
2. **Atomic swap under the existing `@Synchronized` lock.** `writeRekeyInit`/`readRekeyResp` join `encrypt`/`decrypt`/`close` on the session's intrinsic monitor, so the pointer swap cannot interleave with an in-flight same-direction AEAD op — no mixed-key window, no nonce-reuse window (AC #2). The old pair is `destroy()`d on swap (AC #2 "old keys wiped").
3. **Fail-RETAIN, not fail-close** — the key lifecycle difference from #298's `readResp`. On any handshake/crypto failure the live CipherStates are **retained** (transport continues on the current keys) and `NoiseSessionException` is thrown; `pendingRekey` is cleared in `finally`, so the pump may **retry** `writeRekeyInit` (unlike the initial handshake, which is not resumable).
4. **Peer-static continuity is enforced structurally, not by a byte-compare** (AC #3). The initiator re-keys against the *same pinned `rs`* every time, so a `noise_resp` from a different/rotated server static or a relay MITM simply fails `readMessage` (`es`/`se` DH diverge → MAC failure) — there is no attacker-value-vs-secret compare, hence no constant-time obligation. This is the initiator mirror of #453's responder `bytes.Equal(PeerStatic, …)` check.
5. **The device static `s` is taken by parameter, never retained on the session** — preserving #298's bounded RAM window across every hourly re-key (the central design decision; see Patterns).

## Files touched

- **`app/src/main/java/de/pyryco/mobile/data/network/NoiseIkSession.kt`** (+99 lines; still **zero `android.*` imports**):
  - **Two new private fields** (`:81`, `:84`):
    - `pinnedRemoteStatic: ByteArray = remoteStaticPublicKey.copyOf()` — the re-key continuity anchor. A public key, so **no wipe needed**; defensively copied so the caller can't mutate it post-construction.
    - `pendingRekey: HandshakeState? = null` — the in-flight re-key handshake (it holds the re-loaded device `s`); `null` ⟺ no re-key in flight. **The "re-key in flight" state is encoded by this field, not a new `State` enum value** — `state` stays `ESTABLISHED` throughout so `encrypt`/`decrypt` (which `check(state == ESTABLISHED)`) never spuriously throw mid-re-key (AC: transport never pauses).
  - **`writeRekeyInit(s: ByteArray): ByteArray`** (`:172`, `@Synchronized`) — `check(state == ESTABLISHED)` + `check(pendingRekey == null)` (caller-bug guards → `IllegalStateException`); `require(s.size == 32)`; build a fresh `HandshakeState(PROTOCOL, INITIATOR)` (wrap `NoSuchAlgorithmException` → `NoiseSessionException("noise suite unavailable")`); `localKeyPair.setPrivateKey(s, 0)` (derives the matching public key); `remotePublicKey.setPublicKey(pinnedRemoteStatic, 0)` (the SAME pinned `rs`); `start()` (**never `setPrologue`** — the empty prologue is load-bearing, same as the initial handshake); `writeMessage(out, 0, EMPTY_EARLY_DATA, 0, 0)` into `out = ByteArray(IK_MSG1_OVERHEAD)` (96; zero-length payload); store `pendingRekey`; `return out.copyOf(n)`. Transport stays valid on the **current** keys until `readRekeyResp`. Caller MUST zero `s` after this returns (KDoc contract, mirroring `NoiseSessionFactory.create()`).
  - **`readRekeyResp(resp: ByteArray)`** (`:203`, `@Synchronized`, returns `Unit`) — mirrors `readResp` with **swap-and-retain** instead of first-establish-and-fail-close. `check(state == ESTABLISHED)`; `val hs = pendingRekey ?: throw IllegalStateException("no re-key in flight")`; then a `try { … } finally { hs.destroy(); pendingRekey = null }`:
    - `hs.readMessage(resp, 0, resp.size, earlyDataBuf, 0)` into `ByteArray(resp.size)` (empty early-data; recovered length discarded). `BadPaddingException` → `NoiseSessionException("noise_resp rekey verification failed")`; `ShortBufferException` → `NoiseSessionException("malformed noise_resp")`.
    - `if (hs.action != SPLIT) throw NoiseSessionException("noise rekey handshake did not complete")`.
    - `val newPair = hs.split()` — **initiator does NOT swap**: `newPair.sender` = encrypt-out, `newPair.receiver` = decrypt-in (same assignment as `readResp`; responder mirror-swaps).
    - **Atomic swap (the critical section, under the lock):** `val oldPair = ciphers; ciphers = newPair; sender = newPair.sender; receiver = newPair.receiver; oldPair?.destroy()`. Any throw *before* the reassignment leaves `ciphers`/`sender`/`receiver` pointing at the live pair (AC #3 retain); the swap+wipe is the only mutation.
    - **No `conn_id` is parsed** (unlike `readResp`) — it is unchanged across re-key and the resp carries empty early-data.
    - The `finally` wipes the re-key handshake (and its copy of `s`) **regardless of outcome** — the bounded RAM window.
  - **`close()`** (`:263`, +2 lines) — added `pendingRekey?.destroy(); pendingRekey = null` so an abandoned mid-re-key handshake (and its `s` copy) is wiped on teardown; idempotent.
  - **Companion** (`:333`, +1) — `val EMPTY_EARLY_DATA = ByteArray(0)` (the re-key `noise_init` carries no early-data). `IK_MSG1_OVERHEAD = 96` reused unchanged.
  - KDoc updated: the class header now names the re-key methods and notes they are `@Synchronized` (the swap can't interleave with an in-flight same-direction AEAD op) and that re-key runs in place over an established session without pausing transport.

## Patterns established

- **Re-loaded-per-use secret over session-resident secret (the central re-key decision).** The re-key needs the device static `s` again, but #298 deliberately discards it after the first handshake to bound its RAM window. Two options: (A) retain `s` on the session (simplest API, no parameter) vs (B) re-load `s` per re-key and pass it in. **Chose (B).** `writeRekeyInit` takes `s` as a parameter; the only place `s` lives across the re-key is the *pending re-key `HandshakeState`*, destroyed on `readRekeyResp` (success or failure) and on `close()`. Option A would have re-resident the phone's **long-term identity** (strictly more valuable than per-session transport keys — leaking it enables future-handshake impersonation until re-pair) in RAM for the whole multi-hour session, defeating #298's bound on every hourly re-key. Cost of (B): one method parameter + one line of caller zero-after-use discipline (mirroring `NoiseSessionFactory.create()`). **General rule: when a long-lived object needs a high-value secret only intermittently, re-supply it per use rather than caching it — the RAM-window cost of caching scales with object lifetime, the re-supply cost does not.**
- **Fail-RETAIN as the correct fail-safe for an in-place key rotation** (contrast #298's `readResp` fail-close). A failed re-key has leaked no old-key material (the failure means the responder couldn't complete the new handshake), so the live, *uncompromised* CipherStates stay in place and transport continues — tearing down a working session on a forged/failed re-key would be a needless availability hit *and* would hand an attacker a session-downgrade lever. The old keys are wiped (`oldPair.destroy()`) **only on a successful swap**. A failed re-key is retryable; the initial handshake is not. (Initiator mirror of `pyrycode` #453's responder behaviour.)
- **"Operation in flight" encoded by a nullable field, not a new state-machine state.** Re-key must not pause transport (frames flow on the current keys up to the atomic switchover), so a `REKEYING` enum value would have made `encrypt`/`decrypt`'s `check(state == ESTABLISHED)` wrongly throw mid-re-key. Encoding "re-key in flight" as `pendingRekey != null` keeps `state == ESTABLISHED` invariant throughout. Reach for an orthogonal nullable field (not a new enum value) when a sub-operation must run *concurrently with* the primary state, not *instead of* it.
- **Extend the existing lock, don't invent a new one (carried forward from #298).** The atomic swap reuses the session's intrinsic `@Synchronized` monitor rather than adding an ad-hoc swap lock — `encrypt`/`decrypt`/`writeRekeyInit`/`readRekeyResp` never call one another and the two ciphers are distinct objects, so no deadlock; the lock stays the deterministic floor under the stochastic single-pump contract (belt-and-suspenders, same fabric distinction as #298's nonce-reuse net).

## Lessons learned

Lifted from the PR's *Lessons learned* section:

- **A peer-static-discontinuity test (AC #3) cannot be staged by "drive the responder re-key leg with a different static key."** A responder *not* holding the pinned `rs` **fails `readMessage` of the initiator's `noise_init`** (the IK transcript diverges) and so never produces a `noise_resp` at all — the naive sketch in the spec's testing strategy can't even reach the line under test. The faithful, mechanically-correct stand-in is a well-formed `noise_resp` from a **fully independent** handshake against a *different* `rs` (`foreignRekeyResp()`: spin up an independent `TestResponder` + a throwaway `NoiseIkSession` pinned to *its* key, run a complete handshake + re-key leg, and harvest the resulting `noise_resp`). Fed to the pinned session, *that* frame reaches `readMessage` and MAC-fails (the pinned-`rs` handshake state diverges). The on-the-wire shape of a rotated server static / relay MITM is "a valid resp from the wrong key," not "a resp the wrong key tried to produce." (This matches the recalled continuity-test-shape note carried from #298's family of tickets.)
