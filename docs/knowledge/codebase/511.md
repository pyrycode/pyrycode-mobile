# #511 — SettingsScreenTest: restore androidTest compilation (missing `serverLabel`)

**Issue:** [#511](https://github.com/pyrycode/pyrycode-mobile/issues/511) ·
**Spec:** [`docs/specs/architecture/511-settings-test-serverlabel-compile-fix.md`](../../specs/architecture/511-settings-test-serverlabel-compile-fix.md) ·
**PR:** [#512](https://github.com/pyrycode/pyrycode-mobile/pull/512) ·
Size **XS**, not `security-sensitive`.

## Summary

Pure compile-restoration. Commit `51501f3` (#503 — *paste-pairing-code dialog + live server
label in Settings*) added a **required** `serverLabel: String` parameter to the
[`SettingsScreen`](../features/settings-screen.md) composable and updated the production call
sites and both `@Preview`s, but not the three `SettingsScreen(...)` invocations in
`SettingsScreenTest.kt`. The `androidTest` source set therefore stopped compiling on `main`.
This ticket threads the argument into the three existing test call sites — no behaviour change,
no new coverage.

## Files touched

One file, three one-line insertions. **No production code** (AC#4).

- `app/src/androidTest/java/de/pyryco/mobile/ui/settings/SettingsScreenTest.kt` (**mod**, +3) —
  in each of `wallpaperColorsRow_rendersMaterialYouLabel` (`:34`),
  `archivedDiscussionsRow_rendersSupportingTextWithCount` (`:73`), and
  `aboutRow_navigatesOnClick` (`:113`), one line added immediately after the
  `connectionStatus = …` argument:

  ```kotlin
  serverLabel = "abc123 · wss://relay…",
  ```

  The literal mirrors the preview fixtures (`SettingsScreen.kt:344,377`) — non-empty (AC#1) and
  consistent with the canonical example used elsewhere. Placement after `connectionStatus`
  mirrors the composable's parameter order (`serverLabel` is the 2nd parameter); the calls are
  fully named, so this is readability only. No import change — `serverLabel` is a plain `String`.

The three assertions ("Use Material You dynamic color" row exists, "11 archived" supporting text,
About-row click fires once) are untouched — none depends on `serverLabel` (AC#3).

## Root cause — the androidTest gate gap

The break shipped undetected because the mandatory gates (`./gradlew check`, `assembleDebug`,
`test`, `lint`) do **not** compile the `androidTest` source set — the documented gap
[[androidtest-not-compiled-by-mandatory-gates]]. A required-parameter addition to a composable
that is exercised only from `androidTest` is invisible to every gate that ran on #503's PR.

It surfaced on PR #510 (#492) purely because that PR touches `app/src/androidTest/`, which
triggers the QA androidTest-compile gate. PR #510 does **not** reference `serverLabel` and does
**not** touch this test file; a baseline against `git merge-base HEAD origin/main` reproduced the
identical three errors → pre-existing on `main`, not caused by #510.

## Verification

Acceptance signal (AC#2) — the source set that actually fails:

```bash
./gradlew compileDebugAndroidTestKotlin   # FAILED → BUILD SUCCESSFUL
```

`test` / `check` / `assembleDebug` do **not** exercise this fix (they skip androidTest
compilation — the very gap that let it ship). `connectedAndroidTest` (on-device run of the three
tests) is optional confirmation of AC#3 and was not run: no device attached, and the assertions
plus the composable's rendered output for the three cases are independent of `serverLabel`.

## Lessons learned

- **A required composable-parameter addition can break `androidTest` while every mandatory gate
  stays green.** The introducing PR (#503) passed `check`/`assembleDebug` because those gates
  don't compile `androidTest`; the break sat latent on `main` until an unrelated PR touching
  `androidTest/` tripped the compile gate. When a composable signature changes, grep the
  `androidTest` tree for its call sites and run `compileDebugAndroidTestKotlin` explicitly — the
  mandatory gates will not. See [[androidtest-not-compiled-by-mandatory-gates]].
- **"Surfaced by PR X" ≠ "caused by PR X."** The fix belongs to a standalone ticket against
  `main`, not folded into the PR that merely ran the gate. A `merge-base` baseline is the cheap
  way to prove pre-existence before assigning provenance.
