# #522 — `OkHttpRelayTransport` frame-rejection tests (binary + oversize)

Adds the two missing input-validation tests for the [relay WS transport](../features/relay-ws-transport.md):
a **binary** WebSocket frame and an **oversize** text frame (length `> MAX_INBOUND_FRAME_CHARS`)
each tear the connection down and deliver nothing downstream. Both reject paths already existed in
production (`failLocally(WS_UNSUPPORTED_DATA, …)` / `failLocally(WS_MESSAGE_TOO_BIG, …)`) but neither
was covered by a test — the 2026-07-03 cross-repo review flagged the gap. **Test-only; production
behaviour is unchanged.** Split from #500 (independent sibling of the [#521 `RelayLog`](./521.md) facility).

## Summary

- Two new `@Test` methods in `OkHttpRelayTransportTest`, each a near-clone of the existing
  `inbound_malformedJsonTearsDownWithDown` template, differing only in the frame the mock server
  drives in. Both assert the **observable outcome** (per the AC): a terminal `TransportEvent.Down` on
  `events`, and an **empty** `inbound` stream — *not* the close code or the `cause` type.
- `inbound_binaryFrameTearsDownWithDownAndDeliversNothing` — server sends `ByteString.of(1.toByte())`,
  routing to the `onMessage(_, bytes: ByteString)` overload → binary-reject branch.
- `inbound_oversizeTextFrameTearsDownWithDownAndDeliversNothing` — server sends
  `"a".repeat(OkHttpRelayTransport.MAX_INBOUND_FRAME_CHARS + 1)` (131_073 chars) → size-guard branch.
- File is now 14 `@Test` (was 12 before this ticket).

## Patterns established

- **Untrusted-boundary reject tests assert the outcome, not the mechanism.** For a protocol-violation
  teardown, await `events.first { it is TransportEvent.Down }` (proves `terminate()` ran) then assert
  `inbound.toList().isEmpty()` — **do not** assert the WS close code or the `cause` type. The close
  codes (`1003`/`1009`) are an implementation detail the transport is free to change; the contract is
  "torn down, nothing leaked to `inbound`". This mirrors the malformed-JSON template and is the shape
  every future reject-branch test in this class should follow.
- **Anchor a boundary test to the constant, not a literal.** The oversize frame is
  `MAX_INBOUND_FRAME_CHARS + 1`, referenced via the public companion member — so the test tracks the
  cap if it ever moves, and documents the strict-`>` boundary in the expression itself.

## Lessons learned

- **The size guard runs *before* the JSON decode**, so the oversize frame's non-JSON content
  (`"a".repeat(…)`) is intentional and correct: `OkHttpRelayTransport.kt:153` checks
  `text.length > MAX_INBOUND_FRAME_CHARS` and returns *before* the `decodeFromString` at :164. A frame
  over the cap trips the **size** branch regardless of validity — so this test exercises the size
  path, not the malformed-JSON path already covered. Using valid JSON here would test nothing extra.
- **The cap is a strict `>`** — a frame of *exactly* `MAX_INBOUND_FRAME_CHARS` (131_072) is **accepted**
  and would not tear down; the trip requires `+ 1` (131_073). Getting this wrong yields a silently
  passing test that never exercises the branch.
- **Order the collectors: `events.first { Down }` first, then the single `inbound.toList()`.**
  `terminate()` closes `inboundChannel`, so once teardown has run, `inbound` completes empty and
  `toList()` returns `[]` promptly rather than blocking. `inbound` is a single-consumer
  `receiveAsFlow()` — collect it **once** per test.
- **`runTest`/virtual time will not work here** — real OkHttp reader/dispatcher threads feed the
  Channel-backed flows, so both tests bridge with `runBlocking { withTimeout(TIMEOUT_MS) { … } }`,
  like every test in this class (see the class KDoc). Virtual time cannot advance real network I/O.
- **Both listeners must extend `ClosingServerListener`.** `failLocally` closes the socket client-side;
  without the server echoing that close, `tearDown()`'s `server.shutdown()` blocks on its ~5 s drain
  timeout. This is the same harness trap documented in [#306](./306.md).
