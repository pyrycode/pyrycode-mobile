# #312 — `RemoteConversationRepository` + `observeConversations` list path (Mobile Protocol v2)

The **first concrete Phase 4 `ConversationRepository` implementation**: introduces
`RemoteConversationRepository : ConversationRepository` and wires the **conversation-list read path**
(`observeConversations`) live over the [Noise session pump](../features/noise-session-pump.md)
([#309](309.md)), mapping `conversations` snapshots to domain [`Conversation`](../features/data-model.md)
values via the [#316](316.md) mapping layer. Every other interface method ships as a clearly-marked
not-yet-implemented stub the sibling slices replace in the **same** class. Repository slice split from
[#278](https://github.com/pyrycode/pyrycode-mobile/issues/278); the last-message preview was carved into
its own follow-up [#329](https://github.com/pyrycode/pyrycode-mobile/issues/329).

See the feature doc [`remote-conversation-repository.md`](../features/remote-conversation-repository.md)
for the evergreen "how the remote repo works / what plugs into it" reference. This file is the
implementation record. **No new ADR** — pure `data/`-layer orchestration over existing seams; no crypto,
no new dependency, no build edit. **Not `security-sensitive`** — this slice runs **behind** the
authenticated Noise channel; the untrusted-payload decode-and-validate boundary is the #316 mapper, and
the internet-exposed frames + crypto are owned by the pump/transport (#309/#306/#307).

## Scope

**The conversation-list read path only — one repository, one live method.** Sized **S**. The repository
**owns**: the `SessionPump` consumer interface it depends on, a single inbound-stream collector that
demultiplexes by `Envelope.type` into one `StateFlow` projection, and the cold `observeConversations`
fan-out (issue `list_conversations`, map via #316, apply the `ConversationFilter`, sort). Out of scope,
by design and named in the spec:

- **The thread read path** (`observeMessages`) — [#313](https://github.com/pyrycode/pyrycode-mobile/issues/313).
- **The last-message preview** (`observeLastMessage`) — [#329](https://github.com/pyrycode/pyrycode-mobile/issues/329).
  The v2 `conversations` payload carries **no message content** (only a `last_message_ts` timestamp that
  maps to no domain field), so the real preview must come from the message read path (#317 + a
  per-conversation read) — a different wire path with a different dependency. See [[v2-app-payload-shapes-ssot]].
- **The mutation path** (`sendMessage` / `createDiscussion` / `promote`) — [#314](https://github.com/pyrycode/pyrycode-mobile/issues/314)
  (consumes #318's `ConversationResponseDto`).
- **The five methods with no documented v2 wire message** (`archive` / `unarchive` / `rename` /
  `startNewSession` / `changeWorkspace`) — a follow-up specs the wire contract.
- **`NoiseSessionPump : SessionPump` + the live Koin binding** — the DI/connection-coordinator slice
  ([#279](https://github.com/pyrycode/pyrycode-mobile/issues/279) / [#302](302.md)): add `: SessionPump`
  + two `override`s to `NoiseSessionPump`, provide the connection-scoped `CoroutineScope`, and swap the
  Koin binding from `FakeConversationRepository` when paired/connected. Keeping that out held #312 to
  **two new production files, zero edits to existing files**.

## Summary

**Two new production files** (`SessionPump.kt`, 30 lines; `RemoteConversationRepository.kt`, 172 lines)
verified by **one new JVM test file** (`RemoteConversationRepositoryTest.kt`, 313 lines, **8 `@Test`**).
**Purely additive: all-new code, zero edit fan-out, no Koin binding, no gradle change, no consumer
edits** — `RemoteConversationRepository` is referenced nowhere yet (the binding is #279/#302), confirmed
by the code review's codegraph check. No new dependency.

The load-bearing facts, all test-pinned:

1. **One inbound consumer, one projection, cold fan-out.** `pump.inbound` is hot and **single-consumer**,
   so the repository launches exactly **one** long-lived collector in `init` on the injected connection
   `scope` (`RemoteConversationRepository.kt:59-65`). It demultiplexes by `Envelope.type` into a single
   `private val projection = MutableStateFlow<List<Conversation>?>(null)` (`:55`, `null` = list not yet
   loaded). `observeConversations(filter)` is a **cold** `flow { … }` that (1) issues the request via
   `pump.send(listConversationsRequest())` then (2) `emitAll` of `projection.filterNotNull().map {
   project(it, filter) }` (`:90-97`). N concurrent collectors share the one inbound consumer — multi-collector
   AC satisfied with a single hot consumer.
2. **Any inbound `conversations` snapshot is the list source of truth (no `in_reply_to` correlation).**
   The reply to our `list_conversations` request **and** any unsolicited server change-push both arrive
   as a full-list `{conversations:[…]}` snapshot, so the demux handler (`onInbound`, `:67-88`) treats
   **any** `type == "conversations"` envelope as the projection's new value via
   `MobileJson.decodeFromJsonElement<ConversationsPayload>(envelope.payload).toConversations()` — re-emission
   needs no request correlation (AC #3). `StateFlow` conflation means a value-equal snapshot does not
   re-emit.
3. **`project(list, filter)` mirrors the Fake exactly.** `filter` per `ConversationFilter` (`All` →
   everything; `Channels` → `isPromoted && !archived`; `Discussions` → `!isPromoted && !archived`;
   `Archived` → `archived`) then `sortedByDescending { lastUsedAt }` (`:100-112`) — identical to
   `FakeConversationRepository`, so the UI behaves identically under either binding.
4. **Malformed payload is dropped; the single inbound consumer survives.** The decode is wrapped in a
   per-envelope `try/catch (e: IllegalArgumentException)` (`:76-81`) — the **one** catch covers both #316
   decode-failure families (`MissingFieldException` ⊂ `SerializationException` ⊂ `IllegalArgumentException`,
   and the kotlinx-datetime bad-timestamp `IllegalArgumentException`). A bad snapshot is dropped, the
   projection is unchanged, and the lone collector keeps running rather than freezing every future update
   for the connection. The `ConversationRepository` flow type has no error channel and the Fake never
   errors, so dropping is the only interface-consistent option.
5. **`list_conversations` request shape.** `Envelope(id = requestId.incrementAndGet(), type =
   "list_conversations", ts = Clock.System.now().toString(), payload = JsonObject(emptyMap()))` where
   `requestId` is a private `AtomicLong` (`:114-120`). Payload is `{}` per protocol.
   **send-on-each-subscribe is intentional**: redundant requests are absorbed by `StateFlow` conflation,
   and re-subscribing (e.g. on lifecycle resume) naturally re-issues — more robust than a send-once guard
   if an early send was dropped pre-`Open`.
6. **Stubs name their owning follow-up; defaults are inherited, not overridden.** Every method other than
   `observeConversations` throws `UnsupportedOperationException` with a message naming the owner
   (`:124-163`): `observeMessages` → #313, `observeLastMessage` → #329, `sendMessage`/`createDiscussion`/
   `promote` → #314, and `archive`/`unarchive`/`rename`/`startNewSession`/`changeWorkspace` → "no v2 wire
   message defined". `delete`, `recentWorkspaces`, `createWorkspaceFolder` are **deliberately not
   overridden** — they have interface defaults (error / empty flow) and are outside this slice's surface.

## Patterns established

- **Consumer-defined pump interface in `data/repository/`, real impl in `data/network/`.** `SessionPump`
  follows the [`ConnectionStateSource`](../features/connection-state.md) precedent: the repository depends
  on a minimal local contract, not on the concrete `NoiseSessionPump` a layer down. The DI slice makes
  the concrete class satisfy the interface (`: SessionPump` + `override`s). Reuse this shape whenever a
  `data/` consumer needs a `data/network/` capability without an upward dependency.
- **Single hot-inbound consumer → one `StateFlow` projection → cold fan-out.** The repository is the
  **sole** collector of the pump's single-consumer `inbound`; it owns the multiplex so any number of cold
  `observe*` flows can fan out. The sibling slices (#313 `messages`, #314 mutation deltas, #329
  last-message) **extend the same `onInbound` `when` and the same class** — they do not add a second
  inbound collector. This is the canonical shape for every future read/push path on the remote repo.
- **One `catch (IllegalArgumentException)` covers both #316 decode-failure families.** Per [#316](316.md),
  a field-incomplete payload throws `MissingFieldException` (a `SerializationException`) and a malformed
  RFC 3339 timestamp throws a kotlinx-datetime `IllegalArgumentException` — both subtypes of
  `IllegalArgumentException`, so a single catch is total over decode failures. Because #316 decodes
  timestamps to `Instant` **at the DTO**, `toConversations()` is genuinely total and is safely called
  **outside** the catch.
- **`project()` mirrors the Fake's filter+sort verbatim** so the UI is binding-agnostic. When a later
  slice adds a remote-only field derivation, keep the observable shape identical to the Fake unless the
  AC explicitly diverges.
- **Single-row conversation deltas are NOT a `conversations` snapshot.** `conversation_updated` /
  `conversation_created` are single-`Conversation` payloads mapped by #318's `ConversationResponseDto`,
  not #316's list mapper — `onInbound` no-ops them here. Merging a delta into the live projection (so a
  promote/rename/archive made elsewhere re-emits without a full re-`list_conversations`) is owned by the
  #318-dependent slice (#314). This is exactly why #312 depends on **#316 only, not #318**.

## Lessons learned

Lifted from the PR's *Lessons learned* section + the code review:

- **Drive the push→demux→project→emit cascade with `runCurrent()`, not `advanceUntilIdle()`.** When a fake
  inbound is a `Channel.receiveAsFlow()` feeding a single repository-internal collector launched on
  `backgroundScope`, `advanceUntilIdle()` did **not** deliver the buffered channel item to the background
  collector (there are no timers to elapse), leaving every projection-dependent assertion empty.
  `runCurrent()` (the `NoiseSessionPumpTest` idiom for non-timer steps) drains the whole current-time
  cascade deterministically. **Applies to the sibling slices #313/#314/#329** — same pump-fan-out test
  shape. See [[remote-repo-test-runcurrent-not-advanceuntilidle]].
- **Flow-returning stubs throw eagerly on call, not on collection (code-review NIT, non-blocking).**
  `observeMessages` / `observeLastMessage` are expression-body `throw` (`= throw …`), so they throw the
  moment they're **called** rather than returning a `flow { throw … }` that throws on collection. This is
  a deliberate, test-asserted stub and does not block merge (no production consumer reaches them under the
  Remote binding before #313/#329 land), but **#313/#329 should wire real cold flows** that defer work to
  collection — the owning slices were asked to keep this in mind.
