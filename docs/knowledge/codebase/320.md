# #320 — parse scanned QR payload → `PairedServer` + persist (replaces #295 stub)

Closes the pairing loop the live scanner opened: a successful QR scan no longer drives a throwaway
stub persist — it is **parsed, validated, and persisted as the real reconnect record**. Adds a pure,
`data/`-portable `parsePairingPayload(scanned)` that decodes the outer base64url-no-pad transport
wrapper, deserializes [`QrPayload`](../features/mobile-protocol-v2-wire-layer.md) via `MobileJson`,
validates every field, and maps to [`PairedServer`](../features/paired-server-store.md) — yielding a
typed `PairingParseResult.Success`/`Failure` and **never throwing**. `MainActivity` rewires the
`Decoded` binding (#334) to persist `Success` via `PairedServerStore.save` then navigate, routing any
failure into the existing `ScannerUiState.Error` surface. Parse + persist **only** — the
fingerprint / safety-number confirm gate is **#321**, the handshake is **#302 + #309**, and the
"paste the pairing code" text path stays out of scope (the paste button still runs the #295 stub).
Split from #277. See the new [Pairing payload parser](../features/pairing-payload-parser.md) feature
doc for the evergreen treatment.

## Summary

Five production files (two new) + three test files. The untrusted→trusted boundary is a **single
pure function** (`parsePairingPayload`): input is the raw scanned string, output is either a
fully-validated `PairedServer` (`Success`) or a byte-safe `Failure` — never a half-validated record,
never a throw. `MainActivity` holds only `Success.server` (→ save + navigate) or routes to `Error`;
nothing is persisted on any reject path. No new DI binding, no model change, no signature cascade —
`QrPayload`/`PairedServer` are consumed unchanged. The architect sized this 1-new-file; the ktlint
filename rule forced a second new file (the sealed result split out — see Lessons).

## Files touched

- **`data/network/PairingPayloadParser.kt`** *(new, 91 LOC)* — the boundary. Public:
  `fun parsePairingPayload(scanned: String): PairingParseResult`. Pure, synchronous, no I/O, no
  persist, **never throws** (every failure path returns a `Failure`). First-failure-wins pipeline:
  1. `decodeBase64UrlNoPad(scanned)` — catch `IllegalArgumentException` → `Failure("bad-encoding")`.
  2. `String(bytes, Charsets.UTF_8)` (substitutes, never throws — bad UTF-8 falls through to JSON).
  3. `MobileJson.decodeFromString<QrPayload>(json)` — catch `SerializationException` →
     `Failure("malformed-json")`. **One catch covers three AC rejects**: non-JSON, **trailing bytes
     after the top-level object** (kotlinx requires EOF after the value — no Go-style double-decode
     idiom needed), and **absent required fields** (`MissingFieldException ⊂ SerializationException`).
  4. `server`/`relay`/`token` each `isNotBlank()` else `Failure("missing-field")` — catches
     present-but-`""` (absent already failed at step 3).
  5. `isValidRelayOrigin(relay)` else `Failure("invalid-relay")` — `java.net.URI` parses (catch
     `URISyntaxException`) **and** `scheme.lowercase() ∈ {ws, wss}` **and** `host` non-empty. A
     present path/port is **not** rejected (stays close to the Go emitter's opaque-origin treatment).
  6. `decodeServerStaticPubkey(qr)` — catch `IllegalArgumentException` → `Failure("invalid-server-key")`.
     **Validation only**: the returned bytes are discarded; `PairedServer` stores the base64 string.
  7. `Success(PairedServer(serverId = qr.server, token = qr.token, relayUrl = qr.relay,
     serverStaticPublicKey = qr.serverStaticPubkey))`.
  - The `Failure.reason` strings are fixed `private object PairingParseFailure` constants —
    category labels, never a field value or the scanned bytes. The function does **no logging at
    all** (both `scanned` and the decoded `json` carry the plaintext token; the caller logs only the
    fixed reason).
- **`data/network/PairingParseResult.kt`** *(new, 22 LOC)* — `sealed interface PairingParseResult`
  with `data class Success(server: PairedServer)` and `data class Failure(reason: String)`. **Lives
  in its own file** because ktlint's `standard:filename` forbids a public top-level type co-habiting
  `PairingPayloadParser.kt` (whose only public top-level symbols are functions) — see Lessons.
- **`data/network/MobileWireCodec.kt`** *(modify, +12)* — adds
  `fun decodeBase64UrlNoPad(data: String): ByteArray = Base64.getUrlDecoder().decode(data)`, the
  **outer-wrapper** decoder (Go `base64.RawURLEncoding`). Co-located next to `base64StdDecode` (the
  inner-key decoder) **on purpose** — so the two-alphabet trap stays visible to the next reader. The
  url-safe decoder's load-bearing behavior is rejecting the std-alphabet `+`/`/`; it tolerates
  optional `=` padding (real `RawURLEncoding` is unpadded, so it round-trips — no hand-rolled
  no-pad check).
- **`ui/onboarding/ScannerViewModel.kt`** *(modify, +8)* — adds
  `data class PairingFailed(val message: String) : ScannerEvent` and the one `when` branch
  `is ScannerEvent.PairingFailed -> ScannerUiState.Error(event.message)` — mirrors the existing
  `CameraError → Error`. `message` is a UI-owned app constant (never a payload byte), so no redacting
  `toString()` is needed. The VM stays a pure synchronous state machine (no `viewModelScope`, no
  Android types).
- **`MainActivity.kt`** *(modify, +33)* — rewires the `Decoded` `LaunchedEffect(state)` binding
  (~`:191-216`). Replaces `if (state is Decoded) stubPairAndNavigate()` with
  `when (parsePairingPayload(decoded.payload))`: `Success` → `try { pairedServerStore.save(server);
  navController.navigate(CHANNEL_LIST){ popUpTo(SCANNER){inclusive=true}; launchSingleTop=true } }
  catch (PairedServerStoreException) { Log.w(TAG, …javaClass.simpleName);
  vm.onEvent(PairingFailed(SAVE_FAILED_MSG)) }`; `Failure` → `Log.w(TAG, "pairing parse failed:
  ${result.reason}"); vm.onEvent(PairingFailed(PARSE_FAILED_MSG))`. Two new UI-copy consts
  (~`:393-396`): `PARSE_FAILED_MSG` and `SAVE_FAILED_MSG` (generic, never interpolate a field value).
  **Left untouched** (out-of-scope paste path): `stubPairAndNavigate`, `STUB_PAIRED_SERVER`, and
  `onPasteCode = stubPairAndNavigate`. The parse is microsecond CPU work on a small string → runs
  inline on the `LaunchedEffect`'s Main coroutine (no `withContext(Dispatchers.Default)`).
- **`test/.../data/network/PairingPayloadParserTest.kt`** *(new, 157 LOC, 13 cases)* — JUnit4,
  mirrors `MobileWireCodecTest`. A `wrap(json)` helper builds a valid scanned string via
  `Base64.getUrlEncoder().withoutPadding()`. Covers: success + exact field mapping, round-trip
  (`MobileJson.encodeToString` → wrap → parse), extra-field tolerance, and every reject path — outer
  not-base64url, **std-alphabet `///+` trap**, non-JSON, trailing bytes (`{…}garbage` and `{…}{}`),
  absent + present-but-empty fields, malformed relay (`::::` / `http://x` / `ftp://x` / `wss://`),
  pubkey wrong-length (31 bytes) / non-base64, and the **no-leak** assertion (`Failure.reason` echoes
  neither a distinctive token nor pubkey).
- **`test/.../data/network/MobileWireCodecTest.kt`** *(modify, +3 cases)* — `decodeBase64UrlNoPad`
  decodes a known no-pad vector (`"aGVsbG8"` → `"hello"`), round-trips `getUrlEncoder().withoutPadding()`
  output, and `assertThrows<IllegalArgumentException>` on `"///+"` (the std-alphabet trap).
- **`test/.../ui/onboarding/ScannerViewModelTest.kt`** *(modify, +1 case)* —
  `pairingFailed_movesToErrorCarryingMessage` (`PairingFailed("boom")` → `Error("boom")`).

## Patterns established

- **The untrusted→trusted boundary is one pure, never-throwing function returning a sealed result.**
  `parsePairingPayload` is the *only* place the scanned bytes become a `PairedServer`; the boundary is
  not scattered across the call site. It never throws (all I/O-free, all failures typed) and persists
  nothing — the caller either holds a fully-validated `Success.server` or routes to `Error`. This
  keeps the persist site (`MainActivity`) trivially correct and makes the future #321 fingerprint gate
  a clean interpose **between** `Success` and `save(...)` with no restructuring. Reuse this shape for
  any "parse external input into a domain record" boundary.
- **Co-locate the two base64 alphabet decoders in one file so the trap stays visible.**
  `decodeBase64UrlNoPad` (outer wrapper, url-safe-no-pad) sits directly beside `base64StdDecode`
  (inner `server_static_pubkey`, std-with-padding) in `MobileWireCodec.kt`, with a KDoc on each
  pointing at the other. The next reader can't miss that there are two alphabets and which is which.
- **Validate a TOFU relay origin with `java.net.URI`, not `android.net.Uri` / OkHttp `HttpUrl`.**
  Parseable + scheme ∈ {ws, wss} + non-empty host keeps the check `data/`-portable (no `android.*`, no
  OkHttp dep) and matches the codec's existing `java.util.Base64` JVM-stdlib bar. A present path/port
  is deliberately tolerated — the relay is an origin the transport appends `/v1/client` to.
- **UI owns the copy; the parser emits only byte-safe category labels.** `Failure.reason` is a fixed
  constant for logging; the two user-facing strings (`PARSE_FAILED_MSG` / `SAVE_FAILED_MSG`) live in
  `MainActivity`. A field value never reaches a log line or the screen.

## Lessons learned

Lifted from [PR #341](https://github.com/pyrycode/pyrycode-mobile/pull/341)'s *Lessons learned* + the
code-review NIT:

- **ktlint `standard:filename` (1.5.0) forced a +1-file deviation from the spec.** A file whose only
  public top-level type is a class must be named after that class. A single `PairingPayloadParser.kt`
  holding both `parsePairingPayload` (a function — doesn't count) **and** the `PairingParseResult`
  sealed type fails the gate. Fix: split the sealed result into its own `PairingParseResult.kt` (the
  repo's sealed-type-per-file convention; no `@file:Suppress` precedent exists). The parser file kept
  its architect-named name because its only public top-level symbols are functions. This is the same
  rule recorded in the [filename-rule memory] — it bites any ticket that puts a public type next to
  top-level functions in one file.
- **The `pyry pair` backticks in `PARSE_FAILED_MSG` render verbatim** (cosmetic NIT, **not fixed**
  this slice). `ScannerErrorContent` renders the message via a plain `Text(text = message)` with no
  markdown styling (`ScannerScreen.kt:333`), so the user literally sees the backtick characters. The
  string ships as-is; a future copy-polish ticket should drop the backticks (or the error surface
  should gain inline-code styling). Left as a known cosmetic blemish, not a blocker.

## Verification

- `./gradlew test` ✅ (Parser 13 / Codec +3 / ScannerVM +1, all green), `./gradlew lint` ✅ (clean),
  `./gradlew assembleDebug` ✅. `connectedAndroidTest` **not run** — no device; this slice is
  unit-only by design. The `MainActivity` composable wiring (parse → save → navigate / failure →
  `Error`) is integration-shaped and covered by the parser + VM unit coverage plus manual smoke,
  consistent with how the existing `stubPairAndNavigate` binding is covered (no new instrumented test).
- **Code review: PASS** (one cosmetic NIT, above — non-blocking). Verified: the two-alphabet trap
  handled exactly (outer `decodeBase64UrlNoPad`, inner `decodeServerStaticPubkey`); relay validated as
  a TOFU origin via `java.net.URI`; trailing-data rejected / extra-fields tolerated; `data/`
  portability preserved (parser imports only `java.net.*` + kotlinx + the `PairedServer` model, no
  `android.*`); MVI seam intact (`PairingFailed → Error` mirrors `CameraError`; `popUpTo(inclusive)` +
  one-payload-per-scan prevents re-fire/double-save).
- **Security review: PASS** (ticket carries `security-sensitive`; architect self-review in the spec).
  Worst case is a **hostile QR** the user is tricked into scanning — it can supply an attacker-chosen
  `serverId`/`token`/`relayUrl`/`serverStaticPublicKey`. Structural validation proves the QR is
  *well-formed*, **not** that it came from the user's own server — that control is the fingerprint /
  safety-number confirm gate, **explicitly #321** (named dependency). This is **not a new exposure**:
  #320 replaces an already-unguarded stub persist, the record is not yet trust-bearing in a live flow
  (UI runs against `FakeConversationRepository`; the dialling handshake is gated behind #302/#309), and
  the design is gate-friendly. Leak defenses honored: parser does **no logging**, `Failure.reason` is a
  fixed category const, the caller logs only `e.javaClass.simpleName` + the reason, and
  `failureReason_neverContainsTokenOrPubkey` guards it. The redacting `toString()` nets on
  `QrPayload`/`PairedServer`/`Decoded` remain intact.
