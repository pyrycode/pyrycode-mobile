# #138 — chore(ui/thread): empty-thread state copy + visual

Ships the [`EmptyThreadState`](../features/empty-thread-state.md) composable — a single centered `bodyMedium` / `onSurfaceVariant` prompt ("Send a message to get started") rendered into the message-list area whenever the thread has no `ThreadItem.MessageItem` rows. Layers on top of [#137](./137.md)'s `ThreadUiState.hasMessages` field with no further VM widening; the predicate is the same `!state.hasMessages` half the chip's call site already consumes, so chip and empty-state appear and disappear together on a fresh discussion. The previously-unconditional `LazyColumn` body becomes the `else` arm of an `if (!state.hasMessages) … else …` branch — including the `cutoffChronologicalIndex` `remember` from [#136](./136.md), which is moved into the `else` arm only.

## Summary

- **One new production file: `EmptyThreadState.kt`.** Stateless 68-line composable + two `@Preview`s (Light/Dark). Body is one `Box(modifier, contentAlignment = Alignment.Center) { Text(stringResource(R.string.thread_empty_state), style = MaterialTheme.typography.bodyMedium, color = MaterialTheme.colorScheme.onSurfaceVariant, textAlign = TextAlign.Center) }` — no icon, no secondary line, no `Modifier.padding` baked in (the caller owns the size + padding modifier). Single text node; the M3 token spelling matches [`SessionBoundaryDelimiter`](../features/session-boundary-delimiter.md)'s sibling usage exactly.
- **`ThreadScreen` gains one `if (!state.hasMessages) EmptyThreadState(...) else { … existing LazyColumn block … }` branch.** The empty arm carries `Modifier.fillMaxWidth().weight(1f).padding(horizontal = 24.dp)` — same `weight(1f)` shape the `LazyColumn` had pre-#138, so the prompt fills exactly the space the list would have occupied. The 24.dp inset is intentionally 8dp wider than the chip's `horizontal = 16.dp` — a centered single line wants more breathing room than a left-aligned chip on a 360dp portrait.
- **The `remember(state.items) { mostRecentSessionBoundaryIndex(state.items) }` block (introduced in [#136](./136.md)) moves into the `else` arm.** Its key is `state.items`, which is `emptyList()` in the empty arm; computing the cutoff on an empty list is wasted work and pre-allocates a recomposition slot for a value that's never consumed. Pinning the `remember` block inside the `else` arm reuses the `else`-arm recomposition slot only when the thread actually has rows.
- **Predicate is `!state.hasMessages` (already `MessageItem`-only), not `state.items.isEmpty()`.** Two reasons: (a) symmetric with the chip's `!hasMessages` half from #137 — the chip and the empty-state prompt now appear and disappear on the same `combine`-arm re-emission; (b) the rare `SessionBoundary`-only edge case from #137 (user taps chip → `changeWorkspace` emits a boundary into the stream → no `MessageItem` yet) renders correctly as "still empty" with the prompt visible, rather than as a lonely `SessionBoundaryDelimiter` floating in the void above the input bar. Matches AC #4 ("Hidden as soon as the message list has at least one entry") — a boundary is metadata, not an entry.
- **One new string `R.string.thread_empty_state = "Send a message to get started"`.** Naming follows the existing `<area>_empty…` family (`channel_list_empty`, `discussion_list_empty`, `archived_empty_channels`, `archived_empty_discussions`); `thread_empty_state` (rather than `thread_empty`) disambiguates from a potential future "no search results" empty for a thread-search feature, and the literal AC copy is a full sentence-style prompt rather than a label.
- **No widening of `ThreadUiState`, `ThreadViewModel`, the `combine` reducer, the destination block, the Koin binding, or any test.** `hasMessages` was already exposed by #137; the empty-state branch is a pure UI rendering decision against an existing field.
- **No new tests.** The change is render-only, the gate flips on the same `hasMessages` field the four #137 chip-gate tests (`state_chipFields_reflectChannelAndMessagePresence` + the three workspace-label cases) already cover, and AC #5 ("Preview shows the empty state") is met by the two new `@Preview`s in `EmptyThreadState.kt`. No `androidTest` either — the thread package has no Compose-rule harness and adding one would be a ~100-line sidewinder the AC explicitly doesn't request.

## Patterns established

- **Centered-text "fills the remaining space" empty bodies stay structurally consistent across the codebase.** `EmptyThreadState`'s shape — `Box(Modifier.fillMaxWidth().weight(1f).padding(horizontal = …), contentAlignment = Alignment.Center) { Text(stringResource(…), style = MaterialTheme.typography.bodyMedium, color = MaterialTheme.colorScheme.onSurfaceVariant, textAlign = TextAlign.Center) }` — mirrors [`ChannelListScreen`](../features/channel-list-screen.md)'s `Empty` branch at `ChannelListScreen.kt:127-145`. The caller supplies the size-determining modifier (the `weight(1f)` lives outside the composable); the composable itself takes no opinion on outer size. Apply to any future "centered single-line empty prompt that fills the remaining space" — don't bake `.weight` or `.fillMaxSize` into the composable, hand it a `modifier` parameter and let the parent decide.
- **Move `remember(key) { … }` blocks into the conditional arm whose `key` reads non-trivially.** [#136](./136.md)'s `cutoffChronologicalIndex = remember(state.items) { mostRecentSessionBoundaryIndex(state.items) }` lives inside the `else` arm only, even though pre-#138 it sat at body scope. The key (`state.items`) is `emptyList()` in the empty arm and the helper returns `-1` for that input — computing it and slotting a recomposition cache for a value that's never consumed is waste. The rule: a `remember` block belongs in the smallest scope that actually consumes the value, not in the broadest scope where it would technically compile.
- **Empty-state strings live as `<area>_empty…` in `strings.xml`, even when the literal copy is a sentence-style prompt rather than a label.** `channel_list_empty` ("Tap + to start a conversation"), `discussion_list_empty`, `archived_empty_channels` / `archived_empty_discussions`, and now `thread_empty_state` all follow the same name shape. Reserve the `_state` suffix for "this is the variant name that disambiguates from a future variant of the same screen's empty" (e.g. a future `thread_no_search_results` would coexist with `thread_empty_state`); single-variant screens stay on the unsuffixed `<area>_empty` form.

## Lessons learned

- **`!state.hasMessages` is the right predicate, not `state.items.isEmpty()`.** A `ThreadItem.SessionBoundary`-only stream (zero `MessageItem`s, one or more boundaries) renders correctly as "still empty" under `!hasMessages` — the user sees the prompt, not a lonely delimiter line floating in the void. This is the rare path where the user taps the [`WorkspaceChip`](../features/workspace-chip.md), picks a workspace, and `changeWorkspace` emits a `WorkspaceChange` boundary into the stream before any message lands. Under `items.isEmpty()` the prompt would disappear (because `items` now has one entry, the boundary) and the user would see a `SessionBoundaryDelimiter` with nothing above it — visually broken. The fix is to gate on the same `MessageItem`-only signal the chip already uses, keeping the two empty-state surfaces (chip + prompt) in lockstep on the same emission.
- **`weight(1f)` outside the composable, `height(400.dp)` inside the preview.** The real screen renders `EmptyThreadState(modifier = Modifier.fillMaxWidth().weight(1f).padding(...))` inside the body `Column` so the prompt fills exactly the space between the [`WorkspaceChip`](../features/workspace-chip.md) (or `ConnectionBanner` when the chip is suppressed) and the [`ThreadInputBar`](../features/thread-input-bar.md). Inside `@Preview`, `weight(1f)` has no parent `Column` to weight against and would collapse to zero height — the preview wrappers pass `Modifier.fillMaxWidth().height(400.dp).padding(horizontal = 24.dp)` instead so the centering is observable in the IDE preview pane. Same trade-off any future "centered in the available space" composable will face when documenting its preview.
- **The 24.dp horizontal padding is not Figma-anchored — the empty-state variant isn't drawn.** Figma node `16:8` is the populated thread; the architect's spec confirmed there is no separate empty-state node. The `24.dp` mirrors typical M3 dialog horizontal padding for centered single-line content and gives the prompt visible breathing room on the narrowest supported width (360dp portrait minimum); the chip above uses `horizontal = 16.dp` because a left-aligned chip needs less inset than a centered single line. If a future preview-render review wants to tune the value, the padding modifier on the empty arm is the single dial — the rest of the layout is structurally locked by `weight(1f)` and `Alignment.Center`.
- **No new `ThreadUiState` field, no new VM handler, no new test case.** The temptation to add a derived `isEmpty: Boolean` to `ThreadUiState` (fusing `!hasMessages` into a hidden boolean) was deliberately avoided — same reasoning as [#137](./137.md)'s decision to keep the chip gate inlined at the call site. The raw `hasMessages` signal is consumed by two call sites now (chip gate + empty-state gate); pre-fusing them would require either two derived fields (one per consumer) or one ambiguously-named field (`isEmpty`? `showEmptyState`?) — both cost more than the trivially-correct two-character `!state.hasMessages` inline read.
- **Indented diff inflates the line count without changing behavior.** `git show --stat` reports +112 / −32 across the three files; the bulk of the change in `ThreadScreen.kt` is the `LazyColumn` body's reindent under the `else` brace, not real code addition. The actual new behavior is a single `if (…) … else …` branch around an existing block, plus a 12-line composable body in the new file. Future reviewers can `git diff -w` (ignore whitespace) to see the load-bearing edit cleanly.
