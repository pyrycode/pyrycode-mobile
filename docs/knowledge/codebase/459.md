# Ticket #459 — interrupt affordance on the busy turn

**Issue:** [#459](https://github.com/pyrycode/pyrycode-mobile/issues/459) ·
**Spec:** [`docs/specs/architecture/459-interrupt-affordance.md`](../../specs/architecture/459-interrupt-affordance.md) ·
**PR:** [#471](https://github.com/pyrycode/pyrycode-mobile/pull/471) ·
**Feature doc:** [Interrupt affordance](../features/interrupt-affordance.md) ·
Phase-3 (epic pyrycode#597) phone control. Split from #430; **blocked by [#458](458.md)** (the
interrupt-send path, merged PR #469) — the UI half that #458's send path was waiting on. Size **S**,
**not** `security-sensitive`, Figma 16-8 **design-owed**.

## Summary

Adds the **visible affordance** that stops a running turn: while the open conversation's agent is in
flight — its `thinking` **or** `responding` phase — the thread screen shows a foot-of-list "Stop"
control; tapping it invokes [#458](458.md)'s already-built `ThreadViewModel.onInterrupt()`, and the
control hides on its own when the turn reaches `idle` / `turn_end`. The new signal is
`ThreadViewModel.isBusy` — a hoisted `StateFlow<Boolean>` declared **identically** to `isThinking`
([#406](406.md)) but **broadened** to be `true` across both `thinking` and `responding`, via a dedicated
`busyTransition` reducer. Four production files (one new composable, three wirings) + two strings. Built
test-first, RED→GREEN; all gates green (`compileDebugAndroidTestKotlin` explicitly, since the mandatory
gates don't cover `androidTest`); code review **PASS**, zero blocking findings.

## Patterns established

- **`isBusy` is the fifth hoisted sibling `StateFlow` on `ThreadViewModel`** — joining `connectionState`,
  `isThinking` (#406), `isStalled` (#396), and the modal flows, all taken as separate stateless-screen
  parameters rather than `ThreadUiState` fields. The reducer-per-flag shape (`mapNotNull { transition(it)
  }.stateIn(WhileSubscribed(5_000), false)`) is now used **twice over the same `liveSessionEvents`
  source** (`thinkingTransition` / `busyTransition`); the architect's deliberate call was a **dedicated
  reducer**, not deriving `isBusy` by `combine`-ing `isThinking` with a second flow — it adds no operator
  and keeps the established sibling pattern.
- **One ticket carried both halves.** Unlike the thinking indicator (data #406 + UI #407 split across two
  tickets / two feature docs), #459 ships the `isBusy` flow and the `InterruptAffordance` composable
  together → **one combined feature doc** ([Interrupt affordance](../features/interrupt-affordance.md)).

## Lessons learned

- **A "turn is running" signal can't reuse `isThinking` — it's `false` during `responding`.** Reusing
  `isThinking` would make the interrupt control vanish the moment the agent stops thinking and starts
  emitting text, mid-turn. The fix is the one-line broadening in `busyTransition`
  (`Thinking || Responding`). Two tests pin the distinction so a future "simplify by reusing `isThinking`"
  refactor fails loudly: the unit test pushes `turn_state{responding}` and asserts `isBusy && !isThinking`;
  the screen test opens the turn with `responding` so the affordance must show when the thinking spinner
  is hidden.
- **Thinking-phase dual-affordance stacking is intentional/interim** (code-review NIT, non-blocking):
  during `thinking`, both `isThinking` and `isBusy` are `true`, so the foot-of-list renders the thinking
  spinner **and** the "Stop" button stacked; only during `responding` does "Stop" appear alone. This is
  correct per the AC (in-flight spans thinking + responding) and the placement is **design-owed/interim** —
  the follow-up design pass that draws the control in Figma 16-8 reconciles the stacking. Flagged in the
  PR so the visual-fidelity check reads it as deliberate.
- **Interim visual is design-owed.** Figma 16-8 does not yet draw a dedicated interrupt control (confirmed
  against the locked layout — same status as `ThinkingIndicator` and the stall CTA). The affordance
  follows the existing M3 idiom (`FilledTonalButton` + stop glyph + "Stop") at the foot of the list; a
  follow-up design pass relocates/restyles once the frame draws it.
