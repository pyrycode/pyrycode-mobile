# #561 — Surface the change_workspace result from the thread (no crash, no silent no-op)

Size **S**, `security-sensitive` (PASS).

## Summary

`ThreadViewModel.onWorkspacePicked(path)` routed `repository.changeWorkspace(conversationId, path)` through
the shared `launchGuardedRepoCall`, which inert-swallows every failure (#490) — so once #560 replaced the
`UnsupportedOperationException` stub with a real round-trip, a failed workspace change became a silent
no-op instead of a crash, but still gave the user no feedback. This ticket gives change-workspace its own
surfacing path, cloning archive-from-thread (#556) with two structural differences: the trigger carries a
caller-supplied `path` (a picker selection, not a payload-free event), and success is **passive** — no
`PopBack`, since the chip just re-labels itself off the #560 projection re-emit while the user stays on the
thread.

- **Success is passive and list-driven** — `changeWorkspace`'s confirmed `upsertConversation` fold (#560)
  makes `observeConversations` re-emit with the new `cwd`; the workspace chip derives its label from that
  projection. The VM does nothing else on success.
- **Failure surfaces** — a fixed-string snackbar (`change_workspace_failed`), mirroring `archiveErrors`. Since
  `change_workspace` is request/reply (unlike fire-and-forget `new_session`), both the server-error
  (`RelayErrorException`) and not-connected (`IllegalStateException`) modes are reachable and both trigger the
  same payload-free `Unit` signal.
- **Cancellation is preserved** — `CancellationException` is rethrown first (it extends `IllegalStateException`
  on the JVM), so `viewModelScope` teardown mid-call is never mis-surfaced as a failure.

    `val changeWorkspaceErrors: Flow<Unit> = changeWorkspaceErrorChannel.receiveAsFlow()` (beside
    `archiveErrors`) — payload-free one-shot signal.
  - New `private fun sendChangeWorkspace(path: String)`: `viewModelScope.launch {
    repository.changeWorkspace(conversationId, path) }` wrapped in three catches in order —
    `CancellationException` (rethrow, must be first), `RelayErrorException` (`trySend(Unit)`),
    `IllegalStateException` (`trySend(Unit)`). Uses the VM's own ctor-derived `conversationId` (never
    re-derived); `path` is the caller-supplied picker selection, forwarded verbatim as a wire field to #560's

    return (#560 — no session transition on this verb) is discarded. `IllegalArgumentException`
    (`conversation.not_found`) and the #318 decode exception are **deliberately not caught** — not_found is
    unreachable (you only change the workspace of the conversation you're viewing) and a malformed reply is a

## Patterns established

Fourth confirming instance of the surfacing one-shot-channel idiom (`modalSendErrors` #452 → `newSessionErrors`
#540 → `archiveErrors` #556 → `changeWorkspaceErrors` #561), and the **first** to combine the request/reply
two-catch set (established by #556) with a **passive** (no-`PopBack`) success continuation (established by
#540): pick the catch set from what the wrapped wire call can produce (request/reply ⇒ also catch
`RelayErrorException`), and pick the success continuation from what the trigger actually needs (a picker
selection that only updates a projection needs no navigation). The two axes are independent — clone whichever
combination the new verb needs from the two established twins rather than assuming "surfacing = pops back."

## Lessons learned

- **A ticket's "mirror ticket #N" instruction can be a false precedent — verify against the actual diff before
  hunting for what to mirror.** The ticket said "drop change-workspace from `GuardedRepoLaunch.kt`'s documented
  action list — mirror #556 dropping Archive," but #556's own diff (`git log -p` on the file) never touched
  `GuardedRepoLaunch.kt` at all — `archive` is still listed there today, a debt #556 explicitly chose not to
  pay down. Making the change-workspace-only edit (and leaving `archive` alone, matching #556's own scope
  decision) was correct; going looking for a nonexistent "archive removal to mirror" would have wasted a cycle
  chasing a ticket-body claim that didn't match the code. See [[clone-pattern-default-trap]].
- **When a verb's success continuation and catch set come from two different precedents, name both explicitly
  in the design and the code KDoc** — `sendChangeWorkspace` borrows its catch set from `sendArchive` (request/
  reply) and its success shape from `sendNewSession` (passive), and calling out both twins (rather than saying
  "clone #556") is what let the diff correctly omit `PopBack` while still adding the second catch type.
