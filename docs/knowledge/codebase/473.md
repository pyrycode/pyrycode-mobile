# #473 — Layer 1b: session-boundary divider on the scripted-stream harness

Adds the **component-level** session-divider coverage of the mobile interactive-stream e2e ladder
(`docs/e2e-interactive-stream.md`, **rung 2 / Layer 1b**): a scripted stream that crosses a session
boundary, driven through the **real `RemoteConversationRepository` `session_transition` fold (#336)** →
`ThreadViewModel` → `ThreadScreen`, asserting the shipped `SessionBoundaryDelimiter` (#135/#192) draws
**exactly one** delimiter **positioned between** the two cross-session messages. It rides the
already-shipped **#432 `ScriptedThreadHarness`**; the only change is **one scripting method + one private
envelope builder** in the harness, plus one new test file — all `androidTest`. **Zero production Kotlin.**

This is the render rung the #336 fold was missing. The fold's data-layer behaviour (ordering,
reason-mapping, cross-routing, drop-on-malformed) is exhaustively unit-tested in
`RemoteConversationRepositoryTest` (#336); this ticket adds the one thing that suite cannot show — that a
folded `ThreadItem.SessionBoundary` actually **draws** as a delimiter on screen, in the right place.
Last of the three children #435 was split into 2026-06-23: #472 (tool rows, **shipped**), #474
(connection banner, **shipped**), and **#473 (this — session divider, was `blockedBy` #336)**. #336
shipped in PR #485, unblocking this.

The faithful production path the test reproduces (the **real** fold, per the two-folds gotcha #337):

```
scripted session_transition Envelope
  → FakeSessionPump.inbound → RemoteConversationRepository
      (decode #385/#336 + fold → threadByConversation[c1] = [MessageItem(t1), SessionBoundary, MessageItem(t2)]
       → observeMessages)
  → ThreadViewModel (state = combine(…, threadItems, …))
  → ThreadScreen → LazyColumn keys ThreadItem.SessionBoundary → SessionBoundaryDelimiter(boundary = item)
```

## Patterns established

- **Named args defuse the verbatim-port transpose trap.** The unit-test builder orders its params
  `(…, reason, occurredAt = TS, workspaceCwd = null, id)` — `occurredAt` sits **before** `workspaceCwd`.
  Ported verbatim for fidelity, that ordering means a positional `pushSessionTransition` body would silently
  pass `workspaceCwd` into the `occurred_at` slot. `pushSessionTransition` passes **every** builder arg by
  name (`conversationId = …, previousSessionId = …, …, workspaceCwd = workspaceCwd`), so the param-order
  mismatch cannot transpose. When porting a builder verbatim but calling it from new code, prefer named
  args over re-ordering the port.
- **`reverseLayout` ⇒ chronological top-down ⇒ the between-assertion is `m1Top < delimiterTop < m2Top`.**
  The fold appends oldest-first (`[m1, boundary, m2]`); `ThreadScreen` renders with `asReversed()` +
  `reverseLayout = true`, which lays chronological order out top-to-bottom. So the first session's message
  sits **above** the boundary and the second below — the ascending-`top` ordering is the correct geometric
  encoding of "delimiter between the two sessions' messages" (verified in code review). Don't invert the
  comparison by reasoning from `reverseLayout` alone.
- **The explanation-node count proxies the delimiter count.** There is no test tag and `Done`-style CDs
  don't apply; the reason-independent explanation `Text` renders exactly once per `SessionBoundaryDelimiter`,
  so `onAllNodesWithText(EXPLANATION).size == 1` is a sound "exactly one delimiter" assertion. Assert on the
  reason-**independent** explanation for the count (every reason renders it), and the reason-**specific**
  prefix only for the label-content AC.
- **Assert label prefixes, never the formatted time tail.** `boundaryLabel(Clear)` is
  `"New session — <time>"` where `<time>` is locale/timezone-formatted (`FormatStyle.SHORT`, AM/PM
  separator varies by JDK — see [session-boundary-delimiter](../features/session-boundary-delimiter.md)).
  Keying on the `"New session"` prefix keeps the test locale-robust; the `workspace_change` analogue would
  key on `"Workspace changed to "` before the cwd. (Same faithfully-typeable-substring discipline as #431's
  `ping`/`seed` and #474's glyph-safe ASCII substrings.)
- **New test file, not extending `ScriptedThreadRenderTest`.** A dedicated `ScriptedSessionBoundaryTest.kt`
  keeps the divider scenario cohesive and decoupled from the sibling harness tests; the harness file is the
  one unavoidable shared edit point, and the #435 children's blocking chain serialized those edits. (Same
  call as #472's `ScriptedToolRowTest.kt` and #474's `ScriptedConnectionBannerTest.kt`.)

## Lessons learned

- **The folded-boundary path is robust to the subscribe-before-push race that bit the #432 spinner.**
  Unlike `turn_state`/`isThinking` (which flow through the `replay = 0` `liveSessionEvents` SharedFlow and
  are *dropped* if pushed before the VM subscribes — the #432 spinner flake), the `session_transition`
  fold writes into `threadByConversation`, a retained `MutableStateFlow` projection that re-emits to late
  subscribers; `FakeSessionPump`'s inbound `Channel` is `UNLIMITED` (a pre-subscription push is buffered,
  not dropped). So a folded boundary survives a push at any time after construction. All `push*` calls
  still go **after** `start()` (which runs `awaitReady()`), matching the sibling cases — `awaitReady`
  proves the screen composed and the conversation seeded, so the thread is rendering (not loading/empty)
  before the first assertion. **No new readiness gate needed for the boundary.** See
  [[two-folds-repo-wins-vm-dormant]].
- **Verbatim-porting a builder can leave defaulted params dead in the new source set.** Code review (NIT,
  non-blocking) noted `sessionTransitionEnvelope`'s `occurredAt` and `id` are never exercised by
  `pushSessionTransition` (always defaulted). They're kept for verbatim-port fidelity with the unit-test
  builder, which the spec mandated — acceptable as-is. Worth knowing if a future scenario needs a distinct
  `occurred_at` or `id`: the params already exist, just thread them through (by name).
- **Drive the real repo fold, not the fake and not the dormant VM path.** The harness constructs the real
  `RemoteConversationRepository` with the capability gate open
  (`negotiatedCapabilities = { setOf(CAPABILITY_INTERACTIVE) }`), so `session_transition` folds into a
  `ThreadItem.SessionBoundary` — *not* the boundary `FakeConversationRepository` synthesizes from
  in-memory history (#9 `buildThreadItems`), and *not* the suppressed `ThreadViewModel` fold. This is the
  whole point of riding the #432 harness rather than a fake-repo render test. See
  [[two-folds-repo-wins-vm-dormant]].

## Verification

The deliverable **is** the test; there is no unit test of the harness. Host-JVM checks (no device, per the
spec's strategy):

- `./gradlew test lint assembleDebug` + `compileDebugAndroidTestKotlin` + `spotlessCheck` all green — the
  androidTest sources compile (the mandatory gates do **not** compile androidTest, so the
  `compileDebugAndroidTestKotlin` run is explicit — [[androidtest-not-compiled-by-mandatory-gates]]).
  `onNodeWithText` / `onAllNodesWithText` / `getUnclippedBoundsInRoot` / `assertIsDisplayed` are imported;
  the new `.kt` filename matches its sole public class.
- **`connectedAndroidTest` NOT run** — no device/emulator attached; the new `ScriptedSessionBoundaryTest`
  is instrumented `createComposeRule` (the `ScriptedThreadRenderTest` / `ScriptedToolRowTest` /
  `ScriptedConnectionBannerTest` precedent), so the on-device render run is operator-run, alongside the
  sibling harness tests.
