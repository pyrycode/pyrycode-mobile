# #454 — Layer 2a: deterministic emulator stream render + thinking spinner

Adds the next two scenarios on **#431's deterministic emulator harness** (rung 4 /
**Layer 2a** of the mobile interactive-stream e2e ladder, `docs/e2e-interactive-stream.md`):

1. **`stream`** — a reply that arrives over three `assistant_delta` chunks renders as **one**
   assembled assistant message (the multi-delta twin of #431's single-line `"ping"`).
2. **`spinner`** — the thinking indicator is shown **while** the turn is active and **gone** after it
   ends.

This is the emulator twin of **#432** (Layer 1a, the in-process component-render harness that ships
the same text + spinner cases). The real app on a headless emulator drives the real Noise/relay path
against the scripted `fakeclaude` backend (pyrycode #642) — **no real claude, zero claude turns**,
same pass on every re-run. **No production Kotlin** — it *exercises* the already-shipped, already
security-reviewed #337/#385 delta fold and #406 `isThinking` spinner; it doesn't modify them.

## Patterns established

- **One scenario per script invocation, selected by `SCENARIO`.** Extends #431's
  one-fixture→one-turn→one-scenario model: each scenario maps to exactly one `@Test` method + its own
  fixture(s), and the runner arg becomes `class#method` so a single method runs per run. The seam that
  changes per scenario is just the fixture(s) + the asserted text/state; the seeded-channel entry, the
  fence, and the credential seam are all reused. Sibling scenarios (#455 tool steps, #436
  reconnect/replay) add a `case` arm + a fixture, nothing more.
- **Causally-fenced two-drop for a transient state (the genuinely-novel piece).** A transient UI state
  (the thinking spinner) cannot be asserted with a timing delay — a single `thinking`→`end_turn`
  fixture flips `isThinking` true→false within one tail cycle, before Compose lays out the spinner.
  The pattern: **hold the turn open** with a thinking-only fixture (drop A on the 1st
  `send_message.enqueued`), let the test assert presence, then **end the turn on a causal fence** — a
  2nd user `send_message` the test issues only *after* the presence-assert passes (drop B on the 2nd
  enqueue). The thinking window is then arbitrarily long; there is **no timing dependency and no fixed
  host delay**, so a slow phone can't lose the race. Reusable for any future transient-state scenario.
- **Distinct `message.id` per line to force a multi-delta render.** A per-message-id flush makes the
  producer emit one `assistant_delta` per line (here 3); a shared id would coalesce to one. Then assert
  a **cross-delta-boundary substring** (`"streamed world"`) — present only if the deltas concatenated
  into a single message. Belt-and-suspenders: the tolerant assertion would pass either way, but
  distinct ids genuinely exercise concatenation.
- **Shared setup extracted once all three scenarios need it.** #431/#432 deliberately *duplicated*
  `awaitConnected()` + constants (two tests, Simplicity-First). At three scenarios the setup was pulled
  into `arriveInSeededThread()`/`typeAndSend()` *within the same test class* — still no cross-test-file
  sharing, just DRY within the file.

## Lessons learned

- **The #431 fence token `send_message.ack` does not exist in the current daemon — use
  `send_message.enqueued`.** Post-pyrycode-#704/#721 the send-path enqueues; the only `send_message.*`
  log line is `send_message.enqueued` (`send_message.go:159`), and `router.Route` stamps the producer
  cursor (the fence's whole purpose, #687) *before* that line. Dropping the fixture before the cursor is
  stamped lets the producer tail **past** it (cold-start race) → the phone gets **zero** envelopes. So
  `send_message.enqueued` is the correct, current fence; the single-drop watcher's token was updated to
  match (one token in the same block #454 already edits — leaving two different fence tokens in one
  script would be incoherent). **Operator-tune on first run** if the daemon is older. (#431's
  `codebase/431.md` still documents the old `send_message.ack`; this supersedes it for any later run.)
- **The spinner is the hard case because the state is transient — solve it structurally, not with a
  delay.** See the causally-fenced two-drop pattern above. Asserting on timing or inserting a fixed
  host sleep is wrong: a slow phone would clear the spinner before the presence-assert catches it.
- **The two-drop mechanism's load-bearing production dependency: the send button is gated on text only,
  not turn state.** Code-review verified `ThreadInputBar.kt:153` gates `enabled = text.isNotBlank()`
  alone — so the 2nd `send_message` fires **mid-turn** (while thinking) and triggers drop B. This is
  the one path the Layer-1 twin (#432) does *not* exercise; if a future change gated send on
  turn/thinking state, the spinner scenario would deadlock (drop B never fires).
- **`cp` to `${JSONL_TRIGGER}` is safe to re-issue.** `fakeclaude` removes the trigger after appending
  (`main.go:emitStructuredJSONLIfTriggered`), and drop B waits for the 2nd enqueue — long after
  `fakeclaude` consumed drop A's trigger — so B never clobbers an unconsumed A.
- **Asserted text must not collide with always-present chrome.** Inherited from #431's
  `e2e-ping`→`e2e-seed` rename ([[431-fakeclaude-staticuuid-vs-discussion-session]]): the seeded
  channel name `"e2e-seed"` renders verbatim in the thread top bar, so tolerant substring matches must
  avoid it. `"streamed world"` and `"done"` are safe.
- **Left NIT (non-blocking):** `scripts/e2e-emulator.sh:285` — the daemon-startup comment still reads
  "the `send_message` ack is prompt" (about turn-confirm *latency*, not the fence-grep token). Harmless
  but slightly incoherent with the corrected fence; flagged at review, deliberately left.

## Verification

The deliverable **is** the test harness; there is no unit test of it. Host-JVM checks (no device, per
the spec's strategy), confirmed green by QA:

- `./gradlew check` (unit tests + lint + spotless) and `assembleDebug` green.
- `./gradlew compileDebugAndroidTestKotlin` green — androidTest sources compile (the mandatory gates
  do **not** compile androidTest, so this is run explicitly; [[androidtest-not-compiled-by-mandatory-gates]]).
- `bash -n` + `shellcheck scripts/e2e-emulator.sh` clean; all three fixtures valid JSON with trailing
  newlines.
- **Operator-run (device + host `pyry`/`pyrycode-relay`/`fakeclaude`):** the three scenarios —
  `DETERMINISTIC=1 SCENARIO=ping|stream|spinner … bash scripts/e2e-emulator.sh` — each green and
  re-running back-to-back yielding the same pass. No green e2e is claimed from the pipeline; expect to
  tune the fence token on first run.
