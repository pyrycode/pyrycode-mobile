# #271 — Dedicated About screen (extract inline About section → navigable `AboutScreen`)

Promotes the four inline About rows at the bottom of `SettingsScreen` (Version + build SHA, Open source, Privacy policy, License: MIT) into a dedicated, navigable `AboutScreen`, and replaces the inline section with a single tappable "About" entry that opens it. Pure UI/navigation reorganization — no ViewModel, no repository, no backend; the screen is static (`BuildConfig.VERSION_NAME` / `GIT_SHA` are the only dynamic data, both compile-time `const` reads). Mirrors the locked sub-screen pattern (`Scaffold` + back-arrow `TopAppBar` + scrollable M3 list) established by [Archived discussions](../features/archived-discussions-screen.md), minus the VM/effects/snackbar that About doesn't need. Verbatim content extraction — no row text or click behavior changed.

## Summary

- **`AboutScreen.kt` (NEW)** — public `@Composable fun AboutScreen(onBack: () -> Unit, modifier: Modifier = Modifier)`. `Scaffold(topBar = TopAppBar(title = "About", navigationIcon = back-arrow IconButton))` over a `Column(Modifier.padding(inner).fillMaxSize().verticalScroll(rememberScrollState()))` holding the four rows in order. `val context = LocalContext.current` captured at the top of the body (closed over by the Open source `onClick`). The four rows are a byte-for-byte relocation of `SettingsScreen.kt:256-274`: non-clickable Version row (`"Version <name>"` / `"build <sha>"`), clickable Open source row (`Intent.ACTION_VIEW` on `SOURCE_REPO_URL`, trailing `ExternalLinkIcon`), clickable-but-inert Privacy policy row (`onClick = {}`, trailing `ExternalLinkIcon`), non-clickable "License: MIT" row. Two `@Preview`s (light + dark).
- **`SettingsScreen.kt` (EDIT)** — the entire inline About block collapses to one navigable entry:
  ```kotlin
  SettingsSectionHeader("About")
  SettingsRow(
      headline = stringResource(R.string.about_settings_row),
      trailing = { ChevronIcon() },
      onClick = onOpenAbout,
  )
  ```
  The `SettingsSectionHeader("About")` is **kept** — dropping it would leave a header-less "About" row directly under "Clear cache", reading as a Storage item. The mild "About" header / "About" row repetition is the standard M3 section-title-plus-entry idiom.
- **`SettingsRow` bumped `private` → `internal`** (kept defined in `SettingsScreen.kt`). It's used by every Settings row *and* all four About rows, so it's genuinely shared; `AboutScreen` (same package + module) references it directly. This single-sources the locked row treatment so a future row-shape change can't drift between the two screens, and holds the new-production-file count at exactly 1 (`AboutScreen.kt`).
- **`ExternalLinkIcon` and `SOURCE_REPO_URL` moved** out of `SettingsScreen.kt` into `AboutScreen.kt` (`private` composable / `private const`). Both are used only by the Open source + Privacy rows, which left Settings — defining them in a file that no longer references them would be backwards. `ChevronIcon`, `AddPill`, `SettingsSectionHeader` stay `private` in `SettingsScreen.kt`; the new entry row reuses `ChevronIcon` in place.
- **`MainActivity.kt` (EDIT)** — `const val ABOUT = "about"` in `Routes`; new `composable(Routes.ABOUT) { AboutScreen(onBack = { navController.popBackStack() }) }` (no VM, mirrors the Archived block minus the `koinViewModel`/`collectAsStateWithLifecycle`/`onEvent` machinery); `onOpenAbout = { navController.navigate(Routes.ABOUT) }` threaded into the `SettingsScreen(...)` call; `import de.pyryco.mobile.ui.settings.AboutScreen`.
- **`SettingsScreen` signature** gained `onOpenAbout: () -> Unit` immediately after `onOpenArchivedDiscussions` (before `modifier`) — no default (navigation/event callbacks never carry defaults; rule from #87/#91/#94). Both `@Preview`s and all `SettingsScreenTest` `setContent` blocks pass `onOpenAbout = {}`.
- **Removed from `SettingsScreen.kt`**: `val context = LocalContext.current` (line 92 — nothing else used it once Open source left) and now-unused imports `android.content.Intent`, `android.net.Uri`, `androidx.compose.ui.platform.LocalContext`, `androidx.compose.ui.res.painterResource`, `de.pyryco.mobile.BuildConfig`. (`R` stays — used elsewhere.)
- **Strings** (`strings.xml`): `about_title` = "About" (TopAppBar) and `about_settings_row` = "About" (Settings entry headline). The four *content* rows keep their hardcoded literals — verbatim extraction; converting them to resources would be an unrequested content change (same scaffolding-placeholder rule the rest of Settings follows).
- **Back behavior**: `navigate(Routes.ABOUT)` pushes onto the back stack; TopAppBar back arrow → `onBack` → `popBackStack()` → Settings, and system back is popped automatically by `NavHost` — no `BackHandler` needed. Identical to Archived discussions.

## Patterns established

- **Extracting rows to a sibling screen in the same package: share the row primitive via `internal`, relocate the row-specific helpers.** When a `private` composable is consumed by *both* the origin file and the extracted screen (here `SettingsRow`), widen it to `internal` and leave it where it lives — same package + module resolves it, and the locked treatment stays single-sourced. Helpers used *only* by the extracted rows (`ExternalLinkIcon`, `SOURCE_REPO_URL`) move *with* the rows. This keeps the visibility surface minimal (one keyword change, no public API) and is explicitly extraction, not the forbidden "refactor unrelated Settings rows": `SettingsRow`'s body is untouched. Distinguish from the share-via-`public`-one-package-over case (`Effort.label()`, #229) — that crossed a package boundary and needed `public`; this stays in-package, so `internal` is the right ceiling.
- **`AboutScreen` is the second resident of the locked `ui/settings/` sub-screen pattern** (after `ArchivedDiscussionsScreen`, #94). The shape is now firmly: `Scaffold` + back-arrow `TopAppBar` (`Icons.AutoMirrored.Filled.ArrowBack` + `R.string.cd_back`) over a body; route in `MainActivity.Routes`; `onOpen…: () -> Unit` callback threaded into `SettingsScreen`; `composable(Routes.X) { Screen(onBack = { navController.popBackStack() }) }`. A static sub-screen drops the VM/`collectAsStateWithLifecycle`/`onEvent`/effects entirely — only wire those when the screen has real state. `ui/settings/` previously hosted a third such screen, `LicenseScreen` (#91), deleted in #163 when its entry point disappeared; `AboutScreen` re-establishes the two-resident shape.

## Lessons learned

- **`AboutScreen`'s body `Column` deliberately omits the `.padding(bottom = 32.dp)` that `SettingsScreen`'s scroll column carries.** Flagged as a NIT in code review (non-blocking). Defensible: four fixed rows won't scroll on a phone, and the spec defined the column without it. Documented as a deliberate asymmetry so a future "why does About have no bottom breathing room" question resolves to "intentional" rather than triggering a needless edit — add the padding only if a real visual issue surfaces on a small screen (evidence-based, not speculative).
