# Ticket #388 — tool-use row running/done/failed status affordance

**Issue:** [#388](https://github.com/pyrycode/pyrycode-mobile/issues/388) ·
**Spec:** [`docs/specs/architecture/388-tool-call-row-status-affordance.md`](../../specs/architecture/388-tool-call-row-status-affordance.md) ·
**PR:** [#411](https://github.com/pyrycode/pyrycode-mobile/pull/411) ·
**Feature doc:** [ToolCallRow](../features/tool-call-row.md) (extended) ·
Split from #368, blocked by (and built on) the merged sibling [#387](387.md) (PR #409). Size **S**, **not**
`security-sensitive` (render-only; reads a value #387 already populated).

## Summary

The **visible** half of the live tool-call: [`ToolCallRow`](../features/tool-call-row.md) now shows, at a
glance, whether a call is **running**, **done**, or **failed** — reading the `ToolCall.status`
([`ToolCallStatus`](../features/data-model.md)) field [#387](387.md) ships. The single leading icon slot
became a `when (status)` function (indeterminate M3 spinner → the existing per-tool icon → an
`error`-tinted glyph) at a **fixed `18.dp` footprint** so a row resolving running→done/failed never
reflows; the expanded **Output** section is gated to appear only once the call resolves. The `Done` state
is left byte-identical to the shipped Figma `16-28` design — the diff only moves the existing `Icon` into
the `Done` arm of the `when`. Running/failed are **design-owed** (not drawn in `16-28`), following the
app's M3 progress idiom (mirroring [`ThinkingIndicator`](../features/thinking-indicator.md), #407) until a
frame lands. Code review **PASS**, zero blocking findings.

## Load-bearing design choices

- **The leading slot, not a trailing badge.** The row already had exactly one decorative slot (the
  per-tool icon). Branching *there* on `status` adds zero layout, keeps the `Done` row pixel-identical to
  the shipped design (the "done already matches Figma" guarantee stays trivially true), and gives the
  three-state affordance the most natural home. A fixed `18.dp` footprint across all three arms means the
  running→resolved flip never reflows the row.
- **Output gated on resolution, not on `output.isEmpty()`.** While running, `output` is `""` (the data
  layer fills it on the correlated `tool_result`, #387). Gating the `Output` section on
  `status != Running` (a) avoids an empty "Output" label mid-run and (b) makes "on resolution it reveals
  the output" (AC#2) literally true. A `Failed` row's `output` is the error/result summary #387 placed
  there, so Failed surfaces it under the **same** `Output` section — no separate error branch in the UI.
- **Statelessness preserved (AC#3).** `status` is a pure input read from `toolCall.status` — no
  `remember`/`derivedStateOf` over status, nothing derived from `output.isEmpty()` or any other field.
  The only local state is the pre-existing `expanded` toggle, orthogonal to status.
- **Design-owed default, swappable.** Running/failed glyphs are not in Figma `16-28` (flagged for Juhana in
  the ticket). Rather than block on a frame, the spinner mirrors `ThinkingIndicator`'s M3 progress idiom and
  the failed glyph is a conservative `error`-tinted `ErrorOutline`. The KDoc on `ToolCallStatusIcon` carries
  the design-owed note: when Juhana draws the states, **only the two new arms** need revisiting; the `Done`
  row and all behaviour are final. (Same posture #407's thinking indicator took.)

## Patterns established

Nothing genuinely new — this slice **follows** precedents: `ThinkingIndicator`'s spinner sizing (16–18.dp /
2.dp stroke) and the "design-owed, follow the M3 progress idiom until the frame lands" posture; the `cd_*`
content-description convention; the file-private spacing-`val` posture; the self-contained preview-fixture
posture (fixtures stay file-private, never added to `FakeConversationRepository`). The one reusable point
for future three-state row affordances: **branch the existing single decorative slot on the status enum at a
fixed footprint** rather than adding a new trailing element — it keeps the settled state pixel-identical and
the resolving transition reflow-free.

## Lessons learned

- **Running/failed are a design-owed addition** (not drawn in Figma `16-28`). Kept the visual conservative
  and swappable, in the same posture as [`ThinkingIndicator`](../features/thinking-indicator.md) (#407) —
  only the two new states need revisiting when the frame lands; the `Done` row is byte-identical to the
  shipped component. (Lifted from the PR's "Lessons learned".)
- **The output-encoding hand-off #387 named landed here implicitly, not as new code.** #387's security note
  said treating the server-authored `toolName`/`input`/`output` strings as inert, non-active content at
  render is the #388 consumer's job. Rendering them through Compose `Text` (and the existing `CodeBlock`)
  *is* that output-encoding — the strings are never parsed, interpreted, or treated as markup — so no
  dedicated sanitisation code was needed and the ticket stayed **not** `security-sensitive`. The gate to
  watch is keeping the expanded sections on inert renderers (no HTML/markdown-as-active, no `eval`-shaped
  path); that holds today.

  indeterminate spinner with no `mainClock.autoAdvance` handling).

  findings**, all four ACs verified, M3 tokens (`colorScheme.error` / `onSurfaceVariant`, default spinner
  primary) throughout, no hardcoded hex, exhaustive `when` (no `else`), no debug logs.
