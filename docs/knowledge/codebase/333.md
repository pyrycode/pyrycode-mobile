# #333 — ML Kit QR decode pipeline: once-per-scan debounce + decoded `ScannerUiState`

The **decode core** of the pairing scanner — the success counterpart to #326's dormant `CameraError`
seam. Adds a CameraX `ImageAnalysis.Analyzer` that decodes a camera frame to a QR string via ML Kit
and surfaces it **exactly once per scan** (debounced), feeding the existing `ScannerViewModel.onEvent`
seam through a new `QrDecoded` event → `Decoded` state. Deliberately **camera-independent**: exercised
through the analyzer→ViewModel seam with fake frames, no physical camera. The decoded string is
**untrusted external input** — this slice surfaces it but does not parse, validate, persist, or log it.

## Summary

Four production files (one new), three test files (one new). All new code is UI-layer (camera/decode
is an Android UI concern, kept out of portable `data/` per CLAUDE.md). **No `data/` change, no DI
change, no `MainActivity` change** — the analyzer is not instantiated in production until #334 wires it
to a live CameraX preview, the same "define a dormant seam now, no live producer this slice" pattern
#326 used for `CameraError`. The once-per-scan debounce is a lock-free `AtomicBoolean.compareAndSet`
latch in the analyzer; the decode→surface→debounce core is fully covered on the JVM by `./gradlew test`
through an injected `FrameDecoder` seam (production = ML Kit; test = canned fakes).

## Files touched

- **`ui/onboarding/QrCodeAnalyzer.kt`** *(new, 81 LOC)* — three declarations:
  - `fun interface FrameDecoder { fun decode(image: ImageProxy): String? }` — the synchronous seam
    that makes the analyzer JVM-testable. `null` = "no QR in this frame" (the common case).
  - `class MlKitQrFrameDecoder : FrameDecoder` *(production, not unit-tested — needs a device)* — owns
    a single QR-only `BarcodeScanner` (`BarcodeScanning.getClient(options)` with
    `setBarcodeFormats(Barcode.FORMAT_QR_CODE)`). `decode`: `image.image ?: return null`, build
    `InputImage.fromMediaImage(mediaImage, image.imageInfo.rotationDegrees)`, then
    `Tasks.await(scanner.process(input)).firstOrNull { it.rawValue != null }?.rawValue`, all wrapped in
    `try/catch (_: Exception) { null }` (a failed/empty decode is the normal no-QR case — **logs
    nothing**, AC5). `decode` is `@ExperimentalGetImage` (opt-in for `ImageProxy.getImage()`).
  - `class QrCodeAnalyzer(onQrDecoded: (String) -> Unit, decoder: FrameDecoder = MlKitQrFrameDecoder()) : ImageAnalysis.Analyzer` —
    `analyze(image)` is `try { decoder.decode(image)?.takeIf { hasSurfaced.compareAndSet(false, true) }?.let(onQrDecoded) } finally { image.close() }`
    (the source spells out the equivalent `if`). The `finally { image.close() }` is **mandatory** —
    CameraX will not deliver the next frame until the `ImageProxy` is closed. The `AtomicBoolean
    hasSurfaced` latch **is** the debounce: the first non-null decode flips it and fires `onQrDecoded`;
    every later frame (same or different payload) is ignored for this analyzer instance's lifetime.
- **`ui/onboarding/ScannerViewModel.kt`** *(modify, +22 LOC)* — adds the success counterpart to
  `CameraError`/`Error`, keeping the VM a pure synchronous Android-free mapper:
  - `ScannerUiState.Decoded(payload: String)` — carries the **raw untrusted** string as a bare
    `String` (deliberately not a "validated" wrapper, so #320 cannot mistake it for trusted).
  - `ScannerEvent.QrDecoded(payload: String)`.
  - one exhaustive `onEvent` arm: `is ScannerEvent.QrDecoded -> ScannerUiState.Decoded(event.payload)`
    (`ScannerViewModel.kt:71`). No logging, no side effects.
  - **Redacting `toString()` on both** `Decoded` and `QrDecoded`:
    `"Decoded(payload=<redacted ${payload.length} chars>)"`. This is the AC5 *deterministic* net — even
    an accidental `Log.d(TAG, "$state")` cannot leak the payload, because the data-class `toString()`
    that would otherwise embed it is overridden. It does **not** touch the generated `equals`/`hashCode`,
    so `assertEquals(Decoded("x"), …)` still holds.
- **`ui/onboarding/ScannerScreen.kt`** *(modify, +1 LOC)* — the exhaustive `when (state)` forces a new
  branch; `is ScannerUiState.Decoded,` joins the existing `PermissionRequesting, ReadyToScan ->
  ScannerViewport(...)` arm (`ScannerScreen.kt:61`). **Viewport unchanged — no new visible surface**
  (scope guard). Previews stay on `ReadyToScan`. `MainActivity` does not `when` on `ScannerUiState`, so
  it needs no edit.
- **`gradle/libs.versions.toml`** *(modify, +4)* + **`app/build.gradle.kts`** *(modify, +2)* — two new
  deps via the version catalog: `androidx.camera:camera-core:1.4.2` (provides `ImageAnalysis.Analyzer`
  + `ImageProxy`) and the **bundled** `com.google.mlkit:barcode-scanning:17.3.0`. `camera-core` only —
  `camera2`/`camera-lifecycle`/`camera-view` (preview/binding) are #334's. See *Patterns / decisions*
  for why bundled over the Play-Services-download variant.
- **Tests:**
  - `test/.../QrCodeAnalyzerTest.kt` *(new, 148 LOC, plain JVM, `./gradlew test`)* — drives `analyze()`
    with fake frames via an injected `FrameDecoder`, wiring `onQrDecoded` into a real `ScannerViewModel`
    so the full analyzer→VM seam is exercised (AC4). A `FakeImageProxy` implements `ImageProxy` where
    only `close()` is real (records `closed`); every other member `throw`s `UnsupportedOperationException`
    (the fake decoder ignores the frame). `getImage()` override carries `@ExperimentalGetImage`. A
    `QueueFrameDecoder(vararg values)` returns each scripted value then sticks on the last. Five tests:
    decode→surface+transition (fired once, state `Decoded("qr-payload")`); repeated same payload
    (fired **exactly once**); different payload after first (only `"first"` surfaces — debounce is
    per-scan, not per-payload); null frame then QR (null doesn't consume the latch); `analyze` closes
    the frame even when nothing decoded.
  - `test/.../ScannerViewModelTest.kt` *(modify, +7)* — `qrDecoded_movesToDecodedCarryingPayload`
    (mirrors `cameraError_…`).
  - `androidTest/.../ScannerScreenTest.kt` *(modify, +23)* — `decoded_rendersViewportUnchanged`:
    renders `ScannerScreen(state = Decoded("ignored-payload"), …)` and asserts the viewport is present
    (`"Pair with pyrycode"` + substring `"pyry pair"`), proving the `Decoded` branch is a no-visible-
    change viewport render (scope guard). No test asserts on payload *content* beyond identity (it's
    untrusted, unparsed here).

## Patterns established

- **The success seam mirrors the dormant-failure seam.** `QrDecoded → Decoded` is the deliberate
  counterpart to #326's `CameraError → Error`: a state/event pair defined and unit-tested **before its
  live producer exists**, so the transition is covered now and #334 inherits a defined entry point.
  Same justification as #326 (an unreachable state can't have its transition tested). The naming
  (`QrDecoded`/`Decoded` reading as the counterpart to `CameraError`/`Error`) is a soft convention —
  the load-bearing contract is "a decoded event carrying a `String` → a decoded state carrying that
  `String`."
- **Injected synchronous `FrameDecoder` is the testability lever.** Splitting the blocking ML Kit call
  behind a `fun interface FrameDecoder` (default-argument-injected into the analyzer) is what lets
  `analyze()` run on a plain JVM test thread with canned payloads — no Robolectric, no device, no
  `Tasks.await`. This is the analyzer analog of #326's "route owns the Android API, the VM stays
  Android-free" split: keep the device-bound part (ML Kit) behind a seam, test the logic (debounce +
  dispatch) against a fake.
- **Debounce via lock-free `AtomicBoolean.compareAndSet(false, true)`, not check-then-act.** The
  `compareAndSet` *is* the atomic guard — no TOCTOU even though CameraX may invoke `analyze` on a
  background thread. One latch per analyzer instance = one surfaced payload per scan; re-scan is a
  fresh analyzer (owned by #334).
- **Redacting `toString()` as a deterministic secrecy net for untrusted/sensitive fields.** Overriding
  `toString()` on the data classes that carry the untrusted payload makes the no-log guarantee
  enforced by code, not just by an agent rule — different fabric for the belt-and-suspenders. A
  reusable shape for any future state/event that carries a secret or untrusted string.
- **Bare `String` for the untrusted boundary value.** The decoded payload stays a plain `String`, not
  a wrapped/"validated" type, precisely so the downstream parse step (#320) cannot mistake it for
  trusted input. The trust boundary is named and narrow:
  `QrCodeAnalyzer.onQrDecoded` → `QrDecoded(payload)` → `Decoded(payload)`.

## Lessons learned

Lifted from [PR #339](https://github.com/pyrycode/pyrycode-mobile/pull/339)'s *Lessons learned*:

- **A `Log.`/`Timber` token in a *comment* that also mentions the redacted field trips the security
  review's deterministic grep.** The AC5 check is
  `grep -rn 'Log\.\|Timber' app/src/main/java/.../ui/onboarding/ | grep -i 'payload\|rawValue'` and it
  does not distinguish code from comments — an explanatory comment containing a literal
  `Log.d("$state")` next to the word "payload" tripped it. Reworded. **Future no-log slices should keep
  `Log.`/`Timber` tokens out of comments that also name the redacted field.**
- **`ImageProxy.getImage()` is `@ExperimentalGetImage`; the opt-in must be on the *consuming function*
  AND on the test fake's override.** Annotating `MlKitQrFrameDecoder.decode` (and
  `FakeImageProxy.getImage()`) with `@androidx.camera.core.ExperimentalGetImage` satisfies lint's
  `UnsafeOptInUsageError` under `lint { abortOnError = true }` (which otherwise fails the build). The
  exact `ImageProxy` member set the fake must implement (including the `toBitmap()` default) was
  verified via `javap` on the resolved `camera-core-1.4.2.aar` — **useful reference for #334's live
  binding.**
- **Threading contract handed to #334:** `Tasks.await` in `MlKitQrFrameDecoder.decode` **blocks and
  throws if called on the main thread.** CameraX invokes `analyze` on the executor passed to
  `ImageAnalysis.setAnalyzer(executor, analyzer)` — **#334 must pass a background executor, never the
  main one.** This slice's tests call `analyze` on the test thread with the fake decoder (no
  `Tasks.await`), so the constraint doesn't bite here — documented so the wiring slice doesn't bind on
  main.

## Verification

- `./gradlew test` ✅ (RED→GREEN confirmed: the once-per-scan tests fail when the latch is removed,
  pass with it) · `./gradlew lint` ✅ (`abortOnError=true`, opt-in clean) · `./gradlew assembleDebug`
  ✅ · `./gradlew spotlessCheck` ✅. **`connectedAndroidTest` not run — no device/emulator** in the
  build environment; the new `Decoded`-renders-viewport instrumented test is independent of the AC's
  decode/debounce coverage, which is fully in JVM unit tests.
- **Code review: PASS.** Security review (the ticket carries `security-sensitive`): the decoded QR
  string is the single explicit untrusted-input boundary, surfaced as a bare `String`, never parsed/
  persisted/logged this slice; the no-log guarantee has two layers of different fabric (the stochastic
  no-`Log.*`-references-`payload` rule + the deterministic redacting `toString()`); no filesystem,
  network, crypto, or new exported component. Content validation of a hostile QR → #320; identity/MITM
  confirmation → #321; cross-session replay → #320/#321 (the in-session latch only debounces one scan).
