# #381 — Literal-screen render surface + ViewModel DI registration

The **render half** of the manual "show the literal screen" feature: a stateless Compose surface that
renders the merged [`LiteralScreenViewModel`](../features/literal-screen-viewmodel.md)'s hoisted state
([#378](378.md), on `main`) and dispatches its two events, plus the one Koin line that makes the VM
resolvable. **No change to the VM, the repository, or navigation** — the thread entry-point action +
navigation destination that opens this surface are the sibling slice **#382** (`blockedBy #381`).
Split from #379 (which split #372 → #378/#379; #379 then split on the surface-vs-entry seam → **#381**
surface + DI / **#382** entry + nav). See the feature doc
[`literal-screen-surface.md`](../features/literal-screen-surface.md) for the durable contract.

`security-sensitive`: the snapshot `text` is server-originated and may carry sensitive on-screen content,
so this slice owns the three render-edge confidentiality obligations #378's review propagated here —
verbatim plain-monospace render (never through [`MarkdownText`](../features/markdown-text.md)), never
logged / never `rememberSaveable`, and screen capture blocked (`FLAG_SECURE`). Per-conversation VM
scoping (no cross-conversation text bleed) is **#382's** — this slice only makes the VM resolvable.

## Summary

One new production file + one one-line `AppModule` edit + 8 new string resources + one new instrumented
test file. **Purely additive** — a new composable and a single DI registration; the VM constructor is
unchanged and there are no existing consumers of the new surface, so zero caller blast radius. The
surface stands alone — tested + DI-wired before it is reachable from any UI, exactly as #378 merged the
VM with zero reachability. It is the render face of pyrycode ADR 025's always-available,
parser-independent safe-degradation floor (pyrycode#596).

## Patterns established

- **The repo's first `FLAG_SECURE` pattern — the reusable shape for any future sensitive surface.** A
  private `@Composable SecureScreen()` with `DisposableEffect(Unit)` (apply-on-enter / clear-on-dispose)
  driven by a null-safe `private tailrec fun Context.findActivity()` walk. Clearing on dispose matters —
  the flag does **not** silently harden unrelated screens. The null-safe walk (not `LocalActivity.current`,
  not an unchecked `context as Activity` cast) is *why* it no-ops under `createComposeRule` (non-Activity
  host): no crash, no `Activity` dependency in tests. Copy this for the next screen that shows sensitive
  content.
- **Verbatim plain-monospace render as the deliberate anti-`MarkdownText` path, test-pinned.** When
  rendering server-originated text that must NOT be interpreted: `Text` + `FontFamily.Monospace` +
  `softWrap = false` in a both-axes-scrollable container — never `MarkdownText`, never pre-processed,
  never wrapped in `SelectionContainer` (selection enables one-tap clipboard copy = a confidentiality leak
  straight past `FLAG_SECURE`). The bypass is proven structurally: feed markdown-ish input
  (`"**bold** \`code\`"`) and assert the raw markers appear literally — if `MarkdownText` had run they'd be
  stripped/rendered and the literal node would be absent. (Diverges from `PairingConfirmContent`, which
  *does* use `SelectionContainer` — but the fingerprint there is public; the snapshot here is sensitive.)
- **A stateless surface over a `security-sensitive` UiState carries the render-edge no-leak obligations the
  VM's redaction can't reach.** #378 gave the deterministic half (redacting `Content.toString()`); this
  slice adds the render-edge half: no `Log.*`/`println` in the file, no `rememberSaveable` of the text
  (only the non-sensitive scroll position is `remember`ed — never saveable), and per-reason error copy
  from string resources (the surface never renders `"$state"`, never builds a `contentDescription` from
  the snapshot text). Belt-and-suspenders, different fabric, spanning the VM (#378) + the surface (#381).
- **DI registration that is *resolvable but not yet scoped*.** `viewModel { }` makes the VM obtainable;
  the per-open *instance scoping* (fresh VM per conversation, no cross-conversation `text` bleed) is
  deferred to the obtaining slice (#382, via `koinViewModel()` within the thread back-stack-entry scope).
  This continues the #378→#379 deferral shape: a slice can ship a fully-wired-but-unreachable surface, and
  the registration half can land a slice ahead of the navigation that consumes it.

## Lessons learned

The PR ([#383](https://github.com/pyrycode/pyrycode-mobile/pull/383)) carried a *Lessons learned*
section; lifted + augmented:

- **No `FLAG_SECURE` precedent existed in the repo; the null-safe `tailrec Context.findActivity()` walk is
  the deliberate test-survivability move** — it lets the `DisposableEffect` no-op under `createComposeRule`
  (non-Activity host) instead of crashing, so the security tests run with no device and no `Activity`
  dependency. This is the reusable pattern for any future sensitive surface (PR Lessons-learned, verbatim).
- **The verbatim/monospace proof is structural, not a typeface assertion.** `FontFamily.Monospace` is not
  queryable via the Compose test API, so monospace is *not* asserted directly — the markdown-bypass test
  (raw `**bold**`/backtick node present) plus code review of the `Text` call covers it. Don't try to assert
  the typeface; note it in a test comment instead (the shipped test does).
- **`LaunchedEffect(Unit)` firing `Request` on open shifts every recording-lambda assertion by one.** Each
  test with a recording `onEvent` sees `Request` first, so retry/refresh assertions expect
  `[Request, Retry]`, not `[Retry]`. Account for the open-`Request` or the event-count assertion fails.
- **Code review SHOULD-FIX, deliberately *not* actioned: no `@Preview`.** Repo convention is every
  screen-level composable carries at least one preview (the mirrored `ScannerScreen` has light+dark), but
  this surface has none — deferred because visual design is owed (Figma N/A). A preview with canned
  `Content`/`Error` fixtures is **owed alongside the visual retrofit** when the frame lands (the eventual
  design frame, per the #343 design-later precedent); the review flagged it as a cheap dev aid that will
  help that retrofit. Non-blocking — did **not** gate the merge.
- **Code review NIT, not actioned (harmless):** `LoadingContent`/`SnapshotContent`/`ErrorContent` each
  declare a defaulted `modifier` param the caller never passes — idiomatic Compose, left as-is.

## Verification

- `./gradlew test`, `lint`, `spotlessCheck`, `assembleDebug`, and `assembleDebugAndroidTest`
  (instrumented-test compile) all green (PR [#383](https://github.com/pyrycode/pyrycode-mobile/pull/383)).
  `connectedAndroidTest` not run — no device/emulator; the 7 `LiteralScreenSurfaceTest` Compose tests
  compile cleanly and follow the `ThreadOverflowMenuTest` idiom (instrumented tests run on-device per repo
  convention).
- The 7 tests map to the ACs: `Loading` → spinner `contentDescription` (AC#1); `Content` renders verbatim,
  markers intact = bypasses `MarkdownText` (AC#1); each of `UnknownConversation` / `ServerError` /
  `NotConnected` → its copy, and `Retry`/refresh fire `Retry` (AC#1/#2); `Request` fired exactly once on
  open (AC#1/#2); refresh re-fetches in place, surface still composed (AC#2). The `FLAG_SECURE` no-crash
  guarantee (AC#4) is proven implicitly — **all** tests render under `createComposeRule` without crashing.
- **Code review: PASS** ([PR #383](https://github.com/pyrycode/pyrycode-mobile/pull/383)) — one
  non-blocking SHOULD-FIX (missing `@Preview`) + one NIT (unused `modifier` params), neither gating. The
  reviewer re-walked all 8 architect security findings against the diff and confirmed each is realized in
  code, verified deterministically by grep: `MarkdownText` / `SelectionContainer` appear **only in
  comments** (zero usage), the redacted `toString` is not undone, `FLAG_SECURE` is applied/cleared via
  `DisposableEffect`, no `contentDescription` is built from the snapshot text, and the DI line matches the
  VM's `(SavedStateHandle, ConversationRepository)` constructor.
- **Security review: PASS** (architect self-review in the spec, label-gated). Confidentiality at the
  **render edge**, not integrity — the text is displayed, never parsed/interpreted, so no injection
  surface. Closed in-design: verbatim render + no `SelectionContainer` + no log + no `rememberSaveable` +
  `FLAG_SECURE`. Cross-conversation `text` bleed (VM scope) and accessibility-service eavesdropping (an
  app-wide residual, no per-view defense) are explicitly out of scope — the former → #382.
