# #253 — feat(ui/thread): ThreadViewModel selectedModel state plumbing

Replaces the stringly-typed `STUB_MODEL` companion constant on [`ThreadViewModel`](../features/thread-screen.md) with a typed `selectedModel: Model` field on [`ThreadUiState`](../features/thread-screen.md), initialised from `AppPreferences.defaultModel` (the Settings default already shipped by [#231](./231.md)) and overridable per-conversation via a new `onModelSelected(model: Model)` method backed by an in-memory `MutableStateFlow<Model?>` (override `null` ⇒ "use the Settings default"). The override does not mutate the persisted default — Phase 4 will own real persistence. No user-visible behavioural change: the [`ThreadStatusRow`](../features/thread-status-row.md) still renders `"Opus 4.7"` by default; the screen derives the label from a new `Model.label()` extension co-located with the enum so the sibling Status Sheet slice [#254](https://github.com/pyrycode/pyrycode-mobile/issues/254) can reuse it for the radio group. Split from [#228](https://github.com/pyrycode/pyrycode-mobile/issues/228).

## Summary

- **`ThreadUiState` field renames from `val model: String = "Opus 4.7"` to `val selectedModel: Model = Model.OPUS_4_7`.** Typed contract for the sibling Status Sheet's M3 `ModalBottomSheet` radio group, which needs to compare against an enum rather than a label string. The data-class default propagates into the existing `stateIn(initialValue = ThreadUiState(conversationId, displayName))` literal at `ThreadViewModel.kt` unchanged — the new `selectedModel` slot fills via the data-class default, so pre-subscription `vm.state.value.selectedModel == Model.OPUS_4_7` holds without any reader change at the destination block.
- **`ThreadViewModel` gains `appPreferences: AppPreferences` as a fourth constructor parameter, appended last** so the eight-call-site `makeVm` test helper absorbed the change behind a `prefs: AppPreferences = AppPreferences(newDataStore())` default. The Koin binding at `AppModule.kt:36` gains one `get()` (`viewModel { ThreadViewModel(get(), get(), get(), get()) }`) — the `AppPreferences(get())` singleton has been bound at `AppModule.kt:29` since [#11](./11.md), so no new module entry.
- **Pre-combined `selectedModelFlow` keeps the main `combine` from growing past four args.** A private cold `Flow<Model>` is built once from `combine(appPreferences.defaultModel, modelOverride) { default, override -> override ?: default }`, then folded as the **fourth** source into the existing `combine(observeConversations, observeMessages, pendingWorkspacePicker, selectedModelFlow)`. The alternative of inlining both flows at top level would have pushed the reducer lambda to five args — Kotlin's `combine` overloads cap at five but readability suffers earlier; pre-combining at the model boundary keeps the top-level reducer at four args (the same shape as #137 + #246 left it at three) and centralises the override-wins rule.
- **`modelOverride: MutableStateFlow<Model?>` private to the VM, initialised to `null`.** `null` ⇒ "no per-conversation override; use the Settings default". The override is in-memory only — destroyed with the VM on configuration change or back-stack pop; Phase 4 will persist it (the spec's `Phase 4 will replace this with real persistence` note). `MutableStateFlow<Model?>(null)` already carries a value, so it doesn't gate the main `combine`'s first emission — the pipeline produces its first frame as soon as `appPreferences.defaultModel` yields (which it does immediately under DataStore's replay-1 semantics).
- **`fun onModelSelected(model: Model)` is a synchronous `MutableStateFlow.value` write.** No `viewModelScope.launch`, no `appPreferences.setDefaultModel(...)` call — the AC's "does not mutate Settings default" line is enforced by what the method *doesn't* do. The signature is non-nullable (no reset-to-default path); a future ticket that needs to surface "revert to Settings default" wires a separate method rather than overloading `null`.
- **Fallback chain — `Model.OPUS_4_7` is the load-bearing default at three layers.** (1) `Model { OPUS_4_7, SONNET_4_6, HAIKU_4_5 }` orders `OPUS_4_7` first, (2) `AppPreferences.defaultModel` maps unparseable/missing stored values to `Model.OPUS_4_7` (since [#231](./231.md), `AppPreferences.kt:42`), (3) `ThreadUiState.selectedModel: Model = Model.OPUS_4_7` data-class default feeds the `stateIn(initialValue = …)` constructor. The AC's "falling back to `Model.OPUS_4_7` if the flow has not yet emitted" line is satisfied without a `Flow.onStart { emit(Model.OPUS_4_7) }` operator — the data-class default is the no-collector frame; once a collector lands, DataStore's replay-1 fires synchronously.
- **`ThreadScreen` callsite changes by exactly one token at `ThreadScreen.kt:64`** — `model = state.model` → `model = state.selectedModel.label()`. The [`ThreadStatusRow`](../features/thread-status-row.md)'s `model: String` parameter is preserved (the AC explicitly pins this) so the row's eight previews, its public signature, and its internal `buildAnnotatedString` shape stay byte-identical. The `import de.pyryco.mobile.data.preferences.label` is the only new import on the file.
- **`Model.label(): String` co-located with the enum** at `data/preferences/Model.kt`:
  ```kotlin
  fun Model.label(): String =
      when (this) {
          Model.OPUS_4_7 -> "Opus 4.7"
          Model.SONNET_4_6 -> "Sonnet 4.6"
          Model.HAIKU_4_5 -> "Haiku 4.5"
      }
  ```
  This **walks back** the [#231](./231.md) "no `.label()` extensions on data-layer enums" deferral that the [`app-preferences`](../features/app-preferences.md#design-decision-defer-label-extensions-on-data-layer-enums) doc records. Rationale documented in that anchor (and below in Lessons learned): two callers materialise the same week (#253's status row + #254's Status Sheet radio group); the alternative private helper in `ThreadScreen.kt` would force #254 to extract or duplicate immediately. The reversal is **scoped to `Model`** — `Effort` and `ThemeMode` still own their labels at the Settings call site (the Settings model-picker for `Model` is also still pending; when it lands, it consumes the same extension instead of declaring a parallel mapping).
- **Test setup re-platforms onto the `ChannelListViewModelTest` `TestScope.backgroundScope`+`TemporaryFolder` pattern.** `ThreadViewModelTest` adopts a `@get:Rule val tmp = TemporaryFolder()` and a private `TestScope.newDataStore(): DataStore<Preferences>` helper that creates a unique `tmp.newFile("prefs_${UUID.randomUUID()}.preferences_pb")` per call, scoped to `backgroundScope`. The `makeVm` helper becomes a `TestScope` receiver function with a fourth defaulted parameter `prefs: AppPreferences = AppPreferences(newDataStore())` so every existing test that doesn't care about prefs is a one-character change at the helper call site (none — they don't pass `prefs`). The unique-file-per-call shape (`UUID.randomUUID()`) means tests that build a second VM in the same `runTest { }` block get a second isolated prefs store, not a shared one.
- **Four pre-existing non-`runTest` tests converted to trivial `runTest { … }` wrappers.** `state_initialValue_isConversationIdPlaceholderBeforeSubscription`, `connectionState_initialValue_isConnected`, `state_collapsesAbsentConversationIdToEmptyString`, and the renamed `state_initialValue_includesDefaultModelEffortAndTokenPercentDefaults` could not stay synchronous: the new `TestScope.makeVm(…)` receiver-function shape needs a `TestScope` context, and reads off `vm.state.value` no longer settle synchronously if the DataStore-backed `appPreferences.defaultModel` is still mid-IO. The `runTest { … }` wrapper provides both — `backgroundScope` for the DataStore and the implicit `advanceUntilIdle()` semantics at scope close. The assertions inside each body are unchanged.
- **Two existing test methods renamed from `*Stub*` to `*Default*`.** `state_initialValue_includesStubModelEffortAndTokenPercentDefaults` → `state_initialValue_includesDefaultModelEffortAndTokenPercentDefaults`; `state_postSubscription_emitsStubModelEffortAndTokenPercent` → `state_postSubscription_emitsDefaultModelEffortAndTokenPercent`. The `Stub` prefix no longer applies to `model` (it's now the Settings default, not a stub constant). `effort` and `tokenPercent` are still stubs but the test name conflates all three — renaming once is cheaper than splitting into two test pairs for one slice.
- **Four new `@Test` methods cover the AC.**
  - **`selectedModel_followsAppPreferencesDefault`** — builds an `AppPreferences` over `newDataStore()`, calls `prefs.setDefaultModel(Model.SONNET_4_6)` **before** VM construction, then asserts the VM's `state.first { it.selectedModel == Model.SONNET_4_6 }` settles inside `withTimeout(2.seconds)`. Pins the AC line "populates `selectedModel` from `appPreferences.defaultModel` on conversation open".
  - **`selectedModel_reemitsWhenAppPreferencesDefaultChanges`** — subscribe, assert default `OPUS_4_7`, call `prefs.setDefaultModel(Model.HAIKU_4_5)`, assert `state.first { it.selectedModel == Model.HAIKU_4_5 }`. Pins the reactive contract — the override-less case is a pure passthrough of `appPreferences.defaultModel`.
  - **`onModelSelected_overridesPerConversationWithoutMutatingPreferences`** — the AC's **explicit verification line**: assert `prefs.defaultModel.first() == Model.OPUS_4_7` before, call `vm.onModelSelected(Model.HAIKU_4_5)`, assert `vm.state.value.selectedModel == Model.HAIKU_4_5`, then re-assert `prefs.defaultModel.first() == Model.OPUS_4_7` (unchanged). If anyone in the future "helpfully" wires `onModelSelected` to also call `appPreferences.setDefaultModel(...)` (the per-conversation-equals-new-default mistake), this test fails on the last assertion.
  - **`onModelSelected_overrideWinsOverSubsequentDefaultChange`** — sets an override to `HAIKU_4_5`, then changes the prefs default to `SONNET_4_6`, asserts `selectedModel` stays `HAIKU_4_5`. Pins the override-wins rule baked into `selectedModelFlow`'s `override ?: default`.

## Patterns established

- **In-memory per-screen override stacked over a persistent app-wide default — three-flow shape.** `MutableStateFlow<T?>(null)` for the override (synchronous writes, non-suspend setter, no DataStore writes), a `Flow<T>` for the persisted default, and a pre-combined `Flow<T>` (`override ?: default`) folded as one source into the screen's main `combine`. Apply to any future per-conversation setting that has a "use the Settings default unless this conversation explicitly overrides" semantic: effort, agent identity, model temperature, MCP tool toggles, etc. The setter stays a synchronous `MutableStateFlow.value` write; `appPreferences.set*(...)` is **never** called from the override path. Resetting back to "follow the default" is not currently exposed — when that ticket lands, the right shape is a separate `clearModelOverride()` method (or a `Optional` parameter on `onModelSelected`), not an `onModelSelected(null)` overload.
- **Pre-combine peripheral flow groups before the main `combine` to keep the top-level reducer at four args or fewer.** The main `combine(observeConversations, observeMessages, pendingWorkspacePicker, selectedModelFlow)` block stays at the same arity it had post-#137. Future per-screen flows (e.g. effort override, status sheet visibility) should follow the same shape — a private pre-combined `Flow<Foo>` rather than a sixth or seventh top-level arm. Kotlin's `combine` overloads run to five, but readability falls off earlier; the pre-combine boundary names the sub-flow and lets unit tests target it in isolation if needed.
- **Unique-file-per-DataStore-construction in tests via `tmp.newFile("prefs_${UUID.randomUUID()}.preferences_pb")`.** Each call to `newDataStore()` produces a fresh file inside the same `TemporaryFolder` rule, so a single `runTest { }` block can construct multiple `AppPreferences` instances and they stay isolated. Cheaper than parameterising the rule per test or rotating the folder between tests; `TemporaryFolder` cleans up the directory after the test regardless of file count. Apply to any future test that needs ≥2 independent DataStores inside one `runTest`.
- **Co-locate small enum→label extensions next to the enum when ≥2 UI consumers ship in the same release.** The [#231](./231.md) deferral — "first UI consumer owns the labels" — held until the first **and** second consumer arrived in adjacent slices. The cost of co-locating `Model.label()` once is 7 LOC; the cost of two private helpers across two slices, plus an inevitable third extract-on-third-use later, is more. The rule is **not** "co-locate by default" — the deferral still applies to `Effort` and `ThemeMode`, which only have one current UI consumer each. Re-evaluate per enum when the second consumer materialises.

## Lessons learned

- **`combine` does not emit until every upstream has produced at least one value — but `MutableStateFlow<Model?>(null)` already has one.** The architect spec called this out as a potential race (override set before first `defaultModel` emission), and the answer is that the override flow starts with `null` so it does not gate the main `combine`. `appPreferences.defaultModel` produces its first emission as soon as DataStore yields (replay-1 semantics), which under the fake's in-memory `DataStore` is effectively synchronous. Net: the combine pipeline produces its first emission immediately on first collection; the `stateIn` `initialValue` only covers the pre-collection frame. **No `onStart { emit(Model.OPUS_4_7) }` operator is needed** — adding one would defend a failure mode that cannot happen given the upstream contract.
- **Converting four synchronous tests to `runTest { }` wrappers was non-optional — but the wrappers stay trivial.** The constructor signature shift (`makeVm` is now a `TestScope.()` receiver function so it can call `newDataStore()`) forced every call site into `TestScope` context, and the only ergonomic shape is `runTest { }`. The wrapped bodies don't gain `advanceUntilIdle()` calls — they still read `vm.state.value` synchronously and the assertions land in the same frame; `runTest` is the cheap context provider. If a future ticket prunes the prefs dependency from one of these tests, the wrapper can come back off without other churn.
- **The "`model: String` parameter unchanged on `ThreadStatusRow`" line in the AC was the right contract** — it kept the row's eight previews, its public signature, and its `buildAnnotatedString` body byte-identical. The temptation to "type all the way down" (push `Model` into the row's parameter list) would have rippled into the previews, the eight `darkTheme`-toggled `@Preview` literals, and the row's own internal `if (model == "Opus 4.7") …` branches if any future ticket adds per-model styling. Today the row knows nothing about the enum; the screen does the mapping at the boundary. Apply to similar component edges — keep the leaf composable's parameter list as primitive as it can be while the type-information stays one layer up.
- **`Model.label()` returns Kotlin literals, not `stringResource(R.string.model_label_opus_4_7)`.** Compose Multiplatform's "data/ stays portable" constraint (see [`CLAUDE.md`](../../../CLAUDE.md) and the [`app-preferences` decision anchor](../features/app-preferences.md#design-decision-defer-label-extensions-on-data-layer-enums)) is the load-bearing reason — `R.string.*` lookups require an Android `Context`, which a `data/`-package extension cannot legitimately consume. The labels are product-vendor names (`Opus 4.7`, `Sonnet 4.6`, `Haiku 4.5`) that don't localise — they ship in the same form across locales the same way "Anthropic" or "Claude" would. If a future slice introduces a non-English label that needs localisation (unlikely for product names), the right answer is a UI-layer label function that consumes the enum and uses `stringResource`; the data-layer `Model.label()` stays as the portable identifier-to-display-name shim.
- **The `Stub` → `Default` test rename is semantic, not cosmetic.** Pre-#253 the two assertions pinned three stub constants on a companion object; post-#253 one of those three (`model`) is now sourced from `AppPreferences` and is **not** a stub — Settings can change it, the user can override it. Naming the test `*StubModel*` would have set up a future reader to grep for a stub and find a defaulted-from-prefs flow instead. The rename keeps the assertion correct and the name honest in one breath. The trade-off is that `effort` and `tokenPercent` are still stubs but now live under a test name that says `Default`; documented here so the next reader knows the test is "the data-class default frame", not "everything in this assertion is a stub".
