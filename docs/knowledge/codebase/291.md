# #291 — device X25519 static keypair persisted via Android Keystore

The **device-identity primitive of the Phase 4 crypto chain**: a per-server, generate-once-never-regenerate X25519 (Curve25519) static keypair — the phone's long-term Noise `s` key as the `Noise_IK` **initiator**. The raw 32-byte private scalar is AES-256-GCM-wrapped under a hardware-backed `AndroidKeyStore` key and stored in the existing app-private DataStore; the 32-byte public key is mirrored in plaintext for fast reads. Greenfield — **no consumers yet**; ships the keypair-custody seam that [#275](https://github.com/pyrycode/pyrycode-mobile/issues/275) (Noise_IK session) will consume as the initiator's local static key. `security-sensitive` ticket (the asset is the device's per-server cryptographic identity). Split from [#274](https://github.com/pyrycode/pyrycode-mobile/issues/274).

See the feature doc [`device-static-keystore.md`](../features/device-static-keystore.md) for the evergreen "how custody works / how #275 consumes it" reference, and [ADR 0006](../decisions/0006-keystore-wrap-at-rest-device-static-key.md) for the mechanism-choice decision (wrap-at-rest over non-exportable XDH). This file is the implementation record.

## Summary

One interface + value type + typed exception (`DeviceStaticKeyStore.kt`) plus one Keystore-backed impl (`KeystoreDeviceStaticKeyStore.kt`) under a new `data/crypto/` sub-package, wired with one DI binding, verified by one instrumented test file (6 `@Test` methods). The central design call — noise-java does software DH on **raw** private bytes, so a non-exportable Keystore key can't both stay in-Keystore *and* be DH-able — was resolved to **mechanism (a): wrap-at-rest** (the raw scalar lives as AES-GCM ciphertext at rest, materialises in RAM only transiently during a handshake). See [ADR 0006](../decisions/0006-keystore-wrap-at-rest-device-static-key.md).

The load-bearing invariant is **"never silently regenerate"**: a decrypt failure (tampered blob, wrap-key gone, restore-to-new-device) throws `DeviceStaticKeyException` rather than minting a fresh keypair — a new key would change the device identity the server recognises and silently break re-pairing. Idempotency is given a *deterministic* guarantee by a `Mutex` over check-then-generate, not left to callers not racing.

## Files touched

Two production source files **NEW** under `app/src/main/java/de/pyryco/mobile/data/crypto/`, one DI edit, one **NEW** instrumented test:

- **`DeviceStaticKeyStore.kt`** (43 lines) — the portable contract, **zero `android.*` imports**:
  - `interface DeviceStaticKeyStore` (`:12-26`) — `suspend fun loadOrCreate(serverId): DeviceStaticKeyPair` (`:19`, generate-or-load, idempotent, throws on crypto failure) + `suspend fun publicKey(serverId): ByteArray?` (`:25`, plaintext-mirror read, `null` before first generate).
  - `class DeviceStaticKeyPair(val publicKey, val privateKey)` (`:34-37`) — raw 32-byte X25519 scalars. **Plain class, not `data class`** — left with default reference-equality `equals`/`hashCode`; tests compare the byte arrays directly (`assertArrayEquals`), never the holder (the architect flagged the `ByteArray`-in-`data class` structural-equality trap; the impl avoids it by not being a data class at all).
  - `class DeviceStaticKeyException(message, cause?)` (`:40-43`) — single typed failure; carries no key material.
- **`KeystoreDeviceStaticKeyStore.kt`** (179 lines) — the Android-bound impl (`android.security.keystore.*` + `android.util.Base64`):
  - `loadOrCreate` (`:42-62`) — `withContext(Dispatchers.IO)` → `mutex.withLock` → `runCatchingKeystore { … }`; reads both prefs, three-way `when`: both present → unwrap; both absent → `generate`; **exactly one present → throw "corrupt device static key store"** (the half-keypair guard, unreachable in normal operation by the single-`edit{}` write, defensive against external tampering of `app_prefs`).
  - `publicKey` (`:64-68`) — reads only the mirror pref; **no Keystore op** (AC #4).
  - `generate` (`:70-79`) — `SecureRandom().nextBytes(32)` scalar → derive public → `wrap` → **one `dataStore.edit { }`** writing both prefs (all-or-nothing).
  - `derivePublicKey` (`:82-92`) — derives the public **through noise-java** (`Noise.createDH("25519")` → `setPrivateKey(scalar,0)` → `getPublicKey(…)` → `destroy()` in `finally`) so the mirror is byte-identical to what #275's `Curve25519DHState` produces — no cross-implementation X25519 assumption.
  - `wrap` / `unwrap` (`:94-113`) — AES/GCM/NoPadding; encrypt **omits any IV spec** so the Keystore generates a fresh IV per op (read from `cipher.iv`, prepended); decrypt splits the 12-byte IV back off. `unwrap` validates blob length `> 12` and unwrapped scalar length `== 32`.
  - `getOrCreateWrapKey` (`:115-130`) — get-or-create the single shared AES-256-GCM wrap key, alias `pyrycode.device_static_wrap` (`:163`); `PURPOSE_ENCRYPT or PURPOSE_DECRYPT`, GCM, no padding, 256-bit; no `setUserAuthenticationRequired` (would break headless reconnect), no forced StrongBox (`StrongBoxUnavailableException` on devices without a secure element).
  - Key namespaces (companion, `:169-170`) — `PRIVATE_PREFIX = "pyrycode.device_static."` vs `PUBLIC_PREFIX = "pyrycode.device_static_pub."`, diverging at the fixed char right after the common stem (`.` vs `_`). See Patterns.
  - `runCatchingKeystore` (`:148-159`) — re-throws `DeviceStaticKeyException` un-double-wrapped; wraps `GeneralSecurityException` / `IOException` / `IllegalArgumentException` as `DeviceStaticKeyException("… ${e.javaClass.simpleName}", e)` — cause-class + operation, **never bytes**.
- **`di/AppModule.kt`** (+3 lines) — `single { KeystoreDeviceStaticKeyStore(get()) } bind DeviceStaticKeyStore::class`; `get()` resolves the already-registered `DataStore<Preferences>`. No consumer cascade (#275 doesn't exist yet).
- **`androidTest/.../data/crypto/KeystoreDeviceStaticKeyStoreTest.kt`** (132 lines, **NEW**) — `@RunWith(AndroidJUnit4::class)`, instrumented (real `AndroidKeyStore` needs a device). Test-scoped DataStore via `context.preferencesDataStoreFile("test_device_static_${UUID.randomUUID()}")`; `@After` deletes the `pyrycode.device_static_wrap` alias and the test prefs file so runs are hermetic. Six methods map to the five ACs — see the code-review's AC→test table on [PR #293](https://github.com/pyrycode/pyrycode-mobile/pull/293).

## Patterns established

- **Platform-custodian behind a portable interface — the CMP-walk-back-safe data-layer seam.** The interface (`DeviceStaticKeyStore.kt`) has **zero `android.*` imports**; the Keystore-bound impl carries all of them. This does **not** trip the `data/` "no android.* / CMP-portability" rule — the MUST-FIX trigger is *Context-shaped* (a `Context` constructor param), and the constructor takes only `DataStore<Preferences>`. On a Compose-Multiplatform walk-back the impl becomes an `androidMain` actual; the interface stays in `commonMain`. This is the canonical shape for any future key/secret custodian in `data/` (see the memory note [[data-layer-android-import-exception]]). Cross-references the wire layer's analogous "one JVM-only seam" stance ([#273](273.md)).
- **Collision-safe key namespacing for attacker-influenced identifiers.** `serverId` arrives via the QR pairing payload and is treated as opaque/hostile. The private-blob and public-mirror pref keys use **two independent fixed prefixes that differ in the char immediately after the common stem** (`.` vs `_`), so **no** `serverId` value can make a private-blob key collide with another server's public-mirror key. The rejected shape — a `.pub` *suffix* appended after `serverId` — would let `serverId = "foo.pub"` collide server `foo`'s public mirror with `foo.pub`'s private blob, breaking per-server isolation (AC #1) and able to clobber a device identity. This was the architect's one inline MUST-FIX (fixed in-spec before the PASS verdict); the impl carries a comment (`:165-168`) warning against reintroducing the suffix. Reuse the diverge-at-a-fixed-prefix-char rule for any map-keyed-by-untrusted-id storage.
- **Per-encrypt Keystore-generated GCM IV closes the nonce-reuse footgun deterministically.** Mechanism (a)'s one crypto risk is GCM nonce reuse under a long-lived wrap key. The impl never constructs an IV for encryption — it leaves `setRandomizedEncryptionRequired` at its default `true`, so the Keystore emits a fresh random IV per `init(ENCRYPT_MODE)`, read from `cipher.iv` and persisted with the ciphertext. IV-uniqueness is enforced by the platform, out of the developer's hands. Standard pattern for any Keystore-AES-GCM-wrap envelope.
- **Idempotency as a deterministic `Mutex` guarantee, not a caller contract.** A single `Mutex` (one Koin singleton → one lock) held across read-check-generate-write makes generate-or-load atomic, so AC #2's "never silently regenerates" holds even under concurrent `loadOrCreate` calls. Belt-and-suspenders done right: the deterministic lock backs the invariant rather than a second stochastic rule.
- **Throw-don't-regenerate on decrypt failure is the load-bearing security property, and it is *negatively* tested.** `keystoreLoss_throwsAndDoesNotRegenerate` deletes the wrap key, then asserts `loadOrCreate` throws `DeviceStaticKeyException` — proving the decrypt-failure path does **not** fall through to minting a new identity. A positive-only test suite would miss this; the negative guard is the oracle for the invariant.

## Lessons learned

Lifted from the PR's *Lessons learned* section, plus one from the build that cost a follow-up commit:

- **`android.util.Base64` is acceptable inside a class already Android-bound by the Keystore.** This impl uses `android.util.Base64` where the sibling `data/network/MobileWireCodec.kt` uses `java.util.Base64`. No `expect/actual` split is owed: a Keystore custodian can never live in `commonMain` regardless, so the portability contract is the `DeviceStaticKeyStore` *interface* (zero `android.*`), not the impl. The code review noted the cross-file inconsistency as a NIT only — not a portability blocker. (Contrast [#273](273.md)'s wire codec, where `java.util.Base64` was deliberate because that file *is* otherwise portable.)
- **ktlint (Spotless) settles the wrapped `KeyGenParameterSpec.Builder(...)` chain — don't hand-format it.** ktlint reformats a wrapped builder chain onto the `.Builder(` line; run `spotlessApply` and let it settle the chain indentation rather than fighting it by hand. (The root Spotless config excludes `com.southernstorm.**`, i.e. vendored noise-java, but applies to everything under `de.pyryco.**`.)
- **`publicKey(serverId)` as both a public override and a private pref-key builder is an overload clash that breaks compilation.** The first cut named the private pref-key helper `publicKey(serverId): Preferences.Key` alongside the interface override `publicKey(serverId): ByteArray?` — same name, same arg, different return type → JVM overload clash, compile error. Fixed in follow-up commit `62359e5` by renaming the builders to `privateBlobKey` / `publicMirrorKey`. Lesson: a private helper keyed by the same parameter as a public override needs a name that describes the *key it builds*, not the value the override returns. (The code-review NIT line refs `:293-306` / `:358-361` predate this rename + Spotless reflow; the final file is 179 lines.)
- **The instrumented round-trip cannot be JVM-tested — and "process restart" is survived by construction.** Real `AndroidKeyStore` requires a device/emulator, so there is no `test/` (JVM) companion; `./gradlew check` only *compiles* the test, and `connectedAndroidTest` was **not** run in the PR environment (no device). A fresh `KeystoreDeviceStaticKeyStore` instance over the *same* DataStore is the automatable proxy for an app restart; genuine process death is survived because both the DataStore file and the system Keystore alias outlive the process (documented in a test comment, not faked with a process fork).
