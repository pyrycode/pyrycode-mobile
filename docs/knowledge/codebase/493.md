## Summary

The [`RelayRepositoryCoordinator`](../features/relay-repository-coordinator.md) gated `currentRepository`
behind the pump reaching `PumpState.Open` (the [#421](https://github.com/pyrycode/pyrycode-mobile/issues/421)
fix that stopped the conversation list from
spinning forever), but it derived that gate by **`combine`-ing two independently-mutated `StateFlow`s** — a
repo holder (`mutableRepository`) and a `flatMapLatest` over a *separate* pump holder (`activePumpFlow`). On
a **direct A→B reconnect** (the supervisor emits transport B while A is still live, with no interposed
`null`), `combine` collects its two inputs on separate coroutines: the direct repo emission (`repoB`)
arrives in one hop, while the pump-state input must cancel pumpA's `state` collector and subscribe to
pumpB's — one extra hop. In that window `combine`'s cached pump-state is still **pumpA's `Open`** (and
`FakeManagedPump.close()`, like the real pump, leaves `state` at its last value, so nothing corrects it),
so it transiently emits `(repoB, Open) → repoB`: **the new connection's repo is exposed while its own pump
is still `Handshaking`**. The [#352 facade](../features/stable-conversation-repository.md) subscribes on the
first non-null repo and fires a one-shot `list_conversations` via `pump.send`, which returns `false` pre-`Open`
and is **dropped** — never re-issued. That is exactly #421's "list never loads", re-introduced through the
two-source race. Manifests only with `USE_RELAY_REPOSITORY` on.

The fix **consolidates the four connection-state holders into one** `activeConnection: StateFlow<Connection?>`
and derives `currentRepository` from a **single** `flatMapLatest` over it, mapping *that connection's own*
`pump.state` to the gated repo. Repo and pump-state become two projections of the **same** switched value, so
the cross-`StateFlow` window is closed **structurally** — there is no interleaving that can pair the new repo
with the old pump's cached `Open`. No public signature changes; it is a strict reduction of mutable state
(4 → 1), not added plumbing.

## The fix

**Before** — four separate holders, and a `combine` of two of them (the race surface):

```kotlin
private val mutableRepository = MutableStateFlow<ConversationRepository?>(null)
private val activePumpFlow    = MutableStateFlow<ManagedSessionPump?>(null)
private val activeRemoteRepo  = MutableStateFlow<RemoteConversationRepository?>(null)
private var active: Connection? = null   // plain var: (pump, scope)

val currentRepository: StateFlow<ConversationRepository?> =
    combine(
        mutableRepository,                                                    // direct — one hop
        activePumpFlow.flatMapLatest { pump -> pump?.state ?: flowOf(null) }, // switched — one EXTRA hop
    ) { repo, pumpState -> if (pumpState is PumpState.Open) repo else null }
        .stateIn(scope, SharingStarted.Eagerly, null)
```

**After** — one holder; repo and pump-state derive from the *same* switched `Connection`:

```kotlin
private val activeConnection = MutableStateFlow<Connection?>(null)            // :115 — the ONE source

val currentRepository: StateFlow<ConversationRepository?> =                   // :154
    activeConnection
        .flatMapLatest { conn ->
            conn?.pump?.state?.map { if (it is PumpState.Open) conn.repo else null } ?: flowOf(null)
        }.stateIn(scope, SharingStarted.Eagerly, null)

private class Connection(                                                     // :357
    val pump: ManagedSessionPump,
    val scope: CoroutineScope,
    val repo: RemoteConversationRepository,   // NEW — concrete type; liveSessionEvents/modalEvents/answerModal need it
)
```

Why this closes the race: the inner lambda **closes over `conn`**, so the mapped `conn.repo` and
`conn.pump.state` are *always the same connection's*. When `flatMapLatest` switches to connection B, the inner
flow is `connB.pump.state.map { … }`, whose **first** emission is `connB.pump.state.value` (`Handshaking`) →
`null`. There is no code path that pairs `connB.repo` with any pump but B's own. The `if (Open) conn.repo else
null` widens `RemoteConversationRepository` to `ConversationRepository?` via `Flow`/`StateFlow` covariance —
the declared type stays `StateFlow<ConversationRepository?>`.

Every other connection-derived seam switches off the **same** consolidated source — no parallel holders
reintroduced:

| Member | Derivation |
|---|---|
| `pyrycodeStatus` (private, :122) | `activeConnection.flatMapLatest { it?.pump?.state ?: flowOf(null) }.map { it.toPyrycodeLinkStatus() }` |
| `liveSessionEvents` (:169) | `activeConnection.flatMapLatest { it?.repo?.liveSessionEvents ?: emptyFlow() }` |
| `modalEvents` (private, :182) | `activeConnection.flatMapLatest { it?.repo?.modalEvents ?: emptyFlow() }` |
| `currentModal` (:212) | **unchanged** — still `modalEvents.scan(…).stateIn(Eagerly)` |
| `connectionStatus` | **unchanged** — still `combine(relayStatus, pyrycodeStatus){…}.stateIn(Eagerly)` |
| `answerModal`/`cancelModal`/`interrupt` (:334/:343/:353) | `activeConnection.value?.repo ?: throw IllegalStateException("no active connection")` |

## Patterns established

- **Derive two projections of a connection from ONE switched source, never `combine` two independently-mutated
  holders.** When a gate needs both A (a repo) and B (a pump-state) of the *same* connection, and both change
  on reconnect, holding them in **separate** `StateFlow`s and `combine`-ing lets one input lag the other by a
  coroutine hop — `combine` then transiently pairs the new A with the old B. Hold the connection as one object
  in one `StateFlow` and derive both via a single `flatMapLatest` whose inner lambda **closes over** the
  connection: the mapped `conn.a` and `conn.b` are then structurally guaranteed to be the same connection's.
  This is the elegant form — *fewer* holders, not more machinery. Contrast the `flatMapLatest`-then-`combine`
  shape, which is the bug.
- **Consolidate connection-scoped mirrors into the `Connection` object rather than adding parallel
  `MutableStateFlow` mirrors.** Each non-interface seam the coordinator threads up (`pyrycodeStatus` needs the
  pump; `liveSessionEvents`/`modalEvents`/`answerModal` need the concrete repo) had accreted its own private
  mirror (`activePumpFlow`, `activeRemoteRepo`) written in lock-step. The `Connection(pump, scope, repo)`
  object already carried the pump and scope; adding `repo` lets every seam switch off the one
  `activeConnection` source. Future connection-scoped seams should add a field to `Connection`, not a new
  top-level holder.

## Lessons learned

- **`spotlessApply` folds the `.stateIn(…)` continuation onto the `flatMapLatest` closing brace.** After
  writing `currentRepository` with `.stateIn` on its own line under the `flatMapLatest { … }` block, ktlint/
  spotless reformats it to `}.stateIn(scope, SharingStarted.Eagerly, null)` (continuation on the same line as
  the closing `}`). `spotlessCheck` fails until you run `spotlessApply`; don't hand-fight the formatter —
  run it and commit its shape. (General reminder: run `spotlessApply` before the final `spotlessCheck`, see
  [[spotless-could-not-autocorrect-warning-benign]] for the adjacent benign-warning trap.)
- **The regression is a *transient* emission, caught by COLLECTING — not by reading `.value`.** The settled
  `currentRepository.value` is `null` on **both** pre- and post-fix code, because a full `runCurrent()` drains
  the buggy path to `(repoB, Handshaking) → null`. So AC #1 attaches `backgroundScope.launch {
  currentRepository.collect { emissions += it } }` and asserts that **no non-null emission other than repoA**
  is ever observed. A `.value` assertion would be green on both and prove nothing. The distinguishing signal
  lives only in the emission *sequence*, so it must be collected. (Same harness discipline as
  [[remote-repo-test-runcurrent-not-advanceuntilidle]] — drive with `runCurrent()`, never `advanceUntilIdle()`.)
- **Confirmed RED against pre-fix `main` before the fix landed** (per `CLAUDE.md` § Conventions test-first):
  `reconnect_directAtoB_neverExposesRepoWhileNewPumpHandshaking` observed `repoB` transiently on the old
  `combine` gate, GREEN after. Under `StandardTestDispatcher` the schedule is deterministic — `combine`
  collects input 0 (`mutableRepository`, direct) before input 1 (the `flatMapLatest`), so the direct A→B path
  reliably surfaces `repoB` before the correcting `null`. (Had it proven non-reproducible, the contract was to
  escalate, not weaken the assertion.)

## Testing

Unit only (`./gradlew spotlessCheck test lint assembleDebug` all green). No instrumented test — pure
coordinator logic. `StandardTestDispatcher` driven with `runCurrent()`, hand fakes, `coordinator.close()`
ends every test. Three tests added, all reusing the existing `newEnv`/`FakeManagedPump`/`StubRelayTransport`/
`conversationsEnvelope` harness (`FakeManagedPump` starts at `Handshaking` and exposes `open()`;
`createPump` records each pump into `env.pumps`, so a test can drive A `Open`, switch `connections` to a
second transport, and leave `pumps[1]` at `Handshaking`):

- **AC #1 — `reconnect_directAtoB_neverExposesRepoWhileNewPumpHandshaking`** (the regression, RED on pre-fix
  `main`): collect every `currentRepository` emission; drive A to `Open` (assert `emissions.last() === repoA`);
  reconnect **directly** A→B (`connections.value = StubRelayTransport(); runCurrent()`) with **no** interposed
  `null` and **without** opening `pumps[1]`. Assert `emissions.filterNotNull().filter { it !== repoA }` is
  empty and settled `.value` is `null`.
- **AC #2 — `reconnect_directAtoB_exposesRepoOnlyOnceNewPumpReachesOpen`**: same setup; assert B's repo is
  hidden while `pumps[1]` handshakes, then `pumps[1].open(); runCurrent()` exposes it (distinct from repoA),
  and the only non-null repos ever exposed are `[repoA, repoB]` in order.
- **AC #3 — `reconnect_afterOpen_listConversationsSucceedsAndListLoads`**: A→`null`→B, `pumps[1].open()`, then
  drive the facade read path (`repo2.observeConversations(All)`) and assert one `list_conversations` frame
  reached `pumps[1].sent` (send **succeeded** post-`Open`, not dropped), then `push` a `conversationsEnvelope`
  and assert the projected list loads (`["c9"]`).
- **AC #4 — no key-wipe / single-use-pump regression**: the existing tests
  (`reconnect_buildsFreshPumpAndRepository_noCarryover`, `close_tearsDownActiveConnection`, the push-token
  once-per-connection tests) are **untouched and green** — all three drop transitions still route through
  `teardownActive → current.pump.close()`, and `onConnection` still builds a fresh pump/scope/repo.

## Security (`security-sensitive`)

Architect self-review **PASS**; code review **PASS** (zero findings). The consolidation *strengthens* the
concurrency posture and preserves every load-bearing invariant:

- **Concurrency** — collapses four independently-mutated holders into one single-writer `StateFlow`,
  eliminating the cross-`StateFlow` `combine` window. The non-suspending `onConnection`/`teardownActive`
  critical section (the cancellation-atomicity invariant, the `:233` KDoc "do not introduce a suspension
  here") is intact — the change adds only non-suspending `.value` writes + object construction, so a racing
  `close()` cannot cancel mid-build and leak a started-but-unclosed pump. Hot/cold flow choices unchanged
  (`currentRepository`/`connectionStatus`/`currentModal` stay `stateIn(Eagerly)`; `liveSessionEvents`/
  `modalEvents` stay cold).
- **Key-wipe / single-use pump (AC #4)** — every pump-drop transition (replace / `null` / `close`) still
  routes through `teardownActive → current.pump.close()`, the load-bearing wipe of the `Noise_IK` session
  ciphers + device-static copy. `onConnection` always builds a brand-new `Connection`, so no pump is reused
  across connections (nonce/ephemeral non-reuse is a crypto invariant, not just hygiene).
- **No-log contract preserved** — the coordinator emits no logs on any path; the fix adds none.
  `reregisterPushTokenOnOpen` is untouched (token never logged, `CancellationException` re-thrown).
- **No trust boundary added or moved** — `pump.state`/`repo` are internal, already-trusted projections;
  untrusted-wire parsing lives downstream in `RemoteConversationRepository`/`MobileWireCodec`, untouched here.
