# #267 — Auto-archive idle discussions after 30 days (`shouldArchive` predicate + fake-only `sweep`)

Adds the idle-archive policy `Conversation.lastUsedAt` was missing: nothing ever expired on it, so unpromoted discussions accumulated forever. The change is a pure `shouldArchive(conversation, referenceTime)` predicate plus a fake-only `sweep(referenceTime): Int` that flips the existing `archived` flag (#93) on every unpromoted discussion idle for at least `ARCHIVE_IDLE_THRESHOLD` (30 days, **inclusive**). Auto-archive converges on the identical observable state as manual `archive()` — swept discussions leave Channels/Discussions, appear under Archived + All, and stay `unarchive()`-able. Kotlin port of the canonical pyrycode (Go) `ShouldArchive(c, now)` predicate.

## Summary

- **`ARCHIVE_IDLE_THRESHOLD: Duration = 30.days`** — single named top-level constant, `internal` so the rule and its boundary test reference one source of truth (AC: "named constant, not a magic literal scattered across rule and tests"). A `val`, not `const val`, because `Duration` is not const-able.
- **`shouldArchive(conversation, referenceTime): Boolean`** — pure top-level `internal` function. Short-circuits `false` on `conversation.isPromoted`; otherwise `referenceTime - conversation.lastUsedAt >= ARCHIVE_IDLE_THRESHOLD`. Reads two fields, returns a `Bool`, cannot fail. The boundary is **inclusive** (`>=`, not `>`): idle for exactly the threshold archives. `referenceTime` is caller-supplied — the rule never reads `Clock.System.now()` — which is what makes the boundary tests deterministic with literal `Instant`s, no fake clock or scheduler.
- **`sweep(referenceTime): Int`** — public `suspend` method on `FakeConversationRepository` (consistent with the other `suspend` mutators; does not actually suspend). Applies `shouldArchive` across the whole store in one `state.update { … }`, flips `archived = true` on each unpromoted, not-already-archived match, and returns the count **newly** archived. Mirrors Go's `Sweep(reg, now) int`. Idempotent: re-running at the same reference time archives nothing, returns 0, and does not re-emit (the rebuilt `mapValues` map is value-equal → `StateFlow` skips the emission, the same property `archive()`/`delete()` rely on).
- **`sweep` is on the concrete fake only — not on `ConversationRepository`.** In Phase 4 the real backend sweeps server-side on its own schedule (the Go daemon's ticker); a client-triggered `sweep` would be meaningless on the remote impl. Keeping it off the interface also meant **zero** changes to the test stubs (`RecordingRepo` ×3, `stubRepo`) — additive with no consumer cascade.
- **No construction-time sweep, no read-time derivation.** The repository does not call `sweep(Clock.System.now())` at construction. The live seeds are dated May 2026; a construction-time sweep with real `now` would silently auto-archive them once wall-clock crossed +30 days, breaking the seed-count tests (`Discussions=2`, `Archived=1`) within days. Caller-supplied reference time keeps every existing test stable forever. See **Lessons learned**.
- No UI change — no screen consumes `sweep` yet (the live trigger is the deferred Phase-4 slice). `observeConversations` already renders the `Archived` filter unchanged.

## Patterns established

- **Pure predicate + caller-supplied reference time is the testability seam for any time-dependent rule.** `referenceTime: Instant` *is* the injection point — no `Clock` interface, no fake clock, no scheduler. This is the same shape `RelativeTime.kt` already uses (`now: Instant = Clock.System.now()` defaulted at the call boundary) and the same shape as the Go `ShouldArchive(c, now)`. Any future time-dependent data-layer rule (idle-evict, retention, sleeping-derivation) should follow this: keep the clock read at the *call* boundary, take the instant as a parameter in the rule, and the boundary tests assert with literal `Instant`s.
- **A fake-only primitive belongs on the concrete impl, not the interface, when its real-backend analog is autonomous.** `sweep` is the client-side test handle for a policy the real backend will run server-side. Putting it on `ConversationRepository` would force a meaningless override on the Phase-4 remote impl and cascade `TODO("not used")` stubs across the anonymous test fakes. The rule generalises: if a method only makes sense for the in-memory fake (because the remote does the same thing autonomously), keep it off the shared contract. Contrast #209/#210/#218, which *did* widen the interface — those are operations a consumer genuinely invokes against either impl.
- **Auto-archive converges on the existing `archived` flag, not a parallel "hidden" path.** `sweep` flips the same bit manual `archive()` flips, so auto-archived discussions are reachable under `Archived` + `All` and stay `unarchive()`-able — exactly the issue body's requirement. The restorability test (`sweep` then `unarchive`) is the convergence proof. Reuses the #93 machinery wholesale; adds no new observable state.

## Lessons learned

- **`MutableStateFlow.update { }` runs its lambda in a compare-and-set retry loop — any counter captured across it must be reset at the top of the lambda, not initialised once outside.** `sweep` returns the count newly archived via a captured `var newlyArchived`. Under contention `update` may re-invoke the lambda; if the counter were only zeroed once (before `update`), a retry would double-count. The fix is `newlyArchived = 0` as the **first statement inside** the lambda, so the final successful application's count is the one returned. This is a general hazard for any `state.update { }` that needs to report "how many records changed" — the loop body must be idempotent in its side effects, including counters. (Flagged by the spec, verified clean in code review.)
- **A construction-time `sweep(Clock.System.now())` would have been a latent time-bomb against fixed-date seeds.** The seed discussions carry literal May-2026 `lastUsedAt` values. Sweeping at construction with the real clock would archive them the moment wall-clock crossed their +30-day mark, silently flipping `Discussions=2 → 0` and breaking the seed-count tests on a calendar date with no code change. The general lesson: never apply a wall-clock-dependent transform to fixed-timestamp fixtures at load time — keep the time a parameter so fixtures stay deterministic, and defer the live-clock trigger to where the data is also live (Phase 4 backend).
- **Read-time derivation of `archived` was considered and rejected because it defeats `unarchive()`.** Deriving archived-ness inside `observeConversations` (without mutating the stored flag) would re-derive an idle discussion as archived on the very next read, so the user could never restore it. Flipping the stored flag preserves restorability. General rule: derive a flag at the projection seam only when it has no independent lifecycle (like `isSleeping`, #20); store it when a user action must be able to override it (like `archived`).

## Open question carried forward (not a bug)

- **Re-archive after `unarchive`, on a later sweep.** Because `sweep` reads `lastUsedAt` (not "was-manually-restored"), unarchiving an idle discussion and then sweeping again with a still-future reference time will re-archive it. Correct per the predicate's definition and harmless in Phase 1 (no automatic re-trigger exists yet). A "respect manual unarchive" carve-out (bump `lastUsedAt` on unarchive, or a sticky flag) is a Phase-4 concern for when a live scheduler exists. Flagged in the spec so review didn't mistake it for a bug.
