# #352 — stable `ConversationRepository` facade across relay connection churn

Builds the **stable indirection** ViewModels hold so relay connection churn never invalidates an
injected repository. [`StableConversationRepository`](../features/stable-conversation-repository.md) is
one process-lifetime singleton whose object identity never changes; it delegates every call to whichever
connection-scoped [`RemoteConversationRepository`](../features/remote-conversation-repository.md) #351's
[coordinator](../features/relay-repository-coordinator.md) publishes on `currentRepository`, switching
transparently as connections come and go, and exposes a defined non-crashing surface while no connection
is live.

This is a **consumer slice**, not a behaviour slice: it adds no wire types, no payloads, and changes
nothing in the coordinator, pump, or repository. It registers the facade as its own resolvable DI type
but does **not** bind it as the `ConversationRepository` default — the Fake stays bound; the flag-gated
Fake↔Remote swap is #350 (already `blockedBy` this slice).

See the feature doc [`stable-conversation-repository.md`](../features/stable-conversation-repository.md)
for the evergreen reference; this file is the implementation record.

## Design — two delegation shapes

The facade's only constructor dependency is the observable, injected at the interface type (not the
concrete remote type), mirroring how the coordinator itself takes `connections: StateFlow<RelayTransport?>`:

```kotlin
class StableConversationRepository(
    private val currentRepository: StateFlow<ConversationRepository?>,  // = coordinator.currentRepository
) : ConversationRepository
```

It overrides **all 14** interface members (including the 3 that ship a default body — `delete`,
`recentWorkspaces`, `createWorkspaceFolder` — so nothing silently falls back to a default), splitting
into two shapes:

1. **Cold reads** (`observeConversations`, `observeMessages`, `observeLastMessage`, `recentWorkspaces`)
   share one private `switchToLive(whenAbsent, select)` helper that does
   `currentRepository.flatMapLatest { repo -> repo?.let(select) ?: flowOf(whenAbsent) }`. A new value
   cancels the prior inner flow and subscribes the new one — so a reconnect drops the previous
   connection's projection (AC #2) and a `null` falls back to the empty projection (`emptyList()` /
   `null`), resuming on the next connection (AC #3).
2. **One-shots** (the 10 suspend methods) read a `private val live get() = currentRepository.value ?:
   throw IllegalStateException(NOT_CONNECTED)` and delegate as one-line `= live.<method>(args)`. With no
   connection live they throw; the snapshot is taken once at entry (a drop *after* the snapshot is the
   delegate's problem — it throws on its own not-`Open` send).

## Patterns established

- **Stable-facade-over-a-churning-delegate.** The reusable shape for "one stable reference over a
  per-connection delegate that is rebuilt on reconnect and absent between connections": cold reads
  `flatMapLatest` over the published `StateFlow<T?>` with a defined empty fallback (`flowOf(whenAbsent)`
  on `null`); one-shots snapshot `.value` once and delegate-or-throw. The facade owns no scope, launches
  no coroutine, and stores no mutable state beyond the injected flow — a pure transformer. Pairs with the
  [per-connection coordinator idiom](../features/relay-repository-coordinator.md) #351 established (which
  *produces* the churning `StateFlow<R?>` this facade *consumes*).
- **Match the delegate's failure type at the facade boundary.** The not-connected outcome is
  `IllegalStateException`, chosen specifically to equal the type `RemoteConversationRepository.sendAndAwaitReply`
  throws on a not-`Open` pump (`RemoteConversationRepository.kt:262`). A caller therefore catches **one**
  type whether the connection was absent at call time (facade throws) or dropped between the call and the
  send (delegate throws). When a facade fronts a delegate that can fail the same way, reuse the delegate's
  exception type rather than minting a new one — it keeps the caller's `catch` single-typed. Stays inside
  the existing "[failures throw, not `Result`-wrap](../features/conversation-repository.md)" convention.
- **`flatMapLatest` cancel-old-on-switch *is* the cross-connection isolation guarantee.** The security
  property (a reader never observes a previous connection's data after a reconnect) is bought by the
  switch operator's semantics + #351's distinct-repo-per-connection — not by any extra bookkeeping. The
  intervening `null` the coordinator publishes is belt; the switch is the load-bearing suspenders.
- **Register-now-bind-later for a DI swap.** Registering the facade as its own resolvable type *without*
  `bind`ing the interface lets a later slice (#350) flip the default with a one-line `bind` + ViewModel
  rewiring, keeping each slice small and the risky binding flip isolated.

## Lessons learned

- **Object-identity assertions on a test-local `val` are tautological.** The AC #1 "stable reference"
  test asserts `assertSame(ref, facade)` where `ref = facade` two lines above — it can never fail, as
  the code review flagged (NIT, no change required). The *meaningful* AC #1 evidence in the same test is
  the routing assertion below it: `sendMessage` lands on `repoA` then `repoB` across churn **while the
  same facade object is reused**, which actually exercises the indirection. When testing "the reference
  is stable across churn", assert the *behaviour through* the stable reference (one-shots routing to
  successive delegates), not the object identity of a local you just assigned. The tautological assert is
  harmless documentation; the routing assert is the test.
- **A hand fake must reproduce the real delegate's *cold, empty-until-snapshot* read shape, or the
  isolation test passes vacuously.** `RecordingConversationRepository.observeConversations` returns
  `conversations.filterNotNull()` over a `null`-initialised `MutableStateFlow` — so a fresh fake "repoB"
  emits **nothing** until the test pushes a snapshot, exactly like the real repo's
  `projection.filterNotNull()`. This is what makes the reconnect test meaningful: after the switch to a
  not-yet-emitted repoB, the facade shows the empty projection (from the `null`→`flowOf(emptyList())`
  fallback), and the assertion that repoA's `[a]` never reappears is a real test of the switch, not an
  artifact of an eagerly-emitting fake.
