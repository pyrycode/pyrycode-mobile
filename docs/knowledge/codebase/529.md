# #529 — A documented pre-ship gate command for the mobile real-claude e2e

Turns #527's `LIVE=1 scripts/e2e-emulator.sh` env-var invocation into one memorable command and names
it a gate an operator is actually told to run. Both blockers (pyrycode#854, #527) had been closed for
two weeks with the shipped real-claude tests sitting unrun, because nothing named the path a gate — the
docs framed rung 3 as running "rarely." XS, not security-sensitive, no Figma (shell entry point + docs).

## Files touched

- **`scripts/e2e-preship-gate.sh`** (new, `0755`) — ~10-line wrapper. Sets nothing but `LIVE=1`, resolves
  its sibling via `BASH_SOURCE` (works regardless of caller CWD), and `exec`s
  `scripts/e2e-emulator.sh`. `exec` (not a plain call) so the harness's own `EXIT`/`INT`/`TERM` teardown
  trap and exit code propagate with no forwarding boilerplate. Deliberately bakes in **only** `LIVE=1` —
  the `e2e-live` `PAIR_NAME`/`PYRY_NAME` isolation is already the `LIVE=1` default inside
  `e2e-emulator.sh:99-104`, so re-setting it here would duplicate a default and risk drift. No new
  guard: the `LIVE`/`DETERMINISTIC` mutual-exclusion preflight stays owned by `e2e-emulator.sh`. Operator
  env overrides (e.g. `LIVE_RELAY_HOST=…`) flow through the `exec` untouched.
- **`README.md`** — new `## Pre-ship gate` section (between `## Build` and `## License`, anchor
  `#pre-ship-gate`): names the command, the two run triggers (before installing a new APK; on any
  daemon/relay change touching the mobile surface, alongside the daemon's `make e2e-realclaude`), and
  the cost (one real claude turn, a few minutes of wall clock, subscription-covered — no tokens
  metered). Links to the e2e doc's mechanics section.
- **`docs/e2e-interactive-stream.md`** — new `## Pre-ship gate` section inserted immediately **before**
  the existing `## Live mode (rung 3, live relay)` section (own anchor `#pre-ship-gate`; the existing
  `#live-mode-rung-3-live-relay` anchor is untouched — it's referenced from the ladder, Verification
  status, and an `e2e-emulator.sh` comment). Same command/triggers/cost as the README, cross-linking
  back to it and to the Live-mode mechanics section. Also appends "a few minutes of wall clock" to the
  pre-existing Live-mode cost line (`:238`, was line 209 pre-insertion) so the two cost statements can't
  contradict.

**Not touched:** the wrapped harness (`e2e-emulator.sh` itself), any Kotlin, any test scenario. No
`.github/workflows/` file added — org policy has no CI; the gate is operator-run only.

## Patterns established

- **Named wrapper script over a positional-argument convention, for a `make`-target-shaped need.**
  `e2e-emulator.sh` dispatches modes purely by env var (`LIVE`, `DETERMINISTIC`, `SCENARIO`); rather than
  add a clashing positional-argument convention on top, this ticket adds a separate, self-locating
  script whose *name* is the memorable command. This is the same shape the daemon uses for
  `make e2e-realclaude` and desktop uses for its own gate wiring — when a repo has no `Makefile`, a thin
  named `scripts/*.sh` wrapper is the substitute target.
- **Command-plus-its-documentation is one deliverable when there's no cross-module seam.** The ticket
  and spec both call this out explicitly: a command nobody is told to run recreates the "nothing names
  it a gate" problem, and a doc pointing at a non-existent command is dead prose. Don't split a
  single-developer, single-PR shell+docs change into a wrapper ticket and a docs ticket.
- **Anti-drift for a command string duplicated by requirement (not by accident):** when an AC requires
  the same literal to appear in more than one doc, contain drift with (a) one canonical string checked
  by grep before commit, (b) mutual cross-links between the duplicating sections, and (c) mechanics
  (URLs, isolation, prerequisites) single-sourced in exactly one place that both link to rather than
  restate.

## Lessons learned

None — the spec's contract (bake in `LIVE=1` only, `exec` not call, `BASH_SOURCE`-resolve the sibling,
no new guard) was followed exactly and code review passed with no findings. The static-verify acceptance
surface (`bash -n`, `shellcheck`, grep for the canonical string, anchor resolution) is inherently
operator-gated for a live run, same as #527 — nothing new to learn about that boundary here.
