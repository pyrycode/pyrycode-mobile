# #272 — Phase 4 networking + crypto dependency substrate

Provisions the three dependencies the rest of the Phase 4 blocking spine consumes — it is the **root** of that spine. Config-only (version-catalog entries + one plugin + dependency lines) plus a single runtime smoke test; **no production networking/crypto/serialization code lands here**. The follow-ups consume it: [#273](https://github.com/pyrycode/pyrycode-mobile/issues/273) (wire models) needs the serialization plugin + `kotlinx-serialization-json` runtime; [#274](https://github.com/pyrycode/pyrycode-mobile/issues/274) (device keypair / Noise session) needs `noise-java` on the classpath. PO sized this S; architect overrode to XS. `security-sensitive` ticket — the supply-chain posture for the crypto lib is the central decision (see [ADR 0004](../decisions/0004-vendor-noise-java-crypto.md)).

## Summary

Three independent provisions, verified by one build (`assembleDebug`) + one gate (`check` = unit tests + lint + `spotlessCheck`) + one runtime smoke test:

1. **WebSocket engine — OkHttp 4.12.0** (`com.squareup.okhttp3:okhttp`). Catalog `[versions]` + `[libraries]` entry + `implementation(libs.okhttp)`. Resolves from the existing `mavenCentral()` — no new repository. Chosen over Ktor (the `CLAUDE.md`-documented intent) because it's the spike-proven engine; see [ADR 0005](../decisions/0005-okhttp-websocket-engine.md). Intentionally **unreferenced by production code** this ticket — `assembleDebug` resolving it is the verification.
2. **JSON serialization — kotlinx-serialization** (plugin + runtime, project style). Both halves: the `org.jetbrains.kotlin.plugin.serialization` compiler plugin (catalog `[plugins]` alias `kotlin-serialization`, `version.ref = "kotlin"` — tracks Kotlin 2.2.10, identical to how `kotlin-compose` is declared) **and** the `kotlinx-serialization-json` 1.8.1 runtime. The plugin is applied in the module `plugins {}` block alongside `alias(libs.plugins.kotlin.compose)`.
3. **Crypto — `noise-java`, vendored** (`com.southernstorm.noise`, rweather/noise-java @ `49377b6`, MIT). 29 `.java` files copied **verbatim** into `app/src/main/java/com/southernstorm/noise/`, package unchanged, no `implementation` line (in-tree source, not an artifact). Pure Java; ships its own ChaCha20-Poly1305 + BLAKE2s + Curve25519 (no JCE provider, no BouncyCastle). Vendored rather than pulled from JitPack — keeps `settings.gradle.kts` on `google()` + `mavenCentral()` with `FAIL_ON_PROJECT_REPOS` intact. Full rationale + trust-boundary analysis in [ADR 0004](../decisions/0004-vendor-noise-java-crypto.md).

The smoke test (`NoiseSuiteSmokeTest`) proves the provisioned substrate is **real at runtime**, not merely resolved on the classpath:
- `noiseIkSuiteLoads()` (AC #5) — constructs `HandshakeState("Noise_IK_25519_ChaChaPoly_BLAKE2s", HandshakeState.INITIATOR)` and `destroy()`s it in `finally` (it is `Destroyable` — wipes key material so it can't leak across tests). A missing primitive or unparseable suite string would surface as `NoSuchAlgorithmException` from the constructor → test fails. Mirrors the proven `noise-spike Main.kt:73`.
- `serializationPluginIsWired()` — a `@Serializable private data class Probe(val x: Int)` round-trip through `Json.encodeToString` / `decodeFromString`. **Fails to compile** if the serialization plugin is on the classpath but not actually *applied* (the one AGP-9 built-in-Kotlin integration unknown), turning a silent #273 surprise into a hard signal now.

## Patterns established

- **Vendoring a small, dependency-free, `security-sensitive` library as in-tree source — verbatim, with a `VENDOR.txt` provenance record — is the codebase's supply-chain posture, distinct from the Maven Central three-line wire-up of [ADR 0001](../decisions/0001-kotlinx-datetime-for-data-layer.md)/[0002](../decisions/0002-markdown-renderer-library.md)/[0003](../decisions/0003-syntax-highlighter-library.md).** The pin *is* the content (immutable, reviewable in the PR diff); update = re-vendor + bump the `Commit:` line, never hand-edit. See [ADR 0004](../decisions/0004-vendor-noise-java-crypto.md). Repository policy (`google()` + `mavenCentral()`, `FAIL_ON_PROJECT_REPOS`) is sacrosanct — prefer vendoring over widening `dependencyResolutionManagement`.
- **Lint carve-outs for vendored source go in `app/lint.xml`, scoped per-issue-id + per-path** (`<issue id="X"><ignore path="…/southernstorm/noise/**" /></issue>`) — never lower `abortOnError`, never edit the vendored bytes. lint.xml ignores are per-issue-id (no wildcard id), so a future re-vendor that trips a new error id adds another scoped entry.
- **Provisioning an unproven build seam? Prove it with a test that fails *now*, not downstream.** The `serializationPluginIsWired()` `@Serializable` round-trip is a deterministic probe of the AGP-9 built-in-Kotlin + serialization-plugin application seam — "on the classpath" ≠ "actually applied". This is belt-and-suspenders done right: a stochastic worry ("will the plugin apply under AGP-9?") backed by deterministic code (a compile-or-fail round-trip in the test set), not by another advisory note.
- **The serialization compiler-plugin alias tracks `version.ref = "kotlin"`**, identical to `kotlin-compose` — KGP compiler plugins layer on AGP-9's built-in Kotlin via the module `plugins {}` block (there is no `kotlin-android` plugin in this project). Runtime artifact version (`kotlinxSerialization = 1.8.1`) is **independent** of the plugin version.
- **OkHttp, not Ktor, is the Phase 4 WS engine** (refines the `CLAUDE.md` "Ktor (networking, Phase 4+)" line) — [ADR 0005](../decisions/0005-okhttp-websocket-engine.md).

## Lessons learned

Lifted from the PR's *Lessons learned* section:

- **The AGP-9 built-in-Kotlin + `kotlin.plugin.serialization` seam works.** Applying the plugin in the module `plugins {}` block (alongside `kotlin.compose`) processes `@Serializable` in **both** `main` and `test` source sets. The `serializationPluginIsWired()` probe (a `@Serializable` round-trip in the test set) is what proves "applied", not just "on the classpath" — this was the one genuine integration unknown and it is now closed for #273.
- **kotlinx-serialization-json `1.8.1` pairs cleanly with the Kotlin 2.2.10 compiler plugin — no version skew.** (A skew would have failed `check` immediately with a kotlinx-serialization version-incompatibility message; the gate is the deterministic oracle, so no external version lookup was needed up front.)
- **Vendored upstream Java trips Android Lint `SuspiciousIndentation`** — caused by upstream's brace-less multi-line `if` guards. Scoped out per-issue-id to the vendored path via `app/lint.xml`; `abortOnError` stays on and upstream bytes stay verbatim. (This is exactly the spec's § Lint fallback — it suppresses a *style* check on vendored code, not a security check, and the code-review security gate confirmed as much.)
- **Recorded for #274 / WS-transport (R8):** `noise-java`'s `Noise.java` has a single reflective call — `Class.forName("javax.crypto.AEADBadTagException")` on the bad-tag decrypt path — but `AEADBadTagException` is a framework class (`android.jar` since API 19), not strippable, so it needs **no** keep rule. It is also not exercised by `HandshakeState` construction, so it is irrelevant to this ticket's smoke test.
