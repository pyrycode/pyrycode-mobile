# #306 — relay WS transport: `/v1/client` dial + bare `InnerFrameV2` frame I/O

The **single-connection relay WebSocket transport** for Phase 4: the OkHttp-backed leg that dials the paired relay's `/v1/client` endpoint and carries bare [`InnerFrameV2`](273.md) JSON **text** frames in both directions. It is the wire under the [Noise_IK session](298.md) — but it is **transport-only and content-blind**: it (de)serializes `InnerFrameV2` ↔ JSON text via [`MobileJson`](273.md) and never inspects a frame's `data` (Noise ciphertext, authenticated one layer up). One `connect()` = one socket; **no reconnect, no Noise, no Koin binding**. Split from #301; sits on the OkHttp engine ([ADR 0005](../decisions/0005-okhttp-websocket-engine.md)). `security-sensitive` — the asset is the phone↔relay channel (the relay is untrusted by design).

See the feature doc [`relay-ws-transport.md`](../features/relay-ws-transport.md) for the evergreen "how the transport works / what plugs into it" reference. This file is the implementation record.

**No new ADR** — this ticket consumes [ADR 0005](../decisions/0005-okhttp-websocket-engine.md) (OkHttp as the WS engine, which named this ticket as the first production reference) and aligns with pyrycode-side ADR 024 (relay is untrusted; E2E auth is Noise). The contract/security choices are captured below + in the feature doc.

## Scope

**The transport surface only — `InnerFrameV2` in/out over one socket.** Out of scope, by design and named in the spec:

- **Noise** (handshake / AEAD / encrypted `hello`) — [#298](298.md)/[#303](303.md). This transport never decodes `data`.
- **Reconnect / backoff / the live `ConnectionStateSource` swap** — the sibling supervisor (a separate child split from #301, **blocked-by** this). This transport is a single dial that surfaces raw `Up`/`Down` events for the supervisor to drive a loop on top.
- **The Noise-bytes → `InnerFrameV2(type, base64(bytes))` wrapping** — the future WS pump that bridges the Noise session to this transport. `send()` takes an **already-built** `InnerFrameV2`.
- **DI wiring** — ships **dormant** (same pattern as [`PairedServerStore`](294.md)/[`NoiseSessionFactory`](298.md)): no `AppModule` change, `FakeConnectionStateSource` stays bound. The supervisor ticket binds the singleton client + transport.

## Summary

**Two new production files** (`RelayTransport.kt` interface + event, `OkHttpRelayTransport.kt` impl) verified by **one new JVM test file** (`OkHttpRelayTransportTest.kt`, 13 `@Test`) driven against an in-process `MockWebServer` WS upgrade. **Purely additive: all-new code, no consumers, zero edit fan-out, no DI binding.** One new `testImplementation`-only dependency (`mockwebserver`), version-shared with the existing `okhttp` — no new production dep, no new version key.

The load-bearing facts, all test-pinned:

1. **Dials `/v1/client` verbatim.** The path is appended as a literal on the URL **string** (`base.trimEnd('/') + "/v1/client"`) passed to `Request.Builder().url(string)`, so the slash is **never** percent-encoded — `addPathSegment("v1/client")` would emit `%2F`. Scheme is converted for OkHttp's `HttpUrl` (which rejects `ws`/`wss`): `wss://`→`https://`, `ws://`→`http://` via `replaceFirst` (the spike idiom), leaving `http`/`https` as-is so a `ws://localhost` test and a `wss://…` production URL both work. **Never `/v2/client`** — the relay serves `/v1/*` only; `v2` is the inner-frame `"v":2`.
2. **Headers from `PairedServer` + `NoiseClientInfo`** (`OkHttpRelayTransport.kt:91-110`): `X-Pyrycode-Server` (= `serverId`, always), `X-Pyrycode-Token` (= `token`, always; relay **ignores** the value under v2 — the real token rides in #298's encrypted hello), `User-Agent` (= `clientInfo.clientVersion`, always), and `X-Pyrycode-Device-Name` (= `clientInfo.deviceName`) **only when `isNotBlank()`** — omitted for empty **and** whitespace-only. `deviceName` is `NoiseClientInfo`'s (from `Build.MODEL`), **not** `PairedServer`'s (which has no such field); `Build.MODEL` is non-nullable, so "available" = non-blank, not non-null.
3. **Single-use lifecycle.** `NEW ─connect()→ DIALING ─Up→ UP ─Down→ terminal`. A second `connect()` throws `IllegalStateException` (caller bug); after the **single** terminal `Down`, `inbound`/`events` complete and the instance is spent — a supervisor discards it and builds a fresh one to reconnect (Noise ephemerals are per-handshake; no resumable state). This keeps the reconnect state machine **out** of this ticket.
4. **`Down` enriches the ticket's `Down(cause)` with `code` + `reason`** (`RelayTransport.kt:76`). `code` is the WS close code (`1000`, `4401`, …) or the HTTP status on a rejected upgrade; `null` on a dial failure / local-violation close / malformed stored data. This is a deliberate stable contract choice (not scope creep): the sibling supervisor and #308 (relay auth-gate) need to distinguish a `4401` reject (→ re-pair, stop retrying) from a network blip (→ backoff retry). OkHttp already hands these to `onClosed`/`onFailure`.
5. **Deterministic inbound backpressure, never a silent drop.** `inbound` is `Channel<InnerFrameV2>(BUFFERED)` fed by `trySendBlocking` — when the buffer fills it **blocks the OkHttp reader thread** → TCP flow-control, so a frame is never dropped (a drop would break the upstream Noise nonce sequence). On `Down` the channels `close()`, draining buffered frames to the consumer before the Flow completes (no truncation).
6. **Bad data → `Down`; caller bugs → throw.** A malformed `relayUrl` (or a header value with illegal CR/LF — a hostile QR-sourced `serverId`/`token` cannot inject a header) is caught in `connect()` and surfaced as `Down(cause=IllegalArgumentException)` so the supervisor handles **all** failures uniformly via `events` — it does **not** throw. Only wrong-*order* calls (`connect()` twice) throw.
7. **Untrusted-relay defence at `onMessage`** (the single trust crossing): a post-receive size guard (`MAX_INBOUND_FRAME_CHARS = 131_072`), then `MobileJson.decodeFromString<InnerFrameV2>`. A malformed JSON, an oversized frame, or an unexpected binary frame is a protocol violation → local `close()` (`1002`/`1009`/`1003`) + a single terminal `Down` (the ordered encrypted stream can't skip a frame, so it tears down rather than drops; the supervisor reconnects with a fresh handshake). `data` is passed through **opaquely** — never base64-decoded.

## Patterns established

- **Single-use transport instance is the reconnect-state-machine boundary.** One `connect()` = one socket, terminal on the first `Down`; the transport holds **no** reconnect/backoff logic. The supervisor reconnects by **discarding the spent instance and constructing a fresh one** — which is correct precisely because Noise ephemerals are per-handshake (there is no resumable transport state to carry across). Reach for "spent-and-discarded, not reset-and-reused" when the layer above already rebuilds all per-connection state on reconnect; it keeps the lower layer a pure single-shot and pushes the state machine to exactly one place.
- **Enrich a minimal event with the fields downstream provably needs, once, rather than force a later breaking change.** The ticket asked for `Down(cause)`; the spec shipped `Down(code, reason, cause)` because the sibling supervisor and #308 *must* tell a `4401` auth-reject (→ re-pair) from a network blip (→ retry), and OkHttp already hands the code over. Still one event type — minimal. Adding the field now (when the consumers are named) beats a breaking widen later. (Contrast #298's deferred `NoiseSession` interface: there, no consumer existed yet, so no seam was added — evidence-based. Here, three named consumers justify the field now.)
- **`Channel.receiveAsFlow()` (not `SharedFlow`) for a single-consumer transport stream, with `trySendBlocking` backpressure.** A transport stream wants exactly **one** logical consumer (the Noise pump for `inbound`, the supervisor for `events`), buffered so an early `Up` can't be missed, with clean completion on `Down`. `trySendBlocking` on the inbound channel blocks the OkHttp reader thread when full → TCP flow-control → **no silent drop** (a drop breaks the upstream Noise nonce sequence — the determinism here is load-bearing, not incidental). No fan-out is wanted, so `SharedFlow`'s replay/multicast machinery would be wrong.
- **Bad *data* surfaces as a uniform `Down`; bad *call order* throws.** Malformed stored `relayUrl`, header-injection attempts, dial/TLS/JSON/size failures all reach the supervisor as `Down` on `events` (one code path to handle); only caller bugs (`connect()` twice) throw `IllegalStateException`. This split — "external/stored failures are events, programmer errors are exceptions" — mirrors #298's wrong-order guards and lets the supervisor own a single failure funnel.
- **Co-locate security-load-bearing client config in a unit-asserted `defaultClient()` here, even though the singleton binding is the next ticket's.** `defaultClient()` pins: `connectTimeout`/`writeTimeout` = 15s; `pingInterval` = 20s (the WS liveness mechanism); **`readTimeout`/`callTimeout` = 0** deliberately (a non-zero value would kill a healthy idle/long-lived WS — both are WS footguns; `pingInterval` provides liveness instead); `connectionSpecs = [MODERN_TLS, CLEARTEXT]` (TLS 1.2+ for `wss://`, `CLEARTEXT` for `ws://` dev relays, legacy `COMPATIBLE_TLS` dropped); and **no `HttpLoggingInterceptor`** (it would dump the `X-Pyrycode-Token` header). Keeping this *here* makes it reviewable + unit-testable in the same ticket as the dial it secures, rather than deferring to the unwritten DI ticket. The supervisor binds **one** app-wide client from it and passes it in — a fresh `OkHttpClient` per reconnect would leak thread pools.
- **The dial seam is the `WebSocket.Factory` constructor param.** Production passes the shared `OkHttpClient`; tests pass a plain `OkHttpClient()` driving `MockWebServer` in-process through the identical `newWebSocket(request, listener)` call — no production/test branching inside the transport.

## Lessons learned

Lifted from the PR's *Lessons learned* sections (initial PR + rework comment):

- **Kotlin block comments *nest* (unlike Java) — a `/*` lexeme inside KDoc/comment prose silently opens a nested comment that never balances and swallows the rest of the file.** Here a literal `` `/v1/*` `` in a KDoc on `buildRequest()` opened a nested comment, truncating the parse → the whole `assembleDebug` failed with an unresolved-reference cascade (`buildRequest`/`terminate`/`Listener`/`WS_NORMAL_CLOSURE`), a phantom "missing `}`", and "unclosed comment" at EOF. **Avoid the `/*` and `*/` lexemes in comment prose** (reword to drop the slash-star). This is a compile-breaker that looks like a dozen unrelated reference errors.
- **`MockWebServer` + WebSocket teardown: a server-side listener MUST echo the peer's close** (`onClosing` → `webSocket.close(code, null)`), or a client-initiated close leaves the server socket half-open in `openClientSockets` and `server.shutdown()` blocks on its drain timeout (~5 s/test: *"Gave up waiting for queue to shut down"*). The fix is a `ClosingServerListener` base that every server-side test listener extends — a reusable harness pattern for any future `MockWebServer` WS test.
- **OkHttp's `WebSocket.close(code, reason)` only permits codes `1000–1003`, `1007–1014`, and `3000–4999`** — `1004–1006`/`1015–2999` throw `IllegalArgumentException` at teardown. The local protocol-violation codes chosen here (`1002` protocol error, `1003` unsupported-data, `1009` message-too-big) are all in-range; a naive `1005`/`1006` would have crashed the teardown path.
- **`./gradlew test --tests <class>` fails with "Unknown command-line option '--tests'"** — the `--tests` filter must target the concrete `testDebugUnitTest` task, not the `test` lifecycle aggregate.
