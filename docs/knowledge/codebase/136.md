# #136 — chore(ui/thread): above-delimiter message opacity treatment

Dims thread rows whose chronological index is strictly before the most recent `ThreadItem.SessionBoundary` to `alpha = 0.55f`, layered on top of [#246](./246.md)'s `state.items.asReversed()` render loop in [`ThreadScreen`](../features/thread-screen.md)'s `LazyColumn`. Presentation-only: no `ThreadUiState`, `ThreadViewModel`, or data-layer change; the cutoff is a pure `indexOfLast { it is SessionBoundary }` against `state.items`, derived inside the composable and `remember`'d against the list reference. The treatment is uniform across user/assistant `MessageBubble`, `ToolCallRow`, and nested `SessionBoundaryDelimiter` rows because the alpha is applied by a parent `Box(Modifier.alpha(...))` wrap around the existing `when (item)` dispatch — none of the row composables hold internal opacity state, so a single render-layer multiplier carries to every child.

## Summary

- **Pure helper `mostRecentSessionBoundaryIndex(items: List<ThreadItem>): Int`.** `internal fun` (not `private`) so `ThreadScreenCutoffTest` under `app/src/test/...` can call it; the file is its only production consumer. Body is the one-line `items.indexOfLast { it is ThreadItem.SessionBoundary }`. Returns `-1` on empty list or no boundaries (per `indexOfLast`'s contract) — the strict `<` comparison at the call site means every row's chronological index `>= 0` is never `< -1`, so AC3 ("zero boundaries → every row full opacity") falls out of the math rather than needing a special case.
- **Cutoff is chronological, not reversed.** `state.items` is chronologically ascending (index 0 = oldest, last index = newest — the invariant pinned by `ConversationRepository.kt:124-152`); the screen renders `state.items.asReversed()` so the newest row anchors to the bottom under `reverseLayout = true`. "Above the most recent boundary" is defined in chronological terms, so the cutoff index is computed against `state.items` (not the reversed view), `remember`'d with `state.items` as the key. Inside the `itemsIndexed(reversedItems) { reversedIndex, item -> }` lambda, the chronological index is reconstructed as `state.items.size - 1 - reversedIndex` before comparison. Each upstream emission produces a new `state.items` reference (the `combine` reducer in `ThreadViewModel` constructs a fresh `ThreadUiState`), so the `remember(state.items) { ... }` key invalidates on every new list — which is the correct invalidation cadence.
- **`items(...)` → `itemsIndexed(...)` migration.** The [#246](./246.md) call shape `items(state.items.asReversed(), key = { item -> ... }) { item -> ... }` becomes `itemsIndexed(reversedItems, key = { _, item -> ... }) { reversedIndex, item -> ... }`. The key function ignores its `Int` first parameter — keys stay identity-based, not position-based (anti-pattern to mix the two). The `reversedIndex` is consumed once to compute `chronologicalIndex`, then dropped. `reversedItems` is hoisted to a `val` outside the `LazyColumn` block (a single `state.items.asReversed()` call shared by both the `items =` arg and the `chronologicalIndex` math) — the stdlib `asReversed()` is an O(1) view, so hoisting doesn't matter for perf but it keeps the two consumers from drifting.
- **Per-row `Box(Modifier.alpha(rowAlpha)) { when (item) { ... } }` wrap.** A single structural `Box` around the existing two-arm `when` dispatch (`MessageItem` → `MessageBubble`, `SessionBoundary` → `SessionBoundaryDelimiter`). `Modifier.alpha(...)` introduces a `graphicsLayer` per dimmed row; acceptable for chat UIs at this scale because `LazyColumn` composes only visible rows. **Render-only effect, not interaction-disabling** — `ToolCallRow`'s `clickable` surface stays expandable when above the cutoff, which matches the user-story intent ("still legible, can scroll up and re-read").
- **`AboveDelimiterAlpha = 0.55f`** — file-private `const val` at the top of `ThreadScreen.kt` (alongside the convention that other components in the same package follow). The user story explicitly cites `0.55f`; the Figma reference uses `0.5f` on each row's `Frame`, and the spec deliberately rounds *up* (not down) to keep above-cutoff text comfortably legible against the M3 dark surface. Named so the (single) production call site and any future "design-token-driven value" swap (the ticket says "or equivalent design-token-driven value") only changes one site. The token system doesn't exist today; the constant is the placeholder.
- **Strict `<` comparison; the boundary itself is full-opacity.** Rows whose chronological index `< cutoffChronologicalIndex` render at `AboveDelimiterAlpha`; rows where the index `>=` the cutoff render at `1f`. The boundary's own chronological index equals the cutoff, so it's excluded from dimming — the latest delimiter is the cutoff *line*, not above it. AC1's "rows at or after that boundary render at full opacity" is the contract this `<` enforces. Older boundaries are themselves dimmed (their chronological index is `<` the latest one's), which is AC5.
- **Second preview seed `previewItemsWithBoundaries(): List<ThreadItem>` with two `SessionBoundary` markers.** Required by AC6. Nine items: two `s0` messages (user + assistant) above an `s0 → s1 BoundaryReason.Clear` delimiter, then three `s1` messages (user + assistant + a `Role.Tool` `ToolCall(toolName = "read_file", input = "kitchenclaw/db/schema.ts", output = "184 lines")`) above an `s1 → s2 BoundaryReason.WorkspaceChange` (`workspaceCwd = "~/Workspace/Projects/KitchenClaw"`), then two `s2` messages full-opacity. Chronologically ascending timestamps via `Instant.parse(...)` literals. Two new `@Preview` composables (`ThreadScreenAboveDelimiterDimLightPreview` + `…DarkPreview`, both `widthDp = 412`) consume the seed and pass `isPromoted = true, displayName = "kitchenclaw refactor"` — same load-bearing preview posture as #246 (`isPromoted = true` suppresses the [`WorkspaceChip`](../features/workspace-chip.md) gate, which would otherwise light because `hasMessages` is a default-`false` raw field on hand-built `ThreadUiState`).
- **Six JUnit 4 unit tests in a new file.** `ThreadScreenCutoffTest.kt` exercises the helper directly: `emptyList → -1`, `messagesOnly → -1`, `singleBoundary → its index`, `multipleBoundaries → latest`, `boundaryAtFirstPosition → 0`, `boundaryAtLastPosition → lastIndex`. Tests use file-private `msg(...)` / `boundary(...)` constructors with `kotlinx.datetime.Instant.parse("…")` literals; no `runTest`, no `Dispatchers.setMain`, no coroutines — the helper is synchronous and pure. The Compose-side rendering correctness (the `Box(Modifier.alpha(...))` wrap, the strict `<` flowing through to actual rendered opacity) is verified visually by the two new `@Preview`s; no `ComposeTestRule` in this ticket because there's no interactive behavior to assert and no scroll behaviour to test.
- **Out of scope: the alpha animation on boundary arrival, `ThreadUiState` widening, role-level dispatch changes, scroll-to-bottom on append, empty-state copy, streaming-typing indicators.** None of the existing ViewModel tests change; no `ThreadUiState` field added; no `MessageBubble` / `ToolCallRow` / `SessionBoundaryDelimiter` internals modified.

## Patterns established

- **Cutoff-style derivations live as `internal` top-level helpers next to the composable, not as private extensions on `List<T>`.** Visibility chosen for testability — `internal fun mostRecentSessionBoundaryIndex(items: List<ThreadItem>): Int` lets the test in the same module call it directly without spinning up a `ComposeTestRule`. The pattern applies to any future "scan-the-list-for-the-last-X" lookup that the screen consumes: write the helper as a pure top-level function, `internal`-visible to the test module, `remember`'d at the call site against the list reference. Cheaper than threading the index through `ThreadUiState` (no new VM surface, no new tests) and cheaper than `derivedStateOf` (which only pays off when multiple recompositions read the same value during one frame).
- **Render-only presentation effects wrap the sealed-row `when (item)` block, not the row composable.** `Box(Modifier.alpha(rowAlpha)) { when (item) { MessageItem → MessageBubble; SessionBoundary → SessionBoundaryDelimiter } }`. The wrap inherits to every row variant uniformly without requiring each row composable to accept an `alpha` parameter or maintain internal opacity state. Apply to future "dim/highlight everything above/below some marker" treatments: keep the effect at the `LazyColumn` body, not at the row composable. The same pattern would work for highlighting an unread cursor, fading streaming-in-progress rows, etc.
- **`itemsIndexed(...)` is the right escape hatch when row-rendering needs the list position, but the `key` lambda still ignores it.** Composite identity stays anchored to the item's own fields (`"msg:${id}"` / `"boundary:${prev}->${new}"` from [#246](./246.md)) — position is only used to derive presentation state inside the lambda body. Mixing the two (position-into-key) is the documented Compose anti-pattern. Apply to any future `LazyColumn` body that needs both stable identity and a positional decision.
- **Per-ticket `previewItemsXxx()` helpers stay file-private and additive.** [#246](./246.md)'s four-item `previewItems()` stays untouched; #136 adds `previewItemsWithBoundaries()` alongside it. A preview's seed is a sample, not a fixture library — different presentation cases get their own seed function rather than parameterising one seed with toggles. Same rule the rest of the package follows.

## Lessons learned

- **`state.items.asReversed()` is referentially stable across the two callsites in this body — but only because the second `state.items` read pins the same list reference.** The screen body has two consumers of the list now: `reversedItems` (for `itemsIndexed`) and `cutoffChronologicalIndex` (for the `remember(state.items)` key + the `mostRecentSessionBoundaryIndex(state.items)` argument). Both read `state.items` directly, not `reversedItems.asReversed()` or a captured local — the `state.items` property is stable within a single recomposition (the `combine` reducer emits one `ThreadUiState` per upstream change, and Compose reads the whole state object at recomposition start). Refactoring this to "hoist `state.items` into a local" would also work but doesn't pay for itself.
- **`Modifier.alpha(...)` doesn't disable clickability — verify before assuming.** `ToolCallRow`'s `Surface` is `clickable`. A naive read of "the row is dimmed" might lead a reader to assume the click is also gated; it isn't. Alpha is render-only in Compose (a `graphicsLayer` multiplier on the `DrawScope`'s `alpha`), pointer-input modifiers run before the draw layer. The user-story intent matches ("still legible, can scroll up and re-read") so no extra interaction-gating is needed. If a future ticket *does* want to gate interaction above the cutoff, the right layering is `Modifier.alpha(...).pointerInput(Unit) {}` (consume gestures) or a conditional `enabled = chronologicalIndex >= cutoffChronologicalIndex` on the inner `Surface` — not stripping the click handler.
- **The Figma source's `opacity: 0.5` is *not* what shipped.** The Figma frame at node `16:8` renders the four above-delimiter rows at `opacity: 0.5` on each row's `Frame`. The user-story copy in the ticket says `alpha = 0.55f` explicitly. The spec deliberately picks `0.55f` (the story value) over `0.5f` (the Figma value) to keep above-cutoff text comfortably legible on the M3 dark surface — the 0.05 delta is small but noticeable on small body-text against `colorScheme.surface`. Future designer-facing "match Figma exactly" reviews should know the story value is canonical for this kind of legibility-sensitive token.
- **The `previewItemsWithBoundaries()` seed has *two* boundaries on purpose.** AC5 is the "older boundaries are themselves dimmed" case — a single-boundary preview can't visually demonstrate it. A reviewer scanning the rendered preview should see the *first* `SessionBoundaryDelimiter` (the `s0 → s1 Clear` one) rendered at `0.55f` alpha, and the *second* (`s1 → s2 WorkspaceChange`) at full opacity. If a future ticket needs to capture a screenshot of "this is what AC5 looks like," it points to this preview, not [#246](./246.md)'s `previewItems()` (which has exactly one boundary and so only exercises AC4).
- **`indexOfLast { … }` returns `-1`, not throws.** The pure helper looks trivial but the `-1` semantics is the load-bearing piece: combined with the strict `<` comparison, it gives AC3 ("zero boundaries → all rows full opacity") for free. A naive replacement like `items.indexOfLast { it is SessionBoundary }.takeIf { it >= 0 } ?: items.size` would also satisfy AC3 but is harder to reason about; the `-1` direct return keeps the test matrix simple (`assertEquals(-1, …)` is the obvious unit-test assertion).
- **No `ComposeTestRule` instrumentation in this ticket — by design.** The render-side correctness (the `Box(Modifier.alpha(...))` wrap actually applies, the strict `<` flows through to per-row opacity) is observable in the Light/Dark `@Preview`s; the cutoff math (the only thing that can produce a wrong result) is covered by six JUnit tests against the pure helper. If a future ticket layers animation on top (e.g. `animateFloatAsState(targetValue = rowAlpha)` for a fade-on-new-boundary effect), that ticket owns its own Compose-side test — the animation is exactly the kind of state that benefits from `ComposeTestRule`'s frame stepping.
