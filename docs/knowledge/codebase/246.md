# #246 — feat(ui/thread): wire ThreadItem stream into ThreadScreen's LazyColumn

Replaces the placeholder `items(emptyList<Unit>()) { }` in [`ThreadScreen`](../features/thread-screen.md)'s `LazyColumn` with a typed iteration over `state.items.asReversed()` that dispatches `ThreadItem.MessageItem` → [`MessageBubble`](../features/message-bubble.md) and `ThreadItem.SessionBoundary` → [`SessionBoundaryDelimiter`](../features/session-boundary-delimiter.md). The data was already collected — [`ThreadViewModel.combine`](../features/thread-screen.md) (since [#137](./137.md)) was binding `items` from `repository.observeMessages(conversationId)` but only deriving `hasMessages: Boolean` from it; this slice exposes the full list on `ThreadUiState` and renders it.

## Summary

- **`ThreadUiState` widened from 6 → 7 fields.** Added `items: List<ThreadItem> = emptyList()` as the final field. Default-valued so the eight pre-#246 `ThreadViewModel(...).state.value` equality assertions in `ThreadViewModelTest` continue to compile and pass — the data-class default propagation extends structural equality with `emptyList()` on both sides. Same widening posture as [#137](./137.md)'s 2 → 6 field expansion.
- **`ThreadViewModel.combine` reducer grows one line.** Inside the existing three-upstream `combine(observeConversations, observeMessages, pendingWorkspacePicker)` block, the `items` parameter (already bound as the second `combine` arg's emission since [#137](./137.md)) is now passed through to the returned `ThreadUiState` as `items = items`. No new flow, no new collection allocation, no new upstream subscription. The `hasMessages = items.any { it is ThreadItem.MessageItem }` line on the previous row stays byte-identical — the list reference flows through unchanged.
- **`LazyColumn` body becomes a typed `items(state.items.asReversed(), key = …) { … }`.** Source-list reversal is required because `observeMessages` returns chronologically ascending (oldest at index 0) but `LazyColumn(reverseLayout = true)` draws the **first** item at the bottom — so for "newest at the bottom" the screen reverses before passing. `state.items.asReversed()` is the Kotlin stdlib O(1) view (no allocation, no copy) and slots into `items(...)` as a `List<ThreadItem>`. The `reverseLayout = true` flag stays untouched.
- **Stable composite keys per `ThreadItem` subtype.** `MessageItem` → `"msg:${item.message.id}"` (the canonical row identity from `FakeConversationRepository.sendMessage` UUID-assignment, surviving all state transitions). `SessionBoundary` → `"boundary:${item.previousSessionId}->${item.newSessionId}"` (each transition is unique by construction: a session can only become `previous` once per stream, and the fake's `buildThreadItems` only emits a boundary when `prior != null && prior != message.sessionId`). The `"msg:"` / `"boundary:"` prefixes namespace the two subtypes so no key collision is possible between a message id and a session id that happen to share a string.
- **Screen treats `MessageItem` as opaque.** The screen-level `when` dispatches only at the `ThreadItem` sealed-interface level; the `Role.User` / `Role.Assistant` / `Role.Tool` dispatch lives inside [`MessageBubble`](../features/message-bubble.md). No role re-dispatch at the screen — `MessageBubble(message = item.message)` is the one-line call.
- **Preview seed introduces a `previewItems(): List<ThreadItem>` file-private helper.** Four chronologically-ordered items: user message ("Can you help me think through the schema migration plan?"), assistant message ("Sure — let me read the existing schema first."), tool call (`read_file` with `kitchenclaw/db/schema.ts` → `184 lines`), and a `SessionBoundary(reason = BoundaryReason.Clear)`. Timestamps via `Instant.parse("2026-05-17T14:32:00Z")` and three offsets at +10s / +20s / +60s. Both `ThreadScreenLightPreview` and `ThreadScreenDarkPreview` now pass `isPromoted = true, items = previewItems()` — `isPromoted = true` suppresses the `WorkspaceChip` (which would otherwise render under `!isPromoted && !hasMessages` since `hasMessages` is a default-`false` raw field on a hand-constructed `ThreadUiState`, not a derived flag).
- **One new test: `state_items_reflectsObserveMessagesStream`.** Boots the VM on `seed-channel-personal` (the seeded fake channel that already carries seeded messages), launches a collector, `advanceUntilIdle()`, and asserts `vm.state.value.items.isNotEmpty()` plus `vm.state.value.items.first() is ThreadItem.MessageItem`. Mirrors the runTest + `UnconfinedTestDispatcher` + collector-cancel shape of `sendMessage_nonBlankText_appendsToConversation` from [#188](./188.md). No Compose-side instrumentation — render correctness is covered by the Light/Dark previews and the AC explicitly defers scroll / interaction tests to downstream tickets.
- **Out of scope: opacity, scroll-to-bottom, empty state, status row, streaming/typing indicators, append animations.** The placeholder render loop is the deliverable; everything else layers additively on top. [#136](https://github.com/pyrycode/pyrycode-mobile/issues/136) (above-delimiter alpha) is `blocked-by` this slice and will compose `Modifier.alpha(0.5f)` against the same `state.items` source.

## Patterns established

- **Sealed-interface dispatch lives at the LazyColumn `when`-arm; sub-dispatch (role → bubble shape) lives one layer deeper in the row composable.** The screen's `when (item)` distinguishes only at the `ThreadItem` level (`MessageItem` vs `SessionBoundary`). The `Role.User` / `Role.Assistant` / `Role.Tool` selection lives inside `MessageBubble.kt:48-57`. Apply to future sealed-row hierarchies: the screen's `LazyColumn` body stays a two- or three-arm `when`; per-row component owns its own internal branching. Avoids forcing every row callsite to re-implement role gating.
- **`List<T>.asReversed()` is the right tool when `reverseLayout = true` meets a chronologically-ascending source.** It's a Kotlin stdlib O(1) view over the underlying list — no allocation, no copy, no observable identity change for `LazyColumn`'s diffing. Pattern: when the data source guarantees ascending order and the layout flag reverses, reverse the source at the `items(...)` boundary rather than reversing the data layer's contract or flipping `reverseLayout`. Stable keys are computed from underlying items, so the view's index is irrelevant for identity.
- **Stable keys on a sealed row hierarchy use a per-subtype string namespace prefix.** `"msg:${id}"` / `"boundary:${prev}->${new}"` rather than collapsing to a bare id. Two `ThreadItem` subtypes today, room for a third tomorrow without key collisions. Same shape applies to any future sealed row family — the prefix is the cheap defence against accidental key reuse across subtypes.
- **Compose preview seed via a file-private `previewItems(): List<T>` helper reused by Light + Dark.** Both previews call the same builder; no duplicated literal blocks. If the seed grows past ~25 lines the architect spec calls for extraction to a sibling `…PreviewData.kt` file, but four items keep it inline. Applies to any preview that needs >2 hand-built rows and a Light/Dark pair.

## Lessons learned

- **`hasMessages: Boolean` is `false` by default on a hand-constructed `ThreadUiState` — even when `items` is populated.** Previews don't go through the VM's `combine` reducer, so the `items.any { it is ThreadItem.MessageItem }` derivation never runs. The four preview items render correctly, but the [`WorkspaceChip`](../features/workspace-chip.md) would *also* render unless suppressed — its visibility gate is `if (!state.isPromoted && !state.hasMessages)` and a hand-rolled `ThreadUiState` with the default `hasMessages = false` and the default `isPromoted = false` lights both clauses. The fix in the preview is `isPromoted = true` (the seed represents a channel anyway). Alternative would have been `hasMessages = true`, but the Figma `16:8` reference is a populated channel thread, and `isPromoted = true` is semantically faithful to the `"kitchenclaw refactor"` name. **Pre-existing landmine** for any future test/preview that hand-builds a `ThreadUiState` with messages: the derived-vs-raw-field divergence means setting one source-of-truth doesn't automatically set the other.
- **`SavedStateHandle(initialState = mapOf("conversationId" to "seed-channel-personal"))` already seeds messages.** The fake's `seedChannel("Personal", id = "seed-channel-personal", …)` constructor populates `currentMessages` with seeded `Message`s (per [#161](./161.md)'s `seedChannel` + `seedDiscussion` shape changes). The new test asserts `items.isNotEmpty()` after `advanceUntilIdle()` because the fake delivers synchronously via `MutableStateFlow.map`; no need to call `sendMessage(...)` to populate.
- **`state.items.asReversed()` reverses each emission, not just once at subscription.** Each upstream emission produces a new `state.items` reference (the `combine` lambda recomputes the `ThreadUiState`); each recomposition pass calls `asReversed()` afresh on the latest list. The view is cheap (no allocation), but if a future Compose perf audit profiles the `LazyColumn` and the reverse view shows up, the right answer is to derive the reversed view in the VM's reducer (`items = items.asReversed()`) rather than caching it at the screen — the screen should stay stateless.
- **The placeholder `items(emptyList<Unit>()) { }` at the LazyColumn body has been the load-bearing "this slot is empty" marker since [#126](./126.md).** Removing it without a typed `items(...)` replacement would have left a bare `LazyColumn { }` which type-checks but raises a "useless content" warning in Compose tooling. The placeholder shape signalled intent (reverse-layout baked in, ready for content) across five tickets (#126, #139, #188, #201, #137) that touched the surrounding `Scaffold` without filling this slot. #246 is the slice where the slot actually gets filled.
- **`kotlinx.datetime.Instant.parse` is the right shape for preview-seed timestamps.** `Instant.parse("2026-05-17T14:32:00Z")` + offset literals is more obvious than `Clock.System.now().plus(...)` (non-deterministic across rebuilds) or `Instant.fromEpochSeconds(...)` (opaque). Used by [#135](./135.md)'s `SessionBoundaryDelimiter` previews — keeping the same shape locally. The `kotlinx-datetime` ADR is [`0001-kotlinx-datetime-for-data-layer.md`](../decisions/0001-kotlinx-datetime-for-data-layer.md).
