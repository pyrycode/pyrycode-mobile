# #351 — connection-scoped coordinator: a Noise pump + remote repository per live relay connection

Stands up the per-connection chain that turns a live relay socket into a working remote conversation
repository. A new [`RelayRepositoryCoordinator`](../features/relay-repository-coordinator.md) observes
[`RelayConnectionSupervisor.currentConnection`](../features/relay-reconnect-supervisor.md) ([#307](307.md))
and, for each live transport, starts a fresh [Noise session pump](../features/noise-session-pump.md)
([#309](309.md)) over it and constructs a [`RemoteConversationRepository`](../features/remote-conversation-repository.md)
([#312](312.md)/[#313](313.md)/[#329](329.md)) against that pump on a connection-scoped child scope. The
live repository — or `null` between connections — is published on `currentRepository`, the seam the
stable-reference facade (#352) consumes. **This is the slice every prior Phase 4 read/mutation slice
deferred to as "the owner (#279/#302)" of the connection scope and the `SessionPump` binding.**

This is a **wiring slice, not a behaviour slice**: it adds no new wire types, no new payloads, and
changes nothing in the pump or repository themselves — it only *owns their lifecycle* across connection
churn. The flag-gated Fake↔Remote swap stays for #350; the stable facade is #352.

See the feature doc [`relay-repository-coordinator.md`](../features/relay-repository-coordinator.md) for
the evergreen reference; this file is the implementation record.

## The two gaps this slice closed

Every prior Phase 4 slice was merged, but nothing stood up the per-connection chain. Two gaps remained,
both this slice's job:

1. **`NoiseSessionPump` did not declare the `SessionPump` contract** the repository consumes — though
   its `inbound`/`send` members already matched structurally. `SessionPump`'s KDoc had explicitly
   deferred this: *"the DI / connection-coordinator slice makes it `: SessionPump` … and provides the
   live binding."*
2. **No code observed `currentConnection`** to build the pump + repository chain and tear it down with
   the connection. The supervisor's KDoc named this seam: *"a layer-up coordinator … hands this
   connection's `inbound` to a fresh pump per connection."*

## Design — the connection→repository state machine

A single, non-suspending `onConnection(transport: RelayTransport?)` per emission, run by one collector:

- **`start()`** (`RelayRepositoryCoordinator.kt:64-67`) launches `connections.collect { onConnection(it) }`
  on the coordinator's own `CoroutineScope(SupervisorJob() + dispatcher)`. Idempotent via
  `AtomicBoolean.compareAndSet` (`:54`, `:65`) — a double registration cannot spawn a second collector
  (= two pumps per connection). Same idiom as the sibling supervisor/pump.
- **`onConnection(transport)`** (`:76-83`): tear down the active connection (always, first); if
  `transport == null` return (the between-connections state); else build a fresh connection —
  `childScope = CoroutineScope(SupervisorJob(job) + dispatcher)`, `pump = createPump(transport).also { it.start() }`,
  retain `(pump, childScope)`, publish `RemoteConversationRepository(pump, childScope)` on `currentRepository`.
- **`teardownActive()`** (`:91-97`): `currentRepository.value = null`, then **cancel the child scope,
  then close the pump** — order matters (see below). Idempotent (no-op with no active connection).
- **`close()`** (`:101-104`): tear down the active connection, then cancel the coordinator scope (ends
  the collector). Idempotent.

## Patterns established

- **Interface Segregation across the pump's two consumers.** `SessionPump` is the *data* view (the
  repository reads `inbound`, calls `send`); `ManagedSessionPump : SessionPump` is the *lifecycle* view
  (the coordinator additionally `start()`s and `close()`s it). The coordinator depends on the richer
  contract and hands the **same instance, upcast to `SessionPump`**, to the repository. This is what
  lets coordinator tests use a ~15-line channel-backed `FakeManagedPump` instead of forcing every
  coordinator test through a full real `Noise_IK` handshake against a `TestResponder`.
- **The per-connection coordinator idiom** (transforms one hot `StateFlow<T?>` into another hot
  `StateFlow<R?>`): own a `SupervisorJob` scope from an injected dispatcher; a single, **non-suspending**
  collector body that tears down the old before building the new; idempotent `start()`/`close()`; the
  per-connection `childScope` is a child of the coordinator job (so it dies on `close()` too) but the
  pump's *own* scope is **not** — it is reached only by `pump.close()`. A reusable shape for any future
  "thing X scoped to live connection Y."
- **`onConnection` must stay non-suspending (a concurrency invariant, documented in-code at `:69-75`).**
  Cooperative cancellation only acts at a suspension point, so a suspension-free build/teardown body is
  handled *atomically* w.r.t. a racing `close()` — closing the one window where a cancellation between
  `pump.start()` and retaining the reference would leak a started-but-unclosed pump. Future edits must
  not introduce a `suspend` call here.
- **Teardown order is load-bearing: cancel the child scope, *then* close the pump** (`:95-96`). The
  child scope stops the repository's inbound collector; the pump's own `SupervisorJob` is **not** a
  child of it, so `pump.close()` is independently required to wipe keys and tear the pump scope down.

## Security invariants (ticket is `security-sensitive`)

The coordinator sits *above* the authenticated Noise channel — it only moves object references
(`RelayTransport` → `ManagedSessionPump` → `RemoteConversationRepository`) and never touches wire bytes.
Two invariants are load-bearing and both are backed by deterministic tests (different fabric from the
stochastic "remember to …" rule):

- **Key-wipe on every pump-reference drop.** Every transition that discards a pump first calls
  `ManagedSessionPump.close()` → `session.close()`, which wipes the transport ciphers + the device-static
  copy. There are exactly **three** such transitions and all three close the pump: (a) a new connection
  replacing an old one, (b) a `null` emission, (c) `close()`. `RelayRepositoryCoordinatorTest` asserts
  `pump.closed == true` after every teardown.
- **No nonce/ephemeral reuse — a fresh single-use pump per live connection.** A `Noise_IK` session's
  ephemeral keys and AEAD nonce counter are *per-handshake*; reusing a session (or its pump) across two
  transports would reuse nonces under one key — a confidentiality break. `createPump` builds a brand-new
  pump per non-null emission, and the pump's `start()` single-use assertion (`NoiseSessionPump.kt:91`,
  `compareAndSet`) makes a spent pump impossible to restart. The reconnect test asserts distinct pump +
  repository instances with **no** projection carryover (`c1` from connection 1 never surfaces on
  connection 2). This is why "no state carryover" is a crypto invariant here, not mere hygiene.
- **The coordinator never collects the transport's single-consumer streams** (`inbound`/`events`) — it
  only hands the `RelayTransport` reference to `createPump`. A stray collection would steal frames from
  the handshake (pump owns `inbound`) or from the supervisor (owns `events`).

**Behavioural consequence (intended, in-scope):** with the coordinator `createdAtStart` and the
supervisor already dialing in a paired+foregrounded app, this slice causes a real `Noise_IK` handshake
to run on each live connection. That is bounded: no `list_conversations`/`backfill_since` is sent until a
subscriber calls a read path (which only #352/#350 wire up), so a live-but-unconsumed pump just completes
the handshake and idles. #350's flag gates what the **UI reads**, not whether the encrypted channel is
established — consistent with [[phase4-no-central-flag-gate-per-piece]] (paired-state gating is automatic:
the supervisor only publishes a transport when paired).

## Lessons learned

- **`dispatcher` had to be a constructor `val`, not the spec's plain param.** The architecture spec's
  snippet showed `dispatcher: CoroutineDispatcher` as a plain (non-stored) parameter, but the
  implementation needs it stored to build a *fresh* per-connection `childScope` on every emission
  (`onConnection` at `:79`). Keeping it `private val` is the correct, minimal deviation — the code
  review explicitly noted this as a *sound* divergence from the spec snippet, not a defect.
- **The pump's own scope is not reachable by cancelling the child scope** — a subtle scope-ownership
  trap. `childScope = CoroutineScope(SupervisorJob(job) + dispatcher)` parents the repository's collector
  under the coordinator job, but `NoiseSessionPump` constructs its *own* `SupervisorJob` scope
  internally; `childScope.cancel()` does not reach it. Hence `pump.close()` is a separate, mandatory
  teardown step — and the security review's "wipe keys on every drop" invariant depends on it being
  called, not on scope cancellation alone.
