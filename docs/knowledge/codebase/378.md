# #378 — Literal-screen snapshot ViewModel + request state

The **state-management half** of the manual "show the literal screen" feature: a thread-scoped ViewModel
that orchestrates one [`ConversationRepository.requestScreenSnapshot`](../features/conversation-repository.md)
read (shipped in [#375](375.md), on `main`) and hoists the result as MVI state. **No Compose, no wire
types, no navigation, no Koin change** — the render surface + thread entry-point action + Koin
registration are the sibling slice **#379** (`blockedBy #378`). Split from #372.

`security-sensitive`: the snapshot `text` is server-originated and may contain sensitive on-screen content,
so it is carried **verbatim** (never parsed/trimmed/sanitized) and **never logged**. See the feature doc
[`literal-screen-viewmodel.md`](../features/literal-screen-viewmodel.md) for the durable state contract.

## Summary

One new production file + one new test file, **two files total** (the spec is the third changed file).
Zero edits to existing production code — every new symbol is additive (`LiteralScreen*`), so there is no
caller blast radius. The VM is the always-available, parser-independent floor of pyrycode ADR 025's
safe-degradation strategy (pyrycode#596), surfaced as `state: StateFlow<LiteralScreenUiState>` +
`onEvent(LiteralScreenEvent)`.

## Patterns established

- **First snapshot *consumer* over the #375 read — and the canonical thread-scoped read-VM shape.** Where
  prior thread VMs project a `Flow` (`ChannelListViewModel`, `ThreadViewModel`), this is a one-shot
  request/result VM: `Request`/`Retry` → cancel-prior-job → `Loading` → `Content`/`Error`. When wrapping a
  one-shot suspend repository read as hoisted MVI state, this is the shape — single `loadJob`,
  latest-request-wins, closed-enum error.
- **A `security-sensitive` content-bearing UiState gets a redacting `toString()`, mirroring
  `ScannerUiState.Decoded`.** The mobile precedent for "a state field may hold sensitive data → override
  `toString` to `<redacted N chars>` (not `equals`/`hashCode`)" now has a second instance
  (`ScannerViewModel` was the first). This is the *deterministic* half of the no-leak guarantee; the
  *stochastic* half is "no `Log.*` in the file." When a new UiState carries server-originated or untrusted
  text, pair both — same fabric won't do (see [pipeline principle: belt-and-suspenders means different
  fabric]).
- **Closed-enum error reason, not the raw exception/message.** `LiteralScreenError` keeps the error state
  free of any server string (no leak through the failure branch) and makes the test matrix exact. The
  three mapped types are genuinely disjoint — `RelayErrorException : Exception` (not `RuntimeException`,
  `MobileWireModels.kt:105`) — so the `reasonFor` `when` ordering cannot mis-classify. User-facing copy is
  deferred to the surface (#379), keeping the data layer of state free of presentation concern.
- **`SavedStateHandle` is read for the route arg only; the sensitive payload never round-trips through it.**
  `conversationId` (non-sensitive) is read; `Content.text` is held only in the in-memory `MutableStateFlow`
  and never written back — saved-state serializes to the disk-backed instance-state bundle. This is the
  concrete "don't persist sensitive screen content across process death" guard; it propagates to #379 as
  "no `rememberSaveable` for the text."

## Lessons learned

The PR ([#380](https://github.com/pyrycode/pyrycode-mobile/pull/380)) carried no *Lessons learned*
section; the non-obvious points worth recording:

- **`catch (CancellationException) { throw e }` must precede the generic `catch (Exception)` — this is the
  load-bearing footgun of the whole slice.** `viewModelScope.launch` jobs are cancelled cooperatively by
  throwing `CancellationException`; because `load()` cancels the prior `loadJob` on every event (and the
  scope cancels on screen exit), a catch-all would swallow that signal and paint a spurious `Error`. The
  re-throw keeps structured cancellation intact. A bare `runCatching` here would be silently wrong. The
  code review verified this ordering explicitly.
- **No dispatcher injection is needed for a VM whose only off-Main work is the suspend repository call.**
  `viewModelScope` runs on `Dispatchers.Main.immediate`; the IO boundary lives inside
  `requestScreenSnapshot` (the repository moves itself off-Main). Tests drive everything with a single
  `StandardTestDispatcher` set as Main — no second dispatcher, no constructor-injected `CoroutineDispatcher`.
  Don't add a dispatcher param to a VM that does no manual thread-hopping.
- **`StandardTestDispatcher` (not `UnconfinedTestDispatcher`) is what makes the `Error → Loading → Content`
  transition observable.** The retry test gates the second read on a `CompletableDeferred`: with the
  *standard* dispatcher, `runCurrent()` after `onEvent(Retry)` lets the relaunch set `Loading` but pauses
  at the suspended `deferred.await()`, so the test can assert `Loading` + `calls == 2`; completing the
  deferred + `advanceUntilIdle()` then drives `Content`. An eager (unconfined) dispatcher would skip past
  the intermediate `Loading` and the assertion would be untestable. (Distinct from the Remote-repo
  `runCurrent`-not-`advanceUntilIdle` rule in [[remote-repo-test-runcurrent-not-advanceuntilidle]] — there
  it's about Channel delivery without timers; here it's about pausing at a real suspension point.)
- **The verbatim invariant is pinned with whitespace + control chars, the redaction with a known secret
  string.** Success-path test value `"  top line\n\tindented body  \n"` makes any accidental
  `trim()`/normalization fail the byte-for-byte equality (the parser-independent floor must be byte-exact —
  same posture as #375's `FAKE_SCREEN_SNAPSHOT_TEXT`). The redaction test asserts
  `Content("super-secret-screen").toString()` neither contains the secret nor omits `"redacted"` — making
  "never logged" a deterministic, observable property rather than an aspiration.

## Verification

- `./gradlew spotlessCheck test lint assembleDebug` — all green (PR body; QA gate `./gradlew check` +
  `assembleDebug` green). `connectedAndroidTest` N/A — pure ViewModel slice, no Compose, no
  `ComposeTestRule`, no device. Run one class with `./gradlew testDebugUnitTest --tests
  "de.pyryco.mobile.ui.conversations.thread.LiteralScreenViewModelTest"` (see [[gradle-single-test-class-task]]).
- Unit tests (8) map to the ACs: initial `Loading` (AC#1), success → `Content` byte-for-byte (AC#2/#4),
  `toString` redaction (AC#4), each of `IllegalArgumentException` / `RelayErrorException` /
  `IllegalStateException` → its `Error` reason (AC#3), `Request` invokes the read with the route id, and the
  real `Error → Loading → Content` retry transition with `calls == 2` (AC#2/#5).
- **Code review: PASS** ([PR #380](https://github.com/pyrycode/pyrycode-mobile/pull/380), no MUST-FIX /
  SHOULD-FIX / NIT). Reviewer confirmed: the `reasonFor` ordering is sound and the three types disjoint
  (`RelayErrorException : Exception`, not a `RuntimeException` subclass); the confidentiality net intact
  (grep-clean of `Log.*`/`println`/`Timber`, redacting `toString` test-pinned, error state carries only the
  enum, only `conversationId` from `SavedStateHandle`); concurrency correct (single `loadJob`,
  `CancellationException` re-thrown first); no `AppModule`/Koin change (correctly deferred to #379); the
  test double stubs all 11 abstract members and overrides only `requestScreenSnapshot`.
- **Security review: PASS** (architect self-review in the spec, label-gated). Confidentiality (not
  integrity) — single trust-boundary crossing, no injection surface, two-layer no-log net, no
  `SavedStateHandle` persistence of the text. Screenshot/screen-recording leakage (`FLAG_SECURE`) is
  out-of-scope here (no window/Compose) → propagated to #379.
