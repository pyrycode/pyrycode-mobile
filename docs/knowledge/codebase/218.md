# #218 — feat(data): `delete()` on `ConversationRepository`

Lands the permanent-delete counterpart to `archive` / `unarchive`: one new `suspend fun delete(conversationId: String)` on the [`ConversationRepository`](../features/conversation-repository.md) interface and a one-line [`FakeConversationRepository`](../features/conversation-repository.md#phase-1-implementation--fakeconversationrepository) override. Tolerant of unknown ids by design — the post-condition ("conversation absent from `observeConversations`") is the only thing callers must reason about. Unblocks the Channel Info sheet's **Delete** action (host ticket deferred from #144); this slice is data-layer-only, no UI touched.

## Summary

- **Interface gained one method with a default implementation:** `suspend fun delete(conversationId: String): Unit = error("delete is not implemented for this ConversationRepository")`. Third member on the interface to ship with a default body, after `recentWorkspaces()` (#209) and `createWorkspaceFolder()` (#210). Same cascade-escape rationale — 11 anonymous `object : ConversationRepository` test fakes across 5 files (`SettingsViewModelTest`, `ArchivedDiscussionsViewModelTest`, `DiscussionListViewModelTest`, `ChannelListViewModelTest`, `ThreadViewModelTest`) inherit the default and don't need stubs.
- **Default body is `error(...)`, not a silent no-op.** Delete is destructive — a test fake that silently no-ops would hide bugs (test wires a fake expecting delete to do something, gets silent success, the test passes vacuously). `error("…")` surfaces accidental invocation loudly. The tolerant "no-op on unknown id" semantic belongs in the concrete `FakeConversationRepository`, not in the interface default. Mirrors the #210 shape (`createWorkspaceFolder` also has no semantically-meaningful zero), not the #209 shape (`recentWorkspaces` returns `flowOf(emptyList())` because an empty stream *is* a valid answer).
- **Deliberate deviation from the "failures throw" convention.** Per [`conversation-repository.md` Conventions](../features/conversation-repository.md#conventions), every other mutator (`archive`, `unarchive`, `rename`, `mintNewSession`, `sendMessage`) throws `IllegalArgumentException` via `unknown(id)` on missing record. `delete` does not. Rationale: delete converges on the *post-condition* — after a successful return, the conversation is not in `observeConversations`. Both an unknown id and a successful delete share that post-condition, so distinguishing them in the contract buys nothing for the caller and adds a try/catch the UI doesn't need. The deviation is documented in the interface KDoc with a contrast line ("Unlike [archive] and [unarchive]…"), not silently encoded.
- **Fake override is one line, leveraging `Map - key` tolerance:**
  ```kotlin
  override suspend fun delete(conversationId: String) {
      state.update { it - conversationId }
  }
  ```
  `Map - missingKey` returns an `equals`-identical map → `MutableStateFlow.update` does not re-emit. Same free idempotency as `archive`'s `record.copy(... archived = true)` shape. No `unknown(id)` throw, no `bumpWorkspace` (delete removes the record; recents are unaffected — same as `archive` / `unarchive`), no `lastUsedAt` bump (lifecycle transition, not usage).
- **Streams re-emit empty, not complete.** Per the AC's architect-resolved question: collectors of `observeMessages(deletedId)` / `observeLastMessage(deletedId)` re-emit `emptyList()` / `null` rather than terminating. This is a property of the existing projection scaffolding (`state.map { records -> records[id] ?: … }`) — no code change required to achieve it; the spec just records the decision. Rationale: a long-lived collector (e.g. a `StateFlow`-backed `UiState` projection in a still-composed ViewModel during a race) that *completed* on delete would silently lose its subscription forever. Re-emit-empty is the safer convergence shape and matches the tolerant unknown-id path `observeMessages` already takes.
- **Five unit tests in `FakeConversationRepositoryTest`** (JUnit 4 + `runBlocking` + `Flow.first()`, matches the file's existing conventions). `delete_removesConversation_from_observeConversations_All` covers AC test 1 (the `none { it.id == created.id }` shape, same as `archive_*`). `delete_onUnknownId_doesNotThrow` is bare-bodied — no try/catch — because for "does not throw" the test passes iff no exception escapes; mirroring `archive_onUnknownId_throws`'s try/catch wrapper would be wrong. `delete_isIdempotent` exercises the `equals`-identical-map free idempotency. `delete_causes_observeMessages_toReEmitEmpty` and `delete_causes_observeLastMessage_toReEmitNull` use the seeded `seed-channel-pyrycode-mobile` (6 messages across 2 sessions) — they anchor the architect-resolved "re-emit empty, don't complete" decision in the test suite; without them the decision is just prose.

## Patterns established

- **Default-body shape `error(...)` extends to mutators with no meaningful zero return.** #209 established that defaults are reserved for the cascade-escape valve and the *form* depends on whether the return type admits a zero. #210 refined: `error(...)` over `NotImplementedError` for the clearer message. This ticket extends the rule once more: even when the return type is `Unit` (no value-zero question), a destructive mutator should `error(...)` rather than silently no-op in the default — silent success in a default body would let tests pass vacuously when they wired an under-stubbed fake expecting the mutator to do something. **Rule for future destructive mutators on this interface:** prefer `error(...)` over a silent no-op default even when `Unit` makes "no-op" syntactically free. Silent success is a worse failure mode than a loud throw.
- **Deviations from the "failures throw" convention must be documented in the interface KDoc, not just the impl.** The Conventions block already says "Unknown `conversationId` throws `IllegalArgumentException` (fake)." `delete` breaks that rule. The interface KDoc carries an explicit contrast line ("Unlike [archive] and [unarchive], which throw `IllegalArgumentException` on unknown ids, `delete` converges on the post-condition…") so a future implementer reading just the interface — no spec, no codebase doc — sees both the deviation and the rationale. **Rule:** when a new method intentionally departs from a documented interface-wide convention, the interface KDoc is the load-bearing place for the explanation. The Conventions block can either gain an exception clause or stay general and let the per-method KDoc carry the deviation.
- **Tests anchoring a spec-resolved open question are mandatory, not optional.** The AC explicitly delegated "complete vs re-emit" to the architect, and the spec chose re-emit. Tests 4-5 (`delete_causes_observeMessages_toReEmitEmpty` / `…_toReEmitNull`) make that decision a property of the test suite, not just spec prose. Without them, a future refactor could collapse the tolerant `records[id] ?: return@map emptyList()` fallback into a `takeWhile { records.containsKey(id) }` and silently regress the long-lived-collector guarantee. **Rule for future architect-resolved open questions:** if the decision is "the existing scaffold already does this, no code change needed," at least one test must assert the property explicitly — otherwise the decision lives only in the spec, which doesn't fail CI.

## Lessons learned

- **`Map<K, V> - missingKey` is silently total — no throw, no exception path to handle.** Kotlin's `operator fun <K, V> Map<out K, V>.minus(key: K): Map<K, V>` returns a map without the key, or an `equals`-identical copy if the key wasn't present. Combined with `MutableStateFlow.update`'s "skip emission if the new value equals the old" semantics, the unknown-id path is free — no `if (records.containsKey(id)) …` guard, no test-only emission to suppress. The free idempotency is the same mechanism `archive`'s `record.copy(... archived = true)` relies on (the second `archive` call produces an `equals`-identical record). **Pattern:** when a mutator's contract permits "no-op on missing target," reach for an idempotent in-place operation (`map - key`, `data class copy` of an already-matching value) before reaching for a conditional guard.
- **"Does not throw" tests don't need a try/catch wrapper.** `delete_onUnknownId_doesNotThrow` is a three-line `runBlocking { … }` that just calls `repo.delete("nope")` and lets the test pass by reaching the end. The adjacent `archive_onUnknownId_throws` uses `try { … } catch (_: IllegalArgumentException) { }` because it *asserts* a specific exception type — without the wrapper the throw would fail the test. Mirroring that wrapper for "does not throw" would be wrong: an unexpected throw escapes the lambda and fails the test naturally; a catch-all would swallow it and let the test pass on the bug it's supposed to catch. **Pattern:** assert "throws X" with try/catch + assertion-in-catch-block; assert "does not throw" with a bare call and let JUnit's natural failure mode do the work.
- **Reusing an existing seed with messages avoids a fresh fixture in the projection-emission tests.** `seed-channel-pyrycode-mobile` already carries 6 messages across 2 sessions for unrelated reasons (#192's `WorkspaceChange` boundary exercise, #184's streaming-reveal, #191's `Role.Tool` row). Tests 4-5 reuse that seed instead of setting up a fresh `repo.createDiscussion()` + `repo.sendMessage(...)` chain. Cheaper to read, cheaper to maintain — and the test name pins the dependency (`seed-channel-pyrycode-mobile`) so a future seed-data refactor that drops messages from this channel surfaces in the test failure. **Pattern:** when a projection-emission test needs a non-empty starting state, prefer a seed channel that already has the shape over a constructed fixture, and name the seed id in the test body so the coupling is greppable.
