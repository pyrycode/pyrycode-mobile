# #412 — record the structured-stream replay cursor (`event_id` on the inbound envelope)

The **wire-substrate** half of the Phase 2 structured-streaming mid-turn-replay contract (ADR 025
§ Backpressure / replay): every interactive structured-stream frame now carries an **envelope-level**
`event_id` — a durable, per-conversation, strictly-increasing id, stable across reconnects (distinct
from the per-connection `id`, which resets each reconnect). This slice adds that field to the inbound
[`Envelope`](../features/mobile-protocol-v2-wire-layer.md) (decode-tolerant, omitted on every
non-interactive frame) and **records** the latest value observed as a reconnect-spanning high-water-mark
cursor — held where it can be read at the *next* connection's `hello`-build time, before that
connection's inbound path exists. It **advertises nothing**: reading the cursor into `hello` +
handling the resync marker is the consuming slice [#413](https://github.com/pyrycode/pyrycode-mobile/issues/413)
(`blockedBy #412`). The cursor is the seam #413 consumes. Split from #402.

Four production files, **one new type** (`ReplayCursor`), no interface change, no Koin change.

## Files touched

Production — 1 new file, 3 modifications:

- **`data/network/ReplayCursor.kt`** (new) — a tiny, thread-safe, reconnect-spanning holder of the
  high-water mark. `val latest: Long?` (the latest recorded value, or `null` when nothing valid has ever
  been observed — a **synchronous** point read valid at any moment, including before a connection's
  inbound path exists); `fun record(eventId: Long)` folds an observed value in. Backing is a
  `MutableStateFlow<Long?>(null)` with an atomic `update {}` max-fold — lock-free, **TOCTOU-free** (the
  recorder coroutine writes; #413's hello-build reads from another coroutine). The flow is **not**
  exposed — only the point read and the write are public (#413 needs a point read, not a stream).
  Portable: imports only `kotlinx.coroutines.flow` (zero Android imports, CLAUDE.md `data/` rule).
- **`data/network/MobileWireModels.kt`** — `Envelope` gains `@SerialName("event_id") val eventId: Long?
  = null` (`:53`), a sibling of `inReplyTo`, modeled **identically**. Under `MobileJson`
  (`explicitNulls = false`) it **omits when null** on encode — so every outbound frame, including
  `hello`, stays byte-identical to today — and the nullable default tolerates its per-frame absence on
  decode (a missing `event_id` never fails the decode of an otherwise-valid envelope). Mirrors the
  server's `omitempty *uint64` (pyrycode#649).
- **`data/repository/RemoteConversationRepository.kt`** — a fifth, **defaulted** ctor param
  `private val replayCursor: ReplayCursor = ReplayCursor()` (`:117`, after `negotiatedCapabilities`); a
  new private `recordReplayCursor(envelope)` (`:354`) called as the **first line** of `onInbound`
  (`:218`), *before* the `when` demux. It gates on `CAPABILITY_INTERACTIVE in negotiatedCapabilities()`
  (symmetric with the structured-stream + `stall` arms), then `envelope.eventId?.let { replayCursor.record(it) }`.
  The `when` arms are untouched.
- **`data/repository/RelayRepositoryCoordinator.kt`** — `internal val replayCursor: ReplayCursor =
  ReplayCursor()` (`:99`), the process-scoped owner; threaded into each per-connection repo in
  `onConnection` as one extra named arg (`:189`). `internal` (module-visible, read-only seam) so #413
  and unit tests read it without a public API surface, mirroring `toPyrycodeLinkStatus`'s visibility.

Tests — 1 new file, 3 modifications (test-first RED→GREEN), 11 new tests:

- **`ReplayCursorTest.kt`** (new) — fresh cursor reads `null` (not `0`); `record(5)`→5, `record(3)`/`record(5)`
  no-op, `record(9)`→9 (strictly-advancing); `record(0)`/`record(-1)` on a fresh cursor stay `null`
  (positive guard); `record(0)` after `record(7)` stays 7.
- **`MobileWireCodecTest.kt`** (+3) — `event_id` round-trips (`"event_id":42` ↔ `eventId == 42L`); absent
  decodes to `null`; a `null` `eventId` **omits** on encode (AC #5), mirroring the `inReplyTo` tests.
- **`RemoteConversationRepositoryTest.kt`** (+~6) — over `FakeSessionPump` + `runCurrent()`: with
  `interactive` negotiated the cursor advances on structured frames and ignores out-of-order; a
  non-interactive frame leaves it unchanged (AC #3); with the gate closed an injected `event_id` records
  nothing (defence-in-depth); a structured frame with a **malformed payload** but a valid `event_id`
  still advances (envelope-level recording is independent of payload decode); and two repos sharing one
  cursor prove survival across a simulated reconnect.
- **`RelayRepositoryCoordinatorTest.kt`** (+~2) — `replayCursor.latest` persists across an `onConnection`
  churn over a fresh pump (`teardownActive` never touches it).

## Patterns established

- **A reconnect-spanning datum lives on the coordinator, not the per-connection repo.** The
  [`RemoteConversationRepository`](../features/remote-conversation-repository.md) is rebuilt every
  reconnect, so any state that must outlive connection churn — and be readable at the *next* connection's
  handshake-build moment, before its inbound path exists — belongs on the process-lifetime
  [`RelayRepositoryCoordinator`](../features/relay-repository-coordinator.md), which already owns both the
  per-connection repo (the recorder) and the per-connection pump (the future hello producer). The shared
  instance is threaded into the per-connection repo via a **defaulted** ctor param (same discipline as
  `deviceName` #365 / `negotiatedCapabilities` #385 / `pushToken` #365) so every existing construction and
  test compiles unchanged, and exposed as an `internal val` seam (no public API, no Koin binding) the
  same way `toPyrycodeLinkStatus` is `internal`. This is the third non-interface surface the coordinator
  threads off the concrete repo/pump (after `liveSessionEvents` #406 and the `pyrycodeStatus` derivation
  #392).
- **Validate-at-the-boundary point read.** `event_id` crosses untrusted→trusted at exactly one named
  point — `ReplayCursor.record` (positive guard + strict-greater fold) — so the only public read
  (`latest`) can only ever return a validated, monotonic, positive value, never a raw wire integer. A
  pathological `uint64 > 2^63` decodes to a negative `Long` and is rejected by the positive guard rather
  than poisoning the cursor; `0`/negative/out-of-order/replayed values are no-ops. The fold is a
  `MutableStateFlow.update {}` max-fold (atomic, lock-free, TOCTOU-free, not check-then-set) so a
  transient writer/reader overlap is still correct. Reuse this shape for any future single-mark held
  across reconnects.
- **Envelope-level recording is type-agnostic and a pure side-write.** Recording reads `envelope.eventId`
  directly — *before* the `when` demux and independent of whether the per-type structured *payload*
  decodes — so a frame with a valid `event_id` but a malformed payload still advances the cursor (the
  durable event occurred; the cursor marks position, not decodability). It has **no feedback into
  delivery**: nothing in the `when` arms, no `liveSessionEvents` emission, and no event delivery reads the
  cursor, so this slice alone cannot mute or drop a live event.

## Lessons learned

- **The watermark-mute exploit is structurally out of scope for the recording slice — and that is the
  load-bearing security property to verify, not assume.** A hostile authenticated daemon sending a giant
  `event_id` → cursor jumps → advertise → daemon replays nothing newer → silent live-stream drop only
  becomes reachable once **#413 advertises** + the server acts on the watermark. Because `recordReplayCursor`
  is a pure side-write with no feedback into delivery, #412 cannot itself mute/drop an event. The
  memory-flagged **#413 security gate** (verify pyrycode#647's watermark-mute is resolved on pyrycode
  `main` *before* #413 advertises) is unaffected by this slice and still stands.
- **The recording path must be total (non-throwing).** It runs inside the single inbound collector
  (`pump.inbound.collect { onInbound(it) }`); a throw there kills the collector and silently dead-ends
  the connection's *entire* inbound stream (`conversations`/`message`/`ack` included). `recordReplayCursor`
  is throw-free by construction — it reads an already-decoded `Long?` (no decode step), a set-membership
  check, and a pure-arithmetic fold — so it needs **no** `try/catch` (unlike the decode arms), but a
  future edit must not introduce one that can throw. This is an availability invariant, not tidiness.
- **A malformed/wrong-typed `event_id` never reaches the cursor — it fails the envelope decode upstream.**
  A JSON string where a number is expected fails `decodeFromString<Envelope>` in `NoiseSessionPump`,
  exactly as a bad `id`/`type`/`ts` does today; the pump tears the session down and the supervisor
  reconnects. The cursor is coordinator-scoped (not pump-scoped), so a teardown never touches it — the
  reconnect re-reads the intact high-water mark. This slice does **not** change the pump's structural-decode
  posture (out of scope; crypto-adjacent file).

## Security

`security-sensitive`. Architect security review **PASS** (no MUST FIX, spec § Security review). Code
review **PASS** with one **non-blocking NIT** (the capability supplier is evaluated twice per structured
frame — once in `recordReplayCursor`, once in the existing `TYPE_TURN_STATE…` arm; a cheap non-suspending
`pump.state.value` read that mirrors the existing per-frame gate idiom, **deliberately not collapsed** —
doing so would add coupling for no measurable gain, Evidence-Based Fix Selection). The untrusted→trusted
crossing is `ReplayCursor.record`, sitting **behind** the already-authenticated Noise channel (the pump
MAC-verifies + decrypts before any envelope reaches `onInbound`), so the `event_id` source is the
authenticated paired daemon, not a relay MITM. `event_id` is a **non-secret** monotonic counter:
nothing logs it or the payload (uniform with every `onInbound` arm). The cursor is **in-memory only**,
never persisted — a fresh process start reads `null` (AC #4 "no cursor", not `0`). Pure `data/` layer,
zero Android imports, no exported/IPC surface (`replayCursor` is `internal`/read-only). The recording
rides **behind** the authenticated [Noise_IK session](../features/noise-ik-session.md) — the pump
MAC-verifies + decrypts before any envelope reaches `onInbound`, so the `event_id` source is the
authenticated paired daemon, not a relay MITM.
