# #374 — snapshot wire DTOs (`request_snapshot` / `screen_snapshot`)

The **wire-vocabulary half** of the mobile screen-snapshot exchange: two `@Serializable` DTOs in one
co-located file, no repository method, no dispatch, no trust decision. The phone asks the daemon for a
one-shot **text** picture of the current claude screen (`request_snapshot`) and parses the daemon's
reply (`screen_snapshot`). This is the parser-independent **floor** of ADR 025's safe-degradation
strategy — it depends on no screen parser, so it survives any parser break. Mirrors the server's own
standalone "only structs and constants" slice (pyrycode#617, merged; daemon handler pyrycode#618,
merged). The trust decision lives in the consumer slice #375 (blocked on this).

See the feature doc [`mobile-protocol-v2-wire-layer.md`](../features/mobile-protocol-v2-wire-layer.md)
§ "The screen-snapshot exchange" for the evergreen reference; this file is the implementation record.

## Summary

One new production file (`SnapshotPayload.kt`, 50 lines) holding **two** DTOs, plus one JUnit4 test file
(`SnapshotPayloadTest.kt`, 99 lines, 5 `@Test`s). Both (de)serialize through `MobileJson`, never a
default `Json`. Purely additive — grep confirms no pre-existing references to either type or wire name;
no call sites to update.

- **`RequestSnapshotPayloadDto`** (encode-only) — `request_snapshot` `{conversation_id}` (phone →
  daemon control). One required field; `@SerialName("conversation_id")` carries the snake_case
  Go-interop wire name. Shape narrowed from `RegisterPushTokenPayloadDto` to a single field.
- **`ScreenSnapshotPayloadDto`** (decode-only) — `screen_snapshot` `{conversation_id, text, ts}`
  (daemon → phone event). All three required + non-null; Go-struct field order. `text` is the
  **rendered text** of the screen (never raw control codes — ADR 025 no-raw-bytes invariant, enforced
  server-side by the daemon's tui-driver renderer); `ts` is the raw wire timestamp.

## Files touched

Both **NEW**, under `app/src/main/java/de/pyryco/mobile/data/network/` (+ test mirror):

- **`SnapshotPayload.kt`** (50 lines):
  - `RequestSnapshotPayloadDto` (`:20-22`) — single `@SerialName("conversation_id") val conversationId:
    String`. Encode-only is a KDoc usage convention, not a structural restriction (the class is plain
    `@Serializable`) — identical to `SendMessagePayloadDto` / `RegisterPushTokenPayloadDto`.
  - `ScreenSnapshotPayloadDto` (`:45-49`) — `conversationId` (`@SerialName`), `text`, `ts`, all
    non-null `String`. `text` / `ts` are already snake-case-free wire names ⇒ no `@SerialName`. **No
    domain-mapping function** — the consumer reads `.text` directly (see Patterns).
- **`SnapshotPayloadTest.kt`** (99 lines) — JUnit4 mirroring `MessagePayloadTest.kt`. Five tests: request
  encodes `conversation_id` (encode via `encodeToJsonElement(...).jsonObject`); `screen_snapshot` decodes
  all three fields; tolerates an unknown extra key (`cols`); preserves multi-line / leading-whitespace
  `text` byte-for-byte (the no-mutation guard); a missing-required-field fixture throws
  `SerializationException`.

**No build edits, no `MobileWireCodec.kt` change** — `MobileJson` already does everything needed;
`ignoreUnknownKeys = true` supplies the unknown-field tolerance for free.

## Patterns established

- **A decode-only payload with NO domain mapper — the first.** Every prior decode-only payload maps to a
  domain type at the boundary: [#316](316.md) `conversations` → `Conversation`-list, [#317](317.md)
  `message` → `Message`, [#318](318.md) `conversation_created`/`conversation_updated` → `Conversation`.
  `ScreenSnapshotPayloadDto` is **terminal display data**, not a wire→domain edge — the consumer (#375)
  reads `.text` directly,
  so there is no `toX()` mapper and no domain target. When a payload's decoded form is itself the value
  the UI shows (rendered screen text), the DTO *is* the boundary; don't invent a domain type to map into.
- **A payload-field timestamp kept as a plain `String`.** `ts` is **not** parsed to `kotlinx.datetime.Instant`
  — a deliberate departure from #316/#318, where the payload timestamp (`last_used_at`) decodes via
  `InstantIso8601Serializer` precisely *because* a domain field (`lastUsedAt`) consumes the instant.
  Here the consumer returns `text` only and never reads `ts`, so parsing it would defend nothing and add
  a parse this slice doesn't need. **Refined rule:** parse-at-decode a payload timestamp only when a
  domain field consumes the instant; otherwise keep it a `String` like `Envelope.ts`. (Don't pattern-match
  `InstantIso8601Serializer` onto every wire timestamp.)
- **First co-located request + event *pair* in one file — and the ktlint filename rule does not fire.**
  `SnapshotPayload.kt` holds an encode-only request **and** a decode-only event because they are one
  logical exchange (the in-file precedent is `BackfillSincePayloadDto` + `MessageChunkPayloadDto` living
  together in `MessagePayload.kt`). Two public top-level types ⇒ ktlint `standard:filename` is silent, so
  the file keeps the spec's `SnapshotPayload.kt` name — **contrast [#318](318.md)**, whose *single*-class file
  spotless forced to rename `ConversationResponseDto.kt`. The trigger for the rename is a genuinely
  single-class file; a multi-type payload file escapes it. See [[ktlint-filename-rule-single-class]].
- **`text` is modeled verbatim — no-mutation decode fidelity is the load-bearing invariant.** The DTO
  must not trim, normalize, or sanitize `text` — decode fidelity is the *entire point* of the
  parser-independent floor (a faithful picture of the literal screen). No custom serializer; the
  `screenSnapshot_preservesTextVerbatim` test pins a multi-line, leading-whitespace value round-tripping
  byte-for-byte. The no-raw-bytes guarantee (ADR 025) is enforced **server-side** by the daemon renderer
  (the trusted authenticated peer), not re-litigated here.
- **No mobile-side type-string constants.** The envelope `type` values `"request_snapshot"` /
  `"screen_snapshot"` are inline literals set by the consumer (#375) when it builds the `Envelope`,
  exactly as `"send_message"` / `"list_conversations"` are inline at their call sites today. There is no
  type-constants registry on the mobile side; don't invent one to mirror the server's `codes.go`
  `TypeRequestSnapshot` / `TypeScreenSnapshot`.

## Lessons learned

The PR ([#376](https://github.com/pyrycode/pyrycode-mobile/pull/376)) carried no *Lessons learned*
section; the non-obvious points worth recording:

- **Deliberate non-redaction — the no-content-logging obligation moves downstream.** `ScreenSnapshotPayloadDto`
  keeps the `data class` auto-`toString()`, which includes `text` (potentially-sensitive rendered screen
  content). This is **correct as-is**: it matches the content-bearing `MessagePayloadDto`
  (`MessagePayload.kt:31-37`), which also has no redaction. `toString`-redaction in this codebase is
  reserved for the `token` *credential* (`HelloClientPayload` / `QrPayload`) — redacting content here
  would be an inconsistent defense against an unobserved failure mode (Evidence-Based Fix Selection). The
  obligation is real but it is a **code-level invariant on the consumer**: #375 and the thread UI MUST
  NOT log decoded `text`, per the [#346](346.md) no-content-logging posture. This slice adds zero log calls, so
  there is nothing to enforce *here*; the architect's SHOULD-note and the code-review NIT both forward
  the obligation to #375 rather than gate this slice.
- **Model what is *sent* / *needed*, not the full surface.** `ts` stays an unparsed `String` (above) and
  `RequestSnapshotPayloadDto` models exactly one field — the encode-only/decode-minimal discipline the
  sibling request encoders established. Don't add `Instant` parsing or a `toSnapshot()` mapper "for
  completeness"; the consumer slice owns whatever shaping it actually needs.

## Verification

- `./gradlew spotlessCheck test lint assembleDebug` — all green (PR body; RED→GREEN, five new tests).
  `connectedAndroidTest` N/A — pure `data/`-layer (de)serialization, no Android UI, no `ComposeTestRule`,
  no coroutines (`runTest` not used). See [[data-layer-android-import-exception]].
- The five tests map to the ACs: request-encode (AC #1), three-field decode + unknown-field tolerance
  (AC #2), verbatim-`text` round-trip (the no-mutation guard), missing-required-field throws
  `SerializationException` (strict-decode posture).
- **Code review: PASS** ([PR #376](https://github.com/pyrycode/pyrycode-mobile/pull/376), no blocking
  findings — "a textbook execution of the spec"). One
  **NIT**, no action: the `data class` auto-`toString()` includes `text`, correct-as-is (matches
  `MessagePayloadDto`), forwarding only the #375 no-content-logging obligation (above). The reviewer
  verified pattern fidelity against the canonical wire DTOs, scope discipline (no constants / repository /
  dispatch / `Envelope` wiring / mapper / codec change), `data/` portability (only `kotlinx.serialization.*`;
  no `android.*` / `kotlinx.datetime`), the strict-decode + verbatim-`text` invariants, and all five test
  scenarios. The spec's self-performed security review (label `security-sensitive`) PASSed: the DTO is the
  untrusted→typed boundary for an inbound `screen_snapshot` arriving inside the cryptographically
  authenticated Noise_IK channel, strict required fields fail closed, and the must-not-mutate-`text`
  finding is honored.
