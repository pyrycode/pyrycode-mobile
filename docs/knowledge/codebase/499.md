# #499 — Idle relay status: stop reporting "Connected" while unpaired/idle

**Issue:** [#499](https://github.com/pyrycode/pyrycode-mobile/issues/499) ·
**Spec:** [`docs/specs/architecture/499-idle-relay-status.md`](../../specs/architecture/499-idle-relay-status.md) ·
**PR:** [#520](https://github.com/pyrycode/pyrycode-mobile/pull/520) ·
**Feature docs updated:** [Relay link status](../features/relay-link-status.md), [Relay reconnect supervisor](../features/relay-reconnect-supervisor.md), [Connection status line](../features/connection-status-line.md) ·
Size **XS**, **not** security-sensitive (idle is a deliberate not-dialing state, no untrusted input, no key material). Commit `c0cccc8`.

## Summary

Fixes a **false green** on the Settings two-part connection status line's **relay** leg. The
[`RelayConnectionSupervisor`](../features/relay-reconnect-supervisor.md) overloaded one
[`RelayLinkStatus.Connected`](../features/relay-link-status.md) value for two unrelated meanings: a
**live socket** (transport `Up`) and three genuinely **idle** situations where nothing is dialing — the
initial pre-`connect()` seed, the unpaired branch (paired store returns `null` → idle, end the loop),
and `close()` (intentional background disconnect). The overload existed so the conversation-list
[banner](../features/connection-banner.md) stays hidden while idle (the banner shows nothing precisely
when the derived legacy [`ConnectionState`](../features/connection-state.md) is `Connected`).

The side effect: the Settings line's [`toLegVisual()`](../features/connection-status-line.md) mapped
`Connected` → the green label "Connected". So while unpaired and dialing nothing, Settings read
"Connected" — a false positive during the exact pairing/connection-diagnosis workflow the line exists to
support. Manifests only with `USE_RELAY_REPOSITORY` on; filed from the Cross-Repo Code Review 2026-07-03.

The fix is the divergence the ticket names: give idle its **own** `RelayLinkStatus.Idle` case. Because
both consumers are **exhaustive `when`s**, the compiler forces both to handle it, and they map it
**differently** — idle → banner-hidden `ConnectionState.Connected` (preserves AC#3) **and** idle → a
non-green "Not connected" (`Down`/error) Settings label (satisfies AC#1). A live socket (transport `Up`)
still reads `Connected`/green; `Connecting`/`Reconnecting`/`DaemonAbsent`/`Offline` are unchanged (AC#4).

## The fix

One new sealed case + three reassignments + two compiler-forced branches, across three production files.

- **New case** — `RelayLinkStatus.kt:20`: `data object Idle : RelayLinkStatus()`. A `data object`
  carrying **no relay-supplied text** (no-log contract), matching `DaemonAbsent`/`Offline`. Named `Idle`
  — not `Disconnected`/`NotPaired` — because it covers all three situations without implying a cause:
  `close()` was paired, and the initial seed predates any pairing check, so a pairing-specific name would
  be wrong for two of the three.
- **Three idle reassignments** — `RelayConnectionSupervisor.kt`: the initial `state` seed (`:78`), the
  `close()` teardown (`:117`), and the unpaired `paired == null` branch (`:138`) flip `Connected → Idle`.
  The **live-socket `Up` branch (`:154`) stays `Connected`** — this is the line the whole fix pivots on.
- **Banner mapper** — `toConnectionState()` `RelayConnectionSupervisor.kt:247`:
  `RelayLinkStatus.Idle -> ConnectionState.Connected`. Idle derives to the banner-hidden legacy state
  (AC#3), **diverging** from the Settings mapper below.
- **Settings-line mapper** — `toLegVisual()` `ConnectionStatusLine.kt:67`:
  `RelayLinkStatus.Idle -> ConnectionLegVisual(ConnectionLegCategory.Down, "Not connected", "Relay: not connected")`.
  Non-green, honest label (AC#1). Renders through the existing `Down → MaterialTheme.colorScheme.error`
  path — category-driven M3 token, **no hardcoded colour**, a11y `contentDescription` intact.

**Design decision — category `Down`, label "Not connected".** The `ConnectionLegCategory` enum is only
`Up`/`InProgress`/`Down`. `Up` is forbidden by AC#1 (must not read green); `InProgress` (amber) would
falsely imply an in-flight dial (nothing is dialing); a genuinely-neutral 4th category would need a new
enum value **and** a new M3 colour token in `theme/`, pushing this past XS. `Down` is the honest,
in-scope choice — during diagnosis, "you are connected to nothing" is truthfully a not-up state, and the
Figma Settings frame (`17:2`) already renders a red dot for a not-connected leg. The label **"Not
connected"** is distinct from `Offline`'s "Offline": two states share the `Down` category but diverge on
the visible text/a11y channel — the exact pattern `Connected`/`DaemonAbsent` use to share `Up`
("Connected" vs "Reachable"). "Not paired" would be wrong for `close()` and the initial seed.

## Patterns established

- **A sealed value overloaded for two meanings is a latent bug the moment a second consumer derives from
  it differently.** `Connected` meaning both "live socket" and "deliberately idle" was harmless while the
  banner (idle = absence of banner) was the only consumer — the two meanings map to the same banner
  outcome. The bug surfaced when a **second** consumer (the Settings line, #390/#397/#398) needed to read
  a *positive* claim off the same value. The fix is not a special-case in the new consumer but a **split
  of the overloaded value at the source**, so each consumer's exhaustive `when` routes the two meanings
  independently. When you find one enum/sealed case standing in for two distinct real states, split it
  before a second reader forces a lie.
- **Divergent exhaustive `when`s are the enforcement mechanism, not just the shape.** Both
  `toConnectionState()` and `toLegVisual()` are `when` with no `else`, so adding `Idle` was a **compile
  error in both** until each mapped it — the compiler guaranteed no silent fallthrough to a wrong default.
  This is why the divergence (idle → hidden banner **and** idle → not-green label) is safe: it cannot be
  half-applied.
- **Prefer reusing an existing category over minting a new token when the honest reading fits.** `Down`
  was the truthful category for idle, so the fix stayed XS (no new `theme/` M3 token, no new enum value).
  A neutral grey "idle" dot is a real future refinement — but it belongs to a combined-status ticket that
  introduces the token, and is explicitly deferred here. Don't grow the design surface for a state an
  existing category already describes honestly.

## Testing

Unit only (`./gradlew testDebugUnitTest`; `spotlessCheck`, `lint`, `assembleDebug`, and
`compileDebugAndroidTestKotlin` all pass — pure mappers + supervisor flow, no instrumented surface, so
`connectedAndroidTest` was not run, same posture as [#307](307.md)/[#391](391.md)/[#498](498.md)).

- **`ConnectionStatusLineTest.relayIdle_mapsToDown_notConnected`** (AC#1) — the executable AC#1:
  `RelayLinkStatus.Idle.toLegVisual()` equals `ConnectionLegVisual(Down, "Not connected", "Relay: not connected")`
  (not "Connected", not green). Asserts the full triple, matching the per-case idiom.
- **`RelayConnectionSupervisorTest.initialState_beforeConnect_relayLegIsIdle`** (AC#2) — before any
  `connect()`, `supervisor.relayStatus.value == RelayLinkStatus.Idle`.
- **Strengthened idle-behaviour tests** — `benignUnpaired_doesNotDialAndStaysConnected`,
  `reloadPerDial_laterNullRead_…`, and `close_tearsDownTransportAndStopsLoop` each keep their existing
  `ConnectionState.Connected` (banner-unchanged) assertion **and** add
  `assertEquals(RelayLinkStatus.Idle, supervisor.relayStatus.value)` — pinning that the *relay leg* is
  idle (unpaired, later-null-read, and post-`close()`) while the *derived banner* stays hidden (AC#1/#2/#3).
- **`toConnectionState_…`** extended with `assertEquals(ConnectionState.Connected, RelayLinkStatus.Idle.toConnectionState())`
  — executable AC#3 (idle keeps the banner hidden).
- **Regression guard (AC#4), untouched:** the live-socket `emitUp()` → `RelayLinkStatus.Connected`
  assertion and every `Connecting`/`Reconnecting`/`DaemonAbsent`/`Offline` assertion stay exactly as-is.
