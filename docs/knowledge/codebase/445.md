## Summary

The **projection/state half** of the permission/choice-modal UI surface. [#437](437.md) (shipped)
decodes the two modal envelopes into a `replay = 0` [`ModalEvent`](../features/modal-events.md)
`SharedFlow` on the **concrete** `RemoteConversationRepository.modalEvents`. This slice (a) **surfaces**
that stream up to the thread ViewModel through a [`RelayRepositoryCoordinator`](../features/relay-repository-coordinator.md)
passthrough seam — the byte-for-byte mirror of the `liveSessionEvents` seam (#406) — and (b) **folds** it
into a single hoisted [`ModalUiState`](../features/current-modal-state.md) on
`ThreadViewModel.currentModal`: a `Shown` sets the open modal; a `Dismissed` matching the open `modalId`
clears it with its verbatim resolution reason; a non-matching `Dismissed` is a no-op; last-shown wins.
Because modal events carry **no `conversation_id`** (`modalId` is the sole key), the state is **app-level**
(one active modal across the app), **not** scoped per conversation. **No UI** — `currentModal` is hoisted
for the render slice #446. Built test-first; all gates green (`test`/`lint`/`assembleDebug`/`spotlessCheck`);
code review **PASS**, zero findings.

## Patterns established

None new — this slice is the **modal twin of the [#406](406.md) `isThinking` projection slice**, reusing
its three moves end-to-end: a coordinator `flatMapLatest` passthrough over `activeRemoteRepo` (mirror of
the `liveSessionEvents` seam), a **defaulted trailing ctor param** so the fake graph + existing tests stay
inert, and a **sibling `StateFlow`** (not a `ThreadUiState` field) exposed beside `isThinking`/`isStalled`.
It **confirms** two existing calls rather than setting new ones:

- **A pure, co-located reduce fold over a sealed event family.** `ModalUiState.reduce` mirrors
  `ThreadFold.reduce` / `thinkingTransition`: side-effect-free, **no logging** of any field, total over the
  sealed `ModalEvent`. The choice of `scan` (accumulate) vs `mapNotNull` (transition) follows what the
  state *is*: `currentModal` must hold an `Open` across unrelated events, so it **accumulates** (`scan`);
  `isThinking` only flips on a phase transition, so it **transitions** (`mapNotNull`).
- **App-level vs per-conversation routing follows the wire key.** `currentModal` has **no
  `conversationId` filter** (contrast `thinkingTransition`'s `conversationId` guard) because modal events
  carry no `conversation_id`. When a new interactive signal arrives, route by its actual correlation key —
  here `modalId` only — not by the convenient sibling's key.

## Lessons learned

- **`scan` + a `replay = 0` source forces `SharingStarted.Eagerly`, not the `WhileSubscribed(5_000)` of
  the sibling signals — this is the load-bearing call of the slice.** `scan` re-emits its **initial
  accumulator** on every fresh upstream collection. Under `WhileSubscribed`, a resubscription past the
  stop window cancels the upstream and, on return, restarts the `scan` — emitting `Hidden` and
  **overwriting a retained `Open`**. Because the source `modalEvents` is `replay = 0`, the prior events do
  **not** replay to rebuild the accumulator, so a still-open modal would silently clear. `Eagerly`
  collects for the VM lifetime, so the accumulator runs exactly once and `.value` is always the true
  current projection (matching the coordinator's accumulate-a-`replay=0`-stream precedent —
  `currentRepository` / `connectionStatus` both use `Eagerly`). The `isThinking` `mapNotNull`+`WhileSubscribed`
  combo is **safe only because `mapNotNull` never re-emits a stale value on resubscription** — the same
  policy is wrong for a `scan` accumulator. Pick the started policy from the operator, not the sibling.
- **`scan`'s accumulator type is inferred from the initial value** — `scan(ModalUiState.Hidden) { … }`
  infers `R = ModalUiState.Hidden` (the `data object`'s singleton type) and **rejects** a lambda returning
  `ModalUiState.Open`. Type it explicitly: `scan<ModalEvent, ModalUiState>(ModalUiState.Hidden)`.
- **Exact-`modalId` match on `Dismissed` is a safety property, not just correctness.** A `Dismissed`
  whose `modalId` ≠ the open modal's is a no-op, so a malformed or out-of-band dismiss cannot silently
  clear an unresolved modal (spoofed-dismiss safety). The producer (pyrycode#716) carries **no per-option
  "destructive" marker** — its safety design is the fail-safe-deny `default_option_id`, carried verbatim
  here and never auto-applied (answering is #444).

## Security (`security-sensitive`)

The untrusted-bytes → typed-events trust boundary is **upstream** at #437's decode seam; this slice
operates on already-decoded in-process `ModalEvent`s and adds **no new parse**. Its obligations are met by
construction: the fold is pure with **no logging** of any modal field (`title`/`prompt`/option `label`s
may name a sensitive command/path); state lives **solely in the `StateFlow`** — no `SavedStateHandle` /
DataStore persistence (would defeat #446's FLAG_SECURE/no-`rememberSaveable` screen-capture hardening);
`defaultOptionId` carried but **never auto-applied** (fail-safe-deny preserved); the exact-`modalId`
guard blocks out-of-band dismisses. Output-encoding of the verbatim strings is the **render slice #446**'s
job (this slice never renders or interpolates them). Architect self-review **PASS**; code review **PASS**,
zero findings.

## Open question (deferred, no AC here)

Should a connection drop / reconnect clear a stale `Open`? The coordinator passthrough emits `emptyFlow()`
on a null repo but pushes **no "clear" event**, so a stale `Open` can persist across a drop. Deferred to
the render slice **#446** + the connection signal — not built here.
