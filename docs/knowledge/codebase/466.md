# Ticket #466 — `dequeue_message` outbound wire frame

**Issue:** [#466](https://github.com/pyrycode/pyrycode-mobile/issues/466) ·
**Spec:** [`docs/specs/architecture/466-dequeue-message-outbound-wire-frame.md`](../../specs/architecture/466-dequeue-message-outbound-wire-frame.md) ·
**PR:** [#468](https://github.com/pyrycode/pyrycode-mobile/pull/468) ·
**Feature doc:** [Queued backlog](../features/queued-backlog.md) (the outbound `dropQueuedMessage` half) ·
Phase-3 **outbound** half of the queued-message backlog (epic pyrycode#597). Split from #462 (itself split
from #429). Size **S**, `security-sensitive` (a brand-new internet-exposed outbound frame).

## Summary

Adds the data-layer send that drops a queued message:
`ConversationRepository.dropQueuedMessage(conversationId: String, queuedMessageId: Long)` dispatches a
`dequeue_message` frame `{conversation_id, queued_msg_id}` and resolves the outcome against the existing
request↔ack correlation ([`sendAndAwaitReply`](../features/remote-conversation-repository.md), #346). It is
the **outbound peer** of #460's inbound `queue_state` decode. Empty `ack` ⇒ success with **no** projection
mutation; server `error` ⇒ caller-visible failure; no live connection ⇒ `IllegalStateException`. **No
optimistic mutation** — this slice touches no `StateFlow`, mints no domain object, and is invisible to
`observeQueue`/`observeMessages`/`observeLastMessage`; the backlog updates only via a later `queue_state` on
the already-shipped [`observeQueue`](../features/queued-backlog.md) path (#460/#461). **No UI** — the per-row
drop affordance that calls this is the follow-up slice **#467** (blockedBy this). Built test-first,
RED→GREEN; all gates green (`spotlessCheck`/`test`/`lint`/`assembleDebug`).

## Placement: defaulted interface method, not injected lambda

The decisive shape question for any outbound control send is *where the operation lives*. Two precedents:

- **Defaulted-throwing interface method** ([`requestScreenSnapshot`](../features/remote-conversation-repository.md), #375) — for **per-conversation** ops.
- **Concrete-only injected lambda** (`answerModal` / `cancelModal`, #438) — for **app-level** ops (modals key off `modal_id` only, no `conversation_id`, so they are fetched off the concrete coordinator).

`dropQueuedMessage` carries a `conversation_id`, so it is **per-conversation** → the `requestScreenSnapshot`
shape. Choosing the interface-method precedent means **no** new ViewModel ctor param, **no** coordinator
passthrough, **no** Koin wiring: #467 calls `repository.dropQueuedMessage(...)` on the
[`StableConversationRepository`](../features/stable-conversation-repository.md) facade the `ThreadViewModel`
already holds. (Code-review confirmed this is the right call.)

## Files touched

- **`data/network/DequeueMessagePayloadDto.kt`** (new, +34): the `internal data class
  DequeueMessagePayloadDto(@SerialName("conversation_id") conversationId: String,
  @SerialName("queued_msg_id") queuedMsgId: Long)` — an **encode-only** DTO mirroring
  `ModalOutboundPayloads.kt`'s `ModalCancelPayloadDto`. Two fields, both required, in Go-struct order
  (`conversation_id`, then `queued_msg_id`). `queuedMsgId: Long` encodes to a JSON **number** (the
  daemon's `uint64`), symmetric with the inbound `QueuedMessageDto.queuedMsgId: Long` — **not** a String
  (the pyrycode#720 trap). Rich never-log KDoc. **Filed under `DequeueMessagePayloadDto.kt`, not the
  spec's proposed `QueueOutboundPayloads.kt`** — see Lessons learned.
- **`data/repository/ConversationRepository.kt`** (+26): the new interface method
  `suspend fun dropQueuedMessage(conversationId: String, queuedMessageId: Long): Unit = error("…")` beside
  `requestScreenSnapshot`, with a KDoc mirroring its shape. **Throwing default** — the fake and inline test
  doubles inherit it untouched (the cascade-avoidance documented on `delete` / `createWorkspaceFolder` /
  `requestScreenSnapshot`); no test double calls it, so the default is unreachable in tests.
  `queuedMessageId: Long` == `QueuedMessage.id`; the caller passes the `id` it got from `observeQueue`
  verbatim (`Long → Long`, no re-derivation). Returns `Unit`: success is "returned without throwing".
- **`data/repository/RemoteConversationRepository.kt`** (+46): the `override suspend fun dropQueuedMessage`
  modeled on `requestScreenSnapshot`/`cancelModal` — build `Envelope(id = requestId.incrementAndGet(),
  type = TYPE_DEQUEUE_MESSAGE, ts = Clock.System.now().toString(), payload =
  MobileJson.encodeToJsonElement(DequeueMessagePayloadDto(...)))`, then `sendAndAwaitReply(request)` and
  **ignore** the empty `{}` ack (no decode, no projection mutation). **No `try`/`catch`** — exceptions from
  `sendAndAwaitReply` propagate verbatim. New companion const `TYPE_DEQUEUE_MESSAGE = "dequeue_message"`
  (the outbound peer of `TYPE_QUEUE_STATE`).
- **`data/repository/StableConversationRepository.kt`** (+5): the one-line facade delegation
  `override suspend fun dropQueuedMessage(...) = live.dropQueuedMessage(...)`, beside the
  `requestScreenSnapshot` delegation. The `live` getter throws `IllegalStateException(NOT_CONNECTED)` when
  no connection is live — the same type the remote throws on a not-`Open` pump, so a caller catches one
  type either way (AC #4).
- **`data/repository/RemoteConversationRepositoryTest.kt`** (+141): 6 new tests + a `startDropQueuedMessage`
  helper mirroring `startCancelModal`, on the existing `FakeSessionPump` harness.
- **`data/repository/StableConversationRepositoryTest.kt`** (+11): the not-connected case added to the
  shared one-shot loop + 1 delegation case + a `dropQueuedMessage` override (recording `convId to id`) on
  the inline `RecordingConversationRepository` double.

`FakeConversationRepository` — **no change** (inherits the throwing default).

## Load-bearing design choices

- **Reuses the #346 request/reply primitive verbatim — no new error-mapping code.** All three failure
  outcomes fall out of `sendAndAwaitReply` + `mapError`: `conversation.not_found` → `IllegalArgumentException`
  (consistent with `sendMessage` / `requestScreenSnapshot`), any other code → `RelayErrorException(code,
  retryable, message)`, malformed reply → fallback `RelayErrorException` (never hangs), `pump.send` false →
  `IllegalStateException`.
- **No bespoke queue-error mapping.** The daemon's response to a stale / already-drained `queued_msg_id`
  (observed code `queue.stale_id`) surfaces **generically** as `RelayErrorException` — that satisfies AC #3.
  Special-casing it would defend a failure mode #467 hasn't yet asked to distinguish visually; deferred to
  the consumer slice if ever needed (Evidence-Based Fix Selection).
- **No echo, no optimistic mutation, nothing to roll back.** Success is an empty `ack`; the projection is
  owned entirely by `observeQueue` (#460) and its render (#461). This send surfaces failure, it does not
  handle it — the downstream UI leaves the backlog unchanged on any throw.

## Patterns established

- **A per-conversation outbound control send goes on the `ConversationRepository` interface (defaulted-
  throwing) + facade delegation — NOT the concrete-only injected lambda.** The discriminator is the
  payload: a frame carrying `conversation_id` is reachable through the facade the thread already holds
  (`requestScreenSnapshot` shape); an app-level frame keyed only by `modal_id` is fetched off the concrete
  coordinator (`answerModal`/`cancelModal` shape). `dropQueuedMessage` is the third precedent for this
  placement rule — reach for the interface method whenever the operation is scoped to a conversation.

## Lessons learned

- **ktlint `standard:filename` fires on a single-class file regardless of visibility — an `internal` data
  class still triggers it.** The spec proposed `QueueOutboundPayloads.kt`, but a file whose only top-level
  class-like type does not match the filename fails the build under ktlint 1.5.0, so it had to be named
  `DequeueMessagePayloadDto.kt` after its single class. `ModalOutboundPayloads.kt` escapes the rule only
  because it holds **two** classes (`ModalAnswerPayloadDto` + `ModalCancelPayloadDto`); a one-class outbound
  file must be named after the class. (Lifted from the [PR #468](https://github.com/pyrycode/pyrycode-mobile/pull/468)
  *Lessons learned*; same rule documented in [[ktlint-filename-rule-single-class]] — #466 is now the cited
  case there.) Code-review flagged the spec/impl filename divergence as a NIT and confirmed the rename is
  the build-required correct call.

## Verification

- **6 new unit tests** in `RemoteConversationRepositoryTest`: the sent frame matches the two-key wire
  contract with `queued_msg_id` a JSON **number** not a quoted string and no extra keys
  (`dropQueuedMessage_sendsDequeueMessageMatchingWireContract`, AC #1/#5); empty ack succeeds and writes
  **no** projection — `observeQueue`/`observeMessages`/`observeLastMessage` for the conversation each show
  only their initial empty/null emission (`dropQueuedMessage_onAck_succeedsWithoutMutatingProjection`,
  AC #2); a server error surfaces `RelayErrorException` exposing `code` + `retryable`
  (`dropQueuedMessage_onServerError_throwsRelayErrorExposingCode`, AC #3); `conversation.not_found` →
  `IllegalArgumentException` (`dropQueuedMessage_onConversationNotFound_throwsIllegalArgument`, AC #3);
  not-connected (`pump.sendResult = false`) → `IllegalStateException` and **does not hang**
  (`dropQueuedMessage_whenSendReturnsFalse_throwsIllegalStateAndDoesNotHang`, AC #4); a
  `queued_msg_id` of `Long.MAX_VALUE` encodes as a bare number with no precision loss — the #720 width
  guard (`dropQueuedMessage_largeQueuedMsgId_encodesAsBareNumber`). **2 facade cases** in
  `StableConversationRepositoryTest`: not-connected throws `IllegalStateException`, and a live delegation
  records `"c7" to 99L` verbatim. All `runCurrent()`-driven, RED→GREEN.
- **`security-sensitive` honored:** send-only outbound; the only inbound boundary is the `error` reply →
  `mapError`, the pre-existing #346 boundary reused **verbatim** (malformed → fallback, never hangs). No
  token/idempotency key (correct — `queued_msg_id` is a monotonic per-conversation ordinal, never recycled,
  so a replayed drop targets an already-consumed id → daemon stale-id reject, no double-effect; the
  `modal_cancel` no-token posture). No injection — `conversationId` is JSON-*encoded* by kotlinx through
  `MobileJson`, not concatenated. **No-log is structural** — `data/repository` + `data/network` carry no
  logger (grep-verified); the frame has no text field, so leaking message *body* through an error is
  structurally impossible. Authorization is daemon-side (validates the `(conversation_id, queued_msg_id)`
  pair against the per-pairing Noise session + per-conversation queue). Architect § Security review **PASS**.
- **Code review PASS** ([PR #468](https://github.com/pyrycode/pyrycode-mobile/pull/468)), zero blocking,
  one NIT (the filename divergence — the correct build-required choice). `connectedAndroidTest` not run (no
  device; data-layer change, no instrumented tests touched).
