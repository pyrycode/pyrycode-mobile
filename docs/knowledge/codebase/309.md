# #309 — Noise session pump: drive the IK handshake + run the open-state `noise_msg` loop (Phase 4)

The **missing foundational layer** of the Phase 4 encrypted-transport chain: the glue that binds the
landed raw WS frame transport ([#306](306.md)) and the landed `Noise_IK` session ([#303](303.md)/[#298](298.md))
into **one** running encrypted session. `NoiseSessionPump` drives the handshake over a connected
[`RelayTransport`](../features/relay-ws-transport.md) (`protocol-mobile.md` § Connection lifecycle →
Phone **steps 3–6**: send `noise_init` → await `noise_resp` within 10 s → derive transport ciphers →
send/receive `noise_msg`) and runs the single open-state `noise_msg` decrypt/dispatch loop on top of
[`NoiseIkSession`](../features/noise-ik-session.md). It is the **mobile mirror of the Go binary's
`V2SessionManager`** (pyrycode [#446](https://github.com/pyrycode/pyrycode/issues/446) dispatch /
[#433](https://github.com/pyrycode/pyrycode/issues/433) IK wrapper) — encrypted-session consumers (the
remote conversation repository #278, the re-key triggers #304) attach **here** instead of each
re-implementing the handshake and the decrypt loop. Surfaced during #304's architect review as the gap
that fell through the #301 → #306 (frame transport) / #307 (reconnect supervisor) split.

See the feature doc [`noise-session-pump.md`](../features/noise-session-pump.md) for the evergreen "how
the pump works / what plugs into it" reference. This file is the implementation record. **No new ADR** —
consumes [ADR 0004](../decisions/0004-vendor-noise-java-crypto.md) (vendored `noise-java` suite) and
[ADR 0005](../decisions/0005-okhttp-websocket-engine.md) (OkHttp WS engine) via #303/#306; aligns with
pyrycode-side ADR 024 (Noise_IK for mobile E2E). `security-sensitive` — the asset is the encrypted
application stream (confidentiality + integrity) and the session CipherStates held in RAM.

## Scope

**The orchestration glue only — drive one session over one connection.** Sized **S**, kept whole (the
pre-authorised S→split of peeling outbound `send` was **not** taken: it is ~15 lines over the *same*
session+transport+responder test scaffold the handshake/inbound loop already stands up — splitting
would duplicate the harness to test 15 lines). The pump **owns**: a connection-scoped `CoroutineScope`,
the `NoiseIkSession` built via `NoiseSessionFactory.create()`, the handshake drive to an open session,
the **single** inbound collector that decrypts each `noise_msg`, the outbound encrypt+frame path, and
clean lifecycle teardown tied to the transport. Out of scope, by design and named in the spec:

- **The socket / reconnect / backoff** — [#306](306.md) + the sibling supervisor [#307](307.md). The
  pump receives an **already-`Up`** transport and never calls `connect()`; it collects only `inbound`
  (the supervisor owns `events`).
- **The crypto state machine or re-key mechanism** — [#303](303.md). `writeRekeyInit`/`readRekeyResp`
  are **not** called here; the open-state `when (frame.type)` `else` branch is the clean **#304 seam**
  where re-key later inserts a `noise_resp` branch.
- **Typed app-message / wire↔domain mapping** — #278 builds that on this pump's `Envelope` surface.
- **DI wiring** — ships **dormant** (no Koin binding, no consumers — confirmed by grep: zero references
  to `NoiseSessionPump`/`PumpState` outside its own two files). A layer-up coordinator (#302) constructs
  a fresh pump per connection off `RelayConnectionSupervisor.currentConnection`; **that wiring is #302's
  job, not this ticket's** (and #302 landed before this pump existed, so the seam is still unwired —
  adding a binding now would be dead code).

## Summary

**One new production file** (`NoiseSessionPump.kt`, 218 lines, **2** exported types) verified by **one
new JVM test file** (`NoiseSessionPumpTest.kt`, 493 lines, **14** `@Test`). **Purely additive: all-new
code, no Koin binding, no gradle change, no consumer edits — zero edit fan-out.** No new dependency.

The load-bearing facts, all test-pinned:

1. **Handshake drive to `Open` (steps 3–6), one signal.** `start()` is single-use (a second call throws
   `IllegalStateException`) and launches **one** coroutine: `factory.create()` → send a `noise_init`
   frame (the encrypted `hello`+token rides sealed inside `writeInit()`) → await the first inbound frame
   **bounded by the 10 s deadline** → require `type == "noise_resp"` → `readResp()` → `state.value =
   Open(connId)`. `state: StateFlow<PumpState>` (`Handshaking → Open(connId) → Closed(cause)`) **is** the
   handshake-completion signal consumers observe (`state.filterIsInstance<Open>().first()`) before sending.
2. **One sequential collector for the connection's lifetime.** The handshake `.first()` (bounded by
   `withTimeoutOrNull(handshakeTimeoutMs)`) and the open-state `.collect()` are the **same** logical
   consumer of #306's single-consumer, `receiveAsFlow()`-backed `inbound` — sequential re-collection
   *distributes* (never duplicates) elements, and the channel buffers anything arriving in the gap, so
   no frame is lost. Code review confirmed this works against production `OkHttpRelayTransport.inbound`
   (a `Channel.BUFFERED` `receiveAsFlow()`), not just the test fake. **Not split across two coroutines**
   — that would fight #306's contract and force a fragile hand-off. (Go built the equivalent as one
   `V2SessionManager`.)
3. **Open-state dispatch is a clean `when (frame.type)`.** `noise_msg` → `decrypt(base64Decode(data))`
   → `MobileJson.decodeFromString<Envelope>` → emit on `inbound` **only after a successful decrypt +
   parse** (never surface an unauthenticated/partial frame). `else` → teardown — the ordered encrypted
   stream **cannot skip a frame**, so an unknown type / base64 / decrypt / parse failure tears the
   session down rather than dropping. The `else` is the **#304 re-key seam**.
4. **Outbound `send(Envelope): Boolean` — the encrypt→enqueue pair is one critical section.** Returns
   `false` (no frame) unless `Open`, else (under `synchronized(outboundLock)`) `encrypt` → `base64Encode`
   → `transport.send(noise_msg)`. The lock spans **both** ops because the AEAD nonce is a per-session
   monotonic counter the wire does not carry: if two concurrent sends enqueue out of encrypt order the
   receiver MAC-fails the reordered frame and the session dies. The session's own `@Synchronized` covers
   `encrypt` alone, not the gap to `transport.send` — so the pump's lock is load-bearing. A `send` racing
   teardown catches `encrypt`'s `IllegalStateException` and returns `false` (no nonce consumed, no throw).
5. **One idempotent fail-closed teardown for every trigger.** `teardown(cause)` is CAS-guarded
   (`terminated.compareAndSet`) and runs once for a handshake fault, a fatal open-state frame, transport
   `Down`, or `close()`. It is a **non-suspend `fun`**: `state = Closed(cause)` → `inboundChannel.close()`
   → `session?.close()` (**wipes keys**) → `transport.close()` (idempotent; active on the fatal path so
   the supervisor sees `Down` and reconnects) → `scope.cancel()` **last**. The key-wipe is never behind a
   cancellable suspension. `cause == null` ⟺ a clean `Down`/`close()`; non-null ⟺ a protocol/crypto fault.
6. **`Down` detection = `inbound` completing; no `events`.** When the open-state `collect` returns
   normally (#306 completes `inbound` on the terminal `Down`), the drive calls `teardown(null)`. The pump
   **never reads `events`** (owned by #307) — keeping the two single-consumer contracts clean (the
   supervisor owns `events`, the pump owns `inbound`). Not resumable: a fresh connection builds a fresh
   pump (Noise ephemerals are per-handshake).
7. **No logs, category-only causes.** The pump emits **no** logs/telemetry; every failure surfaces only
   via `Closed(cause)`, a `NoiseSessionException` whose message is category-only (`"noise_resp not
   received before the handshake deadline"`, `"expected noise_resp as the first handshake frame"`,
   `"unexpected open-state frame type"`, `"session is not available"`) — never interpolating `frame.data`,
   plaintext, or token (#303's contract carried up).

## Patterns established

- **Bind two single-shot byte-array primitives into one running session with a single sequential
  collector.** #303 (`NoiseIkSession`) is byte-array-in/out and #306 (`RelayTransport`) is
  content-blind-frames-in/out — both had **zero callers**. The pump is the missing driver. The key
  discipline: the `.first()` (handshake) and `.collect()` (open-state) are *one* consumer of the
  single-consumer `inbound`, exploiting that a `receiveAsFlow()`-backed channel *distributes* across
  sequential collections. When a layer below declares a single-consumer stream, drive it from exactly one
  coroutine and lean on sequential re-collection rather than splitting the path — splitting forces a
  fragile hand-off and fights the contract.
- **A `StateFlow<sealed PumpState>` is both the handshake-completion signal and the lifecycle/teardown
  signal — one source of truth.** `Open(connId)` is the "begin sending" gate; `Closed(cause)` is terminal
  with `cause == null ⟺ clean`. Consumers observe one flow for "ready" and "dead" instead of a separate
  completion callback + error channel. Reach for a single sealed-state `StateFlow` when "I'm ready" and
  "I'm done/failed" are points on the same lifecycle, not orthogonal events.
- **The ordering lock must span the *whole* encrypt→enqueue pair, not just the AEAD op.** The session's
  `@Synchronized` protects `encrypt` alone; it does **not** cover the gap to `transport.send`. Because the
  AEAD nonce is an implicit per-session counter (the wire carries no nonce), wire order must equal encrypt
  order or the receiver MAC-fails. The pump adds `synchronized(outboundLock)` across both calls — the
  deterministic floor under the single-pump contract (belt-and-suspenders, same fabric distinction as
  #298/#303's nonce-reuse net). *General rule: when an implicit ordering invariant (counter, sequence
  number) spans two calls, the lock must span both, even if each call is individually atomic.*
- **Fail-closed teardown is one CAS-idempotent, non-suspend funnel.** Every trigger (handshake fault,
  fatal frame, `Down`, `close()`) converges on `teardown`, which does its synchronous cleanup
  (state → channel close → key-wipe → transport close) **before** `scope.cancel()` — so cancellation can
  never skip the key-wipe, and callers from inside the collector and from outside are both safe. The
  per-branch error fan-out (7 failure rows in the spec's table) collapses to one path with no per-branch
  logging, which is *why* this stayed sized **S**.

## Lessons learned

Lifted from the PR's *Lessons learned* section + the code review:

- **`kotlinx-coroutines-test` `backgroundScope` coroutines are deliberately NOT drained by
  `advanceUntilIdle()`** (that is the point of `backgroundScope` — it never blocks idle). A "no leaked
  coroutine" assertion that collects `inbound` and checks `job.isCompleted` must launch the collector as a
  **foreground child of the test scope** (`launch { … }` directly in `runTest`), so `advanceUntilIdle()`
  drains it *and* `runTest`'s structured concurrency enforces it completes — both are real leak checks.
  Launched in `backgroundScope`, the assertion would pass vacuously. (See `openSession`'s collector at
  `NoiseSessionPumpTest.kt:327`.)
- **`send` consumes an AEAD nonce *before* `transport.send` can report failure — a `false` return on an
  `Open` session means the session is effectively spent, not "retry this envelope."** OkHttp's
  `WebSocket.send` returns `false` on a full 16 MiB outgoing buffer (not only when closed), so a
  live-but-backpressured socket can drop a frame *after* its nonce was burned, leaving a gap the server
  MAC-fails → the session dies → the supervisor reconnects with a fresh handshake. This is inherent to the
  encrypt-then-enqueue layering and is **within** the architect's documented "reorder/drop = availability
  bug → fresh handshake" envelope (it self-heals), so it was a [NIT], not a blocker. **Awareness note for
  #278's `send` call site: treat a `false` on an `Open` session as "the session is spent," not as a
  retry-the-same-envelope signal.**
- **Spotless/ktlint is a hard QA gate even on a test file.** The first QA-gate run failed
  `:spotlessKotlinCheck` on `NoiseSessionPumpTest.kt` (ktlint wrapping of chained calls + a single-param
  constructor); fixed mechanically via `./gradlew spotlessApply` (commit `5fa44ad`), no behaviour change.
  Run `spotlessApply` before pushing new files. (Matches #306's "format failures are not
  baseline-comparable" QA posture.)

  synchronous (no suspension point to cancel at), so purely a consistency nit.
