# #391 — Relay-leg connection status: branch the 4404 close into a distinct `DaemonAbsent`

The **relay-leg half** of an honest two-part connection status. The relay path has two
independently-failing legs — **phone → relay** and **relay → pyrycode daemon** — but
[`RelayConnectionSupervisor`](../features/relay-reconnect-supervisor.md) used to expose one
socket-level [`ConnectionState`](../features/connection-state.md) and retry *every* `Down`
uniformly (the **`#308 seam`**), so the relay's `4404 "no server"` close (relay reachable, but no
daemon registered behind it) was indistinguishable from a network/connect failure — both just
retried. This slice introduces a new relay-leg model,
[`RelayLinkStatus`](../features/relay-link-status.md), as the supervisor's single source of truth and
branches `4404` into a distinct `DaemonAbsent` while keeping the existing redial schedule. The
Noise-session-readiness half (the pyrycode leg) and the combined `{relay, pyrycode}` model are the
sibling **#392** (`blockedBy #391`), which consumes the `relayStatus` signal this slice produces.

**No server/relay/daemon change** — the `4404` close is already delivered on
`TransportEvent.Down.code` (shipped with [#306](306.md)). **No heartbeat, no status endpoint.**
Split from #389 (the two-part-status parent) → #391 relay leg + #392 pyrycode-leg + combined.
`security-sensitive` (an untrusted relay-controlled close code crosses into trusted state).

## Summary

One new portable model file plus a focused rewrite of the supervisor's state plumbing. The backing
`MutableStateFlow` is **retyped** from `ConnectionState` to `RelayLinkStatus` (initial `Connected`),
making the leg the single source of truth; the legacy 4-case `ConnectionState` is **derived
per-collector** via a new `internal RelayLinkStatus.toConnectionState()` (`DaemonAbsent → Offline`),
so every existing consumer — including the exhaustive-`when` [`ConnectionBanner`](../features/connection-banner.md)
— is untouched (Strangler Fig). The `#308 seam` Down arm sets a loop-local `daemonAbsent` flag from
`event.code == 4404`, threaded into `backoff(attempt, daemonAbsent)`, which emits a steady
`DaemonAbsent` (no per-second countdown) on the **same** jittered-backoff schedule and keeps
redialling, so the leg flips off the instant a daemon registers and the next dial succeeds. Every
other code — `4401`, `1006`, `1000`, and a `null` dial failure — stays on the existing
`Reconnecting`/`Offline` path. No DI change: #392 fetches `relayStatus` off the concrete supervisor
exactly like `currentConnection`.

## Patterns established

- **Strangler-Fig leg type, with the legacy single-signal model derived from it.** When a new,
  richer model must coexist with a legacy one that an exhaustive `when` (no `else`) consumes, introduce
  the new type (`RelayLinkStatus`) as the **single source of truth** and **derive** the legacy type
  (`ConnectionState`) from it per-collector via a pure mapping fun — rather than adding a case to the
  legacy sealed class. Adding `DaemonAbsent` to `ConnectionState` would have broken
  `ConnectionBanner.kt`'s exhaustive `when` at compile time and forced premature banner UI work; the
  banner is re-pointed to #392's *combined* model anyway. This keeps the blast radius at the producer
  (`state` is `private`; the retype is internal), leaves every consumer untouched, and lets #392 make
  the combined model the real source later. The reusable shape for "new model alongside old, old
  derived."
- **A new concrete-supervisor signal is exposed as a plain public property, not via an interface or
  DI.** `relayStatus: StateFlow<RelayLinkStatus>` is added as a public `val` on the concrete
  `RelayConnectionSupervisor` (mirroring `currentConnection`), **not** as a new `ConnectionStateSource`
  method and **not** a new Koin binding. The supervisor is already bound as its concrete type, so #392
  fetches `relayStatus` via `get<RelayConnectionSupervisor>()` with zero DI change — the same pattern
  the `RelayRepositoryCoordinator` uses for `currentConnection`. Widening the shared interface for a
  not-yet-consumed signal would ripple through every `ConnectionStateSource` impl needlessly.
- **An untrusted protocol code crosses into trusted state at exactly one integer comparison.** The
  relay-controlled WS close `code` enters trusted state only at `event.code == RELAY_NO_DAEMON_CLOSE`.
  No relay-supplied `reason` string or `cause` `Throwable` flows into the model — `DaemonAbsent` is a
  static `data object` carrying no relay text. Integer `==` cleanly excludes `null` (dial failure /
  malformed stored data) and every other code, so those can't masquerade as `DaemonAbsent`. The
  no-log contract holds: the branch reads `code` only to compare it.

## Lessons learned

- **The `DaemonAbsent` backoff must still consume exactly one `random.nextDouble()` per attempt**
  (via the shared `jitteredBackoffMs`), or the seeded-`Random` replay (`intervalsFor`) drifts out of
  alignment between the daemon-absent and normal paths. Computing `intervalMs` *before* the
  `daemonAbsent` branch is what keeps the replay aligned — and what lets the interval-band assertion
  prove "same schedule, **reused** not replaced" rather than just "some wait happened." (Lifted from
  the PR's Lessons-learned section; confirmed by the code-review correctness trace.)
- **`observe() = state.map { it.toConnectionState() }` can emit duplicate consecutive `Offline`** when
  the leg toggles `DaemonAbsent ↔ Offline` (both derive to `Offline`). Harmless today and **left
  un-fixed deliberately** (Evidence-Based Fix Selection): the sole consumer
  (`ThreadViewModel`, `:192-199`) wraps `observe()` in `.stateIn(...)`, which conflates the duplicate
  away, and the interface contract never promised distinct-only emissions. A defensive
  `.distinctUntilChanged()` would future-proof a hypothetical raw collector that doesn't exist — so it
  was deferred, not added. (Code-review NIT, non-blocking.)

## Verification

- `./gradlew check assembleDebug` green per PR [#393](https://github.com/pyrycode/pyrycode-mobile/pull/393)
  — 14 supervisor unit tests (the six new branching tests + the eight pre-existing, which pass
  unchanged as the legacy-derivation regression guard). Unit-only per the spec; `connectedAndroidTest`
  N/A — no device, no UI in this data-layer slice.
- **Code review: PASS** ([PR #393](https://github.com/pyrycode/pyrycode-mobile/pull/393)) — one
  non-blocking NIT (the duplicate-`Offline` derivation, above). The reviewer verified all four ACs
  have tests, traced the backoff/seeded-`Random` arithmetic (exactly one `nextDouble()` per backoff on
  either path), and confirmed `code == 4404` cleanly excludes `null`.
- **Security review: PASS** (architect self-review in the spec, label-gated). Verified
  deterministically that no `Log.*`/`Timber`/`println` was added to the supervisor; the trust boundary
  is the single `event.code == RELAY_NO_DAEMON_CLOSE` comparison; no new storage/IPC/crypto/TLS/timeout
  surface; a hostile relay spamming `4404` only forces `DaemonAbsent` + continued redial on the
  **same** capped-exponential backoff (no tighter loop, no amplification). `4401` auth-reject halt/re-pair
  is the `#308 seam`'s eventual *other* branch — explicitly out of scope.
