# #342 — derive Noise static-key fingerprint (BLAKE2s-256[:8] colon-hex)

The pure, `data/`-portable derivation of the server static-key fingerprint the user reads against the
desktop's `Static-key fp:` line during QR pairing to catch a wrong-server / MITM. Adds
`staticKeyFingerprint(staticKey: ByteArray): String` in `data/crypto`: the full **256-bit** BLAKE2s
digest of the 32-byte X25519 static public key, truncated to the **first 8 bytes**, rendered
colon-separated lowercase hex. **Byte-for-byte parity with pyrycode#432's `Fingerprint([32]byte)
string` is the entire contract** — a one-byte divergence makes the human comparison meaningless and
silently defeats the check. Derivation only; the confirm UI that displays the fingerprint and gates the
persist is the separate downstream slice this ticket split from (#321). See the evergreen
[Static-key fingerprint](../features/static-key-fingerprint.md) feature doc.

## Summary

One new production file, one new test file — **+103 LOC, zero modifications to existing files**. No DI
binding, no model change, no new dependency (reuses the vendored `Blake2sMessageDigest` from
[ADR 0004](../decisions/0004-vendor-noise-java-crypto.md)). PO sized this S; the architect dropped it
to XS. The body is two lines behind a `require` guard. This ticket creates the first
`data/crypto` **test** directory.

## Files touched

- **`data/crypto/StaticKeyFingerprint.kt`** *(new, 38 LOC)* — one public top-level function
  `fun staticKeyFingerprint(staticKey: ByteArray): String`. Body:
  `require(staticKey.size == 32) { "static key must be 32 bytes" }`, then
  `Blake2sMessageDigest().digest(staticKey)` (full 32-byte digest) →
  `digest.toHexString(0, FINGERPRINT_BYTES, COLON_HEX)` where
  `COLON_HEX = HexFormat { bytes.byteSeparator = ":" }` and `FINGERPRINT_BYTES = 8`. Pure,
  synchronous, no I/O, no logging; only import is `com.southernstorm.noise.crypto.Blake2sMessageDigest`
  (no `android.*`). The `require` message is a fixed string — never interpolates key bytes.
- **`test/.../data/crypto/StaticKeyFingerprintTest.kt`** *(new, 65 LOC, 6 cases)* — JUnit4, mirrors
  `NoiseSuiteSmokeTest`'s idiom (this is the first file under `test/.../data/crypto/`). Cases:
  `pinnedZeroVectorMatchesServer` (the **hard-coded literal** `"32:0b:5e:a9:9e:65:3b:c2"`, never
  recomputed — the byte-for-byte parity assertion), `shapeAndLengthInvariant` (len 23 +
  `^[0-9a-f]{2}(:[0-9a-f]{2}){7}$`), `bytesAboveSignBitRenderAsTwoHexChars` (the zero vector's
  `a9`/`9e`/`c2` bytes exercise the sign-extension trap), `derivationIsDeterministic`,
  `rejectsTooShortKey` (31 bytes → `IllegalArgumentException`), `rejectsTooLongKey` (33 bytes).

## Patterns established

- **Hard-code the known-answer vector; never recompute it in-test.** The pinned zero vector is a
  literal `"32:0b:5e:a9:9e:65:3b:c2"`, not `staticKeyFingerprint(...)` re-run through the same
  primitive — a recomputed expectation is tautological and passes against a silently-wrong
  implementation. Any *additional* KAT must also be an offline-computed literal. This is the discipline
  that makes a byte-for-byte parity claim actually mean something; reuse it for any cross-implementation
  parity test.
- **Hash bytes in `data/crypto`; keep the base64 decode in `data/network`.** This function takes the
  raw 32-byte `ByteArray`, mirroring the server's `Fingerprint([32]byte)`. The base64-std → bytes
  decode (the QR-alphabet concern) stays in `data/network` (`base64StdDecode`) and is the downstream
  caller's job — the crypto-derivation layer never pulls in the encoding boundary.
- **Full-digest-then-truncate is the parity-safe BLAKE2s pattern.** Compute the full 256-bit digest
  then slice the first 8 bytes — never a BLAKE2s *configured* to emit 8 bytes ("BLAKE2s-64"), which
  folds output length into its init block and yields a different digest. Guaranteed-safe here because
  the vendored `Blake2sMessageDigest` is fixed-256-bit by construction; the rule guards a future swap.

## Lessons learned

Lifted from [PR #344](https://github.com/pyrycode/pyrycode-mobile/pull/344)'s *Lessons learned*:

- **Kotlin 2.2's `ByteArray.toHexString(start, end, HexFormat { bytes.byteSeparator = ":" })` is the
  one-call, sign-extension-safe hex render.** It is lowercase by default and byte-width-correct, so it
  sidesteps the signed-`Byte` trap — `"%02x".format(b)` renders `ffffffa9` for any byte ≥ `0x80`
  without an `and 0xFF` mask. **No `@OptIn` needed at 2.2.x** (the stdlib `HexFormat` API and
  `ByteArray.toHexString` are stable). This is now the preferred hex-formatting idiom in `data/`.
- **Construct `Blake2sMessageDigest()` directly — `MessageDigest.getInstance("BLAKE2S-256")` throws on
  Android.** The algorithm name has no registered JCA provider on Android, so the factory lookup
  `NoSuchAlgorithmException`s at runtime. Direct construction of the vendored class is provider-free and
  deterministic. (Confirmed in the spec's *Files to read first* and the code-review notes.)

## Verification

- `./gradlew test`, `./gradlew lint`, `./gradlew assembleDebug`, `./gradlew spotlessCheck` — all green
  (per PR #344). Pure JVM derivation; **no instrumented tests** (no Android framework, no device, no
  `androidTest` changes).
- **Code review: PASS** — no findings (no MUST FIX / SHOULD FIX / gating NIT). Verified: byte-for-byte
  parity via the hard-coded literal vector; the `security-sensitive` SHOULD-FIX (fixed `require`
  message, no key-byte interpolation) honored at `StaticKeyFingerprint.kt:34`; no "BLAKE2s-64" trap
  (`Blake2sMessageDigest` fixed-256-bit, constructed directly); sign-extension avoided; `data/`-portable
  (no `android.*`); all five ACs satisfied.
- **Security review: PASS** — architect self-review in the spec (`security-sensitive`). The function
  *is* a security control (the human-verifiable MITM fingerprint); input is a **public** key and output
  a digest of it — neither secret. The "displays a wrong fingerprint as valid" attack is closed two
  ways: implementation drift is caught by the hard-coded (non-recomputed) fixed-vector test, and
  wrong-length input is rejected by `require` rather than silently hashed.
