# Ticket #458 — send the `interrupt` control frame

**Issue:** [#458](https://github.com/pyrycode/pyrycode-mobile/issues/458) ·
**Spec:** [`docs/specs/architecture/458-send-interrupt-control-frame.md`](../../specs/architecture/458-send-interrupt-control-frame.md) ·
**PR:** [#469](https://github.com/pyrycode/pyrycode-mobile/pull/469) ·
**Feature doc:** [Interrupt send path](../features/interrupt-send-path.md) ·
Phase-3 (epic pyrycode#597) phone control. Split from #430; sibling **#459** (`feat(ui): interrupt
affordance on the busy turn`, `blockedBy #458`) owns the visible control + busy-state gating. Size **S**,
`security-sensitive`.

## Summary

Adds the phone's **outbound send path** for the bare v2 `interrupt` control frame — the wire half of
pressing **Esc** on a running turn (pyrycode#707: the daemon maps it to `turnevent.Cancel` → one Esc
keystroke to the supervised claude). A vertical slice mirroring the `modal_cancel` outbound path
([#451](451.md)) one-for-one — `RemoteConversationRepository.interrupt()` →
`RelayRepositoryCoordinator.interrupt()` passthrough → DI-injected lambda → `ThreadViewModel.onInterrupt()` —
with **two departures**
the fire-and-forget wire contract requires: plain `pump.send` (no awaited reply, so it can't hang) and
**inert empty-catch swallowing** (no error channel, no log). The frame is bare (`{type:"interrupt"}`, empty
payload, connection-level — **no `conversation_id`**), the `interactive` gate is server-authoritative, and
the phone **always sends** (minimal client). **No UI** — the affordance is #459. Built test-first, RED→GREEN;
all gates green; code review **PASS**, zero findings.

## Load-bearing design choices

- **Fire-and-forget, not request/reply.** Interrupt gets no ack/error/broadcast from the daemon, so it uses
  plain `pump.send` (returns `false` when not `Open`) and never `sendAndAwaitReply` — awaiting a reply that
  never comes would hang the caller. This is the single behavioural difference from `cancelModal` at the
  repo layer.
- **Bare connection-level frame — no `conversationId` anywhere in the send path.** Repo method, coordinator
  method, and VM action all take none. The action lives on the per-conversation `ThreadViewModel` (where the
  busy turn is visible to #459), but the frame stays connection-level: claude serialises turns ⇒ at most one
  running turn ⇒ a bare frame interrupts it unambiguously. **No payload DTO** — `JsonObject(emptyMap())`.
- **Always send; no client-side `interactive` suppression.** The gate is server-authoritative and
  fail-closed (a non-interactive connection's interrupt is dropped daemon-side). An Esc-only bare frame
  argues for the minimal client; the phone does not check its negotiated capability set before sending.
- **Inert on failure — empty catch bodies.** No error channel (no `modalSendErrors` analog), no log. The
  not-connected path surfaces as `IllegalStateException` and is swallowed; any user-visible surface is #459.
- **The injected-lambda placement is the connection-level (app-level) shape** — `answerModal`/`cancelModal`
  ([#438](438.md)/[#451](451.md)), **not** the defaulted-interface-method shape (`requestScreenSnapshot`
  [#375](375.md) / `dropQueuedMessage` [#466](466.md)). The discriminator is the payload: a frame keyed by
  `conversation_id` is reachable through the facade the thread already holds; a frame with no
  `conversation_id` (modal-keyed, or here connection-level) is fetched off the concrete coordinator and
  injected as a defaulted suspend lambda. Interrupt is the third precedent for the injected-lambda branch.

## The retained-but-unreachable `RelayErrorException` catch

On the real fire-and-forget path interrupt never awaits a reply, so `RelayErrorException` (which only
originates from a correlated server `error` inside `sendAndAwaitReply`) **cannot** occur. The catch is kept
deliberately, and **the KDoc says why** so code-review doesn't read it as dead code: (1) AC #4 mandates a
relay-error-swallow test, exercised via the injected double throwing `RelayErrorException`; (2) it preserves
the exact structural twin of `sendCancel`, so the two outbound senders read identically and a future server
that ever replied to `interrupt` with an `error` would already be handled.

## Patterns established

- **A connection-level (no-`conversation_id`) outbound control send is injected as a defaulted suspend
  lambda off the coordinator passthrough — not put on the `ConversationRepository` interface.** This
  sharpens the [#466](466.md) placement rule into a two-way split keyed on the payload: per-conversation
  (`conversation_id` present) → interface method + facade delegation; connection- or modal-level (no
  `conversation_id`) → concrete coordinator passthrough + defaulted VM lambda. `interrupt` joins
  `answerModal`/`cancelModal` on the latter branch.

## Lessons learned

- **A ViewModel inert-swallow test can false-green.** An uncaught throw from `viewModelScope.launch` routes
  to that scope's own `SupervisorJob` exception handler — it does **not** fail `runTest` (the VM scope is a
  separate scope, not the test's). So a `count == 1` assertion alone proves the lambda was *called*, not that
  the production `catch` actually *ran*: a missing/mis-ordered catch would crash the launched coroutine and
  the test would still pass. The test captures uncaught coroutine exceptions via
  `Thread.setDefaultUncaughtExceptionHandler` and asserts none fired — the only signal the typed catch has
  teeth (verified by removing the production catch → the test goes RED). Lifted from the PR #469 *Lessons
  learned*. (This is the concrete shape of the `#451` false-green that
  [[catch-illegalstate-swallows-cancellation]] warns about, now exercised for an empty-catch sender.)
- **Catch ordering is load-bearing** (reused from #451): `catch (CancellationException) { throw e }` **must
  precede** `catch (IllegalStateException)` because `java.util.concurrent.CancellationException extends
  IllegalStateException` on the JVM — reversing it would swallow structured cancellation when `viewModelScope`
  is cancelled mid-send. The cancellation test drives the real teardown via `ViewModelStore.clear()` and
  asserts no crash / no leaked exception. See [[catch-illegalstate-swallows-cancellation]].

## Security (`security-sensitive`)

Architect § Security review **PASS** (all 9 categories); code review confirmed the diff matches the posture:

- **Outbound-only, no untrusted parse.** `interrupt()` / `onInterrupt()` take no arguments and the payload is
  a compile-time-constant `JsonObject(emptyMap())` — zero injection surface, no untrusted→trusted crossing.
- **Cannot ride an unauthenticated channel.** `pump.send` transmits only over an `Open` (post-Noise_IK,
  authenticated) session; a pre-`Open`/null pump throws `IllegalStateException` (coordinator null-guard + repo
  `check`) → inert.
- **No token/nonce by design** — the frame is replay-safe (a replayed Esc with no running turn is a daemon
  no-op), so the deliberate absence of an idempotency key is the protocol's design, not an omission.
- **Permission-gate-exempt** — interrupting one's own paired session is a normal paired action (pyrycode#707
  trust model), not introduced here. **Never-log** inert-swallow satisfies the no-leak contract. No new
  components/exports, no crypto/RNG, no file I/O.
- OUT OF SCOPE → #459: an overlay/accessibility tap on the affordance could trigger an interrupt, but severity
  is negligible (a replay-safe no-op, no data exfiltration or privilege gain).
