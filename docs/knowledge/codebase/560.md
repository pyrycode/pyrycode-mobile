# #560 — Wire `changeWorkspace` over v2 `change_workspace`

**Issue:** [#560](https://github.com/pyrycode/pyrycode-mobile/issues/560) · split from #533 ·
**Spec:** `docs/specs/architecture/560-*.md` ·
**PR:** [#563](https://github.com/pyrycode/pyrycode-mobile/pull/563), `659f3ef` ·
**Feature doc:** [Remote conversation repository](../features/remote-conversation-repository.md) §
`changeWorkspace` (new) ·
Size **S**, `security-sensitive` (PASS).

## Summary

Replaces `RemoteConversationRepository.changeWorkspace`'s `UnsupportedOperationException` stub with a
live v2 round-trip against the daemon's `change_workspace` (server pyrycode#823): encode a new
`ChangeWorkspacePayloadDto {conversation_id, cwd}` → `sendAndAwaitReply` → decode the **reused**
`conversation_updated` reply through the existing #318 `ConversationResponseDto` boundary →
`upsertConversation` (server-authoritative `cwd` folded into the projection). This is the **fourth**
conversation write-verb (after [rename](530.md), [archive/unarchive](549.md), [delete](532.md)) and,
per the [`README`](README.md) note in #549, was the **last** throwing stub on the class — the interface
now compiles with every mutation live.

"Workspace" **is** the conversation's `cwd`; there is no separate workspace-id concept. The interface's
`changeWorkspace(...): Session` signature is **unchanged** — the reply carries no session identity
(`change_workspace` performs no session transition; #823 Out-of-Scope, AC #4), so the method returns a
vestigial placeholder `Session` (empty `id`/`claudeSessionUuid`), the same shape `startNewSession`
(#539) established for exactly this "interface forces a `Session`, wire yields none" situation. Data
layer only — no UI/ViewModel change; surfacing is [#561](https://github.com/pyrycode/pyrycode-mobile/issues/561)
(blocked by this ticket), the rung-3 e2e is [#562](https://github.com/pyrycode/pyrycode-mobile/issues/562).

## Patterns established

None new — this is the fourth confirming instance of the `rename`-shaped mutation template
(build-request → `sendAndAwaitReply` → decode-reply → confirmed-fold → return), the same "mutation
minus/plus a field" cost profile #530's doc already named. Worth repeating: **when the interface forces
a return type the reply can't satisfy (no session identity here, same as `startNewSession`), return an
honestly-empty placeholder rather than fabricate or cascade a signature change** — the architect's
22-site fan-out estimate for changing `: Session` → `: Conversation`/`Unit` (interface + fake body +
facade + 18 test-double overrides) is why this stayed size S instead of ballooning into a split.

## Lessons learned

- **This was the last throwing stub — worth confirming in the Stubs table, not just noting in prose.**
  #549's doc already flagged "the remaining throwing sibling is `changeWorkspace`"; this ticket closes
  that loop. The feature doc's Stubs table and "now-live" method list are updated accordingly (see
  Links). Future Phase-4 conversation-mutation work has no more `RemoteConversationRepository` stubs to
  fill — the class's interface surface is fully wired.
- **Fake-vs-remote behavioural divergence is sometimes the correct outcome, not a bug to chase.**
  `FakeConversationRepository.changeWorkspace` mints a fresh session (a session transition), while the
  real daemon explicitly does not (#823 Out-of-Scope). The architect named this and deliberately left the
  fake untouched: aligning it would cascade across the same 22 sites as a signature change, for no
  in-scope benefit (evidence-based deferral — no observed failure from the divergence). Don't "fix" a
  fake to match a real implementation's edge-case posture unless a concrete bug is observed.
