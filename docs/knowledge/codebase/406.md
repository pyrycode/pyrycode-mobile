# Ticket #406 — surface live turn-state into the conversation thread ViewModel

**Issue:** [#406](https://github.com/pyrycode/pyrycode-mobile/issues/406) ·
**Spec:** [`docs/specs/architecture/406-live-turn-state-thread-viewmodel.md`](../../specs/architecture/406-live-turn-state-thread-viewmodel.md) ·
**PR:** [#408](https://github.com/pyrycode/pyrycode-mobile/pull/408) ·
**Feature doc:** [Turn-state thinking flag](../features/turn-state-thinking-flag.md) ·
Split from #386. Size **S**, not `security-sensitive` (no transport/crypto/wire/model change — it
moves object references and reduces an already-decoded event stream).

## Summary

Closes the reachability gap that kept the decoded `turn_state` stream from the thread ViewModel. The
typed [`LiveSessionEvent`](../features/live-session-events.md) events ([#385](385.md)) live on the
**concrete**, connection-scoped `RemoteConversationRepository.liveSessionEvents` — **not** on the
`ConversationRepository` interface the [`ThreadViewModel`](../features/thread-screen.md) consumes. This
slice threads that non-interface surface up through
[`RelayRepositoryCoordinator`](../features/relay-repository-coordinator.md) (the exact
`registerPushToken` #359/#365 and `connectionStatus` #392/#398 precedent) as a reconnection-surviving
`liveSessionEvents: Flow<LiveSessionEvent>` seam, and `ThreadViewModel` reduces the **active**
conversation's latest turn phase to a sibling `isThinking: StateFlow<Boolean>`. **No UI** — the flag is
hoisted for the sibling indicator composable in #407. Built test-first; all gates green
(`check`/`assembleDebug`); code review **PASS**, zero blocking findings.

## Load-bearing design choices

- **The coordinator seam stays generic.** It exposes the full `Flow<LiveSessionEvent>`, not an
  `isThinking`/turn-state projection. Reducing to "latest phase" is a per-consumer concern; keeping the
  seam generic lets #387 (tool correlation) and #337 (assistant text) subscribe off the same flow with
  no further coordinator change. This is the third non-interface, connection-scoped surface threaded up
  through the coordinator (after `registerPushToken` and `connectionStatus`) — same lock-step-mirror +
  derived-flow shape.
- **Cold `Flow`, not `stateIn`.** Unlike `connectionStatus` (current-value state → `stateIn(Eagerly)`),
  these are *events* with no current value, so the seam is a cold `Flow` with no scope of its own. Each
  consumer's collection independently observes `activeRemoteRepo` (a `StateFlow`) and subscribes to the
  current repo's `SharedFlow` (both multi-subscriber-safe) — no `shareIn` needed. The code-review NIT
  noted per-subscriber `flatMapLatest` re-derivation is fine at today's consumer count; revisit only if
  the count grows.
- **`isThinking` is a sibling `StateFlow`, not a `ThreadUiState` field.** It mirrors `connectionState`
  exactly: a transient, connection-scoped cross-cutting signal the stateless `ThreadScreen` already
  takes as a **separate** parameter beside `state` (ThreadScreen.kt:70). Folding it into the
  max-arity-5 `state` combine would force a sub-combine restructure and touch the `initialValue`,
  risking AC #5 ("existing tests compile and pass unchanged"). The sibling flow is zero-touch to the
  combine. #407 follows the same separate-parameter pattern for the indicator.
- **The reduction is `mapNotNull` → `stateIn(initial = false)`.** `thinkingTransition` routes by
  `conversationId` first (AC #3 — other conversations return `null`, no emission), then maps the phase:
  `Thinking → true`; `Responding`/`Idle`/`TurnEnd → false`; the non-phase events
  (`AssistantDelta`/`ToolUse`/`ToolResult`) → `null`. `mapNotNull` + `stateIn` means a non-matching
  event produces no emission, so the `StateFlow` **retains its prior value**; the `false` initial value
  covers both "before any turn-state event" (AC #2) and the inert empty-flow default (AC #5).
- **`TurnEnd → false` is deliberate, not redundant.** It guards the thinking→turn_end-direct edge where
  a turn ends straight out of `thinking` with no intervening `responding`/`idle` (AC #2 lists
  `turn_end` as a false case). A dedicated test pins it from a prior `true`.

## Patterns established

- **Threading a generic connection-scoped event stream up through the coordinator.** Where #359/#392
  threaded a *device* concern (`registerPushToken`) and a *derived current-value* (`connectionStatus`),
  #406 establishes the shape for a **generic event stream**: a private `activeRemoteRepo` mirror written
  lock-step in the non-suspending critical section + a public cold `flatMapLatest` flow. Future
  live-event consumers (#387/#337) take this exact `coordinator.liveSessionEvents` off the concrete
  singleton at the `AppModule` factory — **no new Koin binding, no projection baked into the seam.**
- **Reduce a live event stream to a presentation flag with `mapNotNull` + `stateIn`, not a `combine`
  field.** When a VM needs a transient connection-scoped signal independent of its main `state`, expose
  it as a sibling `StateFlow` (like `connectionState`) reduced via `mapNotNull` (return `null` to hold
  the prior value) → `stateIn(WhileSubscribed, initial)`. Keeps the main `state` combine untouched.

## Lessons learned

- **A `mapNotNull`-fed `StateFlow` is the idiomatic "latest-wins with hold" reducer.** Returning `null`
  for events that should not move the flag (other conversations, non-phase events) leverages `stateIn`'s
  retain-last-value semantics — no explicit `scan`/accumulator and no `distinctUntilChanged` needed. The
  initial value does double duty as both the "no event yet" and the "inert default" answer.
- **Test the inert default at the 4-arg call shape.** `isThinking_initialValue_isFalseWithNoLiveSource`
  constructs the VM through the *old* 4-arg `makeVm` (no live source) and asserts `false` — this both
  proves AC #5's inert default and compile-checks that the defaulted ctor param keeps every pre-existing
  construction valid without a fixture cascade.
