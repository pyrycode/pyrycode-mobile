# Ticket #608 — thread row for an unrecognized claude message

**Issue:** [#608](https://github.com/pyrycode/pyrycode-mobile/issues/608) ·
**Spec:** [`docs/specs/architecture/608-unrecognized-message-row.md`](../../specs/architecture/608-unrecognized-message-row.md) ·
**PR:** [#612](https://github.com/pyrycode/pyrycode-mobile/pull/612) (`e457263`) ·
**Feature doc:** [Unrecognized message row](../features/unrecognized-message-row.md) ·
Split from #585. Blocks #609 (decode + fold). Size **S**, `security-sensitive` (architect self-review
**PASS**).

## Summary

Adds `ThreadItem.UnrecognizedMessage` — the thread-row type for a claude message the interactive
daemon's stream-json parser could not understand — and `UnrecognizedMessageRow`, the composable that
renders it: a collapsed one-line pill (warning glyph · client-owned label · offending type in mono ·
site label) that expands in place on tap to show the daemon's payload verbatim. This slice builds only
the row and its type; nothing produces it yet. #609 decodes the `unrecognized_message` wire frame,
stamps `id`/`occurredAt`, and folds it into the thread.

## Files touched

- **`data/repository/ConversationRepository.kt`** (`+49`) — new `ThreadItem.UnrecognizedMessage` data
  class (`id`, `site: UnrecognizedSite`, `messageType`, `raw`, `truncated`, `occurredAt: Instant`) beside
  `SessionBoundary`, and a new top-level `enum class UnrecognizedSite { LineType, AssistantBlock,
  UserBlock, Undecodable }` beside `BoundaryReason`. `id` is documented as a **client-owned** identity
  (the wire frame carries neither a message id nor a `turn_id`) with a uniqueness-per-thread invariant
  that is asserted in tests, not enforced at construction — the same idiom `SessionBoundary` already uses
  for `workspaceCwd`. `messageType` is `""` rather than nullable when `site == Undecodable`, keeping the
  future decode arm total. The `ThreadItem` KDoc is extended to mention the new row alongside
  `SessionBoundary`.
- **`ui/conversations/components/UnrecognizedMessageRow.kt`** (new, 331 lines) — the row itself, cloning
  `ToolCallRow`'s structure (stateful entry point owning a `rememberSaveable` expand toggle, stateless
  `…Content` split, collapsed header as one annotated `Text` at `maxLines = 1`) but **not** its palette:
  container is `colorScheme.surfaceContainer` with a `colorScheme.outlineVariant` border, matching Figma
  `16-28` rather than `ToolCallRow.kt:92`'s drifted `surfaceContainerHigh`/no-border. The `messageType`
  span is appended to the collapsed line only when non-empty (AC 4), styled `FontFamily.Monospace` +

  plain `Text` (never `MarkdownText`, no `SelectionContainer`) with no `maxLines`; a truncation note
  renders below it when `truncated` is set. Ships light/dark preview matrices covering collapsed,
  expanded, truncated, and empty-`messageType`.

## Patterns established

Nothing new — this ticket deliberately reuses established idioms rather than introducing any: the
KDoc-invariant idiom for an unenforced construction constraint (from `SessionBoundary`), the
collapsed-pill-with-in-place-expand structure (from `ToolCallRow`), and the total-`when`-over-a-closed-enum
copy-selection idiom (`siteLabel`, same shape as prior `stringResource`-per-case lookups elsewhere in the
tree).

## Lessons learned

- **A fourth exhaustive `when` over `ThreadItem` lives in a unit test, not just `ThreadScreen`'s three.**
  `RemoteConversationRepositoryTest.threadShape()` (`:5866`) matches exhaustively on `ThreadItem` as a
  test-fixture convenience. Adding the sealed subtype compiles `main` and `androidTest` cleanly and only
  breaks at `compileDebugUnitTestKotlin` — so a survey of `main/` sources alone under-counts the call
  sites a new `ThreadItem` subtype owes. Future additions to the sealed hierarchy should grep test sources
  for exhaustive `when`s too, not just production code.
- **`connectedAndroidTest` uninstalls both APKs when it finishes**, so pulling an artefact a test wrote
  (e.g. a `captureToImage()` bitmap for visual validation against Figma) via
  `adb exec-out run-as <pkg> cat` fails afterwards with `unknown package`. To retrieve such an artefact,
  install both APKs by hand and drive the run directly with
  `adb shell am instrument -w -e class <FQCN> <pkg>.test/<runner>` — this tree's runner is the custom
  `de.pyryco.mobile.e2e.E2eInstrumentationRunner`, not `AndroidJUnitRunner`.
