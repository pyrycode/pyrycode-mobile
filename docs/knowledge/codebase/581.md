## Summary

Adds `interactiveTurn_saveAsChannel_promotesToChannelTier` to `InteractiveStreamE2ETest` — the **eighth**
member of the shipped rung-3 mutation-e2e family, and its **backfill**: save-as-channel shipped in #348,
*before* the real-stack definition-of-done rule (pyrycode-mobile-agents#9), so it was the one operator-facing
daemon-action flow with no rung-3 coverage — and it silently answered `unsupported` on the real wire until
pyrycode/pyrycode#949 registered the daemon handler, while the mobile suite stayed green against its fake
daemon the whole time. Creates a scratch discussion, drives the **real** thread overflow "Save as channel…"
→ `SaveAsChannelDialog` to a runtime-unique channel name, taps "Keep in scratch" (the dialog defaults to
the dedicated-folder radio — see Gotcha below), submits, and asserts the promote round-trip on **three**
durable surfaces: the **thread top bar** re-labels in place (no `PopBack`, unlike delete/archive), the
**`WorkspaceChip` unmounts** (the `isPromoted` tier flip, in-thread, free — the chip is gated
`!isPromoted && !hasMessages` and this scenario sends no message), and after `CD_BACK` the name is
**present on the main list** and **absent from the Discussions-tier drilldown**. Zero production code: one
new always-on `@Test` + six companion constants, one `scripts/e2e-emulator.sh` LIVE-curation edit (septet →
**octet**, still 3 turns — promote is a daemon round-trip, not a claude turn), and the ladder doc — all
landed in this single PR.

## Files touched

- **`app/src/androidTest/java/de/pyryco/mobile/e2e/InteractiveStreamE2ETest.kt`** (+216, one new `@Test`,
  an 8-step scenario):
  1. Land on the channel list (`CD_NEW_DISCUSSION` present), `awaitConnected()`.
  2. Create a plain discussion; wait for the send button. "Save as channel…" is gated `!isPromoted` only
     (**not** `mutationsSupported`), so a fresh discussion reaches it unconditionally.
  3. **Absence guard + tier before-state:** `uniqueName = PROMOTE_NAME_PREFIX + System.currentTimeMillis()`
     asserted `assertCountEquals(0)`; the `WorkspaceChip` asserted present (before-state for the step-6 flip).
  4. Drive the real overflow: `CD_MORE_ACTIONS` → wait for exact `SAVE_AS_CHANNEL_ITEM` ("Save as channel…",
     real U+2026 — a substring match would also hit the dialog's own title, "Save as channel", no ellipsis)
     → tap → wait for `hasSetTextAction() and isFocused()` (disambiguates the dialog's pre-filled, fully-
     selected field from the thread composer, identical hazard/resolution to #537's `RenameDialog`) →
     `performTextReplacement(uniqueName)` → tap `KEEP_IN_SCRATCH_OPTION` → tap `SAVE_AS_CHANNEL_SAVE`.
  5. **Top-bar assertion (in-thread, no PopBack):** `waitUntil` spans the `promote_conversation` round-trip
     for `uniqueName` to appear, then `assertIsDisplayed()`. `SaveAsChannelSubmit` clears
     `pendingSaveAsChannelDialog` synchronously before the suspend call, so the dialog and the top bar never
     hold `uniqueName` simultaneously — same non-collision mechanism as #537.
  6. **`WorkspaceChip` unmount assertion (the tier flip, in-thread):** `waitUntil` for the chip's token
     count to reach 0.
  7. **Main-list presence:** tap `CD_BACK`; wait for the list marker, then wait for `uniqueName` on a row
     and confirm displayed.
  8. **Discussions-drilldown absence (the tier read):** tap `SEE_ALL_DISCUSSIONS`; wait for the **FAB to be
     gone** (not the screen title — `discussion_list_title` and `recent_discussions_section_header` are the
     byte-identical literal "Recent discussions", so the title would match instantly on the main list,
     before navigating, and produce a false green); then assert `uniqueName` absent
     (`assertCountEquals(0)`) — a direct read of the `ConversationFilter.Discussions` projection.
  - New companion constants (all others reused verbatim — `CD_NEW_DISCUSSION`, `CD_SEND_MESSAGE`, `CD_BACK`,
    `CD_MORE_ACTIONS`, `awaitConnected()`, the timeouts): `SAVE_AS_CHANNEL_ITEM = "Save as channel…"`,
    `KEEP_IN_SCRATCH_OPTION = "Keep in scratch"`, `SAVE_AS_CHANNEL_SAVE = "Save"` (kept distinct from

## Patterns established

None new at the harness level — a confirming instance of the rung-3 real-claude scenario shape
(#481/#482/#566/#541/#554/#551/#562/#537's template): create → drive the real affordance → tolerant
substring/presence assert on a runtime-unique token, absence-before → presence-after inversion. This ticket
is notable mainly for **closing a real coverage gap that had already caused a silent production failure**
(the daemon answering `unsupported` while the mobile suite stayed green against its fake) — a concrete
justification for the "backfill pre-real-stack flows" category, distinct from the other seven siblings which
were all covering flows that shipped *with* rung-3 coverage from the start.

## Lessons learned

(Lifted from the PR body's own Lessons-learned section.)

- **`./gradlew` needs `ANDROID_HOME` in a worktree, not just `JAVA_HOME`.** Worktrees carry no
  `local.properties` (gitignored, lives only in the canonical checkout) — every Gradle task fails "SDK
  location not found" until `ANDROID_HOME=~/Library/Android/sdk` is exported. See
  [[worktree-gradle-needs-android-home]].
- **`| tail` masks a Gradle failure's exit code.** A first `compileDebugAndroidTestKotlin` run piped to
  `tail` reported `exit=0` over a `BUILD FAILED` body. Redirect to a file and echo `$?` when the exit code
  is the signal being checked.
- **The main list cannot discriminate channel vs discussion tier — a drilldown is structurally required.**
  `cd_conversation_row` and `cd_discussion_preview_row` are byte-identical format strings (`"%1$s, %2$s"`),
  there are no test tags, and `RecentDiscussionsSection`'s `Column` carries no semantics modifier — so tier
  membership is only readable by navigating into the `ConversationFilter.Discussions`-scoped screen. See
  [[conversation-tier-assertion-hazards]].
- **`discussion_list_title` and `recent_discussions_section_header` are the same literal ("Recent
  discussions"), so the drilldown screen's title cannot be its arrival marker.** Using it would pass
  instantly, before navigating — a false green, since the subsequent absence assertion would then run
  against the main list rather than the drilldown. The FAB's disappearance is the safe marker
  (`DiscussionListScreen` has a Back nav icon and no FAB, unlike the main list).
- **`SaveAsChannelDialog` defaults to the dedicated-folder radio, not scratch.** Submitting untouched
  resolves to `pyry-workspace/channels/<slug>` and creates a real directory under the operator's `$HOME` on
  every gate run — tapping "Keep in scratch" is load-bearing, not polish, and is the one divergence from the
  #537 `RenameDialog` clone (no such choice exists on rename).
