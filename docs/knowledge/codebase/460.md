# Ticket #460 — decode `queue_state` into an observable per-conversation queue

**Issue:** [#460](https://github.com/pyrycode/pyrycode-mobile/issues/460) ·
**Spec:** [`docs/specs/architecture/460-observe-queue-state.md`](../../specs/architecture/460-observe-queue-state.md) ·
**PR:** [#463](https://github.com/pyrycode/pyrycode-mobile/pull/463) ·
**Feature doc:** [Queued backlog](../features/queued-backlog.md) ·
Split from #429 (epic pyrycode#597 Phase 3, queued-message backlog). The **data substrate**; the render
slice is **#461** (blockedBy this), the drop slice **#462** (blockedBy #461). Size **S**,
`security-sensitive`.

## Summary

Decodes the capability-gated v2 `queue_state` snapshot envelope into a per-conversation, thread-observable
**ordered backlog** — `observeQueue(conversationId): Flow<List<QueuedMessage>>` on the
[`ConversationRepository`](../features/conversation-repository.md) interface, reachable by the thread layer
through the [`StableConversationRepository`](../features/stable-conversation-repository.md) facade. Each
`queue_state` is a **full snapshot** of the conversation's backlog (the wire form of
`msgqueue.Snapshot(convID)`, FIFO order) that **fully replaces** that conversation's stored entry — there
is no onset/clear edge and **no live-session-arm hook** (the deliberate delta from its twin #395). Gated
on the already-negotiated `interactive` capability (fail-closed, defence-in-depth over the server-side
fan-out gate); malformed payloads dropped without tearing down the single inbound consumer (AC #4). No new
class, no new file — four additive production edits. Built test-first, RED→GREEN; all gates green
(`test`/`spotlessCheck`/`lint`/`assembleDebug`, `compileDebugAndroidTestKotlin`).

## A near-exact structural twin of #395 (`observeStall`)

This slice reuses the [#395](395.md) decode→state→observe shape verbatim — the capability gate, the
fail-closed drop idiom, the facade override, the defaulted interface method, and the #385/#395 test
harness. **Two deltas only:**

1. The observable surface is an **ordered `List<QueuedMessage>`** per conversation, not a `Boolean`, so it
   needs a portable element type (`QueuedMessage`) where stall needed none.
2. Each `queue_state` is a **full-replace snapshot** — there is no onset/clearing model. Stall is
   onset-only on the wire and infers recovery from the next forward-progress `LiveSessionEvent`; a queue
   snapshot is self-describing and authoritative, so the existing live-session arm is **not touched** (the
   `it + (id to queue)` overwrite is the whole fold).

## Load-bearing design choices

- **Full-replace, not merge.** Each `queue_state` is the authoritative current backlog
  (`msgqueue.Snapshot`), so the fold is `queuedByConversation.update { it + (conversationId to queue) }` —
  it overwrites that conversation's entry and leaves every other conversation untouched (AC #3). Wire array
  order is preserved verbatim — no sort, no dedup (AC #1). This is the inverse of #387's tool-call folds
  (in-place per-id update of one row) and of #395's `Set` membership add/remove; a queue is whole-snapshot
  state, replaced atomically.
- **No live-session-arm hook.** Unlike #395, a backlog is replaced by the next snapshot and never "cleared"
  by forward-progress events, so the structured-stream arm is not touched. The new `TYPE_QUEUE_STATE` arm
  is strictly additive and self-contained — the smallest possible change to the demux.
- **`queued` tolerates `null` OR `[]`.** The one documented wire latitude (see Lessons learned).
- **On the interface with a default (like `observeStall`, unlike `liveSessionEvents`).** The thread needs
  current-value backlog state through the connection-churn facade (#461 is the first consumer), so it goes
  on the `ConversationRepository` interface with a `flowOf(emptyList())` default — the cascade-bounded way
  to add a facade-reachable observable ([[post-352-connection-scoped-repo-behind-facade]]). Verified blast
  radius: the many `object : ConversationRepository` doubles across the `ui/` suite inherit the default and
  compile unchanged; no existing `QueuedMessage`/`observeQueue` consumer (code-review confirmed).

## Patterns established

- **A full-snapshot wire event folds as an atomic per-key map replace, no clearing arm.** Where #395
  modeled an onset-only signal (`Set` membership + inferred clearing from a sibling event family), a
  self-describing snapshot event (`queue_state`) is simpler: `Map<key, value>` with `it + (key to value)`
  on each arrival. No second decode, no cross-arm coupling, no recovery inference. Reach for this shape
  when the wire carries the *complete current state* rather than an edge.
- **An ordered-list observable surface puts its element type on the interface file, beside the contract.**
  `QueuedMessage` joins `ThreadItem` / `ConversationFilter` / `BoundaryReason` in
  `ConversationRepository.kt` rather than a standalone `data/model/QueuedMessage.kt` — co-locating a
  contract's element type with the contract keeps the ktlint single-class-filename rule satisfied and
  avoids a needless 5th file. (Code-review flagged as a NIT that this is the only `to*()`-mapper output in
  `data/repository` rather than `data/model`; it is the documented, deliberate architect call — noted for
  #461, which imports the type first.)

## Lessons learned

- **`queued` must be nullable-defaulted (`List<QueuedMessageDto>? = null`) because the wire emits an empty
  backlog as either `null` or `[]`.** The producer (#722) *recommends* but is not forced to emit `[]`; an
  empty Go `[]QueuedItem(nil)` marshals to `null`. `MobileJson` sets **no `coerceInputValues`**, so a wire
  `"queued": null` decoded into a *non-nullable* `List<…>` would throw. Modeling it nullable-defaulted +
  `.orEmpty()` in `toQueue()` collapses all three shapes — `null`, `[]`, and a missing key — identically to
  an empty backlog. This is the **one** relaxation; every other field stays strict-required (fail-closed).
  (Lifted from the [PR #463](https://github.com/pyrycode/pyrycode-mobile/pull/463) *Lessons learned*.)
- **Element-level strictness is still preserved.** A bad **item** (`queued_msg_id` as a string, missing
  `text`, unparseable `ts`) throws inside the `map` and drops the **whole** snapshot — the established "one
  bad row drops the chunk" idiom of the `message_chunk` arm. `Instant.parse` failures surface as
  `IllegalArgumentException`, caught at the same decode boundary as `SerializationException` (⊂ it).

## Verification

  (`queue_orderedDecode_preservesWireOrder`); `queued_msg_id` decodes as a number not a string — the #720
  trap (`queue_queuedMsgId_decodedAsNumberNotString`); empty-until-first-state tolerates `[]`, `null`, and
  a missing key (`queue_emptyUntilFirstState_toleratesEmptyArrayNullAndMissing`); each snapshot fully
  replaces, not appends (`queue_eachSnapshot_fullyReplaces`); per-conversation isolation
  (`queue_perConversationIsolation`); malformed dropped + a later valid snapshot still surfaces, proving
  the collector survived (`queue_malformed_droppedCollectorSurvives`); both capability-gate-closed cases —
  `emptySet()` and `{"something_else"}` (`queue_capabilityGateClosed_blocksDecode`,
  `queue_capabilityGateOtherTokenOnly_blocksDecode`). **2 facade tests** in
  `StableConversationRepositoryTest` (`observeQueue_whileAbsent_emitsEmpty`,
  `observeQueue_delegatesToLiveRepo_andDoesNotLeakAcrossSwitch`). All `runCurrent()`-driven. RED→GREEN.
- **`security-sensitive` honored:** `decodeQueueState` logs nothing on the drop path, uniform with every
  other `onInbound` arm; `QueuedMessage.text` is user-authored queued-message content carried **verbatim,
  never logged**. The data layer surfaces only a `List<QueuedMessage>` — no error type, no raw
  `JsonElement`. Memory posture: the map is **bounded by replacement** per conversation (each snapshot
  overwrites, not accumulates), the same daemon-supplied-id growth posture the four sibling projections
  already accept under the authenticated-paired-daemon threat model. `queued_msg_id` is a per-conversation
  counter, **not** a nonce/secret (no constant-time-compare concern).
- **Code review PASS** ([PR #463](https://github.com/pyrycode/pyrycode-mobile/pull/463)), zero MUST/SHOULD
  FIX, one NIT (the `QueuedMessage` placement, above — the documented architect decision). Implementation
  matches the spec exactly; every `## Security review` finding verified.

## Open questions (flagged to #461, not pre-built here)

- **Stall/queue interaction.** A stalled conversation will typically also have a non-empty queue (turns
  pile up while claude is stuck). This slice exposes the two states **independently** (`observeStall` +
  `observeQueue`); any combined "stalled with N waiting" presentation is a #461 UI derivation over both
  flows, **not** a data-layer concern.
- **Mobile UI-leakage threats** (screenshot/overlay/accessibility eavesdropping of the rendered backlog,
  which contains user message text) are out of scope for this **data** slice and belong to #461 (the
  visible render).
- **`queued_msg_id` width.** Kept `Long` to match the wire `uint64`. If the drop slice (#462) needs to echo
  the id back in `dequeue_message`, it reuses this `Long` verbatim — no string conversion.
