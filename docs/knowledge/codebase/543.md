## Summary

Lands the data-layer round-trip for the Status sheet's "Run configuration" controls (model / effort /
YOLO), which previously updated ViewModel-local state only and never reached the daemon (Tier-3 placebo
in the 2026-07-03 backend-gaps audit). `setSessionSettings` is a direct analogue of the shipped
[`rename`](530.md) path — encode a request → `sendAndAwaitReply` → typed-decode the reply — **minus the
state fold**: session settings live in the ViewModel (#544), not this repository's projection, so there
is no `upsertConversation` and nothing to mutate. It is also the **first session-scoped mutation** on
`ConversationRepository`: every prior mutation takes a `conversationId`; this one takes a `sessionId`
(sourced by #544 from `Conversation.currentSessionId`).

Each of `model` / `effort` / `yolo` is an independently-nullable `String?` / `Boolean?` parameter carrying
a **presence contract**: `null` means "leave unchanged" and is omitted from the wire payload
(`MobileJson`'s `explicitNulls = false`); a non-null value — including `false` / `""` — is always sent.
This mirrors the server struct's pointer + `omitempty` fields exactly, so a single-control change (e.g.
`setSessionSettings(id, model = "opus")`) sends only that one field.

## Patterns established

- **First session-scoped mutation.** Every prior mutation (`sendMessage`, `createDiscussion`, `promote`,
  `rename`, `startNewSession`) keys off `conversationId`. `setSessionSettings` is the first to key off a
  `sessionId` instead — a routing-key precedent future session-scoped verbs (if any) should follow, not a
  conversation-scoped one squeezed to fit.
- **A mutation with no read-model fold is a valid, cheaper shape.** Not every mutation needs to write into
  a `StateFlow` projection — when the daemon's ack carries nothing new to fold (here: the caller already
  knows what it sent), the correct implementation is encode → `sendAndAwaitReply` → decode-for-validation
  → discard → return `Unit`. Look for this shape before reflexively adding a fold to a new mutation.
  `registerPushToken` ([#359](359.md)) established the no-fold precedent first; #543 is the second
  confirming instance and the first where the *reply type itself* (not just the method) required a new
  demux-arm entry (`registerPushToken` reused the existing `ack` arm; #543 added a **new** reply verb).

## Lessons learned

- **Smart-cast dead-code hazard when asserting a negative `is`-check next to a positive `as`-cast on the
  same variable.** In `setSessionSettings_onSessionNotFound_throwsRelayErrorWithCode`, the test needed
  both `ex is RelayErrorException` (positive) and `ex !is IllegalArgumentException` (negative, proving
  `session.not_found` has no IAE-crash path, unlike `rename`'s `conversation.not_found`) plus a
  `(ex as RelayErrorException).code` read. Ordering the `as RelayErrorException` cast **before** the
  negative `is IllegalArgumentException` check lets the compiler smart-cast `ex` to `RelayErrorException`
  at that point, turning `ex is IllegalArgumentException` into a **statically-dead** check (Kotlin warns:
  "Check for instance is always 'false'") — the assertion still passes, but it no longer tests anything at
  runtime. Fix: assert the negative `is` check **first**, against the un-narrowed `Throwable?`, before the
  `as` cast narrows it. Worth grepping for this shape (`is` assertion immediately after an `as` cast on the
  same value) in any future error-type-distinguishing test.
