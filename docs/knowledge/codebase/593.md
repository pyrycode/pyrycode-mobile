# Ticket #593 — decode the `api_retry` wire event as a thread-observable retry state

**Issue:** [#593](https://github.com/pyrycode/pyrycode-mobile/issues/593) ·
**Spec:** `docs/specs/architecture/593-api-retry-decode.md` ·
**PR:** [#595](https://github.com/pyrycode/pyrycode-mobile/pull/595) ·
**Feature doc:** [API-retry status](../features/api-retry-status.md) ·
Split from #582. Data slice; the UI reaction ("Retrying — attempt N/M") is sibling **#594**
(natively blocked by this ticket). Size **S**, `security-sensitive`.

## Summary

Decodes the capability-gated v2 `api_retry` control envelope into a per-conversation,
thread-observable retry status — `observeApiRetry(conversationId): Flow<ApiRetryStatus>` on the
[`ConversationRepository`](../features/conversation-repository.md) interface, reachable by the
thread layer through the [`StableConversationRepository`](../features/stable-conversation-repository.md)
facade (AC #5). The wire event shipped daemon-side in pyrycode#1074 (PR pyrycode#1160); nothing in
the mobile tree mentioned it before this ticket, so the whole design was built off the wire contract
in the issue body, not discovered in-repo.

`api_retry` sits between the two shipped precedents rather than cloning either alone: like `stall`
(#395) it is a coarse conversation-level status signal gated on the `interactive` capability; unlike
`stall` it has both an onset **and** an explicit falling edge, and it carries a counter — which is
why the observable type follows `queue_state`'s (#460) payload-carrying shape (a `Map<String,
ApiRetryStatus>` projection) rather than `stall`'s bare membership `Set<String>`. A `Set` cannot
represent a counter: it would pin the first `attempt N/M` forever and collapse the documented
counter climb (`3/10` → `4/10`), silently violating AC #2. Four production files, no new file, no
new class beyond the domain type and DTO. Built test-first, RED→GREEN; all gates green
(`test`/`spotlessCheck`/`lint`/`assembleDebug`).

## Files touched

- **`data/repository/ConversationRepository.kt`** (+45): the new sealed domain type
  `ApiRetryStatus` (`NotRetrying` / `AttemptUnknown` / `Attempt(current, total)`), co-located with
  the interface next to `ThreadItem`/`QueuedMessage` — a stream's element type lives beside the
  contract it serves. The `data class`/`data object` modifiers are load-bearing: structural equality
  is what makes `observeApiRetry`'s `distinctUntilChanged` behave (a climbed counter is a
  *different* `Attempt` value and re-emits; an unrelated conversation's frame leaves the value equal
  and does not). The interface gains `observeApiRetry(conversationId): Flow<ApiRetryStatus> =
  flowOf(NotRetrying)` — a **defaulted** method, the cascade-avoidance lever `observeStall`/
  `observeQueue` already established: `FakeConversationRepository` and every inline test double
  inherit "never retrying" and need no override.
- **`data/network/InteractivePayloads.kt`** (+57): the decode DTO
  `ApiRetryPayloadDto(conversationId, active: Boolean, current: Int, total: Int)` — all four fields
  strict-required and non-null (the Go struct sets no `omitempty`, so `active: false`/`current: 0`
  always serialize; unlike `QueueStatePayloadDto.queued` there is no documented nullable latitude) —
  next to `StallPayloadDto`/`QueueStatePayloadDto`. The **total** mapper
  `ApiRetryPayloadDto.toStatus(): ApiRetryStatus` (never null, deliberately unlike
  `TurnStatePayloadDto.toEvent()`/`SessionTransitionPayloadDto.toBoundary()`, whose
  unrecognized-*value* drop is a mapper concern — there is no unrecognized value here to reject):
  `!active` → `NotRetrying` **discarding `current`/`total`** (the one place the "ignore the stale
  falling-edge counter" contract is enforced); `active && current > 0 && total > 0` →
  `Attempt(current, total)` verbatim, no clamping; any other active shape (the documented `{0, 0}`
  unparsed case, a partially-zero `{3, 0}`, a hostile negative) → `AttemptUnknown`. Treating an
  undocumented counter shape as `AttemptUnknown` rather than dropping the envelope is the safer
  failure — a drop would discard a real retry onset and leave the thread on the indefinite thinking
  spinner this feature exists to fix.
- **`data/repository/RemoteConversationRepository.kt`** (+82): the sixth connection-scoped
  projection `private val apiRetryByConversation = MutableStateFlow<Map<String,
  ApiRetryStatus>>(emptyMap())`, a structural sibling of `queuedByConversation`. The new
  `TYPE_API_RETRY = "api_retry"` demux arm (inside the existing `interactive` capability gate)
  performs **one unconditional replace** — `apiRetryByConversation.update { it + (conversationId to
  status) }` — with **deliberately no branch on `active`**: `toStatus()` is the sole owner of edge
  semantics, so a second `if` would encode the rule twice. `decodeApiRetry(envelope): Pair<String,
  ApiRetryStatus>?` mirrors `decodeQueueState`'s one `try`/`catch (IllegalArgumentException)` drop
  idiom (`SerializationException ⊂` it); because the mapper is total, structural malformation is the
  only null path. `observeApiRetry(conversationId)` is a pure cold projection — `.map {
  it[conversationId] ?: NotRetrying }.distinctUntilChanged()` — identical shape to `observeQueue`.
  AC #4 (inert toward neighbours: folds no thread row, does not clear an active stall, does not
  touch turn lifecycle) is satisfied structurally by the arm having only that one statement.
- **`data/repository/StableConversationRepository.kt`** (+3): the one-line facade override
  `observeApiRetry(id) = switchToLive(NotRetrying) { it.observeApiRetry(id) }` — `whenAbsent =
  NotRetrying` reads "not retrying" with no live connection, and `flatMapLatest`'s cancel-on-switch
  means a retry state cannot survive a reconnect (combined with #351's fresh-repository-per-
  connection). This is all of AC #5.
- **`data/repository/RemoteConversationRepositoryTest.kt`** (+272, 13 `apiRetry_*` tests) and
  **`data/repository/StableConversationRepositoryTest.kt`** (+48, 2 facade tests) — cloned
  `collectQueue`/`queueStateEnvelope` and the `queue_*`/`stall_*` scenario sets. The load-bearing
  scenario is the counter-climb test: it asserts the **full emission list**
  (`[NotRetrying, Attempt(3,10), Attempt(4,10)]`), not `.last()` — a `.last()` assertion would pass
  under a dedup bug and silently fail to pin AC #2 (no collapsing the climb).

No changes to `FakeConversationRepository` or any other inline test double — they inherit the
interface default, per design.

## Patterns established

- **A `queue_state`-shaped (payload-carrying `Map`) projection is the right template for any future
  coarse status signal that has both edges and a payload**, not `stall`'s bare membership `Set`. The
  choosing question: does the signal need to carry more than a boolean's worth of information across
  its lifetime? If yes, clone `queue_state`'s shape (`Map<String, T>` + full-replace on every frame);
  if the signal is a pure edge with no payload, `stall`'s `Set<String>` is the leaner fit.
- **A total mapper (never null) is the right shape when there is no unrecognized *value* to reject** —
  only an unrecognized *shape* the structural decoder already catches. Contrast with
  `TurnStatePayloadDto.toEvent()`, whose nullable return exists specifically to drop an unrecognized
  enum-like string value. Don't reach for a nullable mapper return by habit; check whether the payload
  actually has a value space narrower than its wire type.

## Lessons learned

- **kotlinx's *tree* decoder (`decodeFromJsonElement`) accepts a quoted primitive even with
  `isLenient = false`.** `{"active":"true"}` and `{"current":"3"}` both decode to the value an
  unquoted frame would give, rather than failing structurally. A quoted-primitive payload is
  therefore **not** a usable malformed-drop test probe — use a genuinely wrong shape instead (a
  number where a `String` is declared, a non-integral or out-of-`Int32` counter, a missing field).
  Measured against this exact DTO, not inferred from documentation. Worth carrying into #583
  (`compacting`), which clones this arm.
  - Same trap makes an existing test half-false-green, noted but deliberately **not** touched (test-
    quality only, no production behaviour involved, out of this ticket's scope):
    `RemoteConversationRepositoryTest.queue_queuedMsgId_decodedAsNumberNotString` asserts a
    string-typed `queued_msg_id` is dropped by checking the prior value still stands — but `"7"`
    decodes to `7L` under the same lenient-tree quirk, so that half of the test passes either way
    regardless of whether the drop actually fires.
- **`distinctUntilChanged` is compatible with the wire's documented no-dedup rising-edge re-fire, and
  the `data class`/`data object` modifiers on `ApiRetryStatus` are exactly what makes it so.**
  Suppression is value-*identity*: a climbed counter is a structurally different `Attempt` and
  reaches the observer as a new emission, while a value-identical frame (or one for another
  conversation) does not re-emit. Assert the full emission list in this style of test, not `.last()`
  — `.last()` cannot distinguish "collapsed the climb" from "correctly reached both values."
