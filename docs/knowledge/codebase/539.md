## Summary

Fills the `startNewSession` stub — the "New session" (`/clear`) affordance's wire half — replacing its
`UnsupportedOperationException` throw with a send against the daemon's `new_session` v2 control frame
(server-side [pyrycode/pyrycode#831](https://github.com/pyrycode/pyrycode/issues/831), split from #824,
PR #836). The wire contract is **`interrupt`-shaped, not `promote`-shaped** — bare, connection-level,
fire-and-forget: no payload (no `conversation_id`, no `workspace`), no ack, no reply, no broadcast owed.
`startNewSession` is now a line-for-line mirror of the existing `interrupt()`: `check(pump.send(...)) { ISE
}` via plain `SessionPump.send`, never `sendAndAwaitReply`. Success (the new session's real identity) is
observed elsewhere, via the pre-existing `session_transition` marker that the #336 fold already renders as
a thread delimiter — **that observe path is out of scope here**, this slice only sends. The interface still
forces a `Session` return with no reply to build one from, so the method returns a locally-constructed
placeholder with empty-string identity fields; the sole consumer (#540, not yet landed) discards it.

## Patterns established

None new — second confirming instance of the `interrupt()` bare-fire-and-forget template (first was #458).
Worth noting for future no-payload control-frame stub-fills on this class: check the nearest shipped
sibling's **frame shape** (does the daemon reply at all?) before assuming the `promote`/`rename`
request-reply template applies — #534's split body originally assumed `new_session` acked like a mutation,
and that assumption was wrong (corrected when #534 split into #539/#540/#541).

## Lessons learned

- **Return-type reconciliation when a fire-and-forget frame meets a reply-shaped interface: return a
  locally-constructed placeholder with explicitly-unassigned identity fields, not a fabricated one.**
  The interface forces `startNewSession(...): Session`, but the wire yields no session identity at
  send-time — the real one arrives later via the out-of-scope `session_transition` marker. The chosen
  shape (`id = ""`, `claudeSessionUuid = ""`) is a self-documenting "not-yet-assigned" sentinel; a minted
  UUID would look real and become a latent trap if a future consumer ever stopped discarding the value.
  Narrowing the interface return type to `Unit` was considered and rejected as out-of-scope ripple
  (`FakeConversationRepository` + `StableConversationRepository` + the interface itself) for an XS slice —
  revisit if a second fire-and-forget mutation ever needs the same reconciliation, since two data points
  might tip the balance toward the signature change.
- **"Gate cleared ≠ buildable" generalizes past UI-visibility gates to wire-shape assumptions.** The #534
  split body assumed `new_session` was request-reply (like `promote`/`rename`); the actual daemon message
  (pyrycode#831) is bare and reply-less. Confirming the wire shape against the server-side ticket — not
  just the split body's prose — before implementing saved a rewrite here; #537's "menu item visible ≠
  mutation implemented" version of this lesson (parked Inbox, no per-ticket doc yet) has a sibling on the
  wire-contract-shape axis too.
