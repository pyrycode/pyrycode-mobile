# #432 — Layer 1a: scripted-stream thread harness + text + spinner

Adds **Layer 1** (the ladder's **rung 2**, `docs/e2e-interactive-stream.md`) of the mobile interactive-stream
e2e ladder: a reusable **component-level** harness, `ScriptedThreadHarness`, that drives a scripted sequence
of structured live-session events through the **real production graph** — `RemoteConversationRepository`'s
fold (#337 `assistant_delta` → streaming row, #406 `turn_state` → `isThinking`) into `ThreadViewModel` into
the stateless `ThreadScreen` — and renders the assembled thread, with **no network, daemon, or
emulator-host**. It ships the harness plus the first two render cases (text, spinner) and is fast enough to
gate every change. The harness joins the two halves that lived apart before: the fold (unit-tested in
`RemoteConversationRepositoryTest`) and the render (`ThreadScreen`, component-tested from a hand-built state
in `ThinkingIndicatorTest`). **Additive androidTest only — zero production change** (the #337 / #406 folds
already ship). Sibling **#435** (Layer 1b: tool rows, session divider, connection banner) rides this same
entry point and is `blockedBy` this one, so the harness contract is the load-bearing deliverable.

## Patterns established

- **Drive the REAL `RemoteConversationRepository` fold, never the dormant VM fold.** #337's delta fold lives
  in **two** production sites: `RemoteConversationRepository` (canonical — its inbound collector runs
  unconditionally on `scope`, and the live app renders this row) **and** `ThreadViewModel.threadItems`
  (`ThreadFold.render()`'s `finished.any { id == turn.turnId }` guard suppresses the VM synthetic whenever
  the repo fold already produced a row with that `turnId`, which it always does live). A fake-repo +
  scripted-`LiveSessionEvent` harness would exercise only the **dormant** VM path and miss regressions in
  the real one. So the harness wires real pump → real repo → real VM → real screen; the only seam is
  `FakeSessionPump`. This is the central design constraint and the contract #435 extends.
  See [[two-folds-repo-wins-vm-dormant]].
- **One shared harness entry point as the #435 contract.** The constructor injects the whole real graph, so
  sibling scenarios add scripting `push*` methods on top without re-deriving the stream → fold → render
  wiring. The scripting surface is kept minimal (only text + spinner); #435 owns its own
  `pushToolUse`/`pushToolResult`/divider additions (YAGNI — don't pre-build them here).
- **Instrumented `createComposeRule`, not Robolectric.** Every existing Compose render test
  (`ThinkingIndicatorTest`, `ThreadScreen*Test`, `StallPromotionBannerTest`) is instrumented; the project
  has no Robolectric stack and porting the `test/` driving helpers is cheap, so adding a new test stack
  earns nothing. The AC's "no … emulator-host" refers to rung-3/4 **host-daemon orchestration**, not the
  test device — the harness joins `./gradlew connectedAndroidTest`.

## Lessons learned

- **Subscribe-before-push is load-bearing for the spinner case.** `repo.liveSessionEvents` is a
  `replay = 0` SharedFlow: a `turn_state` / `assistant_delta` emitted before the VM's collectors subscribe
  is **dropped, not buffered for late subscribers**. `isThinking` is sourced **only** from
  `liveSessionEvents`, so a pre-subscription push silently loses the spinner. `awaitReady()` gates every
  live push on the seeded conversation's name rendering in the top bar — proof the VM `state` / `isThinking`
  collectors composed (via `collectAsState`) and subscribed upstream. (The streaming-text case is more
  robust because that fold also lives in the repo, whose inbound collector runs unconditionally on the
  harness scope — but gating both behind `awaitReady` is uniform and correct.) The seeded `conversations`
  snapshot is safe to push any time: `observeConversations`/`observeMessages` are cold projections that
  re-emit to new subscribers, unlike the `replay = 0` live stream. *(PR "Lessons learned".)*
- **Open the capability gate.** Construct the repo with `negotiatedCapabilities = { setOf("interactive") }`.
  With the default **closed** set, `assistant_delta` folds nothing and `liveSessionEvents` stays silent
  (see `assistantDelta_capabilityGateClosed_producesNoRow`) — both cases would falsely render an empty
  thread.
- **The seed channel name must not be a substring of any asserted text** — the same false-green class as
  #431's `e2e-ping` → `e2e-seed` rename ([[431-fakeclaude-staticuuid-vs-discussion-session]]). The channel
  name renders verbatim in the top bar and coexists on screen with `awaitReady`'s top-bar proof and the
  render assertions, so it must not collide. Named **`"Harness channel"`** — distinct from `"hello world"`
  and the caret `"▎"`.
- **Assert the text case only *after* `turn_end`.** The streaming body reveals progressively (~50 chars/s
  typewriter) and carries the caret `"▎"`; the full concatenated string is reliably present **and**
  caret-free only once the row finalizes to `MarkdownText`. Use **plain alphanumeric** delta text so
  `MarkdownText`'s rendered output matches the raw substring 1:1 (no markdown metacharacters).
- **Script `thinking` specifically for the spinner.** `ThreadViewModel.isThinking` (`thinkingTransition`)
  maps only `thinking → true`; `responding` / `idle` / `turn_end → false`. The ticket's loose "thinking /
  responding" notwithstanding, scripting `responding` would never show the spinner.
- **Every scripted envelope's `conversation_id` must equal the harness `conversationId`** — both
  `applyAssistantDelta` and `thinkingTransition` filter on it first. The builders take it as a parameter;
  the harness threads its own id.

## Verification

The deliverable **is** the tests; there is no unit test of the harness itself. Host-JVM checks (no device,
per the spec's strategy): `./gradlew test lint assembleDebug spotlessCheck` green and
`compileDebugAndroidTestKotlin` compiles. **`connectedAndroidTest` NOT run** — no device/emulator attached;
both cases are instrumented `createComposeRule` (the `ThinkingIndicatorTest` precedent), so the actual
on-device render run is operator-run.
