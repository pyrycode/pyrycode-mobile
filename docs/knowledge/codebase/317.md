# #317 — `message` payload → domain `Message` mapping

The **second application payload** decoded on top of the [#273](273.md) wire layer (after [#316](316.md)): a typed `@Serializable` DTO for the Mobile Protocol v2 `message` payload plus a pure function that maps it — **together with its envelope** — to a domain [`Message`](../features/data-model.md). It is the single decode-and-validate boundary for the message-thread read path: untrusted `Envelope.payload` JSON in, one domain `Message` out, with malformed / field-incomplete / unmappable-role payloads rejected **before any `Message` is built** rather than producing a partial or `null`-punned object. The server echoes this **same** `message` payload as the persisted-message answer to a `send_message`, so that response mapping is covered by this one boundary too. Greenfield, no consumers yet: [#312](https://github.com/pyrycode/pyrycode-mobile/issues/312) (`RemoteConversationRepository`) wires the flow/repository around it and supplies the `sessionId`.

Scope is `message` → `Message` **only**. Per the ticket's scope correction, the `message` payload carries **no** `session_id`, **no** session metadata, and **no** boundary/reason field, so this slice emits **no** `Session` and **no** `ThreadItem.SessionBoundary` — those are synthetic / sequence-level and owned by the observe slice ([#312](https://github.com/pyrycode/pyrycode-mobile/issues/312), see `FakeConversationRepository.buildThreadItems`, which folds the ordered message stream to detect `previousSessionId → newSessionId` transitions and pulls the `reason` from a session-lifecycle side-channel). A single-message decoder cannot produce them. See [[v2-app-payload-shapes-ssot]].

See the feature doc [`mobile-protocol-v2-wire-layer.md`](../features/mobile-protocol-v2-wire-layer.md) § "Application payloads" for the evergreen reference; this file is the implementation record.

## Summary

One `@Serializable data class` + one `@Serializable enum` + a pure mapper, all under `data/network/` next to the sibling [#316](316.md) payload it mirrors, verified by one JUnit4 test file (6 `@Test` methods). The DTO is the camelCase analog of the server's snake_case `MessagePayload` Go struct (`@SerialName` carries the mapping — the Go-interop contract).

The single load-bearing design move: **the wire-role enum models only the *domain-mappable* roles, turning role validation into a free decode-boundary rejection** (see Patterns).

## Files touched

Both **NEW**, under `app/src/main/java/de/pyryco/mobile/data/network/` (+ test mirror):

- **`MessagePayload.kt`** (103 lines):
  - `MessagePayloadDto` (`:31-37`) — the four required wire fields: `conversation_id → conversationId: String`, `message_id → messageId: String`, `role: WireRole` (enum-typed), `text: String`. The payload **is** the object (NOT object-wrapped, unlike #316's `{ "conversations": [ … ] }`). `conversationId` is modeled for wire fidelity but **maps to no domain field** (the domain `Message` carries no conversation id; the consuming repo already knows which conversation it requested) — reuses #316's "model-for-fidelity, drop-in-mapper" precedent (its unused `last_message_ts`); kept a required `String` for strict decode.
  - `WireRole` (`:52-59`) — `@Serializable enum` with **only** `@SerialName("user") User` and `@SerialName("assistant") Assistant`. `system` (a valid wire role) and `tool` (a future-additive role, #272) are deliberately **absent** because the domain `Role` has no `System` and `Role.Tool`/`ToolCall` are unreachable from this payload.
  - `MessagePayloadDto.toMessage(envelope: Envelope, sessionId: String): Message` (`:82-97`) — public extension; per-field copy with every field defined (`id ← messageId`, `content ← text`, `role ← role.toDomain()`, `timestamp ← Instant.parse(envelope.ts)`, `isStreaming = false`, `toolCall = null`, `sessionId` from the param). Takes the **whole `Envelope`** (only `ts` read today) to keep the seam stable for the `send_message`-echo path's future `inReplyTo` correlation; does **not** check `envelope.type` (the caller routes by type and guarantees the envelope/payload correspondence).
  - `private fun WireRole.toDomain()` (`:99-103`) — exhaustive `when`, **no `else`** (compiler-checked total over the two members): `User → Role.User`, `Assistant → Role.Assistant`.
- **`MessagePayloadTest.kt`** (test, 111 lines) — JUnit4 mirroring `ConversationsPayloadTest.kt`. Each scenario builds a `JsonElement` via `MobileJson.parseToJsonElement(fixture)` (mimicking `Envelope.payload`), decodes through `MobileJson`, then maps via `toMessage(envelopeFor(element), sessionId)` — exercising the real #312 consumer path. The six cases: `user` payload → **every** field asserted (incl. `sessionId == "s-active"`, a value absent from the payload, proving it is caller-injected not decoded); `assistant → Role.Assistant`; `system` role → `SerializationException` at decode; an unknown garbage role (`"wizard"`) → same exception (proving closed-set behavior, not a `system` special-case); field-incomplete payload (drops required `text`) → `SerializationException`; malformed envelope `ts` (`"not-a-date"`) → `IllegalArgumentException` at map.

**No build edits** — `kotlinx-datetime` ([ADR 0001](../decisions/0001-kotlinx-datetime-for-data-layer.md), supplies `Instant.parse`) + `kotlinx-serialization-json` ([#272](272.md)) were already present. The domain `Message` ([`data/model/Message.kt`](../features/data-model.md)) is fixed — mapped to as-is, not modified.

## Patterns established

- **A wire enum models only the *domain-mappable* values, so an unmappable value is a free decode-boundary rejection.** `WireRole` omits `system` (no domain `Role.System`) and `tool` (no domain target on this payload). kotlinx-serialization then rejects `system` and any unknown string with a `SerializationException` at `decodeFromJsonElement`, **before any `Message` is built** — co-locating role validation with the rest of shape validation, no hand-written `require` / `when`-`else`-`throw`. **This is the technique to reuse whenever a wire enum carries values with no domain target.** It is robust under `MobileJson`: `ignoreUnknownKeys` affects unknown *keys*, not enum *values*; `coerceInputValues` is unset; and `role` has **no default**, so coercion could not apply even if it were added later (spec note for whoever touches `MobileJson`: do **not** give `role` a default — that would silently coerce an unmappable role).
- **Two validate sites, split across decode and map.** Unlike #316 (both validations at decode, because its timestamps were payload fields decoded by `InstantIso8601Serializer`), here the timestamp is the **envelope `ts`** parsed by `Instant.parse` **in the mapper** — so decode validates shape + role and the mapper adds a second throw site for a malformed `ts`. The sole `Message` construction runs only after a fully-validated DTO *and* a successful `ts` parse, so a partially-populated `Message` is structurally impossible.
- **A non-wire domain field is caller-supplied, not `null`-punned.** `sessionId` is not on the `message` payload, so the mapper takes it as a parameter — #312 passes the active session id at map time. This differs from #316's "wire-absent fields get documented list-tier defaults": there the value didn't exist at the call site (so a default), here it genuinely does (so a parameter). Both honor the no-`null`-pun rule.
- **`toolCall` always `null` / `Role.Tool` unreachable.** No `tool` wire role today, so the domain "non-null `toolCall` iff `role == Tool`" invariant holds vacuously. A comment at the mapping site (`:93-95`) tells a future reader **not** to "wire it up" — there is no tool-call field on this payload.
- Same as #316: **per-payload file (DTO + mapper extension + `private` helper) in `data/network/`**, decode = the single validate boundary, and **decode-only — no encode round-trip test** (the phone never *sends* `message`; it is server → phone, and the `send_message` echo is also inbound).

## Lessons learned

Lifted from the PR's *Lessons learned* section:

- **The two typed failure surfaces split cleanly across decode vs map — and the throw families differ.** An unmappable / unknown wire `role` (including `system`) and any missing required field fail at `decodeFromJsonElement` as a **`SerializationException`** (`MissingFieldException` for the missing-field case). A malformed envelope `ts` throws **`IllegalArgumentException`** from `Instant.parse` **in the mapper** — the one validation step #316 didn't have, since its timestamps were payload fields decoded by `InstantIso8601Serializer`. **Consequence for #312:** the consumer must catch **both** families (or `Exception`) when surfacing decode errors — catching only `SerializationException` would let a malformed-`ts` message crash the read path. This is the **same "catch both" consequence as #316**, reached for a different reason (here the second throw is at *map*, not decode). Both are still "a typed failure at the boundary": no partial `Message` is ever constructed.

## Verification

- `./gradlew test` (6 `MessagePayloadTest` cases + full suite), `./gradlew lint`, `./gradlew assembleDebug` — all green in the PR.
- **No instrumented test** — pure `data/`-layer slice, nothing to instrument; the decode/map path is fully exercised by JVM unit tests.
- **Code review: PASS** ([PR #324](https://github.com/pyrycode/pyrycode-mobile/pull/324), no findings). The reviewer confirmed the DTO mirrors the server SSOT byte-for-byte, the role-rejection mechanism is sound under `MobileJson` (keys ≠ enum values, no `coerceInputValues`, no `role` default), both decode failures are typed, and the slice is purely additive (`Message.kt` / `Envelope` untouched — no call sites to update). The architect security-review (in the spec, **Verdict: PASS**) confirms this is the explicit untrusted-JSON→typed-value boundary, the payload carries no secret (message `text` is user content, not a credential), and no file / IPC / crypto / network surface is introduced — with a SHOULD note handed to #312: don't log raw `text` at release level.
