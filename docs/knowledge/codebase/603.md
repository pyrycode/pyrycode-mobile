# Ticket #603 — Delete the context-window stub state from `ThreadViewModel`

**Issue:** [#603](https://github.com/pyrycode/pyrycode-mobile/issues/603) ·
**Spec:** [`docs/specs/architecture/603-delete-context-window-stub-state.md`](../../specs/architecture/603-delete-context-window-stub-state.md) ·

**Feature docs:** [Thread status row](../features/thread-status-row.md), [Status sheet](../features/status-sheet.md), [Thread screen](../features/thread-screen.md) ·
Split from #584 (chain: #601 → #602 → #603, last child). Both upstream siblings merged first — #601
replaced the Status sheet's stub render with "Context usage unavailable", #602 dropped the status row's
usage segment — so nothing read `ThreadUiState.tokenPercent` / `tokensUsed` / `tokensTotal` by the time
this ran. Size **XS**. Client-only, pure deletion — no wire call, no DTO, no repository method, no new
production code. Code review **PASS**.

## Summary

`ThreadViewModel` carried three fields (`tokenPercent`, `tokensUsed`, `tokensTotal`) populated from
companion-object constants (`STUB_TOKEN_PERCENT = 73`, `STUB_TOKENS_USED = 146_000`,
`STUB_TOKENS_TOTAL = 200_000`) marked with a "Phase 4 swap point" comment that was never acted on. This
ticket deletes all three fields, their `combine`-block assignments, and the companion object that held
only those constants — the companion is removed outright rather than left empty, since the three
constants were its sole members. #591 (blocked on daemon-side pyrycode PR #1215) reintroduces state
against a shape it designs for the real wire data, rather than restoring these fields.

Net-negative diff: 8 insertions / 42 deletions across 4 files, no new production code.

## Files touched

- **`ui/conversations/thread/ThreadViewModel.kt`** — deleted `tokenPercent` / `tokensUsed` /
  `tokensTotal` from `ThreadUiState`, their three `combine`-block assignments, and the `companion
  object` (its only members were the three `STUB_*` constants and the "Phase 4 swap point" comment). The
  *other*, unrelated "Phase 4 swap point" comment on `AUTO_SUGGESTED_CHANNEL_NAME` was left alone — the
  spec called out the risk of a same-string grep match and it was avoided by matching the full comment
  text, not the substring.
- **`ui/conversations/thread/ThreadScreen.kt`** — stripped the trailing token-triple args from all 5
  `@Preview` `ThreadUiState(...)` literals (`ThreadScreenLightPreview`, `ThreadScreenDarkPreview`,
  `ThreadScreenQueuedBacklogDarkPreview`, `ThreadScreenAboveDelimiterDimLightPreview`,
  `ThreadScreenAboveDelimiterDimDarkPreview`). The token args were always trailing, so the preceding arg
  simply picked up the trailing comma; ktlint's trailing-comma rule needed no manual fixup.
- **`ui/conversations/thread/ThreadStatusRow.kt`** — reworded the one KDoc clause naming
  `ThreadViewModel.STUB_TOKEN_PERCENT` to say "a hardcoded constant, deleted in #603" instead, preserving
  the sentence's actual point (the percentage was never measured, which is why the row renders two
  segments instead of Figma `16:58`'s three). No code in the file changed. Reflowing the clause changed
  more lines in the diff than the single sentence being edited — expected, not a violation of "nothing
  else changes."
- **`ThreadViewModelTest.kt`** — dropped the three trailing token assertions from
  `state_initialValue_includesDefaultModelEffortAndTokenPercentDefaults` and
  `state_postSubscription_emitsDefaultModelEffortAndTokenPercent`, renaming both to
  `…AndYolo` so the names stop advertising coverage that no longer exists. Both tests were kept rather
  than collapsed — they pin different things (pre-subscription `stateIn` initial value vs. post-`combine`
  emission) that only read as duplicates once stripped, because the preference default happens to match.

## Patterns established

None new — this ticket follows the deletion pattern already established by #601/#602 (strip stub state
once nothing reads it) to its conclusion, rather than introducing a new one.

## Lessons learned

- The build stayed silent exactly as the spec predicted: all 13 `ThreadUiState(…)` construction sites
  outside `ThreadScreen.kt`'s previews (7 in `androidTest`, 3 in `ThreadScreenMapperTest`, 1 in
  `ThreadViewModelTest`, 2 inside `ThreadViewModel` itself) use named args and pass no token args, so
  deleting *defaulted* fields left them compiling untouched. `compileDebugAndroidTestKotlin` converted
  that inference into a fact for the 7 `androidTest` sites — worth running deliberately, since
  `test`/`lint`/`assembleDebug` never compile that source set and would have gone green regardless.
- The AC's verification grep (`tokenPercent|tokensUsed|tokensTotal|STUB_TOKEN`) had to widen past the
  three field names to catch `STUB_TOKEN_PERCENT`, which the case-sensitive narrower grep misses, and
  which `ThreadStatusRow.kt`'s plain backtick-prose KDoc keeps invisible to the compiler, lint, and
  spotless alike — a deletion AC that greps only the camelCase field names can go all-green with a
  dangling reference to a deleted constant still sitting in production source.
- Shortening a KDoc clause reflows the surrounding paragraph's line wrap, so a one-sentence prose edit
  can read as several changed lines in the diff. Meaning-preserving, not a scope violation.
