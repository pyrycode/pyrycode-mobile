## Summary

The **render half** of the permission/choice-modal UI surface. [#445](445.md) (shipped) folds the decoded
[`modalEvents`](../features/modal-events.md) stream into a single hoisted app-level observable,
[`ThreadViewModel.currentModal: StateFlow<ModalUiState>`](../features/current-modal-state.md). This slice
collects that state in the route host, forwards it into the **stateless** `ThreadScreen` as a new defaulted
param, and renders the `Open` state as a **separate-surface** overlay (M3 `BasicAlertDialog`, **not** a row
in the thread `LazyColumn`) — verbatim title / prompt / options in wire array order, the fail-safe-deny
`defaultOptionId` option highlighted as a filled `Button`. On `Dismissed` no overlay renders and a snackbar
surfaces the mapped resolution reason (`remote` / `local` / `timeout` + a graceful forward-compat fallback).
Render-only: option-tap / cancel hooks are declared but **inert** — answering / cancelling is sibling
**#444** (blocked by this one). Built test-first; all gates green (`test` / `lint` / `assembleDebug` /
`spotlessCheck`); code review **PASS**, two non-blocking NITs.

## Patterns established

- **Compose-dialog `FLAG_SECURE` via `DialogProperties(securePolicy = SecureOn)`, not the Activity flag.**
  The first secure *dialog* in the app — the [#381](381.md) `LiteralScreenSurface.SecureScreen()`
  precedent flags the **Activity** window, which a dialog (its own window) would not inherit. `SecureOn`,
  not the default `Inherit`, is load-bearing because the host thread screen carries `FLAG_SECURE` nowhere.
  Any future secure overlay/dialog follows this, not `SecureScreen`.
- **Map a verbatim wire reason to a local string, never echo it, when the surface is outside the secured
  window.** The dismiss snackbar draws in the **un-secured Activity** window (`FLAG_SECURE` covers only the
  dialog), so `dismissReasonText` mapping `source` → a local resource (with a generic `else` fallback) is a
  **confidentiality** requirement, not just UX. Mirrors `LiteralScreenSurface.ErrorContent`'s
  "no server-supplied string is shown" posture.
- **Fail-safe-deny highlight = filled `Button` for `id == defaultOptionId`, `OutlinedButton` otherwise.**
  The producer (pyrycode#716) marks no option "destructive"; its safety design is that the visually
  prominent default is always the deny/safe option. The highlight is driven **solely** by the id equality
  — no option-id semantics interpreted. The default also carries an accessible/test-observable
  `stateDescription` so a screen reader announces "default" and the test locates it without colour
  inspection.
- **Non-dismissable render overlay** (`dismissOnBackPress = false` / `dismissOnClickOutside = false`): a
  permission gate must not treat a stray back-press / outside-tap as an implicit answer. The overlay leaves
  composition **only** when `currentModal` transitions away from `Open` (a daemon `Dismissed`, including
  timeout). Local cancel/back wiring is #444's concern.

## Lessons learned

- **`androidx.compose.ui.test.onNode` / `onAllNodes` are members of the test rule's
  `SemanticsNodeInteractionsProvider`, not importable top-level symbols** — importing them fails to
  compile, unlike `onNodeWithText`. Call them on the `composeTestRule` receiver
  (`composeTestRule.onAllNodes(...)`), don't `import` them.
- **`FLAG_SECURE` on a Compose dialog must be set via `DialogProperties(securePolicy =
  SecureFlagPolicy.SecureOn)`** — a dialog draws in its **own** window, so the `LiteralScreenSurface` /
  [#381](381.md) Activity-window flag does not cover it, and the default `SecureFlagPolicy.Inherit` would
  leave it unsecured since the host thread screen carries no `FLAG_SECURE`. (Cannot be asserted via the
  Compose test API — there is no semantics node for a window flag; it is a **code-review-verified**
  invariant.)
- **`ModalUiState.Open` carries `options: List<ModalOption>`, which the Compose compiler treats as an
  unstable type → the overlay is non-skippable** (code-review NIT). Harmless here — a one-at-a-time dialog,
  not a row in a heavy `LazyColumn`. If #444's later visual spec moves this into a hot list, reach for an
  `ImmutableList`. Noted only to confirm recomposition was checked.
- **The dismiss snackbar can re-show once on a configuration change** while `Dismissed` is still the
  current value (code-review NIT) — the `LaunchedEffect(modalId)` host is `remember`'d (not saveable), so
  it re-fires on the recreated composition. Identical to the existing `ArchivedDiscussionsScreen` effect
  shape; the surface is design-owed, so left as-is. Flagged forward for #444, which may swap the snackbar
  for an inline confirmation anyway.

## Security (`security-sensitive`)

This slice discharges the two render-time obligations [#445](445.md) deferred to it; the untrusted-bytes →
typed-events trust boundary is **upstream** at #437's decode. Code review **PASS** (no MUST/SHOULD FIX),
architect self-review **PASS**:

- **Output-encoding** — `title` / `prompt` / option `label`s render through plain `Text(String)` only
  (literal, no markup): never `MarkdownText`, no `buildAnnotatedString` parse, no `SelectionContainer`
  (a clipboard-exfiltration path past `FLAG_SECURE`). Verified by grep: the only `MarkdownText` /
  `SelectionContainer` tokens in the file are the KDoc documenting their avoidance.
- **Screen-capture hardening** — `securePolicy = SecureOn` sets `FLAG_SECURE` on the dialog's own window
  (deterministic Compose property — a real code-level net, not a stochastic rule).
- **No persistence** — no modal-derived text reaches `rememberSaveable` / `SavedStateHandle` / DataStore;
  `modalState` is a hoisted param, the dialog holds no saved state, the snackbar shows a mapped local
  string. No server text survives process death.
- **Fail-safe-deny preserved** — highlight by `id == defaultOptionId` only; no auto-answer (answering is
  #444), no path bypasses the user's explicit choice.
- **Out of scope (named, not skipped):** tapjacking on the answer is **#444**'s (taps are inert here, so
  moot); accessibility-service eavesdropping is an accepted residual (`FLAG_SECURE` blocks capture, not the
  a11y node tree — suppressing it would break TalkBack); stale-`Open`-across-reconnect clear is deferred to
  #444 + the connection signal (the daemon validates `modalId` server-side, so a stale answer is rejected).
