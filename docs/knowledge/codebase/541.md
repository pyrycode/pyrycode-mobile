## Summary

Adds `interactiveTurn_newSession_rendersSessionBoundaryDelimiter` to `InteractiveStreamE2ETest` — a
rung-3 real-claude scenario for the operator-facing "New session" happy path, cloning #566's structure
but simpler (no picker, no recents). With a live, exercised session it: creates a discussion, sends the
constrained ping and waits for the reply (one real-claude turn, proving the session is genuinely live),
asserts the session-boundary delimiter is **absent**, opens the real thread overflow menu (`More
actions` → `New session`), and asserts the delimiter **appears** — proving the #540 fire-and-forget wire
and the #336 `session_transition` → `ThreadItem.SessionBoundary` fold end to end against a real daemon
`/clear`, not the boundary the Fake synthesizes. Zero production code: one new `@Test` + companion
constants, one `scripts/e2e-emulator.sh` LIVE-curation line, and the ladder doc.

Reachability was the open blocker carried from the #534 split (and the #537 twin's park reason): the
"New session" item was hidden behind `mutationsSupported == false`. PR #572 flipped that flag to `true`
in relay mode now that every co-gated sibling wire had shipped, making this scenario — and the sibling
family #545/#551/#562/#566 — buildable without further gate work.

## Files touched

- **`app/src/androidTest/java/de/pyryco/mobile/e2e/InteractiveStreamE2ETest.kt`** (+95) — the new
  `@Test`, reusing the ping scenario's tail verbatim:
  - Lands on the channel list, `awaitConnected()`, creates a **plain discussion** (regular tap, not
    long-press) — sufficient because the "New session" item gates on `mutationsSupported` only, never
    on `isPromoted`.
  - Sends `PING_PROMPT`, waits for the reply via `pingNodeCount()` baseline/delta (one real-claude turn;
    `/clear` spends none) — this both proves liveness and leaves de-emphasized above-delimiter content.
  - **Absence guard (deterministic, no extra turn):** `onAllNodesWithText(DELIMITER_EXPLANATION,
    substring = true).assertCountEquals(0)` before opening the menu, so the delimiter's later appearance
    is attributable to the New-session tap, not pre-existing content.
  - Opens `CD_MORE_ACTIONS` ("More actions"), waits for `NEW_SESSION_ITEM` to render, taps it —
    `NEW_SESSION_ITEM` locates the tap target **only**, never the assertion (see token collision below).
  - Asserts `DELIMITER_EXPLANATION` (substring, generous `REPLY_TIMEOUT_MS`, presence) — never a delta
    count or timing.
  - New companion constants: `CD_MORE_ACTIONS = "More actions"`, `NEW_SESSION_ITEM = "New session"`,
    `DELIMITER_EXPLANATION = "Claude doesn't remember messages above this line"`.

## Patterns established

None new — a confirming instance of the rung-3 real-claude scenario shape (#481/#482/#566's template):
clone the ping scenario's wait/act/assert skeleton, extend the LIVE `TEST_TARGET` comma-separated
`class#method` list by one more entry (the #566-established pattern for growing the LIVE gate),
constants added to the shared companion object.

## Lessons learned

- **Token-collision discipline for delimiter-adjacent copy.** `boundaryLabel(BoundaryReason.Clear)`
  renders `"New session — <time>"`, whose prefix is byte-identical to the overflow menu item text. The
  fix generalizes past this ticket: whenever a menu item's label and a resulting UI artifact's label
  share copy, the durable/load-bearing matcher must be a substring that's unique to the artifact (here,
  the delimiter's reason-independent explanation line), never the shared prefix. `NEW_SESSION_ITEM` is
  kept in the companion object as a documented tap-target-only constant specifically to make this
  distinction visible to future readers/editors.
- androidTest is not compiled by the mandatory `test`/`lint`/`assembleDebug` gates —
  `compileDebugAndroidTestKotlin` is the real build gate for e2e-only tickets. Already captured as
  [[androidtest-not-compiled-by-mandatory-gates]]; re-confirmed by this ticket's PR, no new content.
