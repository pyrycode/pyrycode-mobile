# Ticket #461 — render the queued-message backlog in the conversation thread

## Summary

The **render** half of the queued-message backlog. [#460](460.md) reduced the inbound `queue_state`
envelope to a thread-observable [`observeQueue(conversationId): Flow<List<QueuedMessage>>`](../features/queued-backlog.md);
this slice **shows** it. The queue is surfaced onto `ThreadUiState.queuedMessages` (folded into the single
`state` combine via a file-private `ThreadContent`) and a new stateless
[`QueuedBacklog`](../features/queued-backlog-section.md) component renders the ordered backlog as a
**de-emphasized foot-of-list section** below the message list — the render-after-decode twin of the
**thinking indicator** ([#407](407.md) → `ThinkingIndicator`) and the **stall promotion**
([#396](396.md) → `StallPromotionBanner`). Read-only (no callbacks): the per-row drop affordance is #462.
No new wire, no decode, no trust boundary — `QueuedMessage` arrives pre-validated from the data layer.
Code review **PASS**, zero blocking findings.

## Load-bearing design choices

- **A `ThreadUiState` field, not a sibling `StateFlow` (deliberate divergence from the #396 stall
  precedent).** [#396](396.md) exposed `isStalled` as a sibling `StateFlow<Boolean>` beside
  `connectionState` / `isThinking`, because a stall is a **transient cross-cutting scalar**. The queue is
  the opposite: it is **thread content** — an ordered list of message text that extends the user's side of
  the conversation, the same category as `ThreadUiState.items`. So it goes **on `ThreadUiState`**, exactly
  as AC #4 asks ("state in via `UiState`; the composable reads no repository directly"). This keeps
  `ThreadScreen`'s signature stable (no new param → **`MainActivity` untouched**, zero call-site cascade),
  makes the screen test a one-liner (`ThreadUiState(queuedMessages = …)`), and preserves "single source of
  state per ViewModel". The two render twins split the other way on this exact axis — same component shape,
  opposite hoisting decision, each correct for its signal class.
- **Folded into the `state` combine, not a sixth arm.** The `state` `combine` is already at the 5-arg typed
  overload ceiling. Rather than drop to a vararg-`combine`, `observeQueue` is paired with `threadItems` into
  a file-private `ThreadContent` (the same pre-combiner trick `TransientDialogs` / `RunConfig` already use
  to stay at five arms). Both inputs seed immediately (the `threadItems` `scan` seeds `emptyList()`,
  `observeQueue` seeds `emptyList()`) and each already carries `distinctUntilChanged`, so the combine never
  stalls and adds no operator.
- **A separate wrap-content section, not a `LazyColumn` row.** The backlog sits directly below the message
  list (it continues the user's side of the conversation) and above the foot-most `ThinkingIndicator`. It is
  **not** placed inside the `LazyColumn`, which keeps the list's keying / alpha-dimming / auto-scroll logic
  untouched (lowest blast radius) — the established foot-of-list-affordance pattern (`ThinkingIndicator`,
  `StallPromotionBanner`). The list's `weight(1f)` absorbs the section's height; real backlogs are short
  (the daemon's `msgqueue` cap is server-side).
- **De-emphasized user bubble (the visual distinction AC #1 requires).** Queued entries render as user-side
  `primaryContainer` bubbles (same shape/colour family as the thread's sent bubbles) but at `QUEUED_ALPHA =
  0.6f` (in the spirit of `ThreadScreen.ABOVE_DELIMITER_ALPHA = 0.55f`) with a leading "waiting" glyph and a
  "Queued" caption — so a queued message reads as *not yet sent*, distinct from the full-opacity sent
  bubbles. **Design-owed:** Figma `16-8` has no backlog treatment drawn yet, so the visual follows the app's
  M3 message-row idiom until it lands — exactly how #386/#396 shipped against the same un-drawn frame.
- **Not `security-sensitive`; no new `FLAG_SECURE` surface.** This resolves the UI-leakage flag #460
  forwarded to this visible-render slice. `entry.text` is user-authored message text — the *same content
  class* `ThreadScreen` already renders for sent user messages (`UserMessageBubble`) **without**
  `FLAG_SECURE`. In this app `FLAG_SECURE` is reserved for verbatim screen-content surfaces
  ([`LiteralScreenSurface`](../features/literal-screen-surface.md), the
  [permission modal](../features/permission-modal-overlay.md)); the backlog renders in the same host, adds
  no new exposure, logs nothing, and holds no state — consistent with the not-`security-sensitive` label.

## Patterns established

Nothing genuinely new — this slice **follows** the render-after-decode precedents (the early-return
show/hide idiom, the `cd_*` merged-`semantics` anchor, the design-owed M3 default against an un-drawn
frame, light/dark previews). The one point worth carrying forward, and the divergence to remember:

- **A render-after-decode signal that is *content* (an ordered list extending the conversation) is hoisted
  onto `ThreadUiState`, not exposed as a sibling `StateFlow` like a transient scalar.** Decide by signal
  class, not by reflex: `isThinking` / `isStalled` are cross-cutting booleans → siblings; `queuedMessages` /
  `items` are thread content → `ThreadUiState`. Surfacing content onto the state also avoids the
  `ThreadScreen`-param + `MainActivity`-wiring cascade entirely (the queue rides the already-collected
  `state`).

## Lessons learned

- **A `mergeDescendants = true` a11y group defeats per-row text assertions — read the unmerged tree.** The
  `QueuedBacklog` container carries `semantics(mergeDescendants = true)` for the group label + the screen-test
  anchor, which collapses every row's `Text` into one accessible node. So the AC #5 wire-order assertion must
  resolve each row via `onNodeWithText(text, useUnmergedTree = true)` before comparing
  `getUnclippedBoundsInRoot().top` — the merged tree can't distinguish rows by text. (Lifted from the
  [PR #464](https://github.com/pyrycode/pyrycode-mobile/pull/464) *Lessons learned*.)
- **A public composable with a raw `List<…>` param trips the `ComposeUnstableCollections` Compose-lint
  Warning — pre-existing, accepted here.** `QueuedBacklog(queued: List<QueuedMessage>, …)` raises it, as
  `ChannelListScreen` / `WorkspacePickerSheet` / `ChannelInfoSheet` already do. It is a non-fatal **warning**
  (the project ships no `kotlinx-collections-immutable` dependency), not a new defect — `assembleDebug` /
  `lint` stay green. Don't "fix" it by adding an immutable-collections dependency for one component.
