# #521 — `RelayLog`: debug-gated, redacted relay diagnostic logging facility

Delivers `RelayLog`, a safe-by-construction diagnostic logger for the relay transport. It exists to
end the "add raw `Log.i`/`Log.w` → diagnose → remember to strip" churn that nearly shipped the relay
host, live `conn_id`, close cause, pump state, and negotiated capabilities to **production** logcat
(2026-07-03 cross-repo review; R8 strips `Log.d`/`Log.v` but keeps the `Log.i`/`Log.w` the near-miss
used). The facility **cannot reach release output** (explicit `BuildConfig.DEBUG` gate, not R8
log-level stripping) and **cannot assemble a sensitive value in release** (message via a lambda
invoked only when enabled). Ships the facility **only** — the four relay files keep their "Emits no
logs" contract; adoption is a future ticket. Split from #500. Security-sensitive.

## Summary

- New `object RelayLog` with `d`/`i`/`w(message: () -> String)` log methods and
  `redactConnId(connId: String): String`. Two `internal var` seams (`enabled`, `sink`) exist purely
  for tests. Zero production consumers — this is a tool put on the shelf, not installed.
- `redactConnId` hashes the daemon-issued `conn_id` (full 256-bit BLAKE2s → first **4 bytes** →
  8-char lowercase hex), revealing zero bytes of the live id, mirroring
  [`staticKeyFingerprint`](../features/static-key-fingerprint.md)'s digest-then-truncate idiom.
- No new dependency (reuses the vendored `Blake2sMessageDigest`, [ADR 0004](../decisions/0004-vendor-noise-java-crypto.md);
  `BuildConfig` already generated for this module), no consumer changes.

## Files touched

- `app/src/main/java/de/pyryco/mobile/data/network/RelayLog.kt` — new, 93 LOC. One top-level type.
  - `internal var enabled = BuildConfig.DEBUG` — the gate; the emit branch is `if (enabled) sink(…, message())`.
  - `internal var sink: (Int, String, String) -> Unit` — default `android.util.Log.println`; test seam.
  - `d`/`i`/`w` are **non-`inline`** one-liners forwarding `Log.DEBUG`/`INFO`/`WARN` over one shared path.
  - `redactConnId` = `Blake2sMessageDigest().digest(connId.toByteArray(UTF_8)).toHexString(0, REDACT_BYTES)`,
    `REDACT_BYTES = 4`.
  - Object KDoc carries the MUST-NOT-log contract (host/URL, pairing token, raw key material, full
    `conn_id`, payloads) and the safe-to-log allowlist (event type, redacted id, pump state name,
    close code, capability names).
- `app/src/test/java/de/pyryco/mobile/data/network/RelayLogTest.kt` — new, 109 LOC, five `@Test`s:
  redaction produces a derived 8-char hex token (deterministic, distinct-per-input); short/empty input
  still isn't the input; disabled gate invokes neither lambda nor sink; enabled gate forwards the
  redacted message; level→priority mapping. `@After` restores both seams.

No production consumer, build-script, manifest, or `libs.versions.toml` change.

## Patterns established

- **Debug-diagnostic logging goes through `RelayLog`, never raw `android.util.Log`.** The safe gate is
  an explicit `BuildConfig.DEBUG` check plus a lambda-wrapped message — **do not** rely on R8 stripping
  `Log.d`/`Log.v`, because R8 keeps `Log.i`/`Log.w` and that is exactly how the near-miss would have
  shipped. Any future relay diagnostics adopt this facility.
- **Redaction width is chosen by *purpose*, not copied.** A **correlation** token (`redactConnId`,
  4 bytes) is deliberately narrower than the **authentication** fingerprint
  ([`staticKeyFingerprint`](../features/static-key-fingerprint.md), ≥8 bytes / brute-force-resistant).
  Reuse the digest-then-truncate *idiom*; re-derive the *width* from whether an adversary could forge
  the value. Don't "align to 8" here — see [[blake2s-fingerprint-full-then-truncate]].
- **Prefer hashing over prefix-truncation for redaction.** A fixed-width digest of an arbitrary-length
  string can never equal the input, so "not the full input" holds for *every* input including short
  and empty — no edge-case guard. `connId.take(8)` would leak real bytes and return the whole value
  for a short id.
- **Test seams stay `internal`, and the logger stays non-`inline`.** Making the log methods `inline`
  would force the seams to `@PublishedApi internal`; the non-inline gate gives the identical
  string-not-built-when-disabled guarantee with clean seams. The **runtime gate**, not inlining, is
  load-bearing.

## Lessons learned

- **`android.util.Log.*` throws `"not mocked"` in this module's plain-JVM unit tests** — there is no
  Robolectric and no `unitTests.returnDefaultValues` (`app/build.gradle.kts` `testOptions`). Route
  emission through an injectable `sink` seam so the enabled path is testable without touching the real
  `Log`. See [[android-log-throws-in-plain-jvm-unit-tests]].
- **The `Log.DEBUG`/`INFO`/`WARN` `int` constants are safe to reference in a unit test** even though
  `Log` methods throw — they are `static final int`, so the compiler **inlines** the literal and the
  `Log` class is never loaded. Asserting priority against `Log.DEBUG` needs no mock.
- **`BuildConfig.DEBUG == true` on the `testDebugUnitTest` classpath**, so `enabled` defaults *true* in
  tests. The disabled-path test must set `enabled = false` explicitly, and every test must restore the
  `object`'s process-global seams in `@After` or state leaks across tests.
- **No `@Volatile` on the seams.** In production they are write-once at class init (effectively final
  at runtime); only single-threaded tests mutate them. Adding `@Volatile` would be cargo-cult.
