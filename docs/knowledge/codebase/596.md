# Ticket #596 — decode the `compacting` wire event as a thread-observable compaction state

**Issue:** [#596](https://github.com/pyrycode/pyrycode-mobile/issues/596) ·
**Spec:** `docs/specs/architecture/596-compacting-decode.md` ·
**PR:** [#600](https://github.com/pyrycode/pyrycode-mobile/pull/600) (commit `da4c3f9`) ·
**Feature doc:** [Compacting state](../features/compacting-state.md) ·
Split from #583. Data slice; the UI reaction (a compaction banner) is sibling #597 (natively
blocked by this ticket). Size **S**, `security-sensitive`.

## Summary

Decodes the capability-gated v2 `compacting` control envelope into a per-conversation,
thread-observable compaction state — `observeCompacting(conversationId): Flow<Boolean>` on the
[`ConversationRepository`](../features/conversation-repository.md) interface, reachable by the
thread layer through the [`StableConversationRepository`](../features/stable-conversation-repository.md)
facade (AC #1–#4). The wire event shipped daemon-side in pyrycode#1074 (PR pyrycode#1160, merged
2026-07-21) — the banner-only twin of `api_retry` (#593), which landed in PR #595 (`022c0b8`)
shortly before this ticket was written and served as its closest in-tree provenance relative.

Clones the shipped `stall` arm (#395) rather than `api_retry`: compaction is a bare on/off edge
with no counter, so the observable is a `Flow<Boolean>` over a membership `Set<String>` — no new
domain type, no mapper function. The one place `stall`'s shape doesn't transfer: compaction has an
explicit wire **falling edge** (`active: false`), so removal is driven by the frame rather than
inferred from forward progress. Four production files, no new file, no new class. Built test-first,
RED→GREEN; all gates green (`test`/`spotlessCheck`/`lint`/`assembleDebug`).

## Files touched

- **`data/network/InteractivePayloads.kt`** (+33): the new decode DTO `CompactingPayloadDto(
  @SerialName("conversation_id") conversationId: String, active: Boolean)` — both fields
  strict-required and non-null (the Go struct sets no `omitempty`, so `active: false` always
  serializes), next to `StallPayloadDto`/`ApiRetryPayloadDto`. **No `toX()` mapper** — the two wire
  fields already are the domain shape, so a mapper would be a ceremonial identity function; this is
  the one deliberate divergence from cloning `ApiRetryPayloadDto.toStatus()`.
- **`data/repository/ConversationRepository.kt`** (+14): one defaulted interface method,
  `observeCompacting(conversationId): Flow<Boolean> = flowOf(false)`, placed after
  `observeApiRetry` — the cascade-avoidance lever `observeStall`/`observeQueue`/`observeApiRetry`
  already established: `FakeConversationRepository` and every inline test double inherit "never
  compacting" and need no override.
- **`data/repository/RemoteConversationRepository.kt`** (+90): the seventh connection-scoped
  projection `private val compactingConversations = MutableStateFlow<Set<String>>(emptySet())`, a
  structural sibling of `stalledConversations` (not `apiRetryByConversation` — no counter to
  represent). The new `TYPE_COMPACTING = "compacting"` demux arm (inside the existing `interactive`
  capability gate) performs `compactingConversations.update { if (active) it + conversationId else
  it - conversationId }` — **the `if (active)` branch lives in the arm itself**, unlike `api_retry`'s
  "no branch, mapper owns the edge" rule, because here there is no mapper to own it: the membership
  transition *is* the edge, expressed exactly once. `decodeCompacting(envelope): Pair<String,
  Boolean>?` mirrors `decodeStall`'s one `try`/`catch (IllegalArgumentException)` drop idiom — there
  is no unrecognized *value* to reject (`active` is a bool), so structural malformation is the only
  null path. `observeCompacting(conversationId)` is a pure cold projection —
  `.map { conversationId in it }.distinctUntilChanged()` — identical shape to `observeStall`. AC #1–#3
  (inert toward neighbours: folds no thread row, does not clear an active stall, does not touch turn
  lifecycle) is satisfied structurally by the arm having only that one statement.
- **`data/repository/StableConversationRepository.kt`** (+2): the one-line facade override
  `observeCompacting(id) = switchToLive(false) { it.observeCompacting(id) }` — `whenAbsent = false`
  reads "not compacting" with no live connection, and `flatMapLatest`'s cancel-on-switch means a
  compaction state cannot survive a reconnect (combined with #351's fresh-repository-per-connection).
  This is the rest of AC #4.
- **`data/repository/RemoteConversationRepositoryTest.kt`** (+216, 11 `compacting_*` tests) and
  **`data/repository/StableConversationRepositoryTest.kt`** (+45, 2 facade tests) — cloned
  `collectStall`/`stallEnvelope` and the `stall_*`/`apiRetry_*` scenario sets. The load-bearing
  scenario is the round-trip test: `active: true` then `active: false` → `[false, true, false]`, and
  the state is not active afterwards — the behaviour `stall` structurally cannot have, so cloning
  `stall` too literally would fail exactly here. Also cloned
  `apiRetry_inertTowardNeighbours_keepsStallAndFoldsNoThreadRow` verbatim in shape: seed a stall,
  push a `compacting` rising edge, assert the stall is still `true`, `observeMessages` is still
  empty, and the compaction state landed anyway (AC #3).

No changes to `FakeConversationRepository` or any other inline test double — they inherit the
interface default, per design. The two `turn_state`-phase tests naming `"compacting"` as an
unrecognized phase value (`liveEvents_unrecognizedTurnState_droppedNextSurvives`,
`stall_notClearedByUnrecognizedOrMalformedLiveEvent`) were left untouched, as the spec required —
they test an unrelated wire vocabulary member, not this envelope type.

## Patterns established

- **A bare on/off edge with no payload is `stall`'s `Set<String>` shape; a payload-carrying signal
  is `queue_state`'s `Map<String, T>` shape.** This is now the second confirmation of the choosing
  rule #593 established: does the signal need to carry more than a boolean's worth of information
  across its lifetime? If no, clone `stall`; if yes, clone `queue_state`/`api_retry`.
- **An explicit wire falling edge belongs in the demux arm, not a mapper, when there is no mapper to
  own it.** `api_retry` pushed `active` handling into `toStatus()` specifically to avoid encoding the
  edge rule twice (once in a mapper, once in the arm). Here, with no mapper, the `if (active)` branch
  in the arm *is* the single place the rule lives — the same principle, opposite conclusion, because
  the domain shape differs.

## Lessons learned

- **Three similar arms (`stall`, `api_retry`, `compacting`) is where a shared status-event
  abstraction starts looking tempting — and the spec explicitly declined to build one.** #593's spec
  left a directive for this ticket's architect: clone the arm, don't generalize it; a
  registry/base-type/`observeStatus(kind)` abstraction is a call for PO to make later, on evidence,
  not something to reach for on the third sample. Worth remembering for any *fourth* status-shaped
  wire event: the threshold for "this is now a pattern worth extracting" is a product/architecture
  decision, not a default reflex once three examples exist.
- **The quoted-primitive decode latitude measured on `ApiRetryPayloadDto` (`{"active":"true"}`
  decodes to `true` even at `isLenient = false`) applies identically here** — confirms the trap is a
  property of kotlinx's tree decoder (`decodeFromJsonElement`), not something specific to the
  `api_retry` DTO's fields. Any future boolean-bearing DTO decoded the same way inherits this; don't
  reach for a quoted value as a malformed-payload test probe.
