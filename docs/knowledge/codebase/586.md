# #586 — Parser-gap sentinel: fail every live scenario on an unrecognized-message row

## Summary

Arms `InteractiveStreamE2ETest` (rung 3) with a single `UnrecognizedRowSentinel` `TestRule` field: any
curated `LIVE=1` scenario during which the daemon reports a claude message kind its stream-json parser
couldn't map (#609's `unrecognized_message` → `ThreadItem.UnrecognizedMessage`, rendered by #608) now
fails the scenario, naming the frame's `site` (wire token) and a sanitized, length-capped `message_type`
— never the payload body, never a conversation id. Red doesn't mean broken: it means claude gained a
message kind and the daemon's measured ignore-list needs re-taking. Every one of the eight curated
methods becomes a sentinel for free; a ninth scenario added tomorrow inherits the guard with no per-test
wiring. Non-vacuity (proof the guard *can* fail) is demonstrated on rung 2, since rung 4 runs the PTY
runner and has no emitter for this frame. Test + harness + doc only — zero production lines.

## Patterns established

- **Test-only repository tap via Kotlin interface delegation (`by delegate`).** One override
  (`observeMessages`), zero maintenance as `ConversationRepository` grows new defaulted members, and
  "records but never filters or alters" is checkable by inspection. Reusable shape for any future
  androidTest-only cross-cutting observer that must not add its own subscription (see also #620's
  discovery in this ticket's PR testing notes).
- **Rule vs. `composeTestRule` ordering is immaterial when the guard's data lives in a lifecycle-independent
  accumulator** — don't reach for `RuleChain`/`@Rule(order=...)` unless the two rules actually need
  sequencing; the smaller diff (leave the existing rule untouched) is correct here.
- **A pure `finding(rows): String?` function shared between the rung-2 non-vacuity test and the rung-3
  rule** is the mechanism that lets "the guard fired" and "what may be printed" have one definition instead
  of two that can drift.
- **Envelope builders carrying a payload that is itself JSON (here `raw`) must use `kotlinx.serialization`
  (`buildJsonObject`), not string interpolation** — interpolating an already-JSON string produces a
  malformed envelope the real decoder silently drops, so the probe passes for the wrong reason. Same trap
  family as the #593/#460 quoted-primitive lesson.

## Lessons learned

(lifted from the PR body's "Lessons learned" section, verbatim)

- **AGP's instrumentation XML report left-trims each line of an assertion message.** A two-space-indented
  `  - site=...` row came back as `- site=...` in the report. Any assertion matching a multi-line failure
  string against a line prefix should `trimStart()` first, or it passes locally and fails only in the
  report-driven read.
- **A raw ESC byte in a Kotlin string literal compiles but is invisible in review and unsearchable** — and
  it also trips tool-input validation on the way through a shell. Write the `` escape instead. Worth
  knowing for any test that probes terminal-injection handling.
- **Kotlin interface delegation (`by delegate`) is the right shape for a test-only repository tap** — see
  Patterns above.

Two more surfaced during code review's rework pass:

- **A Kotlin compiler-daemon session marker (`.kotlin/sessions/*.salive`) got tracked** by the dispatcher's
  unconditional safety-net auto-commit (`.kotlin` was absent from `.gitignore`). Once tracked, the daemon
  recreating it on every build makes every worktree permanently dirty, and the safety-net commit would
  re-commit that churn on every future agent run in every column — self-perpetuating. Same class as the
  `.codegraph` worktree-symlink chain already documented in `.gitignore:16-23`. Fixed by `git rm --cached`
  + adding `.kotlin` (no trailing slash, same reasoning as the `.codegraph` entry) to `.gitignore`.
- **A security-property test scenario can be vacuous even with a passing assertion.** The first pass's
  log-forging test forged `site=forged…` with no `- ` row-line prefix, so the `- site=` line-count assertion
  stayed `1` whether or not the newline was sanitized — the test could not detect the regression its own
  comment named. Fixed by reproducing the real row-line shape in the forged payload *and* asserting the
  finding's total line count (header + row + remedy), so an extra line of *any* shape is caught. Verified by
  mutation: temporarily widening `sanitize`'s allowlist to permit `\n` turned the scenario red before the
  fix and stayed green after — this is the standard this repo now expects for any test whose whole point is
  "this input cannot do X" ([[sanitizer-test-must-forge-the-readers-own-shape]]).
