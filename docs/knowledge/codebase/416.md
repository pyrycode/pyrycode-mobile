# #416 — advertise the live replay cursor as `last_event_id` on reconnect

The **advertise** half of the Phase 2 structured-streaming mid-turn-replay contract (ADR 025
§ Backpressure / replay): on every reconnect the phone reads [#412](412.md)'s reconnect-spanning
[`ReplayCursor`](../features/replay-cursor.md) at `hello`-build time and sends it as
`HelloClientPayload.lastEventId`, so the daemon replays the conversation's missed structured-stream tail
(events with id `> last_event_id`) from its in-memory ring (pyrycode#646) **before** the live stream
resumes — instead of leaving a silent mid-turn gap. A fresh connection that observed nothing omits the
field. The cursor is **consumed, never moved or re-introduced** (#412 owns it). Split from #413; sibling
#417 (resync reset + surface-gap) is `blockedBy` this.

Four production files, **no new types, no interface change, no `createPump`/coordinator/pump churn.** The
only cross-layer edge is a single composition-root lambda — the `data/network` layer stays free of any
repository dependency.

## Patterns established

- **A cross-layer *live read* is threaded as a `() -> T?` supplier, with the only cross-layer edge
  confined to the composition root.** Rather than re-thread the cursor through `createPump` /
  coordinator / pump (6 files, disturbing the guarded `onConnection` cancellation-atomicity invariants
  for no benefit), the factory holds a `() -> Long?` lambda that reads
  `RelayRepositoryCoordinator.replayCursor.latest`. The `data/network` layer keeps **zero** repository
  dependency — the read is a deferred lambda whose only knowledge is "give me a `Long?`"; the network →
  repository edge exists **only** as the `AppModule` lambda. Reuse this shape whenever a lower layer must
  read a value that lives in a higher layer **at call time** (not at construction).
- **Consume the seam; do not move or duplicate it.** #412 deliberately exposed `replayCursor` as an
  `internal val` on the coordinator "specifically so the advertise slice can read `ReplayCursor.latest`
  to advertise the resume point" (#412's KDoc). This slice is exactly that reader and re-introduces
  nothing — no second cursor, no relocation. When a prior slice has built a seam **for** you, read it.
- **A defaulted lambda param keeps a security-sensitive identity builder backward-compatible.** Both
  `NoiseIkSession` and `NoiseSessionFactory` took the supplier as `() -> Long? = { null }` after their
  existing params — every prior positional construction and the re-key path compile unchanged, and the
  default omits the field, so the change is inert until `AppModule` opts in. Same defaulted-param
  discipline as `deviceName` (#365) / `negotiatedCapabilities` (#385) / `replayCursor` (#412).

## Lessons learned

- **The factory holding a `() -> Long?` that reads `get<RelayRepositoryCoordinator>().replayCursor.latest`
  is NOT a Koin DI cycle.** Constructing the factory only *stores* the lambda; it resolves the
  coordinator **only when invoked at `hello`-build** — per connection, after the coordinator is
  constructed and started — by which point `get<RelayRepositoryCoordinator>()` returns the
  already-cached singleton. The coordinator single *does* resolve this factory eagerly at its own
  construction (`AppModule`), but the lambda is **not** invoked there. The no-cycle reasoning is recorded
  inline in `AppModule.kt` so a future edit that "simplifies" the lambda into an eager `get` (which would
  cycle) is warned off. (Lifted from the PR's *Lessons learned*.)
- **The factory-forwards test could not reuse the `TestResponder` harness.** `TestResponder` (which
  decrypts `writeInit()` and recovers the `hello`) is `private` to `NoiseIkSessionTest.kt`, so
  `create_forwardsLastEventIdSupplierIntoHello` inlines a raw `HandshakeState(PROTO, RESPONDER)` +
  `readMessage` to recover the `hello` from the factory-built session. Code review flagged this as a
  **non-blocking NIT** (a future consolidation point — extracting a shared test util was judged out of
  scope for an S ticket, against "touch only what's necessary").

## Security

`security-sensitive`. Architect security review **PASS** (no MUST FIX, spec § Security review); code
review **PASS** (one non-blocking NIT, above). The one new boundary is the **outbound** advertise of
`last_event_id` (phone → daemon): the phone advertises **only** `replayCursor.latest` — a value it
recorded from its own authenticated inbound stream through #412's positive-guarded, strictly-advancing
fold — **never** a conversation id (the daemon resolves the conversation), **never** an unvalidated
server value. `last_event_id` is a non-secret event ordinal, not a credential; the `hello` token path is
untouched (still sealed in Noise early-data, still `token=***` in `toString()`), and no new
`Log`/`Timber`/`println` was added. No file/storage, IPC/Android, subprocess, or crypto surface.

This slice was **Inbox-gated** until the *server* stopped trusting `last_event_id` unboundedly: an
unfixed server set its per-conn dedup watermark (`replayThrough`) straight from the untrusted
`last_event_id` even when the ring was caught up — silently suppressing **all** live frames after a
`/clear`+reconnect (rotated id-space below a stale cursor) or a hostile `2^64-1` cursor. That gate is
**closed by pyrycode#663**: the `min(afterID, newest)` clamp (`internal/relay/v2session.go:1493`), the
`NewestID` ring accessor (`internal/eventring/ring.go:198`), and the bounded dedup guard, re-verified
present on pyrycode `main` @ `0386940` at architect time, with two delivery regression tests
(`…OutOfRangeLastEventID_LiveStreamDelivered`, `…ClearRotation_LiveStreamDelivered`). The advertise
composes with the recording's positive guard so the caught-up-watermark suppression cannot trigger.

> ⚠️ Do **not** be misled by pyrycode `docs/knowledge/codebase/647.md` § "Known issue" — it still reads
> "unresolved MUST FIX (do NOT merge as-is)" because the fix landed under the *separate* #663 ticket and
> 647.md was never back-updated. The current server state is `codebase/663.md` ("Blocks
> pyrycode-mobile#416"), not 647.md.

**Out of scope (deferred):** reconstructing an in-flight turn whose *pre-cursor* deltas the fresh
per-connection repo never saw — closed downstream by the `resync` reaction (#417, `blockedBy` this) and
the deferred full reload via `backfill_since` (no daemon-side message-history store exists yet). This
slice's contract ends at the wire-advertise.
