# #226 — feat(ui/thread): host ChannelInfoSheet from thread overflow (display + delegation)

Connects the two halves that landed separately: the stateless [`ChannelInfoSheet`](../features/channel-info-sheet.md) + `ChannelInfoUiModel` (shipped host-agnostic in [#217](./217.md)) and the thread overflow scaffold (`ThreadEvent` + `onOverflowEvent`, mounted in [#251](./251.md) / [#252](./252.md)). Tapping the overflow menu's **Channel info** item now opens the populated sheet — channel name, workspace path, created / last-activity relative labels, session + message counts. **Rename** and **Change workspace** delegate to the existing `ThreadEvent.Rename` / `ThreadEvent.ChangeWorkspace` cases; **Install memory plugin / Archive / Delete** are dismiss-only placeholders this slice (Archive + Delete ship for real in sibling [#227](https://github.com/pyrycode/pyrycode-mobile/issues/227), which needs a one-shot pop-back nav mechanism + a delete-confirmation dialog). Three production edit sites, no new files, no visibility widening. Split (eventually) from #144 → #219.

## Summary

- **`ThreadEvent` gains one case: `data object ChannelInfoDismiss`** — mirrors `RenameDismiss`. `ChannelInfo` already existed (no-op stub since #251); this slice lifts it out of the no-op branch and gives it a real handler. No other event is added — Install is a pure no-op lambda with no event, and Archive/Delete from the sheet route through `ChannelInfoDismiss` only.
- **`ThreadUiState` gains four defaulted fields.** `channelInfoOpen: Boolean = false` (the sheet-visibility flag) plus three raw ingredient fields the screen layer assembles the model from: `workspacePath: String = ""` (= `conv.cwd`, the full path — distinct from the leaf-only `workspaceLabel`), `lastUsedAt: Instant? = null` (= `conv.lastUsedAt`, formatted in the screen layer), `sessionCount: Int = 0` (= `conv.sessionHistory.size`). All defaulted so no construction site (previews, `initialValue`, the existing equality-asserting tests) is forced to change. Adds `import kotlinx.datetime.Instant` to `ThreadViewModel.kt`.
- **The internal `ChannelInfoUiModel` is never put on the public `ThreadUiState`.** That would be a public-API-exposes-internal-type error. Instead the state carries stdlib-typed ingredients and the model is assembled in the screen layer (see the mapper below). `conversationName`, `channelId`, `createdLabel`, and `messageCount` need no new fields — they derive from existing `displayName`, `conversationId`, and `items`.
- **`channelInfoOpen` folds into the existing `TransientDialogs` group — the 5-arg `combine` ceiling is preserved (the key constraint).** A new private `pendingChannelInfo = MutableStateFlow(false)` source (precedent: `pendingRenameDialog`) joins the existing inner `transientDialogs` `combine`, widening it 2→3 args (well under the arity limit); `TransientDialogs` gains a `channelInfoOpen: Boolean` field. The top-level `state` `combine` stays at **5 args** (Kotlin's overload maximum, hit since #229 collapsed run-config into `RunConfig` and transient dialogs into `TransientDialogs`). A 6th top-level arg would not compile; re-collapsing the whole block would be unnecessary over-engineering.
- **`onOverflowEvent` adds two arms; the no-op branch shrinks to two cases.** `ThreadEvent.ChannelInfo -> pendingChannelInfo.value = true` and `ThreadEvent.ChannelInfoDismiss -> pendingChannelInfo.value = false`. The exhaustive `Unit` branch is now just `ThreadEvent.NewSession, ThreadEvent.ChangeWorkspace -> Unit`. No `viewModelScope` job, no dispatcher change, no repository call — display + local flag flips only.
- **Pure mapper `internal fun ThreadUiState.toChannelInfoUiModel(now: Instant = Clock.System.now()): ChannelInfoUiModel` in `ThreadScreen.kt`.** A plain (non-`@Composable`) top-level extension, `internal` so the JVM unit test calls it directly. Field derivations: `conversationName = displayName`; `workspacePath = workspacePath`; `createdLabel = items.firstOrNull()?.let { formatRelativeTime(it.timestamp(), now) } ?: "—"` (em-dash when the stream is empty — no created anchor); `lastActivityLabel = lastUsedAt?.let { formatRelativeTime(it, now) } ?: "—"`; `sessionCount = sessionCount`; `messageCount = items.count { it is ThreadItem.MessageItem }`; `memoryPlugins = emptyList()` (no plugin data source until Phase 3+ — renders the `None` + Install empty-state); `channelId = conversationId`. A small `private fun ThreadItem.timestamp(): Instant` near `mostRecentSessionBoundaryIndex` maps `MessageItem → message.timestamp`, `SessionBoundary → occurredAt`. `items` is chronological-ascending, so `items.first()` is the earliest item (the created-date anchor).
- **Both time labels reuse the app-wide `formatRelativeTime` helper** (`ui/conversations/components/RelativeTime.kt`, `internal`, injectable `now`). Its output past 7 days is an absolute date ("May 8"), **not** "3 weeks ago" — the `ChannelInfoSheet` preview's "3 weeks ago" was #217 placeholder text, not a spec. Matching the app-wide helper is deliberate (every conversation-list row already uses it); extending it to week/month granularity would change every row and is out of scope.
- **Sheet host slots alongside the existing `StatusSheet` host**, gated on the ViewModel-driven flag (`if (state.channelInfoOpen) ChannelInfoSheet(...)`), not local screen state — because the trigger arrives through `onOverflowEvent`, not a screen-local tap. Lambda wiring: **Rename** = `{ onOverflowEvent(Rename); onOverflowEvent(ChannelInfoDismiss) }` (downstream rename dialog already wired via [#141](./141.md), so it fully takes effect); **Change workspace** = emit `ChangeWorkspace` then dismiss (downstream still a no-op pending its own ticket — harmless and forward-compatible); **Archive / Delete** = dismiss-only; **Install memory plugin** = `{ /* TODO: Phase 3+ */ }` (no event, no dismiss, no user-visible feedback); **onDismiss** = `ChannelInfoDismiss`. New imports: `ChannelInfoSheet`, `ChannelInfoUiModel`, `formatRelativeTime` (all `internal` in the `components` package, same-module visible), and `kotlinx.datetime.Clock`.
- **Archive / Delete must NOT emit `ThreadEvent.Archive`** — even though `ThreadEvent.Archive` *is* already wired to `repository.archive(...)`. The sheet's Archive needs a pop-back nav after archiving (the channel leaves the list) and Delete needs a confirmation dialog; both are owned by [#227](https://github.com/pyrycode/pyrycode-mobile/issues/227). Emitting `ThreadEvent.Archive` here would archive the channel with no nav follow-up — a half-built flow. Dismiss-only is intentional, and an inline comment in `ThreadScreen.kt` says so.
- **No new dependencies, no Koin changes, no new strings.** `ChannelInfoSheet` / `ChannelInfoUiModel` / `formatRelativeTime` are all `internal` in the single Gradle module — the `thread`-package screen constructs the model directly with no visibility widening. `kotlinx.datetime.Clock` / `Instant` ride in via the existing catalog entry. `Conversation` is unchanged — **no persisted `createdAt` field added** (deferred to a future schema ticket; adding it now cascades ~45 constructor literals across ~16 files and breaks S).

## Patterns established

- **Pure non-`@Composable` extension mapper on `UiState` for device-free coverage of UI-derived values.** `ThreadUiState.toChannelInfoUiModel(now: Instant = Clock.System.now())` keeps the derivation (relative-time labels, message count, model assembly) out of the composable and in a plain top-level `internal fun` — so a JVM unit test (`ThreadScreenMapperTest`) covers it with an injected `now`, no `createComposeRule`, no device. Reuse this shape whenever a screen derives a child component's model from `UiState`: a defaulted `now: Instant = Clock.System.now()` argument is the seam that makes time-dependent rendering testable. (Same injectable-`now` posture the underlying `formatRelativeTime` already uses.)
- **Expose stdlib-typed ingredients on a public `UiState`, assemble an `internal` component model in the screen layer.** When a stateless component's model type is `internal` but the `UiState` is `public`, putting the model on the state is a public-API-exposes-internal-type error. The fix: the VM projects raw `String` / `Instant?` / `Int` ingredients onto the state, and the screen's mapper assembles the `internal` model just before the host call. No visibility widening, no leak.
- **Fold a new transient UI flag into the existing `TransientDialogs` pre-combiner rather than adding a top-level `combine` arg.** The top-level `state` `combine` is pinned at the 5-arg Kotlin ceiling; a new boolean that behaves like `renameVisible` joins the inner `transientDialogs` `combine` (which has headroom) and gets a field on `TransientDialogs`. This is the third flag to use the group (`renameVisible` #141, `saveAsChannel` #142, now `channelInfoOpen`). The pre-combiner pattern (introduced #142, mirrored by #229's `RunConfig`) is the standard release valve when the outer combine is full.
- **Emit-then-dismiss for delegating sheet actions; dismiss-only for actions a sibling ticket owns.** Rename / Change workspace fire `{ onOverflowEvent(<Action>); onOverflowEvent(ChannelInfoDismiss) }` — delegate to the existing event, then close. Archive / Delete are dismiss-only with an inline comment explaining that wiring the obvious-looking `ThreadEvent.Archive` would half-build the flow (the real archive/delete-from-sheet path needs pop-back nav + a confirm dialog, owned by #227). When a button's full behaviour is out of scope, dismiss-only + a comment naming the owning ticket is the honest placeholder — not a partial wire-up.

## Lessons learned

- **The pure mapper is directly JVM-testable because it's a top-level `fun`, not a `@Composable`.** `ThreadUiState.toChannelInfoUiModel(now)` lives in `ThreadScreen.kt` but carries no Compose runtime dependency, so `ThreadScreenMapperTest` calls it from a plain `./gradlew test` — relative-time labels, the `MessageItem`-only count, and the em-dash fallbacks all get covered without an emulator. The instrumented `ThreadScreenChannelInfoTest` then only has to prove the *wiring* (sheet shows, taps record the right events), not the *derivation*. Splitting derivation (unit) from wiring (instrumented) this way keeps the high-value assertions on the fast, device-free path — worth doing whenever a screen has non-trivial model derivation. (Flagged in the PR's Lessons-learned section.)
- **Button-initiated sheet close flips the boolean directly (immediate composition removal), not `sheetState.hide()` (animated slide-down).** The #217 contract note anticipated the host driving `sheetState.hide()` before `onDismiss` for an animated button-dismiss. This slice instead routes every button close through `ChannelInfoDismiss`, which flips `channelInfoOpen = false` and yanks the sheet out of composition immediately — matching the established house pattern (the sibling [`StatusSheet`](../features/status-sheet.md) and `WorkspacePickerSheet` hosts both flip a boolean the same way). Swipe-down / scrim / back-press still animate (the M3 `ModalBottomSheet` runs those before calling `onDismiss`). Code review flagged the button-dismiss-without-animation as a **non-blocking NIT** and judged it intentional; if animated button-dismiss is ever wanted it's a cross-sheet polish ticket, not a per-sheet concern.
