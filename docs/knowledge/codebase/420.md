# #420 — Rung-3 e2e harness polish: four host fixes into `scripts/e2e-emulator.sh`

Mechanical port of four operator-proven host-side fixes into the committed rung-3 emulator e2e runner,
so the script as checked in drives a live run instead of needing manual edits each session. The rung-3
harness (`scripts/e2e-emulator.sh` + `app/src/androidTest/.../e2e/` + `docs/e2e-interactive-stream.md`)
landed on `main` as a prototype merge (`f887814`); during the 2026-06-17 live session the operator found
four things the committed script still got wrong. This is the unblocked, pipeline-doable half of #419 —
the "reach green" half (live-run diagnosis + timeout tuning) is operator-run and tracked separately (#421).
**Not a redesign.** Four surgical edits, one shell script; no Kotlin, no Gradle, no new files.

## Files touched

- **`scripts/e2e-emulator.sh`** — the only behaviour-bearing changes. Four independent edits:
  - **`:48` (AC#3)** — `DAEMON_RELAY_URL="ws://127.0.0.1:${PORT}/v1/server"`, with the inline note
    `# newer daemons append /v1/server automatically`. The daemon (server side) needs the explicit
    `/v1/server` because v0.14.0-era daemons don't append the relay path themselves. The phone side
    (`PHONE_RELAY_URL`, `:51`) stays a bare **origin** (`ws://10.0.2.2:${PORT}`, no path) because
    `OkHttpRelayTransport` appends `/v1/client` itself — see [[pairedserver-relayurl-is-origin]] /
    [[phase4-wire-v1-path-trap]].
  - **`:106` (AC#1)** — `pyry pair -pyry-name=… --name=…`: the `pair` **subcommand now precedes** the
    global `-pyry-*` flags, matching the argument ordering current `pyry` requires.
  - **`:109,115` (AC#4)** — the inline python payload parser now reads `pair.out` by **file path via
    `argv`** (`python3 - "${PAIR_OUT}" <<'PY'` → `with open(sys.argv[1]) as f: for line in f:`) instead
    of the old `python3 - <"${PAIR_OUT}" <<'PY'` + `for line in sys.stdin:`. The loop body, the
    `{"server","token","server_static_pubkey"} <= obj.keys()` membership gate, and the three
    `SERVER_ID`/`TOKEN`/`SERVER_STATIC_PUBKEY` output lines are unchanged. **This is the only
    behaviour-bearing change** — the other three are config/ordering.
  - **`:141` (AC#2)** — `PYRY_ALLOW_INSECURE_RELAY=1` prepended to the daemon's env so it will connect
    to the plaintext (`ws://`, no-TLS) local relay; a daemon refuses a cleartext relay without this
    opt-in. (The daemon keeps its `-pyry-name` **global** flag here — it's not a subcommand invocation,
    so AC#1's ordering rule doesn't apply to this line.)

- **`app/src/androidTest/.../e2e/E2eTestApplication.kt`**, **`InteractiveStreamE2ETest.kt`** —
  spotless-only formatting (wrap a long `Log.i(...)`, add a blank line before a comment) on pre-existing
  rung-3 harness files, applied as a QA-gate rework (`bec916f`). **No behavioural change** — see Lessons.

**Not touched:** `docs/e2e-interactive-stream.md` (shared human-facing doc; its prose already describes
the intended flow — the "Assumptions to confirm on first run" section at `:95–111` is the context for
why pairing runs before the daemon and what the relay-path asymmetry is). The four fixes are
script-internal.

## Patterns established

- **Deliberate non-change (no scope creep against an unobserved failure mode):** `DAEMON_RELAY_URL` is
  also read by the pair invocation (`:106`) via `PYRY_RELAY_URL`, so after the AC#3 edit the minted
  token's embedded `relay` field carries the `/v1/server` path. The script **already ignores** the
  token's `relay` and the phone dials `PHONE_RELAY_URL` instead, so this is harmless. A second variable
  to keep the pair on a pathless origin was explicitly rejected — one-line edit, single source of truth.

## Lessons learned

- **`python3 - <file <<'HEREDOC'` collides on fd 0.** The heredoc and the file both claim stdin, so
  Python ends up reading the *file* as its program source (and `sys.stdin` no longer points at the file).
  On-host this raised `SyntaxError` on the QR line — the parser never saw the pairing payload and the run
  failed. Pass the file as **`argv`** instead: one stdin source (the heredoc = the program), no
  collision, and the parser becomes runnable standalone for verification. (Re-adding a clean
  `<fixture` redirect would have put the fixture on stdin and left no stdin for the heredoc program —
  you'd have to drop the heredoc and ship the parser as a separate file; argv keeps it inline.)
- **Pre-existing format violations surface on the first branch that runs `./gradlew check`.** The two
  rung-3 `androidTest` files were committed format-dirty in the `f887814` prototype merge (which never
  ran the pipeline's QA gate). This PR — which doesn't touch them — was the first to hit
  `:spotlessKotlinCheck`, so it inherited the failure and fixed it with `spotlessApply` (mechanical,
  no behavioural change). Format/lint failures aren't baseline-comparable; they route to a mechanical
  rework. See [[ktlint-filename-rule-single-class]] for the related ktlint filename rule.

## Verification

No Gradle/emulator/daemon/relay reachable from the pipeline — verification is host-local, per the spec's
strategy:

- **AC#4 (the only behaviour test):** the committed parser body, extracted and run standalone against a
  synthetic `pair.out` fixture (leading noise/QR line + one Go `RawURLEncoding` **no-pad** payload line —
  see [[pairing-qr-two-base64-alphabets]]). Happy path → `SERVER_ID`/`TOKEN`/`SERVER_STATIC_PUBKEY`
  extracted, exit 0. RED→GREEN: the same fixture failed under the old `<file <<'PY'` form (`SyntaxError`,
  exit 1). Negative fixture (missing `server_static_pubkey`) → skipped, "could not find … payload line",
  exit 1 — the key-membership gate stays selective.
- **AC#5:** `bash -n scripts/e2e-emulator.sh` → exit 0.
- `./gradlew check` → green after the spotless rework (`assembleDebug` green; `compileDebugAndroidTestKotlin`
  green because the diff touches `androidTest/`). The standard `test`/`assembleDebug` are N/A to the
  behaviour of a shell-script change.
- **Live end-to-end run** (headless emulator + host daemon + real claude reaching green) is **out of
  scope** — operator-run, sibling "reach green" ticket #421.
