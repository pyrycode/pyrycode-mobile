# #494 — declare the `INTERNET` permission explicitly

Adds `<uses-permission android:name="android.permission.INTERNET" />` to the app's own manifest so network capability is owned by us rather than folded in from a transitive library's manifest merge. Standard Android hygiene; **no runtime behaviour change** — INTERNET is a `normal` (install-time) permission and the merged manifest already granted it via a dependency. This only moves ownership of the declaration into `app/src/main/AndroidManifest.xml`.

## Summary

The app reached the network only because a transitive dependency's manifest declared INTERNET and the manifest merger folded it in — a hidden dependency with **no compile-time signal** if the carrying library were ever swapped or dropped. The committed "paste the pairing code instead" onboarding fallback (see the camera `uses-feature` comment, `AndroidManifest.xml:7-8`) makes dropping the QR-scanner dependency viable, so the fragility is real: losing it would break all networking, including the Phase 4 Noise_IK relay transport, at runtime. Declaring INTERNET ourselves removes the hidden dependency. Filed from the Cross-Repo Code Review 2026-07-03.

## Files touched

- `app/src/main/AndroidManifest.xml:5` — single line added: `<uses-permission android:name="android.permission.INTERNET" />`, placed immediately **before** the existing `CAMERA` declaration (now line 6). No other files; no Kotlin changes.

Deliberately **not** touched:

- `app/src/debug/AndroidManifest.xml` — the debug overlay declares no permissions (only `networkSecurityConfig` for cleartext to the local relay in e2e) and inherits `main`'s permission set, so the single `main` declaration also covers debug builds. No second edit needed.
- No code coupling. INTERNET is `normal`-protection: granted at install, no runtime consent prompt, no `checkSelfPermission`/`requestPermissions`. The only permission check in code stays `MainActivity.kt:206` (CAMERA). No permission-check code was added, correctly.

## Patterns established

- **`<uses-permission>` placement convention.** Group the permission elements contiguously at the top of the manifest, and keep the CAMERA permission + its explanatory comment + the camera `uses-feature` as an unbroken trio. New permissions go **before** CAMERA, not between CAMERA and its comment. See the CAMERA + `uses-feature` grouping first established in [#326](326.md).

## Lessons learned

- **The merged-manifest output path is AGP-version-dependent — the AC's cited path was stale.** AC2 / the spec point at `app/build/intermediates/merged_manifests/debug/AndroidManifest.xml`, but under the current AGP that file doesn't exist. The actual outputs are:
  - `app/build/intermediates/merged_manifests/debug/processDebugManifest/AndroidManifest.xml` — final debug variant
  - `app/build/intermediates/merged_manifest/debug/processDebugMainManifest/AndroidManifest.xml` — main-only merge (note: singular `merged_manifest`)

  Both show `grep -c 'android.permission.INTERNET'` → `1` (the merger dedupes the app-owned and transitive declarations by `android:name`). When a future ticket needs to inspect the merged manifest, don't trust a hardcoded path from an older spec — glob under `app/build/intermediates/merged_manifest*/<variant>/process*Manifest/` for the current AGP's layout.
