# #431 — Rung-4 deterministic emulator e2e: scripted `fakeclaude` backend

Adds **rung 4** of the mobile interactive-stream e2e ladder: a `DETERMINISTIC=1` mode on the rung-3
`scripts/e2e-emulator.sh` that swaps **real claude** for the scripted `fakeclaude` backend (pyrycode
#642), which replays a fixed claude-format JSONL fixture. The real app on the headless emulator and
the whole Noise/relay path stay real; **only claude is scripted**, so the daemon spawns no real claude
and the run consumes **zero claude turns** — cheap enough to run often, deterministic enough to re-run
back-to-back for the same pass. Foundation for #433 (spinner + tool steps) and #436 (reconnect +
replay), both `blockedBy` this. **No production Kotlin** — exercises the already-shipped, already
security-reviewed #337/#385 decode/fold path, doesn't modify it.

## Patterns established

- **Path B (seeded bootstrap-bound channel), not Path C (a pyrycode change).** The rung-3 flow taps
  **"New discussion"** → `create_conversation` mints a **fresh** per-conversation claude session
  (random UUID, passed as `--session-id`); the daemon's structured-turn producer tails that
  conversation's transcript **by that id** with no latest-file fallback. Real claude honours
  `--session-id`; **`fakeclaude` is env-only** — it ignores argv and always writes
  `<PYRY_FAKE_CLAUDE_INITIAL_UUID>.jsonl`. So a created-discussion turn lands in a file the producer
  never tails. The resolution (**no pyrycode change**) mirrors #642's bootstrap-bound model through the
  real UI: pre-seed **one promoted Channel** bound to the bootstrap session id and tap **that seeded
  channel**. One conversation, one session, one fixture file → the by-id tail matches exactly the file
  `fakeclaude` writes. (Path C — make `fakeclaude` honour `--session-id` — was rejected: the discussion
  flow still spawns two `fakeclaude` processes sharing one trigger path, so it needs per-session trigger
  support *on top of* `--session-id`; strictly more cross-repo work for marginal value, and rung 3
  already covers the real created-discussion flow.)
- **A flag on the existing script, not a sibling.** `DETERMINISTIC=1` (matching the script's
  `PORT=`/`DEVICE=`/`PYRY_NAME=` env-tunable convention) branches at three seams; the substantial shared
  scaffolding stays one source of truth — the rung-3 prototype is still being tuned, so two copies would
  mean fixing both. (Sibling-script was the documented fallback only if branching turned unwieldy; it
  did not.)
- **The fixture is a real file (`scripts/e2e-fixtures/ping.jsonl`), the documented extension point.** One
  claude-format line per turn-event, **trailing newline** (the producer tails line-delimited;
  `fakeclaude` appends verbatim). The "ping" line — a single `assistant` with `stop_reason:"end_turn"` +
  non-empty text — maps via the producer/mapper oracle to `turn_state(responding)` →
  `assistant_delta("ping")` → `turn_end` → `turn_state(idle)`, which the phone's #337 fold renders as a
  streaming assistant row finalized on `turn_end`. #433/#436 add sibling fixtures of the same shape.
- **The relay-path asymmetry is inherited from rung 3, not re-derived.** Daemon dials `…/v1/server`
  (explicit, v0.14-era daemons don't append it); phone dials a bare origin and `OkHttpRelayTransport`
  appends `/v1/client`. See [[phase4-wire-v1-path-trap]] / [[pairedserver-relayurl-is-origin]].

## Lessons learned

- **The seeded channel name must NOT contain the asserted substring (code-review MUST FIX).** It first
  shipped as `e2e-ping`. The channel `name` renders **verbatim** in the thread top bar
  (`displayName` → `ThreadTopAppBar`), so the reply assertion `onAllNodesWithText("ping", substring=true)`
  matched the **title node** and passed the moment the thread opened — a false green that held even if
  the scripted reply never arrived. Renamed to **`e2e-seed`** (test constant, script default + comments,
  doc) so the scripted "ping" reply is the **only** on-screen "ping"; a broken stream now correctly
  times out. General rule for tolerant substring asserts: the asserted token must not appear in any
  always-present chrome (titles, labels) the screen renders before the awaited event.
- **Fixture-drop fence: drop only *after* `send_message.ack`.** The ack stamps the producer cursor; drop
  the fixture earlier and the producer tails **past** it (cold-start race) → the phone gets **zero**
  envelopes. The host-observable fence is the `event=send_message.ack` line in `daemon.log` (logged at
  Info from the daemon-side `send_message` handler, which calls `WriteUserTurn`). Match the **event
  value**, robust to the slog handler's exact rendering.
- **Watcher polls in a bash `while` loop, not `tail -F | grep -m1`.** A single `kill` of the subshell on
  EXIT then fully reaps it — no orphaned `tail` left following a deleted log. (PR "Lessons learned".)
- **Isolated `HOME` must use a short `/tmp` prefix, not `$TMPDIR`.** On macOS `$TMPDIR` is long enough
  that the daemon's unix control-socket path can exceed the ~104-char `sun_path` limit (this is why
  pyrycode's `shortHome` uses a short prefix). `os.UserHomeDir()` reads `$HOME`, so the override
  redirects both `.pyry/<name>/` and `.claude/projects/` for `pyry pair` and the daemon alike. (PR
  "Lessons learned".)
- **`grep -qF`, not `grep -q`, for `send_message.ack` (code-review NIT).** Matching a literal so the `.`
  isn't treated as a regex wildcard.
- **Pre-create `<INITIAL_UUID>.jsonl` (`{}\n`) before the daemon starts.** Seeds the producer's first
  resolve at a tiny offset; an empty dir makes the first resolve retry ~500 ms later, possibly *past* the
  fixture. `{}` maps to no structured event.
- **`current_session_id == INITIAL_UUID` is load-bearing.** `sessionRouter.Route` rejects an empty
  `current_session_id` (pyrycode #678), and reconciliation binds the bootstrap session to the
  most-recent (here: only) `<uuid>.jsonl`, which is `<INITIAL_UUID>` — so the by-id tail matches
  `fakeclaude`'s file.

## Verification

The deliverable **is** the test; there's no unit test of the harness. Host-JVM checks (no device,
per the spec's strategy):

- `./gradlew test lint assembleDebug` green; `compileDebugAndroidTestKotlin` + `spotlessCheck` green
  (the new `.kt` filename matches its single public class — [[ktlint-filename-rule-single-class]]).
- `bash -n scripts/e2e-emulator.sh` + shellcheck clean; `ping.jsonl` is valid JSON; the bash
  `encode(workdir)` verified byte-for-byte against Go `encodeWorkdir`.
- **Operator-run (device required):** the actual headless-emulator run —
  `DETERMINISTIC=1 PYRYCODE_SRC=… bash scripts/e2e-emulator.sh` (`pixel2Api33AtdDebugAndroidTest`). No
  green e2e is claimed from the pipeline. Re-running back-to-back must yield the same pass — that
  determinism is the whole point and the thing to confirm once on real infra.
