# #145 — feat(ui/thread): status row component (Figma 16:58)

Adds the always-visible status row above the [`ThreadInputBar`](../features/thread-input-bar.md) at the bottom of [`ThreadScreen`](../features/thread-screen.md): a new public `ThreadStatusRow` composable mounted inside a `Column` in the `bottomBar` slot, showing `Model · effort · NN% used ▴` with threshold-driven coloring for the trailing `NN% used` segment. Three new fields land on `ThreadUiState` (`model`, `effort`, `tokenPercent`) populated by `ThreadViewModel` from companion-object stub constants inside the existing `combine(...)` block — the Phase-4 swap point is the three constant references. A new `onExpandClick: () -> Unit` parameter on `ThreadScreen` plumbs through to `MainActivity` as `{}` until [#146](https://github.com/pyrycode/pyrycode-mobile/issues/146) hosts the Status Sheet. See the new [Thread status row](../features/thread-status-row.md) feature doc.

## Summary

- **`ThreadStatusRow` is a single stateless composable** at `ui/conversations/thread/ThreadStatusRow.kt` (152 lines including eight previews). Public signature `ThreadStatusRow(model: String, effort: String, tokenPercent: Int, onExpandClick: () -> Unit, modifier: Modifier = Modifier)`. No stateful overload — there is no internal state to hoist; the spec's three primitives (`String`, `String`, `Int`) are the entire input contract. Same shape as a hoisted-state preview in the [thread-input-bar](../features/thread-input-bar.md) two-overload pattern, just without the stateful sibling.
- **Single `Row` with three text spans + trailing icon.** `Row(Modifier.fillMaxWidth().clickable(onClick = onExpandClick).semantics { role = Role.Button }.padding(horizontal = 16.dp, vertical = 4.dp).alpha(0.85f), verticalAlignment = Alignment.CenterVertically)`. Body: a single `Text` over an `AnnotatedString` built with three `withStyle(SpanStyle(color = …)) { append(…) }` blocks (model → `onSurface`; ` · $effort · ` → `onSurfaceVariant`; `$tokenPercent% used` → threshold color), then `Spacer(Modifier.width(4.dp))`, then `Icon(Icons.Filled.KeyboardArrowUp, contentDescription = stringResource(R.string.cd_thread_status_expand), tint = onSurfaceVariant, modifier = Modifier.size(14.dp))`. The `clickable` rides on the whole `Row` — the icon is not its own `IconButton`.
- **Text is `FontFamily.Monospace`, `12.sp` / `16.sp` line-height.** No custom font asset — `FontFamily.Monospace` is the project convention for monospace text (same primitive [`ToolCallRow`](../features/tool-call-row.md) uses). The 0.85f alpha matches the Figma `opacity-85` on the `16:58` node and is applied to the whole `Row` via `Modifier.alpha(0.85f)` rather than per-span — composing alpha three times in `SpanStyle` would have lost the icon.
- **Token-% color helper is private and file-local.** `@Composable private fun tokenPercentColor(tokenPercent: Int): Color` — `coerceIn(0, 100)` clamp first, then `< 50 → onSurfaceVariant`, `< 95 → warning` ([`MaterialTheme.colorScheme.warning`](../features/warning-color.md), [#119](./119.md)), `else → error`. The clamp is **defensive over the Phase-4 backend swap** — a real `AgentStatus.tokenPercent` could conceivably overshoot 100 during a usage spike; clamping in the helper means the threshold rules never branch incorrectly. Note the AC's `95%+` boundary is `>= 95` (i.e. `< 95 → warning`, `>= 95 → error`).
- **`ThreadUiState` gains three fields with Phase-2-stub defaults on the data class.**
  ```kotlin
  data class ThreadUiState(
      // ...existing seven fields unchanged...
      val model: String = "Opus 4.7",
  ```

  The defaults serve a dual purpose: (1) the `initialValue = ThreadUiState(conversationId, displayName = conversationId)` literal at `ThreadViewModel.kt:55-58` keeps compiling unchanged (defaults fill the three new fields); (2) `model`/`effort` defaults match the Phase-2 stub so the pre-subscription initial frame already paints the right strings — only `tokenPercent` differs (0 default vs 73 post-subscription) and that's intentional, see the test pair below.
- **`ThreadViewModel` populates the three fields from companion-object constants inside the existing `combine(...)` block.**
  ```kotlin

      // Phase 4 swap point: replace with backend AgentStatus flow.
      private const val STUB_MODEL = "Opus 4.7"
      private const val STUB_EFFORT = "high"

  ```
  Used in the combine emission as `model = STUB_MODEL, effort = STUB_EFFORT, tokenPercent = STUB_TOKEN_PERCENT`. The KDoc on the companion is the Phase-4 swap signpost: when the backend `AgentStatus` flow lands, this companion deletes and the three field references inside `combine` swap to reads off a new flow arm. The field shape (`String`, `String`, `Int`) is the stable contract — no premature `enum class Effort` or `value class TokenPercent` wrapper.
- **The Phase-2 stub `tokenPercent = 73` lands inside the warning band.** Deliberate — the developer (and the reviewer) immediately see the threshold-driven warning color rendering live in the running app, not just in previews. The four preview values (20, 60, 88, 97) sweep all three threshold buckets so every color path is visually verifiable.
- **`ThreadScreen.kt` `bottomBar` slot widens from one child to a `Column` of two children.** Pre-#145 was `bottomBar = { ThreadInputBar(onSend = onSendMessage) }`. Post-#145:

No new modifier on the outer wrapper `Column`.

## Patterns established

- **Phase-4 swap point as a companion-object constant trio.** Stub state with a clear backend-swap signpost goes on a `companion object` with `private const val STUB_*` names plus a one-line KDoc naming the phase. The combine-block assignments reference the constants by name rather than inlining the literals — the swap is two `find-and-replace` steps (delete the companion, swap each `STUB_*` reference to a `agentStatus.field` read) rather than a hunt for stub literals across the file. Future Phase-4-swap points (model/effort/tokens here, but also any future stub like agent identity, project label, etc.) should follow the same shape: companion-object constants + one-line phase KDoc + named references in the flow emission.
- **`Modifier.alpha(0.85f)` at the `Row` level for Figma `opacity-85` text-row treatments.** Setting the alpha on the whole row covers both the `AnnotatedString` and the trailing `Icon` in one place; applying alpha per-`SpanStyle` would have lost the icon and required a parallel `Icon` tint adjustment. Future text-with-trailing-icon rows that need a uniform translucency treatment should mirror this — row-level alpha is one line and theme-token-correct.
- **Eight previews for a tiny component is fine when the parameter sweep exercises distinct visual paths.** `ThreadStatusRow` ships with 4 × 2 previews (four token-% values × two themes) because each cell verifies a distinct color path (3 thresholds + 1 within-band) under both light and dark surfaces. The alternative `@PreviewParameter` provider with a single composable was flagged as acceptable in the spec; eight literal previews won on tap-target-to-render-time for the threshold-tuning reviewer, who wants to scroll the matrix in Android Studio's preview pane without an extra click.

## Lessons learned

- **`AnnotatedString` + per-`SpanStyle` colors is the right primitive for "three differently-colored segments in one `Text`".** The alternative — three sibling `Text` composables inside a `Row` — would have introduced per-text horizontal padding gaps (the ` · ` separators would be inter-`Text` space, not glyphs) and a layout-time variable width per cell. `buildAnnotatedString { withStyle(SpanStyle(color = …)) { append(…) } }` keeps the row a single layout node with glyph-perfect `·` separator placement.
- **`Modifier.alpha(0.85f)` at the row level, not at the SpanStyle level.** The Figma `opacity-85` is on the whole `16:58` node (text + iconography). Composing the alpha into each `SpanStyle.color = onSurface.copy(alpha = 0.85f)` works for the text portion but loses the icon — the icon would render at full opacity while the text reads dimmer, breaking the visual cluster. `Modifier.alpha(...)` runs in the draw layer and uniformly applies to every child of the `Row` including the `Icon`. This is the inverse of the [#188](./188.md) lesson on `BasicTextField`'s cursor — there, the override has to be in the explicit text-style slot because alpha doesn't reach the cursor brush. Different primitives, different places.
- **Defaulting `tokenPercent = 0` on the data class while the VM publishes `73` is a one-frame visual blip, not a bug.** The initial `stateIn` value emits before the `combine`'s first emission lands; for a tick the row says `Opus 4.7 · high · 0% used` (rendered in `onSurfaceVariant`, the under-50% color) before flipping to `73% used` in the warning color. Acceptable because the fake's `combine` upstream emits synchronously on first subscription — the initial frame is invisible in the running app — but a test reviewer might flag the asymmetry. Documenting here so the next reviewer doesn't re-derive the answer: the two test methods (initial-frame `tokenPercent == 0`, post-subscription `tokenPercent == 73`) pin both states intentionally; the asymmetry is a deliberate seam at the data-class-default vs combine-emission boundary.
- **`Icons.Filled.KeyboardArrowUp` over the Unicode `▴` glyph.** The spec listed both as acceptable; the vector won on accessibility (`contentDescription = stringResource(R.string.cd_thread_status_expand)` is a clean TalkBack label) and on tint stability (the glyph would inherit the trailing-span color, which is the threshold color — wrong, the icon stays `onSurfaceVariant` regardless of token-%). The `Modifier.size(14.dp)` was tuned to read at the same baseline as the 12.sp text without dominating; a 16.dp icon felt heavy next to the 12.sp typeface.
- **`semantics { role = Role.Button }` on the row's `Modifier` chain after `clickable`.** The spec called this "recommended; not strictly required by the AC" — it was added because the sibling [`WorkspaceChip`](../features/workspace-chip.md) and the [`thread-input-bar`](../features/thread-input-bar.md)'s title-tap `Text` already carry `Role.Button` semantics. TalkBack now announces the row as `"Opus 4.7 · high · 73 percent used, Button"` rather than just `"Opus 4.7 …"`, matching the surrounding accessibility profile.
