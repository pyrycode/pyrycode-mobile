# #417 — handle the `resync` marker: reset the replay cursor + surface the gap

The **react** half of the Phase 2 structured-streaming mid-turn-replay contract (ADR 025
§ Backpressure / replay), and the close of the chain #402 → #412 (record) → #416 (advertise) → **#417
(react)**. When the position the phone advertised as `hello.last_event_id` ([#416](416.md)) has **aged
out of the daemon's bounded ring** (pyrycode#646), gap-free in-ring replay is impossible, so the daemon
emits a **`resync` marker** — `type = "resync"`, binary → phone, v2-only control, inline
`{conversation_id}`, **no** `event_id` (server producer: `emitResync` / `TypeResync` in pyrycode
`internal/relay`; wire SSOT: pyrycode `docs/protocol-mobile.md` § "Interactive events (v2,
capability-gated)" → the `resync` row). This slice reacts by doing exactly two things on the existing
single inbound path:

1. **Reset the replay cursor** ([`ReplayCursor`](../features/replay-cursor.md), #412) back to its
   no-cursor state, so the next reconnect's `hello`-build reads `null` and **omits** `last_event_id`
   (#416) — a fresh resume rather than re-advertising the aged-out position and mis-resuming.
2. **Surface that a gap occurred** as a new `LiveSessionEvent.ReplayGap` on the existing
   [`liveSessionEvents`](../features/live-session-events.md) stream (#385) — an observable signal a
   future UI layer can render.

**Out of scope — deferred:** issuing a `backfill_since` full reload on resync. The daemon-side
full-reload handler the marker ultimately points at is **not built** (no daemon message-history store
yet; `internal/conversations` is metadata-only, `backfill_since` has no handler). This slice's contract
ends at "reset the cursor + surface the gap"; the full-reload fallback lands in a later ticket once the
daemon handler exists.

Three production touches in `data/` plus one mechanical consumer compile-fix in `ui/`. **No new files,
no interface change, no wire-model change, no DI change.**

## Files touched

Production — 4 modifications:

- **`data/network/ReplayCursor.kt`** — a single new `fun reset()` (`:49`) beside `record`: `mark.value
  = null`, a direct atomic [`MutableStateFlow`] set back to the no-cursor state, consistent with
  `record`'s lock-free backing. Called only from the single inbound collector (the same writer as
  `record`), so reset and record never race within a connection; `latest`, read at the next
  connection's hello-build, sees the cleared value via the `StateFlow` happens-before.
- **`data/model/LiveSessionEvent.kt`** — a sixth subtype `data class ReplayGap(override val
  conversationId: String) : LiveSessionEvent` (`:91`), carrying **only** the conversation the gap
  concerns (for routing) — no turn / event / text content. The file's top-level KDoc gained a
  paragraph noting the family now also carries one **control-derived** signal beyond the five
  binary→phone render envelopes: `ReplayGap` is not itself a render event and carries no verbatim
  user/tool text. A `data class` with a single `String` field → **stable** for Compose; consumers that
  later render it stay skippable.
- **`data/repository/RemoteConversationRepository.kt`** — a new `TYPE_RESYNC = "resync"` companion
  constant (`:1083`, beside `TYPE_STALL`) and a `TYPE_RESYNC` arm in `onInbound`'s `when (envelope.type)`
  demux (`:340`), gated **identically** to the `stall` / structured-event / `recordReplayCursor` arms
  (`CAPABILITY_INTERACTIVE in negotiatedCapabilities()`):

  ```kotlin
  TYPE_RESYNC -> {
      if (CAPABILITY_INTERACTIVE in negotiatedCapabilities()) {
          replayCursor.reset()                              // unconditional on the type match
          resyncConversationId(envelope)?.let { id ->       // surface only if the id decodes
              mutableLiveSessionEvents.tryEmit(LiveSessionEvent.ReplayGap(id))
          }
      }
  }
  ```

  Plus a small throw-free helper `private fun resyncConversationId(envelope: Envelope): String?`
  (`:434`) that reads `conversation_id` as a JSON string **directly off `envelope.payload`** cast to
  `JsonObject` (no `decodeFromJsonElement`, no DTO — mirrors the server's payload-less inline-struct
  precedent), returning `null` when the payload is not a `JsonObject`, the field is absent, or it is not
  a JSON string. New import: `kotlinx.serialization.json.JsonPrimitive`.
- **`ui/conversations/thread/ThreadViewModel.kt`** — the **only** consumer fan-out: two lines. The
  6th subtype broke the two **exhaustive** `when (event: LiveSessionEvent)` blocks, so
  `is LiveSessionEvent.ReplayGap` joins the existing ignore-group in each — `thinkingTransition`
  (`:281`, the `→ null` group: a gap is not a thinking transition) and `reduceLive` (`:503`, the
  `→ this` group: a gap does not change the thread fold in this slice). **No `else` branch** was added —
  keeping both `when`s exhaustive preserves the Kotlin safety that forces the future rendering consumer
  to consciously handle `ReplayGap`.

## Patterns established

- **A payload-less inline control marker is read structurally off `JsonObject`, never via a DTO.** Where
  the server models a marker as a payload-less inline struct (no named `…Payload`), the mobile side
  mirrors it: `resyncConversationId` casts `envelope.payload as? JsonObject` and pulls the one field as a
  `JsonPrimitive` string — **no `@Serializable` DTO, no `decodeFromJsonElement`**. Because it is pure
  structural access it **cannot throw**, so it cannot kill the single inbound collector (no `try/catch`
  needed, unlike `decodeStall` / `decodeLiveSessionEvent`). Reuse this shape for any future
  `{single_field}` control marker the server defines without a payload struct.
- **Split a control arm into an unconditional safety action + a payload-conditional surface.** The reset
  (the safety action — avoid mis-resuming) is **unconditional on the type match**, because the cursor is
  **process-global** and does not depend on which conversation the payload names (per the ticket's
  Technical Notes — "reset it regardless"); the `ReplayGap` surface is **conditional on a decodable
  `conversation_id`** (it needs an id to route). So a malformed/absent `conversation_id` still resets the
  cursor and only drops the surface. The principle: the action that prevents a wrong state must not
  depend on untrusted payload shape; only the routing-dependent part may.
- **Add a sealed-family member → grep `is <SealedType>\.` across `src/test` too, not just `src/main`.**
  See Lessons learned — the test tree can hold its own exhaustive `when`.

## Lessons learned

- **A new sealed-interface subtype can break a third exhaustive `when` that lives in the *test* tree.**
  The architect's "only consumer fan-out" note named the two exhaustive `when (event: LiveSessionEvent)`
  blocks in `ThreadViewModel` — but missed a third in `RemoteConversationRepositoryTest` (an
  ordering-assertion mapper that turns each event back into its wire-`type` string). Adding `ReplayGap`
  broke that test's compile too (it needed an `is LiveSessionEvent.ReplayGap -> "replay_gap"` branch).
  **Before adding a sealed subtype, grep `is LiveSessionEvent\.` across `src/test` as well as
  `src/main`** — a `when` with no `else` is a compile-time tripwire wherever it lives, and exhaustive
  `when`s deliberately have no `else` (here, in both prod and test, to force conscious handling).
  (Lifted from the PR's *Lessons learned*.)

## Security

`security-sensitive`. Architect security review **PASS**, no MUST FIX (spec § Security review). The one
new trust boundary is the `TYPE_RESYNC` arm. The `resync` frame arrives **post-`Noise_IK`** (authenticated
as from the paired daemon) but is still treated as untrusted — a buggy/compromised daemon could emit a
spurious `resync`. Three properties bound the blast radius:

- **The inline `conversation_id` is read throw-free and used only to tag the surfaced `ReplayGap`** for
  routing — never to index a filesystem path, never for an authorization decision, never trusted beyond
  "which conversation to tag." The cursor reset does **not** read it (process-global).
- **Blast radius of a spurious/forged `resync` is self-inflicted and bounded:** a false gap-surface + a
  cursor reset → the next reconnect re-advertises a *fresh* position (omits `last_event_id`) and
  re-replays. No cross-party compromise, no data corruption. Crucially the reset can only **lose** the
  in-ring tail-replay optimization (fall back to a fresh resume); it cannot **suppress** live frames —
  the historical caught-up-watermark suppression was the *server* concern, already clamped by
  pyrycode#663 (re-verified at #416's architect time; see [#416](416.md) § Security).
- **Fail-closed `interactive` gate** (consistent with the `recordReplayCursor`, `stall`, and
  structured-event arms): a non-interactive phone never advertised a cursor (the cursor only advances
  under the same gate, so `latest` is always `null` there), so a `resync` to a non-interactive phone is
  ignored — no reset (a no-op anyway), no surface.

No token/secret on the path (`conversation_id` is non-secret, already held by the phone; the cursor is a
non-secret event ordinal). No file/storage (`ReplayCursor` is in-RAM only — `reset()` is a
`MutableStateFlow.value = null`). No IPC/Android, no crypto surface. **Inbound-only** — adds no new
outbound frame, size cap, timeout, or TLS setting. A `resync` flood is bounded: `reset()` is idempotent
(null→null after the first) and `tryEmit` is the existing non-blocking `DROP_OLDEST` bounded-buffer emit,
so a flooding daemon can neither grow memory nor back-pressure the single inbound collector. **Nothing on
the arm logs** the envelope or its payload (uniform with every other `onInbound` arm — no-secrets-in-logs).
