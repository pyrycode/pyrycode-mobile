# #270 — feat(ui/a11y): Channel List row accessibility — merged TalkBack semantics + idle announcement

Phase 5 accessibility. Closes the one code-observable a11y gap on the Channel List: channel and recent-discussion rows are now exposed to TalkBack as **single, merged, focusable labels** (display name + last-active relative time), and channel rows additionally announce the idle ("sleeping") state that was previously conveyed only by a silent visual dot. Additive — no public API change, no signature change, **no visual change** (Figma `15-8` is content-reference-only; the diff introduces no colour/`TextStyle` literals and leaves the dot/layout/tokens untouched).

Scope was narrowed from the original three-screen icon-description pass after a 2026-05-30 audit found the icon-only controls already carry `cd_*` descriptions and that Conversation Thread + Settings are a11y-compliant. The residual, testable gap was the list rows — that is all this ticket touches.

Mirrors the established in-repo merged-semantics pattern: `SeeAllDiscussionsRow` in `ChannelListScreen.kt` (`.semantics(mergeDescendants = true) { contentDescription = …; role = Role.Button }`). No new types, no new composables, no ViewModel/state changes.

## Summary

- **`ConversationRow.kt`** — hoisted the relative-time string to a single `val relativeTime = formatRelativeTime(conversation.lastUsedAt)` (reused by both the new label and the existing `trailingContent`, replacing the inline call), computed a `rowDescription` that branches on `conversation.isSleeping`, and appended `.semantics(mergeDescendants = true) { contentDescription = rowDescription; role = Role.Button }` to the gesture modifier. The branch picks `cd_conversation_row_idle` when sleeping, `cd_conversation_row` otherwise. `headlineContent` / `trailingContent` / the 8.dp sleeping dot are untouched — `mergeDescendants` collapses the children into one node and the explicit `contentDescription` becomes the authoritative announcement.
- **`DiscussionPreviewRow.kt`** — same hoist (`relativeTime`), a `rowDescription = stringResource(R.string.cd_discussion_preview_row, displayName, relativeTime)`, and `.semantics(mergeDescendants = true) { contentDescription = rowDescription }` appended to the `Column`'s modifier chain **between** the existing `.clickable(role = Role.Button, …)` and `.padding(…)` (matching `SeeAllDiscussionsRow`'s semantics-before-padding ordering). `role` is not repeated in the semantics block — it already comes from `clickable`.
- **`strings.xml`** — three positional-arg format strings (locale-safe, no runtime concatenation):
  - `cd_conversation_row` = `"%1$s, %2$s"` → "leaky-faucet, 3h ago"
  - `cd_conversation_row_idle` = `"%1$s, idle, %2$s"` → "leaky-faucet, idle, 3h ago"
  - `cd_discussion_preview_row` = `"%1$s, %2$s"` → "Help me debug auth flow, 2h ago"
- **`ConversationRowTest.kt`** (new androidTest) — three `@Test`s: active channel exposes exactly one node with `contentDescription == cd_conversation_row(name, time)` (`assertCountEquals(1)` proves single focusable node, not fragments); idle channel exposes the `cd_conversation_row_idle` label and the active label is **absent**; the merged node `assertHeightIsAtLeast(48.dp)`.
- **`DiscussionPreviewRowTest.kt`** (new androidTest) — three `@Test`s: discussion-with-message and discussion-without-message both expose the single `cd_discussion_preview_row(name, time)` label; the row meets the 48dp touch target.

## Patterns established

- **`.semantics(mergeDescendants = true) { contentDescription = …; role = Role.Button }` is now the standard way to make a multi-`Text` list row a single, state-bearing TalkBack label** — applied to `ConversationRow` and `DiscussionPreviewRow`, matching `SeeAllDiscussionsRow`. The explicit `contentDescription` is the authoritative announcement; child `Text`s still contribute their `text` property to the merged node (so `hasText`-based finders keep matching), but TalkBack reads the `contentDescription`. **Use `semantics`, never `clearAndSetSemantics`** — the latter would drop the child `text` and break the existing `ChannelListScreenTest` / `DiscussionListScreenTest` `hasText` guards.
- **Accessibility labels for state are sourced from a flag + a positional-arg format string, not from runtime concatenation.** The idle announcement is the `isSleeping` flag selecting between `cd_conversation_row` and `cd_conversation_row_idle`; args are `(displayName, relativeTime)`. This is the first `cd_*` string family that is a *full row label* rather than a single-control description, and the first place a row's visible-only state (the sleeping dot) got a spoken equivalent.
- **Spoken idle term is "idle", not "sleeping"** — clearer in audio and matches the user-story's primary word, even though the data flag is `isSleeping` and the visible dot is described internally as "sleeping". String-only, reversible if a later on-device TalkBack pass disagrees.
- **Message preview is intentionally excluded from the discussion row's *announced* label** (AC #3 makes it optional). The preview `Text` stays visible and still merges into the node's `text`; only the `contentDescription` is name + time — the deterministic, testable signal. Idle state is **not** added to discussion rows because `DiscussionPreviewRow` renders no sleeping dot (parity with the screen — nothing visible to mirror).
- **Component-level androidTest is now established for these row primitives.** Before #270 the rows had no instrumented tests (their visual contract was exercised only through the screen tests). The two new files follow `SessionBoundaryDelimiterTest`'s idiom (`createComposeRule`, `setContent { PyrycodeMobileTheme { Component(...) } }`, `onAllNodes(hasContentDescription(...)).assertCountEquals(...)`), and build expected labels from the same `stringResource` + `formatRelativeTime` the production code uses — no hardcoded time strings, so no clock-skew flake.

## Lessons learned

- **`onNode` / `onAllNodes` are members of the compose test rule** (`SemanticsNodeInteractionsProvider`), **not top-level functions.** Adding `import androidx.compose.ui.test.onAllNodes` is an unresolved-reference compile error. Only the `onNodeWithText`-style standalone helpers need importing; the rule-method finders (`onNode`, `onAllNodes`) are called on `composeTestRule`. (Lifted from the PR's Lessons-learned section.)
- **Test determinism via mid-bucket fixtures.** The tests pin `lastUsedAt` to `now - 2.hours` / `now - 3.hours`, which sit mid-bucket in `formatRelativeTime`'s hour band (`inWholeHours` truncation), so the production-computed relative time and the test's expected-label string are identical without flake. Don't pick a fixture near a bucket boundary (e.g. `59.minutes`, `47.hours`) — the truncation could disagree between the two computations.
- **The change has a wider blast radius than the spec stated, and that's desirable.** The architecture spec claimed both rows are "consumed only by `ChannelListScreen`" with "0 consumer cascade." In fact `ConversationRow` is also consumed by `DiscussionListScreen.kt:197` (the long-press "Save as channel" row) and `ArchivedDiscussionsScreen` (#94). Because the merge was applied to `ConversationRow` itself (not at a call site), **all three** consumers now get the merged label + idle announcement — the sleeping dot renders in `DiscussionListScreen` too, so the parity is correct. Code review verified this does **not** break `DiscussionListScreenTest` (its `hasText(substring = true)` finders still resolve through the merged node). Flagging so the spec's "single consumer" claim isn't taken at face value in a future refactor of `ConversationRow`.
- **Tests are compile-verified, not device-run.** `./gradlew connectedAndroidTest` was **not** executed (no emulator/device); the two new instrumented files were verified only via `./gradlew compileDebugAndroidTestKotlin` (green). Code review read both test files and confirmed the logic (merged-label assertions, idle negative-assertion, 48dp target, expected-string construction) is correct, but recommended an on-device/CI run before treating them as a live regression guard. This is the same "instrumented tests compile-verified only, no headless device CI" boundary that recurs across the project.
