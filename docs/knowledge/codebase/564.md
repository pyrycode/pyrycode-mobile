# #564 — Wire `create_workspace_folder` to the daemon's v2 wire message

**Spec:** `docs/specs/architecture/564-*.md` ·

**Feature docs:** [Remote conversation repository](../features/remote-conversation-repository.md)

Size **S**, `security-sensitive` (PASS).

## Summary

Overrides `RemoteConversationRepository.createWorkspaceFolder(name)` — previously the throwing
interface default (`error(...)`) — with a live round-trip against the daemon's v2
`create_workspace_folder` (server pyrycode#887): encode `{parent: "~/pyry-workspace", name: name.trim()}`
→ `sendAndAwaitReply` → decode the **new** `workspace_folder_created` reply's bare `{path}` → return the
server-authoritative canonical path. Registers the new reply type in the inbound demux (the load-bearing
edit — a missed registration hangs the pending deferred, the same hazard [`delete`](532.md) faced). Then
fixes the actual user-facing bug the ticket exists for: the shared `WorkspacePicker.kt` create-launch had
**no** `try`/`catch`, so any failure (not-connected, server error, malformed reply) crashed the app —
reproducing identically from all three entry points that mount the shared picker (thread workspace flow,
settings default-workspace row, FAB long-press). The launch is now wrapped: `CancellationException`
rethrown first, everything else caught and shown as a fixed generic `AlertDialog` message.

This is the **leanest** write-verb in the family — no `conversation_id`, no projection fold, a genuinely
new reply type, and (unlike every prior mutation) its return value is the *sole* effect.

## Files touched

- **`app/src/main/java/de/pyryco/mobile/data/network/CreateWorkspaceFolderPayloads.kt`** (new, 46 lines)
  — two DTOs in one file (the `DeleteConversationPayloads.kt` two-in-one shape, sidesteps the ktlint
  single-class-filename rule): `CreateWorkspaceFolderPayloadDto` (encode-only, `{parent, name}`) and
  `WorkspaceFolderCreatedPayloadDto` (decode-only, `{path}`). No `@SerialName` on any field — all three
  keys are already the wire names.
- **`app/src/main/java/de/pyryco/mobile/data/repository/RemoteConversationRepository.kt`** (+78/−9):
  - `onInbound`'s correlated-success-reply `when` arm (:341, **load-bearing**) — adds
    `TYPE_WORKSPACE_FOLDER_CREATED` beside `TYPE_ACK, TYPE_CONVERSATION_CREATED, TYPE_CONVERSATION_UPDATED,
    TYPE_CONVERSATION_DELETED, TYPE_SCREEN_SNAPSHOT, TYPE_SESSION_SETTINGS_UPDATED`. Without this the
    reply falls through to `else -> Unit` and the waiter hangs until #488 teardown.
  - `override suspend fun createWorkspaceFolder(name: String): String` (new, ~1691) — `require(name.isNotBlank())`
    first (no send on blank/whitespace) → build `Envelope(type = TYPE_CREATE_WORKSPACE_FOLDER, ...)` →
    `sendAndAwaitReply` → `decodeFromJsonElement<WorkspaceFolderCreatedPayloadDto>(reply).path`. No
    per-error catch (inherits centralized `mapError`), **no fold** — the only effect is the return value.
  - Three new companion constants: `TYPE_CREATE_WORKSPACE_FOLDER`, `TYPE_WORKSPACE_FOLDER_CREATED`, and
    `WORKSPACE_FOLDER_PARENT = "~/pyry-workspace"` (the fixed, tilde-anchored client root — anchoring at
    `~/` is load-bearing: a bare relative string would resolve against the daemon's process cwd instead of
    its `$HOME`).
- **`app/src/main/java/de/pyryco/mobile/ui/conversations/components/WorkspacePicker.kt`** (+42/−9,
  **the crash fix**): `WorkspacePickerInternal` gains `var errorMessage by rememberSaveable { mutableStateOf<String?>(null) }`.
  The create-launch wraps `onPicked(repository.createWorkspaceFolder(name))` in
  `catch (CancellationException) { throw it }` (must be first — JVM `CancellationException extends
  IllegalStateException`, see [[catch-illegalstate-swallows-cancellation]]) then `catch (Exception) {
  errorMessage = CREATE_FOLDER_ERROR_MESSAGE }` (a fixed generic literal — never the server's
  `RelayErrorException.message`, never the attempted name/path). A trailing `errorMessage?.let { ... }`
  renders an `AlertDialog` ("Couldn't create folder" / OK) above the still-open `ModalBottomSheet`
  (`onPicked` was never called on failure, so the sheet stays visible). Deliberately **not**
  [`GuardedRepoLaunch`](../features/guarded-repo-launch.md) (#490) — that guard silently swallows, which
  fails AC #3's "user-visible message."
- **`app/src/test/java/de/pyryco/mobile/data/network/CreateWorkspaceFolderPayloadsTest.kt`** (new, 55
  lines) — request encodes to exactly `{"parent":"~/pyry-workspace","name":"foo"}`; reply `{"path":...}`
  decodes correctly.
- **`app/src/test/java/de/pyryco/mobile/data/repository/RemoteConversationRepositoryTest.kt`** (+154) —
  `startCreateWorkspaceFolder` + `workspaceFolderCreatedEnvelope` helpers, mirroring the `delete_*`/
  `rename_*` suites: request-shape (proves the fixed parent + client-side trim), success returns the
  **reply's** path (fed a path that is *not* a naive join of the request — proves server-authoritative),
  blank/whitespace name → IAE with **nothing sent**, not-connected → ISE, server error
  (`protocol.malformed`) → `RelayErrorException` (message asserted to carry no name/path leak), malformed
  reply → decode throws. The success test also proves the demux registration — without it the deferred
  never completes and the test times out.
- **`app/src/androidTest/java/de/pyryco/mobile/ui/conversations/components/WorkspacePickerTest.kt`**
  (+39) — new component test: injects a repository whose `createWorkspaceFolder` throws
  `IllegalStateException`, drives row → dialog → Create, asserts the generic error message displays,
  `onPicked` was never invoked, and tapping OK dismisses it. `androidTest` is not compiled by the
  mandatory gates; verified via `./gradlew compileDebugAndroidTestKotlin` (not run against a device this
  session — no emulator connected).

**Not touched** (zero consumer fan-out — the interface signature is unchanged): `ConversationRepository`
interface, `StableConversationRepository` (already delegates), `FakeConversationRepository` (its
`createWorkspaceFolder` still returns a relative `pyry-workspace/$name` path — a deliberate, benign
fake≠remote divergence, not aligned here), `WorkspacePickerSheet.kt`, `CreateFolderDialog.kt` (already
trims + disables Create on blank).

## Patterns established

None new for the data-layer spine — this is a confirming instance of the `rename`-shaped
request→`sendAndAwaitReply`→decode template, minus the fold (the delta from every prior mutation:
zero projection writes, because the verb names no conversation). The genuinely new pattern is on the UI
side: **the first bespoke (non-`GuardedRepoLaunch`) failure surface in the picker family**, because this
is the first call site where "silently swallow" (the guard's posture) fails the acceptance criteria
outright — a crash fix, not a UX nicety, needs the failure *seen*. Future shared-composable call sites
that must never crash but also must never silently no-op should reach for this shape (catch
`CancellationException` first and rethrow, catch `Exception` broadly, surface a fixed generic message)
rather than `GuardedRepoLaunch`.

## Lessons learned

- **`FakeConversationRepository` is `final` — a throwing test double needs interface delegation, not
  subclassing.** The component test builds `object : ConversationRepository by FakeConversationRepository() {
  override suspend fun createWorkspaceFolder(name: String): String = throw IllegalStateException(...) }`
  rather than trying to subclass the fake. No production change to the fake was needed or made. (From the
  PR's own "Lessons learned" section.)
- **A verb with a brand-new reply type always needs the demux registration — this is now the fourth time
  the pattern repeats** (after [#532](532.md) delete): whenever a mutation's reply is not a reuse of an
  already-routed type (`conversation_updated`, `ack`, etc.), grep the `onInbound` success-arm `when` list
  before assuming the request/reply spine is complete. `changeWorkspace` ([#560](560.md)) is the
  contrasting case — same request/reply shape, but reused `conversation_updated`, so it needed no demux
  edit at all. Read the reply type name against the existing arm list, don't assume from the request
  shape alone.
