Compact context-overflow reliability, Mobile #2442

Supported mechanism
Core #3725 / PR #3726, merged as 3d5379ec4b778c569c27b7639a2ae495b32cee0d,
repairs accepted-message publication identity. Previously operatorMessageHistory
appended the message before its linked send_delivered outcome. A follower could
publish that message under an identity which the later join withdrew. The
publisher then required a baseline and retired the live peer. Reconnection can
recover durable thread content without recovering the original fresh recovery
offer. The repaired message carries its committed accepted_entry_id before it
can become public. Delivery and outcome update the same permanent item.

This mechanism is consistent with BOTH historical Compact failures below.
Neither archived Mobile failure establishes the exact assertion phase or actual
history publication boundaries. Core's controlled regression establishes the
mechanism; a passing Mobile rerun alone does not diagnose it. No distinct Mobile
production defect has been established. The teardown-time destroyed Activity
and focus record is not evidence that lifecycle caused either failure.
